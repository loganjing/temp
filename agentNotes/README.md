# 项目 Agent Notes 导航

这里记录稳定的项目事实和工作导航，不复制当前 Work Item 的需求、计划或执行报告。先读当前任务输入和批准设计，再读工作区根目录 `AGENTS.md` 与 `platform-baseline.json`，然后只按任务影响选择所需资料。修改 `app/<app-name>/` 时，还要读该包内的 `AGENTS.md`。

## 权威来源与冲突处理

- 用户当前指令和当前批准 Work Item 决定目标与验收范围。
- 根目录 `AGENTS.md` 规定工作区级协作约定；应用包内 `AGENTS.md` 规定源码布局与依赖边界。
- `platform-baseline.json` 记录初始化后的包路径、已选模块状态和代码入口，不代替需求或批准设计。
- 本目录只记录确认后仍然有效的项目事实。项目说明、历史记录或旧结论不能覆盖当前批准的目标。
- 源码、Schema、迁移和真实运行结果用于判断当前实现。若实现证据与批准目标冲突，报告差异、影响和需要处理的 owner；不要静默更改目标或宣称目标已实现。
- receipt/report 记录本次工作和验证结果；不要把一次执行结果复制成长期项目事实。长期决定只有在后续 Work Item 仍需遵守时才写入项目 notes。

## 按任务影响选择资料

| 任务影响 | 优先读取 | 重点检查 |
|---|---|---|
| 页面、交互或视觉 | 当前需求/设计、`platform-baseline.json` 中的 client 入口；需要浏览器验收时读 QA 指南 | 页面状态、语言、主题、加载/错误/空状态 |
| API 或跨端契约 | 已批准 technical contract（若有）、server/client/shared 入口及相关调用链 | 请求响应、校验、错误形状和转换边界 |
| 业务规则或计算 | 当前批准需求/设计、相关业务代码和现有测试 | 规则 owner、边界条件、失败行为和可重复证据 |
| 数据、迁移或生命周期 | 数据设计、地图中的迁移/存储入口 | 数据 owner、约束、状态转换、事务、失败恢复和兼容要求 |
| 身份、授权或租户隔离 | 安全/身份设计、server auth 与授权入口 | 可信身份来源、服务端授权、资源范围和拒绝路径 |
| 架构、模块或部署接线 | 架构基线、`platform-baseline.json`、选定模块 manifest 和运行配置 | 依赖方向、模块状态、启动/关闭及部署入口 |
| 浏览器验收 | `00-qa-start-here.md`、`qa-browser-guide.md` 和当前验收条件 | 启动方式、隔离数据、核心用户流程和真实结果 |

一个任务影响多个类别时，只补读相应资料。不要为了“读全”遍历整个 `agentNotes/` 或地图列出的全部源码。

## 资料维护

- `00-qa-start-here.md` 是 QA 阅读入口；`qa-browser-guide.md` 记录经实现核实的运行方式、隔离测试数据和核心浏览器流程。两者不重复维护同一信息。
- 新增架构、数据生命周期或已知差距说明前，先确认这些事实不能由批准设计、代码地图或 Work Item 唯一承载。只在有持续维护价值时创建文件，并在任务计划中指定唯一写入 owner。
- 长期决定应记录状态、日期、理由、影响和替代关系。一次 Work Item 的决定留在该 Work Item；不要另造任务报告、审计收据或自动化台账。
- 已知差距必须写明 owner、影响和下一步/复查条件。列出差距不代表允许绕过需求、安全要求或验收。
- “计划增加的自动化”和“已经运行的自动化”要区分；只有可重复命令和真实结果才是执行证据。

## 有状态变更的计划要点

任务涉及新数据或持久状态时，按风险说明：所表示的事实及唯一 owner、字段和约束、读写路径、允许状态转换、权限条件、并发/事务要求、重复请求行为、失败回滚或恢复、迁移兼容和验证证据。只列适用项，不把整份清单复制进每个子任务。
