# QA 从这里开始

本页用于说明 QA 的准备和执行顺序。它是导航说明，不是验收基线或测试结论。

## 按此顺序阅读

1. 阅读当前任务已确认的需求、已批准设计、验收条件和 QA 报告契约。
2. 从 `ReadMe.md`、应用包配置、已批准设计和实现交接资料中核实应用入口、启动方式、安全的测试数据准备方式、角色和候选浏览器流程。
3. 阅读派发的 QA Skill 以及报告 schema/validator 说明。在开始测试或浏览器操作前，完成要求的报告预检。
4. 阅读实现交接资料和开发验证证据，以了解本次改动和风险；不要把它们当作 QA 证据。

## 执行顺序

报告预检通过后，先核实并启动应用，确认预期入口页面正常。使用隔离测试数据和安全的测试账号，然后从最短的真实浏览器流程开始，覆盖当前 UI 验收条件。若无法核实启动方式、角色或数据准备方法，停止相关验证并在 QA 报告中记录阻塞原因；不得猜测或使用真实凭据、真实用户数据。只有当浏览器流程无法证明相关验收或风险时，才补充 API 或安全检查。

以当前验收条件为准。项目文档帮助定位路由、命令、角色和数据准备方式，但不能证明任何行为已通过。如果资料与已批准设计、当前配置、启动日志或本轮浏览器/API 观察结果冲突，应以当前可核实的信息为准，并在指定 QA 报告中记录差异。不要在项目文档或 QA 报告中填写凭据或秘密值。
