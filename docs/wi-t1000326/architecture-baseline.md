# 130-clock 架构基线（simple-frontend / 紧凑路线）

- 需求基线：`docs/wi-t1000326/requirements.md`（prepare 已按 SHA-256 校验的批准快照）
- 应用分类：simple-frontend（只读展示；无服务端、无持久化、无共享数据），已通过 classify 固定为 compact 路线
- 覆盖关系：本设计承载 AC-01（页面实时显示当前时分秒）；不复制需求语义与验收场景

## 页面与交互范围

- 单一页面 SPA，无路由、无多视图。页面唯一内容是实时时钟：时、分、秒三个部分，格式 `HH:MM:SS`（24 小时制，各部分两位补零）。
- 用户无任何输入或操作：页面打开即显示当前时间，随真实时间自动按秒更新，无需手动刷新。
- 不显示日期、不提供 12/24 小时制切换（需求未规定制式，保守默认 24 小时制）；版式为单个居中的时钟显示，样式细节留给实现层。

## 浏览器状态与数据归属

- 本应用无业务数据存储：不写 `localStorage`，不持久化任何记录。需求不要求刷新后保留任何值——时钟刷新或重开页面后重新读取设备当前时间即满足语义。
- 唯一数据来源是用户设备本地时钟（浏览器 `Date` API），与需求"时间来源默认采用用户设备本地时间"一致。
- 显示状态（当前时分秒）是组件内瞬态状态，实时派生自当次读取的系统时间；仅在本浏览器当前页面会话内使用，不与其他浏览器、设备或用户共享，也不与服务端同步（无服务端）。

## 实现入口与运行方式

- 新建 React + Vite SPA（npm）。入口为 Vite 标准 SPA 入口（`index.html` + 根组件挂载），时钟组件为唯一页面组件。
- 时钟驱动机制（承载秒级精度与"始终最新"）：
  1. 组件挂载时立即读取一次设备时间并渲染，保证打开即可见；
  2. 之后按秒边界驱动：计算距下一秒边界的延时并链式调度，每次更新都重读 `Date` 而非累加计数，避免定时器漂移引入显示偏差；
  3. 监听 `visibilitychange`，页面从后台恢复可见时立即重读一次，规避后台标签定时器节流造成的滞后。
- 精度边界：显示值始终来自当次读取的系统时间，驱动调度只决定"何时重读"，不改变时间语义；上述机制使页面显示与设备时间的偏差远小于 1 秒。
- 运行方式：开发期使用 Vite 开发服务器启动（`npm run dev`）；构建产物为纯静态文件，可由任意静态服务承载。不在本设计中虚构工作区路径，实际落位由实现阶段在授权写范围内确定。

## 边界与不做的事

- 不引入服务/API、数据库、认证、后台任务、外部集成或数据同步层。
- 不生成技术契约、工作区引导文件或 ADR；本文件是本设计阶段唯一的用户产物。
