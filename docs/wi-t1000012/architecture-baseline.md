# 教师管理系统 — 架构基线

> 需求基线：`docs/wi-t1000012/requirements.md`（SHA-256: `488a3181e10501754df244dc3d90a0527e34d343a69742ccd713361956ae174a`）

## 路线决策

应用分类为 **simple-frontend**（精简前端路线）。

依据：需求仅要求单用户教师记录 CRUD，未涉及服务端权威数据、认证/权限、后台任务、外部服务或跨用户/跨设备数据共享。需求明确说明技术选型未规定、跨重启持久性未要求。因此无需后端服务层，浏览器 `localStorage` 即为权威数据存储。

## 页面与交互范围

单页应用（SPA），包含以下视图区域：

| 视图区域 | 说明 |
|---------|------|
| 教师列表 | 以表格/列表形式展示已保存的教师记录，每行提供编辑与删除入口 |
| 新增/编辑表单 | 收集教师名称、教授课程、年级、手机、邮箱五个字段，提交保存 |
| 教师详情 | 展示单条教师记录的全部字段值 |

交互流程：

1. 列表页为默认入口，展示所有教师记录，提供「新增教师」入口。
2. 点击「新增」打开空表单；点击列表行「编辑」打开预填充表单。
3. 表单提交时执行字段校验（教师名称非空、手机号合理格式、邮箱包含 `@` 且有有效域名）。校验通过则写入存储并返回列表；校验失败则提示错误并阻止保存。
4. 列表行「删除」操作移除对应记录并刷新列表。
5. 列表行点击查看详情，展示全部字段。

## 数据归属

- **存储方式**：浏览器 `localStorage`，键名以应用前缀命名（如 `teacher-mgmt:teachers`）。
- **数据格式**：JSON 数组，每个元素包含 `id`（唯一标识）、`teacherName`、`course`、`grade`、`phone`、`email` 字段。
- **持久范围**：数据在同一浏览器配置文件中刷新或重新打开页面后仍保留；不与其他浏览器、设备或用户共享。
- **无服务端**：所有读写操作均在浏览器本地完成，不经过任何远程 API。

## 校验边界

| 字段 | 校验规则 |
|------|---------|
| 教师名称 | 不为空 |
| 手机 | 合理电话号码格式（数字为主，长度合理） |
| 邮箱 | 包含 `@` 且有有效域名部分 |

校验在前端提交时执行；校验不通过时阻止保存并给出提示。

## 实现入口与运行方式

- **技术栈**：React + Vite SPA（新建项目）。
- **开发运行**：Vite 开发服务器，通过 `npm run dev` 启动。
- **构建产物**：`npm run build` 输出静态资源，可部署到任意静态托管环境。
- **入口文件**：Vite 标准 SPA 入口（`index.html` → `src/main.jsx`）。

## 架构边界

- 不引入后端服务、数据库、认证层、后台任务或外部集成。
- 不实现跨设备/跨浏览器数据同步。
- 教师数据仅以 `localStorage` 为权威来源；清除浏览器存储将移除全部数据。
