# 教师管理系统需求

## 目标

用户明确提出：构建教师管理系统，支持对教师记录的增删改查（CRUD）操作。

## 核心规则

### 教师信息字段（用户明确提出）

| 字段 | 说明 |
|------|------|
| 教师名称 | 教师姓名 |
| 教授课程 | 该教师所教授的课程 |
| 年级 | 教师所带年级 |
| 手机 | 教师联系电话 |
| 邮箱 | 教师电子邮箱 |

### CRUD 行为（用户明确提出）

- **新增**：填写教师名称、教授课程、年级、手机、邮箱，创建并保存教师记录。
- **查询**：查看教师列表，支持查看教师详情。
- **修改**：编辑已有教师记录的字段信息，保存后更新生效。
- **删除**：移除指定教师记录。

### 数据校验（推荐基线）

以下校验为闭合核心目标必需的推荐基线，用户可调整：

- 手机号应为合理格式的电话号码（数字长度在合理范围内）。
- 邮箱应为合理格式的电子邮件地址（包含 `@` 及有效域名部分）。
- 教师名称不应为空。

> 技术选型（数据库、存储方式等）未规定。CRUD 要求成功写入后可通过相应读取行为读回；跨重启或部署后的持久性未规定。

## 验收场景

### AC-01：新增教师记录后可通过查询读回

- 验收条件：用户填写教师名称、教授课程、年级、手机、邮箱并保存后，该教师记录出现在教师列表中，且可查看详情确认各字段值与录入一致。
- 入口类型：用户界面
- 验证动作：新增一条教师记录并提交保存，随后在教师列表中查找该记录并打开详情。
- 预期结果：教师列表中包含刚新增的记录；详情页各字段（教师名称、教授课程、年级、手机、邮箱）与录入内容一致。
- 证据类型：runtime-render, interaction

### AC-02：修改教师信息后查询确认更新生效

- 验收条件：用户对已有教师记录修改一个或多个字段并保存后，再次查询该记录，字段值已更新为修改后的内容。
- 入口类型：用户界面
- 验证动作：选择一条已有教师记录，修改教授课程和手机字段后保存，随后查询该记录详情。
- 预期结果：查询结果显示教授课程和手机字段已变更为修改后的值，其他未修改字段保持原值不变。
- 证据类型：runtime-render, interaction

### AC-03：删除教师记录后查询确认已移除

- 验收条件：用户删除一条教师记录后，该记录不再出现在教师列表中。
- 入口类型：用户界面
- 验证动作：选择一条已有教师记录并执行删除操作，随后查询教师列表。
- 预期结果：教师列表中不再包含已删除的教师记录。
- 证据类型：runtime-render, interaction

### AC-04：手机和邮箱格式校验（推荐基线）

- 验收条件：当用户输入的手机或邮箱格式明显不合理时，系统应给出提示并阻止保存。
- 入口类型：用户界面
- 验证动作：新增或修改教师记录时，在手机字段填入非数字或超长字符串，在邮箱字段填入不含 `@` 的文本，尝试保存。
- 预期结果：系统提示手机或邮箱格式不正确，记录未被保存。
- 证据类型：error-feedback
