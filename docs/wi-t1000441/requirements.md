# 工单系统需求文档

> Work Item: wi-t1000441 | 项目: jlg-ticket

## 1. 目标

构建一个面向多公司的工单管理系统，支持工单从创建到完成的全生命周期管理，包含工单分配、协作转派、处理通知、用户评价、统计分析和工作台等功能，并按公司维度进行数据隔离。

## 2. 角色

以下角色由用户需求中明确提及的工作流行为推导：

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单、回复工单、接收完成通知、进行满意度评价 | 用户明确提出 |
| 处理人 | 处理工单、回复工单、记录处理信息 | 用户明确提出 |
| 业务组成员 | 接收按分类自动分配到所属业务组的工单 | 用户明确提出 |

> **未规定**：业务组和分配规则的管理操作由谁执行（如公司管理员或系统管理员），用户未明确说明。此为待确认事项，不作为当前基线的一部分。

## 3. 核心实体

### 3.1 工单（Ticket）

工单包含以下字段（用户明确提出）：

- **工单ID**：唯一标识
- **主题**：工单标题
- **描述**：工单详细内容
- **分类**：问题分类（用户明确提出支持问题分类）
- **SLA优先级**：P0、P1、P2、P3、P4（用户明确提出）
- **提交人信息**：含姓名、邮箱（用户明确提出含邮箱）
- **创建时间**
- **当前状态**：见生命周期
- **公司归属**：用于公司隔离
- **处理人**：记录实际处理人
- **处理时间**：记录处理完成时间

### 3.2 工单回复（Ticket Reply）

- 支持多轮回复（用户明确提出）
- 每条回复包含：**回复人**、**回复时间**、**回复内容**

### 3.3 业务组（Business Group）

- 属于某个公司（用户明确提出"给某个公司增加多个业务组"）
- 可设置成员（用户明确提出）
- 用于接收按分类自动分配的工单

### 3.4 分类自动分配规则（Assignment Rule）

- 按公司维度配置（用户明确提出"某个公司的工单按照分类自动分配到某个业务组"）
- 规则关联：公司 + 分类 → 业务组

### 3.5 用户评价（Satisfaction Rating）

- 用户在收到工单完成后进行满意度评价（用户明确提出）

## 4. 工单生命周期

用户明确提出的生命周期状态及流转：

```
创建 → 待分配 → 待处理 → 完成
                                  ↘
                 任意状态 → 取消
```

| 状态 | 说明 | 来源 |
|------|------|------|
| 创建 | 工单已创建，等待进入分配流程 | 用户明确提出 |
| 待分配 | 工单等待分配到业务组或处理人 | 用户明确提出 |
| 待处理 | 工单已分配，等待处理人处理 | 用户明确提出 |
| 完成 | 工单已处理完成，触发邮件通知 | 用户明确提出 |
| 取消 | 工单被取消，终止流程 | 用户明确提出 |

**状态流转规则（用户明确提出）**：
- 工单创建后进入"待分配"状态
- 分配到业务组/处理人后进入"待处理"状态
- 处理完成后进入"完成"状态，并发送邮件通知
- 工单可被取消，进入"取消"状态

> **推荐基线**：当工单的分类在自动分配规则中无匹配项时，工单保持"待分配"状态等待人工处理。此为闭合核心流程所必需的兜底行为，可后续调整。

## 5. 功能需求

### 5.1 工单创建与管理

- 用户可创建工单，填写主题、描述、分类，设置SLA优先级（P0-P4）
- 工单创建时自动记录提交人信息（含邮箱）和创建时间
- 工单按公司隔离：用户只能查看和操作本公司范围内的工单（用户明确提出）
- 工单支持查看完整信息，包括所有字段和多轮回复

### 5.2 工单回复

- 工单支持多轮回复，提交人和处理人均可回复
- 每条回复记录回复人、回复时间和回复内容
- 回复按时间顺序展示

### 5.3 工单分配

**业务组管理**：
- 允许给某个公司增加多个业务组
- 每个业务组可以设置成员

**自动分配**：
- 允许为某个公司配置分类到业务组的自动分配规则
- 工单创建后，根据其分类按规则自动分配到对应的业务组
- 工单分配后状态从"待分配"流转到"待处理"

### 5.4 工单协作（转派）

- 支持工单转派操作：将工单从一个处理人/业务组转派给另一个处理人/业务组
- 转派后工单状态保持"待处理"
- 转派操作需记录

### 5.5 工单处理

**查看提交人完整信息**：
- 在处理工单时，处理人可查看提交人的完整信息，包括：
  - 姓名、公司、部门
  - 历史工单列表

**处理记录与通知**：
- 工单处理完成后，记录处理人和处理时间
- 工单状态流转到"完成"
- 工单完成时发送邮件通知提交人

### 5.6 用户评价

- 用户收到工单完成通知后，可对工单进行满意度评价

> **未规定**：满意度评价的具体评分尺度（如1-5星、满意/不满意等），用户未明确说明。

### 5.7 统计分析

**工单分布统计**：
- 支持按公司维度统计工单分布
- 支持按部门维度统计工单分布

**运营仪表盘**：
- 查看工单量
- 查看平均响应时间
- 查看满意度
- 查看热点问题

> **未规定**：仪表盘的具体图表类型、时间范围筛选方式、热点问题的统计口径（如按分类数量排名Top N），用户未明确说明。

### 5.8 工单工作台

- 查看待处理工单列表
- 支持筛选（含按公司维度筛选）
- 支持搜索
- 支持排序

### 5.9 操作日志

- 记录工单相关操作日志
- 包括但不限于：创建、分配、转派、回复、处理完成、取消等操作

## 6. 公司隔离规则

- 工单按公司隔离：用户只能访问本公司范围内的工单数据（用户明确提出）
- 业务组和分配规则按公司维度管理
- 统计分析按公司、部门维度统计

## 7. 验收场景

### AC-01：工单创建与生命周期流转

- 验收条件：用户可创建工单并填写必要信息，工单按SLA优先级和分类创建后进入正确的生命周期状态流转。
- 入口类型：用户界面
- 验证动作：创建一个工单，填写主题、描述、分类，设置SLA优先级为P1，提交后查看工单详情。
- 预期结果：
  - 工单创建成功，生成唯一工单ID
  - 工单记录提交人信息（含邮箱）和创建时间
  - 工单初始状态为"创建"，随后进入"待分配"
  - 巢单按公司归属隔离，其他公司用户无法查看该工单
- 证据类型：runtime-render, interaction, session-persistence

### AC-02：工单多轮回复

- 验收条件：工单支持多轮回复，每条回复记录回复人和回复时间，按时间顺序展示。
- 入口类型：用户界面
- 验证动作：在已创建的工单中，提交人和处理人分别添加多条回复，查看回复列表。
- 预期结果：
  - 回复成功添加，每条回复包含回复人、回复时间和回复内容
  - 回复按时间顺序展示
  - 多轮回复均可正常显示
- 证据类型：interaction, session-persistence

### AC-03：业务组与成员管理

- 验收条件：可为某个公司增加多个业务组，每个业务组可设置成员。
- 入口类型：用户界面
- 验证动作：为某个公司创建两个业务组，分别为每个业务组添加成员。
- 预期结果：
  - 业务组创建成功并关联到指定公司
  - 业务组成员设置成功
  - 可查看各业务组及其成员列表
- 证据类型：interaction, session-persistence

### AC-04：工单按分类自动分配

- 验收条件：某个公司的工单可根据分类按规则自动分配到对应业务组，分配后状态变为"待处理"。
- 入口类型：用户界面
- 验证动作：为某公司配置分类到业务组的自动分配规则，创建一个匹配该分类的工单，查看工单分配结果。
- 预期结果：
  - 工单创建后按分类自动分配到对应业务组
  - 工单状态从"待分配"流转到"待处理"
  - 工单归属的业务组可被查看
- 证据类型：interaction, session-persistence

### AC-05：工单转派

- 验收条件：支持将工单从一个处理人/业务组转派给另一个处理人/业务组。
- 入口类型：用户界面
- 验证动作：对处于"待处理"状态的工单执行转派操作，选择目标处理人/业务组，查看转派结果。
- 预期结果：
  - 转派操作成功，工单归属更新为目标处理人/业务组
  - 工单状态保持"待处理"
  - 转派操作被记录
- 证据类型：interaction, session-persistence

### AC-06：工单处理与邮件通知

- 验收条件：处理人在处理工单时可查看提交人完整信息（含历史工单），处理完成后记录处理人和处理时间，工单状态变为"完成"并发送邮件通知提交人。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人完整信息（姓名、公司、部门、历史工单），完成处理后提交，检查工单状态和邮件通知。
- 预期结果：
  - 处理人可查看提交人姓名、公司、部门信息
  - 处理人可查看提交人的历史工单列表
  - 处理完成后记录处理人和处理时间
  - 工单状态变为"完成"
  - 提交人收到工单完成的邮件通知
- 证据类型：interaction, session-persistence

### AC-07：用户满意度评价

- 验收条件：用户在工单完成后可对工单进行满意度评价。
- 入口类型：用户界面
- 验证动作：工单完成后，提交人对该工单进行满意度评价，查看评价结果。
- 预期结果：
  - 提交人可对已完成的工单进行满意度评价
  - 评价结果被记录并可在工单中查看
- 证据类型：interaction, session-persistence

### AC-08：统计分析与运营仪表盘

- 验收条件：支持按公司、部门维度统计工单分布，仪表盘可查看工单量、平均响应时间、满意度和热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：进入统计分析页面，分别按公司维度和部门维度查看工单分布，查看运营仪表盘的各项指标。
- 预期结果：
  - 可按公司维度查看工单分布统计
  - 可按部门维度查看工单分布统计
  - 仪表盘展示工单量、平均响应时间、满意度、热点问题等指标
- 证据类型：runtime-render, visual-style

### AC-09：工单工作台

- 验收条件：工作台可查看待处理工单列表，支持筛选、搜索、排序，可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：进入工单工作台，使用筛选条件（含公司维度）筛选工单，使用关键词搜索工单，按某字段排序，查看列表结果。
- 预期结果：
  - 工作台展示待处理工单列表
  - 筛选功能正常工作，包括按公司维度筛选
  - 搜索功能可按关键词匹配工单
  - 排序功能可按指定字段排序
- 证据类型：interaction, runtime-render

### AC-10：操作日志记录

- 验收条件：工单相关操作（创建、分配、转派、回复、处理完成、取消等）均被记录在操作日志中。
- 入口类型：用户界面
- 验证动作：执行一系列工单操作（创建、分配、回复、转派、处理完成），查看操作日志记录。
- 预期结果：
  - 各操作均有对应的日志记录
  - 日志记录包含操作类型和相关工单信息
  - 日志可被查看
- 证据类型：session-persistence
