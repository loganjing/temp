# 工单系统需求文档（164-tickets）

## 1. 目标

构建一套工单管理系统，支持工单的创建、分配、处理、协作、评价与统计分析全生命周期管理，按公司隔离，覆盖工单工作台和运营仪表盘等核心场景。

## 2. 角色与权限

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单、查看自己工单状态、回复工单、对已完成工单进行满意度评价 | 用户明确提出 |
| 处理人 | 业务组成员，处理分配到本组的工单，可转派工单，记录处理信息 | 用户明确提出 |
| 管理员 | 为公司配置业务组及成员、配置分类自动分配规则 | 用户明确提出（"允许给某个公司增加多个业务组"） |

工单按公司隔离：提交人、处理人、管理员只能看到本公司工单及配置（用户明确提出）。

## 3. 核心实体与生命周期

### 3.1 工单属性

| 属性 | 说明 | 来源 |
|------|------|------|
| 工单ID | 唯一标识 | 用户明确提出 |
| 主题 | 工单标题 | 用户明确提出 |
| 描述 | 工单详情 | 用户明确提出 |
| 分类 | 问题分类，用于自动分配 | 用户明确提出 |
| SLA优先级 | P0-P4 五级 | 用户明确提出 |
| 提交人信息 | 姓名、邮箱、公司、部门 | 用户明确提出 |
| 创建时间 | 工单创建时间戳 | 用户明确提出 |
| 处理人 | 处理工单的业务组成员 | 用户明确提出 |
| 处理时间 | 处理操作的时间戳 | 用户明确提出 |

### 3.2 工单生命周期

```
创建 → 待分配 → 待处理 → 完成
                    ↘ 取消
```

- **创建**：提交人新建工单，初始状态为"创建"。
- **待分配**：工单进入待分配状态，等待分配到业务组（可手动或按分类自动分配）。
- **待处理**：分配到业务组后进入待处理，处理人开始处理。
- **完成**：处理人完成工单处理，系统发送邮件通知提交人。
- **取消**：工单可被取消，终止处理流程。

> 状态流转方向用户已明确；"创建"是否独立于"待分配"为可见状态、以及各状态间的取消入口未规定，保留为未规定。

### 3.3 工单回复

工单支持多轮回复（用户明确提出）。每轮回复记录：
- 回复人
- 回复时间
- 回复内容

> 回复内容格式（纯文本/富文本）未规定。

## 4. 模块需求

### 4.1 工单分配

**业务组管理（用户明确提出）：**
- 允许给某个公司增加多个业务组。
- 每个业务组可以设置成员（处理人）。

**按分类自动分配（用户明确提出）：**
- 允许配置某个公司的工单按照分类自动分配到某个业务组。
- 工单创建后，根据其分类匹配自动分配规则，分配到对应业务组。

> 分配规则的具体配置入口（界面/API）未规定。手动分配操作入口未规定，但"待分配"状态隐含可手动分配。

### 4.2 工单协作

**工单转派（用户明确提出）：**
- 支持工单转派操作：处理人可将工单转派给其他业务组或成员。
- 转派后工单状态保持"待处理"，接收方继续处理。

> 转派是否可多次转派、转派是否记录日志未明确规定，但结合"记录相关日志"要求，转派操作应记入操作日志（推荐基线）。

### 4.3 工单处理

**提交人信息查看（用户明确提出）：**
- 处理工单时可查看提交人的完整信息，包括：姓名、公司、部门、历史工单。

**处理记录（用户明确提出）：**
- 处理工单后记录处理人、处理时间。

**完成通知（用户明确提出）：**
- 工单完成后发送邮件进行通知（通知对象为提交人邮箱）。

> 邮件内容模板、发送方式（同步/异步）未规定。历史工单范围（同一提交人/同一公司）未规定，推荐为同一提交人的历史工单。

### 4.4 用户评价

**满意度评价（用户明确提出）：**
- 用户收到已完成工单后进行满意度评价。

> 评价维度（如评分/评语）未规定。评价入口（邮件链接/工单详情页）未规定。评价后是否可修改未规定。

### 4.5 统计分析

**工单分布统计（用户明确提出）：**
- 支持按公司、部门维度统计工单分布。

**运营仪表盘（用户明确提出）：**
- 查看工单量、平均响应时间、满意度、热点问题等运营指标。

> 平均响应时间计算方式、热点问题定义未规定。仪表盘为统计展示入口，不指定具体图表类型。

### 4.6 工单工作台

**待处理工单列表（用户明确提出）：**
- 查看待处理工单列表。
- 支持筛选、搜索、排序。
- 可按公司维度筛选。

> 工作台面向处理人/管理员，展示待处理工单。具体筛选字段、排序字段未规定。

### 4.7 操作日志

**日志记录（用户明确提出）：**
- 记录相关日志。

> 日志覆盖范围未明确规定，推荐基线为：工单创建、状态变更、分配/转派、处理完成、评价等关键操作记入日志，日志包含操作人、操作时间、操作类型和工单ID。

## 5. 验收场景

### AC-01：工单创建与生命周期管理

- 验收条件：提交人可创建工单（含工单ID、主题、描述、分类、提交人信息含邮箱、创建时间），设置SLA优先级（P0-P4）和问题分类，工单在创建→待分配→待处理→完成/取消状态间流转，且工单按公司隔离（A公司用户无法看到B公司工单）。
- 入口类型：用户界面
- 验证动作：以公司A提交人身份创建一张工单并设置优先级和分类，流转至"待处理"后标记完成；以公司B用户身份查看工单列表。
- 预期结果：工单创建成功并显示所有属性；状态按生命周期正确流转；公司B用户无法看到公司A的工单。
- 证据类型：runtime-render, interaction, authorization

### AC-02：工单多轮回复

- 验收条件：在工单详情中，提交人和处理人可进行多轮回复，每轮回复记录回复人、回复时间和回复内容。
- 入口类型：用户界面
- 验证动作：在一张已创建的工单中，提交人和处理人分别回复多次。
- 预期结果：所有回复按时间顺序展示，每条回复显示回复人、回复时间和内容。
- 证据类型：interaction, runtime-render

### AC-03：业务组管理

- 验收条件：管理员可为某个公司增加多个业务组，每个业务组可设置成员。
- 入口类型：用户界面
- 验证动作：以管理员身份为公司A创建两个业务组，分别添加成员。
- 预期结果：业务组创建成功，成员列表正确显示，不同业务组相互独立。
- 证据类型：interaction, runtime-render

### AC-04：工单按分类自动分配

- 验收条件：配置某公司工单按分类自动分配到业务组的规则后，新建工单时根据其分类自动匹配规则并分配到对应业务组。
- 入口类型：用户界面
- 验证动作：配置"分类X→业务组Y"的自动分配规则，创建一张分类为X的工单。
- 预期结果：工单自动分配到业务组Y，工单状态变为"待处理"。
- 证据类型：interaction, runtime-render

### AC-05：工单转派

- 验收条件：处理人可将工单转派给其他业务组或成员，转派后接收方可继续处理。
- 入口类型：用户界面
- 验证动作：在一张待处理工单中，处理人执行转派操作，选择目标业务组或成员。
- 预期结果：工单转派成功，目标接收方可在工作台看到该工单并继续处理。
- 证据类型：interaction, runtime-render

### AC-06：工单处理与提交人信息查看

- 验收条件：处理人在处理工单时可查看提交人完整信息（姓名、公司、部门、历史工单），处理后记录处理人和处理时间，工单完成时发送邮件通知提交人。
- 入口类型：用户界面
- 验证动作：处理人打开一张待处理工单，查看提交人信息面板，执行完成操作。
- 预期结果：提交人信息面板显示姓名、公司、部门和历史工单列表；完成操作后工单记录处理人和处理时间；提交人邮箱收到完成通知邮件。
- 证据类型：interaction, runtime-render, other

### AC-07：用户满意度评价

- 验收条件：工单完成后，提交人可对该工单进行满意度评价。
- 入口类型：用户界面
- 验证动作：以提交人身份打开一张已完成工单，进行满意度评价。
- 预期结果：评价提交成功，工单关联显示评价结果。
- 证据类型：interaction, runtime-render

### AC-08：统计分析与运营仪表盘

- 验收条件：系统提供统计与仪表盘，支持按公司、部门维度查看工单分布，展示工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：进入统计分析页面，按公司维度筛选；进入仪表盘查看运营指标。
- 预期结果：统计页面按公司/部门维度展示工单分布数据；仪表盘展示工单量、平均响应时间、满意度、热点问题指标。
- 证据类型：runtime-render, interaction

### AC-09：工单工作台

- 验收条件：处理人/管理员可在工作台查看待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：进入工单工作台，执行筛选、搜索和排序操作，并按公司维度筛选。
- 预期结果：工作台展示待处理工单列表，筛选/搜索/排序功能正常，按公司筛选后仅显示对应公司工单。
- 证据类型：interaction, runtime-render

### AC-10：操作日志

- 验收条件：系统记录工单相关关键操作日志，包含操作人、操作时间、操作类型和工单ID。
- 入口类型：内部
- 验证动作：执行工单创建、状态变更、分配、转派、完成等操作后，查看操作日志。
- 预期结果：日志记录了上述关键操作，每条日志包含操作人、操作时间、操作类型和工单ID。
- 证据类型：other
