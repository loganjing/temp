# 231-clock 架构基线

## 范围与依据

本设计基于已批准的需求基线 `docs/wi-t1000086/requirements.md`（sha256: `1090e7cc0ffa4d37a10f4aeb6eff266fe7d426f2c89dc1042f31703ce9882390`）。需求只要求一个页面实时显示当前时、分、秒，格式为 24 小时制 `HH:MM:SS`，用户无需手动刷新。设计不扩展或改变产品语义。

路线：`simple-frontend`（精简前端）。理由见分类回执：需求未要求服务端权威数据、认证、后台任务、外部集成或跨用户/设备共享，全部行为可由浏览器端时间 API 与定时器完成。

## 页面与交互范围

单页面应用，只包含一个时钟视图：

- 页面打开后立即渲染当前时间，格式 `HH:MM:SS`（24 小时制，时/分/秒均两位补零）。
- 通过 `setInterval` 以 1 秒为节拍驱动重新读取 `Date` 并更新显示，用户无需手动刷新。
- 没有其他页面、路由、表单或交互操作；不显示日期、时区等需求未规定的附加信息。

## 浏览器状态与数据归属

- 时间来源：浏览器宿主提供的 `Date`（系统本地时间）。不持久化任何数据，不读写 `localStorage`，不存在跨设备/跨用户/跨浏览器共享。
- 运行状态：仅当前页面的定时器与渲染状态随页面生命周期存在，关闭页面即释放。无服务端状态、无数据库、无认证态。

## 实现入口与运行方式

新建 React + Vite + TypeScript 单页应用：

- 入口：`index.html` → `src/main.tsx` 挂载 React 根组件。
- 时钟组件：一个 `Clock` 组件，内部用 `useState` 保存当前时间字符串，`useEffect` 中启动 `setInterval(update, 1000)`，并在卸载时清理定时器。
- 时间格式化：用 `padStart(2, '0')` 对时/分/秒补零，组合为 `HH:MM:SS`。
- 视觉风格需求未规定，采用清晰可读的居中大号等宽/无衬线数字排版，保持最小实现，不引入额外 UI 库。
- 运行方式：Vite 开发服务器（`npm run dev`）；构建命令 `npm run build`。

## 验证边界

- AC-01 为 runtime-render 类型验收：实现/验证阶段启动前端服务后，打开页面观察显示的 `HH:MM:SS` 是否随系统时间每秒变化即可判定。
- 时间由系统时钟决定，属于非确定但可观察值；验收时不需固定结果，只需确认每秒递增且与系统时间一致。
- 无自动推进、随机结果、外部异步事件等需要特殊测试控制入口的场景，故不增设测试专用控制入口。

## 不做的事

- 不引入服务端、API、数据库、认证、后台任务、外部集成或同步层。
- 不生成 `technical-contract.md`、`workspace-bootstrap.json`、ADR 或实现计划。
- 不规定视觉风格、字体、配色等需求未指定事项（实现阶段选择最小可读方案）。
