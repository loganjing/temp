# 工单系统需求文档

## 1. 产品目标

为多公司环境提供一个工单管理平台，支持工单从创建到完成的全生命周期管理，按公司隔离数据，通过业务组和分类规则实现自动分配，支持转派协作、满意度评价和运营统计分析。（用户明确提出）

## 2. 角色与权限边界

| 角色 | 说明 | 来源 |
|------|------|------|
| 工单提交人 | 创建工单的用户，属于某个公司和部门，含邮箱信息，可回复工单、接收完成通知、进行满意度评价 | 用户明确提出 |
| 工单处理人 | 业务组成员，负责处理分配到其业务组的工单，可回复、转派、处理工单，可查看提交人完整信息 | 用户明确提出 |
| 业务组管理员 | 负责管理公司业务组的成员设置 | 用户明确提出（"每个业务组可以设置成员"） |

工单数据按公司隔离：用户只能查看和处理其所属公司范围内的工单、业务组和统计数据。（用户明确提出）

## 4. 工单生命周期

工单状态流转如下（用户明确提出）：

```
创建 → 待分配 → 待处理 → 完成
                ↘ 取消
```

| 状态 | 说明 |
|------|------|
| 创建 | 工单刚被提交人创建，尚未分配 |
| 待分配 | 工单等待分配到业务组（手动或自动分配规则触发） |
| 待处理 | 工单已分配到业务组，等待处理人处理 |
| 完成 | 工单处理完毕，发送邮件通知提交人 |
| 取消 | 工单被取消，不再处理 |

状态流转规则：
- 从"待分配"可通过分配操作流转到"待处理"；
- 从"待处理"可通过处理完成流转到"完成"，也可通过取消操作流转到"取消"；
- "完成"和"取消"为终态。（推荐基线——用于闭合生命周期定义中用户未明确的状态流转方向）

## 5. 模块需求

### 5.1 工单管理

- 工单创建时必须填写主题、描述、分类，并设置SLA优先级（P0-P4），自动记录提交人信息（含邮箱）和创建时间。（用户明确提出）
- 工单支持多轮回复，每条回复记录回复人和回复时间，按时间顺序展示。（用户明确提出）
- 工单数据按公司隔离，用户只能访问所属公司范围内的工单。（用户明确提出）

### 5.2 工单分配

- 允许给某个公司增加多个业务组，每个业务组可以设置成员。（用户明确提出）
- 允许某个公司配置分类分配规则，将工单按分类自动分配到对应业务组。（用户明确提出）
- 工单创建后进入"待分配"状态，若匹配到分类分配规则则自动流转到"待处理"并分配到对应业务组。（用户明确提出 + 推荐基线——自动分配的具体触发时机）

### 5.3 工单协作

- 支持工单转派操作：处理人可将工单转派给其他业务组或处理人。（用户明确提出）
- 转派后工单状态保持"待处理"，转派操作记录在操作日志中。（推荐基线——转派后状态和日志记录）

### 5.4 工单处理

- 处理人在处理工单时可查看提交人的完整信息，包括姓名、公司、部门、历史工单列表。（用户明确提出）
- 工单处理后，记录处理人和处理时间。（用户明确提出）
- 工单完成时发送邮件通知提交人。（用户明确提出）

### 5.5 用户评价

- 提交人在工单完成后可进行满意度评价。（用户明确提出）

### 5.6 统计分析

- 支持按公司、部门维度统计工单分布。（用户明确提出）
- 统计与分析仪表盘：查看工单量、平均响应时间、满意度、热点问题等运营指标。（用户明确提出）

### 5.7 工单工作台

- 查看待处理工单列表。（用户明确提出）
- 支持筛选、搜索、排序操作。（用户明确提出）
- 可按公司维度筛选。（用户明确提出）

### 5.8 操作日志

- 记录工单相关操作日志，包括但不限于创建、分配、转派、处理、状态变更等操作。（用户明确提出 + 推荐基线——日志覆盖的具体操作类型）

## 6. 验收场景

### AC-01：提交人可创建工单并填写必要信息

- 验收条件：提交人能够创建工单，填写主题、描述、分类，设置SLA优先级（P0-P4），系统自动记录提交人信息（含邮箱）和创建时间。
- 入口类型：用户界面
- 验证动作：提交人进入工单创建入口，填写主题、描述、分类，选择SLA优先级，提交工单。
- 预期结果：工单创建成功，生成唯一工单ID，记录提交人信息（姓名、邮箱）、创建时间，工单状态为"创建"或"待分配"。
- 证据类型：interaction, runtime-render

### AC-02：工单支持多轮回复

- 验收条件：工单创建后，提交人和处理人均可对工单进行回复，每条回复记录回复人和回复时间，按时间顺序展示。
- 入口类型：用户界面
- 验证动作：在工单详情中，不同用户分别添加回复。
- 预期结果：回复成功保存，每条回复显示回复人、回复时间和回复内容，多条回复按时间顺序排列。
- 证据类型：interaction, runtime-render

### AC-03：工单按公司隔离

- 验收条件：用户只能查看和处理其所属公司范围内的工单，无法访问其他公司的工单数据。
- 入口类型：用户界面
- 验证动作：使用A公司用户登录，尝试查看工单列表和详情；对比B公司用户视角。
- 预期结果：A公司用户只能看到A公司的工单，B公司用户只能看到B公司的工单，互相不可见。
- 证据类型：authorization, runtime-render

### AC-04：公司可配置业务组和成员

- 验收条件：允许给某个公司增加多个业务组，每个业务组可设置成员。
- 入口类型：用户界面
- 验证动作：为公司新增业务组，为业务组添加成员。
- 预期结果：业务组创建成功并关联到指定公司，成员成功加入业务组，可在业务组管理中查看。
- 证据类型：interaction, runtime-render

### AC-05：工单按分类自动分配到业务组

- 验收条件：公司配置分类分配规则后，新创建的工单按分类自动分配到对应业务组，工单状态从待分配流转到待处理。
- 入口类型：用户界面
- 验证动作：配置某分类对应某业务组的分配规则，创建该分类的工单。
- 预期结果：工单创建后自动匹配规则，分配到对应业务组，状态变为"待处理"。
- 证据类型：interaction, runtime-render

### AC-06：支持工单转派操作

- 验收条件：处理人可将工单转派给其他业务组或处理人，转派操作记录在日志中。
- 入口类型：用户界面
- 验证动作：在待处理工单中执行转派操作，选择目标业务组或处理人。
- 预期结果：工单转派成功，目标接收方可查看该工单，转派操作记录在操作日志中。
- 证据类型：interaction, runtime-render

### AC-07：处理工单时可查看提交人完整信息

- 验收条件：处理人在处理工单时可查看提交人的完整信息，包括姓名、公司、部门、历史工单列表。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息区域。
- 预期结果：显示提交人姓名、公司、部门信息，以及该提交人的历史工单列表。
- 证据类型：runtime-render

### AC-08：工单完成后记录处理信息并发送邮件通知

- 验收条件：工单处理完成后，记录处理人和处理时间，并向提交人发送邮件通知。
- 入口类型：用户界面
- 验证动作：处理人将待处理工单标记为完成。
- 预期结果：工单状态变为"完成"，处理记录保存处理人和处理时间，提交人邮箱收到工单完成通知邮件。
- 证据类型：interaction, runtime-render

### AC-09：用户可对已完成工单进行满意度评价

- 验收条件：提交人在工单完成后可进行满意度评价。
- 入口类型：用户界面
- 验证动作：提交人在已完成工单中进行满意度评价操作。
- 预期结果：评价提交成功，工单关联满意度评价结果。
- 证据类型：interaction

### AC-10：统计分析支持按公司、部门维度统计工单分布

- 验收条件：支持按公司、部门维度统计工单分布情况。
- 入口类型：用户界面
- 验证动作：进入统计分析页面，分别按公司维度和部门维度查看工单分布。
- 预期结果：统计结果按选定维度展示工单分布数据。
- 证据类型：runtime-render

### AC-11：统计与分析仪表盘展示运营指标

- 验收条件：统计与分析仪表盘可查看工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：进入仪表盘页面，查看各运营指标展示。
- 预期结果：仪表盘展示工单量、平均响应时间、满意度、热点问题等指标数据。
- 证据类型：runtime-render

### AC-12：工单工作台支持筛选、搜索、排序和按公司筛选

- 验收条件：工单工作台可查看待处理工单列表，支持筛选、搜索、排序，可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：进入工单工作台，使用筛选条件、搜索关键词、排序选项和公司维度筛选进行操作。
- 预期结果：工单列表根据筛选、搜索、排序和公司条件正确呈现匹配的待处理工单。
- 证据类型：interaction, runtime-render

### AC-13：记录工单相关操作日志

- 验收条件：工单相关操作（包括创建、分配、转派、处理、状态变更等）均记录在操作日志中。
- 入口类型：内部
- 验证动作：执行工单创建、分配、转派、处理等操作后，查看操作日志。
- 预期结果：操作日志记录了对应的操作类型、操作人、操作时间和关联工单。
- 证据类型：other
