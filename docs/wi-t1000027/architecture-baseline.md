# 教师管理系统 — 架构基线

## 1. 需求基线引用

本设计基于已批准的需求基线 `docs/wi-t1000027/requirements.md`（SHA-256: `ad558069d49e09b788689589d23933e296c98e46c687e5b91203ccea6c0278cd`）。产品范围、业务对象、字段、行为规则和验收语义均以该基线为准，本设计仅给出必要的技术承载方式，不扩展或裁剪产品语义。

## 2. 应用类型与数据归属

- **应用类型**：单用户简单前端应用（simple-frontend）。
- **数据存储**：使用浏览器 `localStorage` 作为唯一数据持久层，通过一个清晰的应用读写边界管理教师记录的增删改查。
- **数据归属**：数据仅存在于当前浏览器配置文件中，刷新页面或重新打开标签页后仍可保留；不会与其他浏览器、设备或用户共享。无服务端权威数据、无跨设备同步。
- **无服务端能力**：不包含服务端 API、数据库、认证/权限、后台任务、外部服务集成或数据同步层。

## 3. 页面与交互范围

系统为单页应用（SPA），包含以下交互区域：

| 交互区域 | 说明 |
|----------|------|
| 教师列表页 | 以表格展示全部教师记录（教师名称、教授课程、年级、手机、邮箱），每行提供编辑、删除操作入口；列表顶部提供按教师名称关键字模糊搜索的筛选输入框 |
| 新增教师 | 通过"新增"按钮打开表单（弹窗或行内面板），录入教师名称、教授课程、年级、手机、邮箱，提交时执行非空校验与格式校验 |
| 编辑教师 | 对已有记录点击"编辑"后，表单回填当前信息，修改后提交更新该条记录，执行与新增一致的校验规则 |
| 删除教师 | 对已有记录点击"删除"后弹出二次确认，确认后移除该条记录 |

所有字段（教师名称、教授课程、年级、手机、邮箱）均为必填。手机号需为有效数字格式，邮箱需包含 `@` 和域名。校验不通过时阻止提交并显示字段级错误提示。

## 4. 技术选型

- **前端框架**：React + Vite 构建的 SPA。
- **数据持久化**：`localStorage`，以 JSON 数组结构存储教师记录列表。
- **样式**：内联或轻量 CSS，保持紧凑可扫描的操作型布局。
- **不涉及**：后端服务、数据库、ORM、认证中间件、外部 API 集成。

## 5. 实现入口与运行方式

- **新建项目**：使用 Vite 初始化 React 应用。
- **开发运行**：通过 Vite 开发服务器启动（`npm run dev`），在浏览器中打开本地开发地址即可访问教师管理页面。
- **构建产物**：`npm run build` 生成静态前端产物，可部署至任意静态文件服务器或直接本地访问。
- **数据初始化**：首次打开时 `localStorage` 中无教师记录，列表为空；用户通过新增操作逐步创建教师数据。应用负责 `localStorage` 的读写和 JSON 序列化/反序列化。

## 6. 设计边界

- 本设计不引入需求未规定的服务端能力、认证体系或外部集成。
- 教授课程与年级字段采用自由文本输入，不做预设选项约束（需求未规定）。
- 列表暂不分页（需求未规定分页方式），数据量增长后通过名称搜索筛选定位。
- 所有校验（必填、手机格式、邮箱格式）在前端表单层完成，不依赖服务端校验。
