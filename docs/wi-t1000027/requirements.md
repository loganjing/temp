# 教师管理系统需求文档

## 1. 目标

为学校或教育机构提供一个教师管理系统，支持对教师信息的增删改查操作。系统核心对象为教师，管理教师的基本信息和教学关联信息。

## 2. 对象与字段

教师信息包含以下字段：

| 字段 | 说明 | 是否必填 |
|------|------|----------|
| 教师名称 | 教师的姓名 | 是 |
| 教授课程 | 该教师教授的课程 | 是 |
| 年级 | 教师所带的年级 | 是 |
| 手机 | 教师的手机号码 | 是 |
| 邮箱 | 教师的电子邮箱 | 是 |

## 3. 核心行为与规则

### 3.1 教师列表查看
- 用户可查看所有已创建的教师信息列表，列表展示教师全部字段。
- 列表支持按教师名称搜索筛选（推荐基线：支持按教师名称关键字模糊搜索，便于在数据量增长后快速定位教师）。

### 3.2 新增教师
- 用户可通过新增功能录入教师信息，包括教师名称、教授课程、年级、手机、邮箱。
- 所有字段均为必填，提交时进行非空校验。
- 手机号格式校验：需为有效手机号格式（数字组成，长度合理）。
- 邮箱格式校验：需为有效邮箱格式（包含 `@` 和域名）。
- 新增成功后，该教师出现在列表中，可通过查看操作读回。

### 3.3 编辑教师
- 用户可在列表中对已有教师进行编辑操作。
- 编辑时表单回填该教师当前信息。
- 提交编辑后，列表中该教师信息更新为编辑后的值。
- 编辑同样执行与新增一致的格式校验规则。

### 3.4 删除教师
- 用户可在列表中对已有教师执行删除操作。
- 删除需二次确认，防止误操作。
- 删除成功后，该教师不再出现在列表中。

## 4. 验收场景

### AC-01：用户可新增教师并在列表中查看
- 验收条件：用户能成功创建一条教师记录，并在列表中查看该记录的全部字段信息。
- 入口类型：用户界面
- 验证动作：在教师列表页面点击新增，填写教师名称、教授课程、年级、手机、邮箱并提交，然后返回列表查看。
- 预期结果：提交成功后列表中出现新增的教师记录，且各字段值与录入内容一致。
- 证据类型：interaction, runtime-render

### AC-02：用户可编辑已有教师信息
- 验收条件：用户能对已有教师记录进行编辑，编辑后列表中该教师信息更新为最新值。
- 入口类型：用户界面
- 验证动作：在列表中对一条已有教师记录点击编辑，修改其中一个或多个字段（如手机号和邮箱）并提交，然后返回列表查看。
- 预期结果：列表中该教师对应字段更新为编辑后提交的值。
- 证据类型：interaction, runtime-render

### AC-03：用户可删除已有教师
- 验收条件：用户能删除一条已有教师记录，删除后该记录不再出现在列表中。
- 入口类型：用户界面
- 验证动作：在列表中对一条已有教师记录点击删除，在确认弹窗中确认删除，然后查看列表。
- 预期结果：列表中不再出现该教师记录。
- 证据类型：interaction, runtime-render

### AC-04：表单校验阻止无效输入
- 验收条件：新增和编辑教师时，必填字段为空、手机号格式不合法或邮箱格式不合法时，系统阻止提交并给出错误提示。
- 入口类型：用户界面
- 验证动作：在新增或编辑表单中清空某个必填字段后提交，或填入格式非法的手机号/邮箱后提交。
- 预期结果：表单不提交成功，页面显示对应的字段校验错误提示。
- 证据类型：interaction, error-feedback
