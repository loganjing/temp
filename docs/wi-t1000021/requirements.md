# 工单系统需求文档

## 1. 目标与范围

构建一个工单管理系统，支持工单的创建、分配、处理、协作、评价和统计分析全生命周期管理。系统按公司隔离，支持多业务组配置与分类自动分配，提供工作台、仪表盘和日志审计能力。

**范围边界（未规定事项）**：用户未明确部署平台、技术选型、数据保留周期、并发量级和非功能指标，以下不作为基线约束。

## 2. 角色定义

以下角色由用户明确描述的操作行为推导，非自行新增：

| 角色 | 来源 |
|------|------|
| 提交人 | 用户明确提出"提交人信息"、"用户收到工单后进行满意度评价" |
| 处理人（业务组成员） | 用户明确提出"每个业务组可以设置成员"、"记录处理人" |
| 管理员 | 用户明确提出"允许给某个公司增加多个业务组"、配置自动分配规则 |

## 3. 工单生命周期

用户明确要求以下状态流转：**创建 → 待分配 → 待处理 → 完成**，以及**取消**状态。

```
创建 → 待分配 → 待处理 → 完成
  │                │
  └→ 取消    └→ 取消
```

- **创建**：提交人创建工单后进入此状态。
- **待分配**：工单已创建，等待分配到业务组。可由自动分配规则触发流转到待处理。
- **待处理**：已分配到业务组，等待处理人处理。
- **完成**：处理人完成处理，记录处理信息并发送邮件通知。
- **取消**：工单被取消，终止后续流程。

## 4. 用户旅程

### 4.1 工单创建与处理主流程

1. 提交人创建工单，填写主题、描述、分类，系统记录提交人信息（姓名、邮箱、公司、部门）和创建时间。
2. 系统根据工单分类自动匹配该公司下的业务组分配规则，将工单分配到对应业务组；若无匹配规则，工单保持待分配状态等待手动分配。
3. 业务组成员在工作台看到待处理工单，开始处理。
4. 处理过程中可查看提交人完整信息（姓名、公司、部门、历史工单）。
5. 处理期间支持多轮回复沟通（含回复人、回复时间）。
6. 处理人完成处理，记录处理人和处理时间，工单状态变为完成，发送邮件通知提交人。
7. 提交人收到通知后可对工单进行满意度评价。

### 4.2 工单协作流程

- 处理人可将工单转派给同公司其他业务组成员，转派后工单仍处于待处理状态，新处理人继续处理。

### 4.3 工单取消流程

- 工单在创建后、完成前的任意阶段可被取消，取消后终止后续处理流程。

## 5. 模块需求

### 5.1 工单管理

- 工单必须包含以下字段：工单ID、主题、描述、分类、提交人信息（姓名、邮箱、公司、部门）、创建时间。（用户明确提出）
- 工单支持多轮回复，每条回复记录回复人和回复时间。（用户明确提出）
- 工单数据按公司隔离，不同公司的工单互不可见。（用户明确提出）
- 工单支持 SLA 优先级设置，级别为 P0-P4。（用户明确提出）
- 工单支持问题分类设置。（用户明确提出）
- 工单生命周期状态：创建、待分配、待处理、完成、取消。（用户明确提出）

### 5.2 工单分配

- 允许给某个公司增加多个业务组，每个业务组可设置成员。（用户明确提出）
- 允许按公司维度配置工单分类与业务组的自动分配规则：工单创建后，根据其分类自动匹配该公司下的分配规则，将工单分配到对应业务组。（用户明确提出）
- 若无匹配的自动分配规则，工单保持待分配状态，等待手动分配。（推荐基线——闭合"工单创建后无匹配规则"的处理缺口，行为可观察且可逆）

### 5.3 工单协作

- 支持工单转派操作：处理人可将工单转派给同公司其他业务组成员。（用户明确提出）

### 5.4 工单处理

- 处理工单时可查看提交人的完整信息：姓名、公司、部门、历史工单。（用户明确提出）
- 工单完成后，记录处理人和处理时间。（用户明确提出）
- 工单完成时发送邮件通知提交人。（用户明确提出）

### 5.5 用户评价

- 用户收到工单完成通知后可对工单进行满意度评价。（用户明确提出）

### 5.6 统计分析

- 支持按公司维度统计工单分布。（用户明确提出）
- 支持按部门维度统计工单分布。（用户明确提出）
- 统计与分析仪表盘，展示以下运营指标：工单量、平均响应时间、满意度、热点问题。（用户明确提出）

### 5.7 工单工作台

- 查看待处理工单列表。（用户明确提出）
- 支持筛选、搜索、排序功能。（用户明确提出）
- 支持按公司维度筛选。（用户明确提出）

### 5.8 日志记录

- 记录工单相关操作日志。（用户明确提出）
- **推荐基线**：以下关键操作应记录日志——工单创建、分配、转派、处理完成、取消、满意度评价。日志内容至少包含操作人、操作时间、操作类型和工单ID。（推荐基线——闭合"相关日志"的范围缺口，确保审计可观察）

## 6. 验收场景

### AC-01：提交人创建工单并记录完整信息

- 验收条件：提交人创建工单后，工单包含工单ID、主题、描述、分类、提交人信息（姓名、邮箱、公司、部门）和创建时间，状态为"创建"或进入"待分配"。
- 入口类型：用户界面
- 验证动作：提交人填写主题、描述、分类并提交创建工单。
- 预期结果：工单成功创建，可读取到工单ID、主题、描述、分类、提交人姓名、邮箱、公司、部门和创建时间，初始状态正确。
- 证据类型：interaction，session-persistence

### AC-02：工单支持多轮回复

- 验收条件：工单创建后，多个用户可对同一工单进行多轮回复，每条回复记录回复人和回复时间。
- 入口类型：用户界面
- 验证动作：在已创建的工单上，先后提交两条回复。
- 预期结果：可读取到两条回复内容，每条回复均记录回复人和回复时间，按时间顺序排列。
- 证据类型：interaction，session-persistence

### AC-03：工单按公司隔离

- 验收条件：不同公司的工单数据互不可见，某公司用户只能看到本公司的工单。
- 入口类型：用户界面
- 验证动作：分别以A公司用户和B公司用户身份查看工单列表。
- 预期结果：A公司用户只看到A公司工单，B公司用户只看到B公司工单，互不交叉。
- 证据类型：interaction，authorization

### AC-04：工单生命周期状态流转

- 验收条件：工单状态可按"创建→待分配→待处理→完成"流转，且工单在完成前可被取消。
- 入口类型：用户界面
- 验证动作：创建工单后触发分配使状态变为待处理，处理完成后状态变为完成；另创建一个工单并执行取消操作。
- 预期结果：第一个工单状态依次流转到完成；第二个工单状态变为取消，终止后续处理流程。
- 证据类型：interaction，session-persistence

### AC-05：工单SLA优先级与问题分类设置

- 验收条件：工单可设置 SLA 优先级（P0-P4）和问题分类。
- 入口类型：用户界面
- 验证动作：创建工单时选择优先级为 P1、分类为"网络故障"，保存后读取工单信息。
- 预期结果：工单的优先级字段为 P1，分类字段为"网络故障"，可被正确读取。
- 证据类型：interaction，session-persistence

### AC-06：公司业务组与成员配置

- 验收条件：管理员可为某个公司增加多个业务组，每个业务组可设置成员。
- 入口类型：用户界面
- 验证动作：管理员为A公司创建两个业务组"网络组"和"硬件组"，分别为两组添加成员。
- 预期结果：A公司下可读取到两个业务组，各组成员列表正确。
- 证据类型：interaction，session-persistence

### AC-07：工单按分类自动分配到业务组

- 验收条件：当公司已配置分类与业务组的自动分配规则时，工单创建后根据分类自动分配到对应业务组，状态流转到待处理。
- 入口类型：用户界面
- 验证动作：为A公司配置"网络故障→网络组"的自动分配规则，然后创建一个分类为"网络故障"的工单。
- 预期结果：工单自动分配到网络组，状态变为待处理，网络组成员可在工作台看到该工单。
- 证据类型：interaction，session-persistence

### AC-08：工单转派操作

- 验收条件：处理人可将工单转派给同公司其他业务组成员，转派后工单仍为待处理状态。
- 入口类型：用户界面
- 验证动作：处理人将一个待处理工单转派给同公司另一业务组成员。
- 预期结果：工单的处理人变更为被转派人，状态保持待处理，被转派人可在工作台看到该工单。
- 证据类型：interaction，session-persistence

### AC-09：处理工单时查看提交人完整信息

- 验收条件：处理人在处理工单时可查看提交人的完整信息，包括姓名、公司、部门和历史工单。
- 入口类型：用户界面
- 验证动作：处理人打开一个待处理工单，查看提交人信息区域。
- 预期结果：可读取到提交人姓名、公司、部门信息，以及该提交人的历史工单列表。
- 证据类型：interaction，runtime-render

### AC-10：工单完成记录处理人与邮件通知

- 验收条件：工单完成时记录处理人和处理时间，并发送邮件通知提交人。
- 入口类型：用户界面
- 验证动作：处理人对一个待处理工单执行完成操作。
- 预期结果：工单状态变为完成，记录处理人和处理时间，提交人邮箱收到完成通知邮件。
- 证据类型：interaction，session-persistence

### AC-11：用户满意度评价

- 验收条件：工单完成后，提交人可对工单进行满意度评价。
- 入口类型：用户界面
- 验证动作：提交人对一个已完成的工单提交满意度评价。
- 预期结果：工单的满意度评价被记录，可被读取。
- 证据类型：interaction，session-persistence

### AC-12：按公司与部门维度统计工单分布

- 验收条件：系统支持按公司维度和部门维度统计工单分布。
- 入口类型：用户界面
- 验证动作：在统计页面分别按公司维度和部门维度查看工单分布。
- 预期结果：可读取到按公司分组的工单数量统计和按部门分组的工单数量统计。
- 证据类型：interaction，runtime-render

### AC-13：统计分析仪表盘展示运营指标

- 验收条件：仪表盘展示工单量、平均响应时间、满意度和热点问题指标。
- 入口类型：用户界面
- 验证动作：打开统计分析仪表盘页面。
- 预期结果：可读取到工单量、平均响应时间、满意度评分和热点问题分类指标。
- 证据类型：interaction，runtime-render

### AC-14：工单工作台筛选搜索排序

- 验收条件：工单工作台可查看待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：打开工单工作台，执行按公司筛选、关键词搜索和排序操作。
- 预期结果：工单列表按筛选条件和排序规则正确展示，搜索结果匹配关键词，公司筛选仅显示对应公司工单。
- 证据类型：interaction，runtime-render

### AC-15：工单操作日志记录

- 验收条件：工单的关键操作（创建、分配、转派、完成、取消、评价）被记录日志，日志包含操作人、操作时间、操作类型和工单ID。
- 入口类型：用户界面
- 验证动作：执行工单创建操作后查看操作日志。
- 预期结果：可读取到对应操作的日志记录，包含操作人、操作时间、操作类型和工单ID。
- 证据类型：interaction，session-persistence
