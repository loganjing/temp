# 资产领用单需求文档

来源：用户提供的《资产领用单产品需求文档（PRD）v2》（/Users/loganjing/work/codingtest/资产领用单prd-v2.md）。除单独标注外，本文规则均为用户在 PRD 中明确提出或已确认的内容。

## 1. 目标

- 提供标准化的固定资产领用单据，支持主从结构（主单 + 资产明细分录）。
- 记录领用人、领用部门、领用日期、用途说明及每项资产的详细信息。
- 通过单据自动编号保证领用单号的唯一性和可追溯性。
- 支持打印模板，满足纸质单据存档需求。

## 2. 核心旅程

资产管理员在系统中录入资产领用单：填写领用人、领用部门、领用日期、用途说明等主表信息，在明细分录中逐行录入资产的名称、规格型号、数量、资产编码等信息；保存时系统执行校验并自动生成领用单号；保存成功后可通过打印模板输出纸质单据，并支持按条件查询领用单。

## 3. 功能需求

### 3.1 资产领用单主表

记录资产领用单整体信息：

| 字段名称 | 字段编码 | 字段类型 | 必填 | 说明 |
|----------|----------|----------|------|------|
| 领用单号 | billno | 单据编号 | 是 | 系统自动生成，唯一标识 |
| 领用日期 | pick_date | 日期 | 是 | 资产领用日期 |
| 领用人 | picker | 用户 | 是 | 领用资产的员工 |
| 领用部门 | pick_dept | 组织 | 是 | 领用人所属部门 |
| 用途说明 | purpose | 多行文本 | 否 | 领用资产的用途描述 |
| 备注 | remark | 多行文本 | 否 | 其他补充说明 |
| 单据状态 | billstatus | 单据状态 | 是 | 系统预置（创建/已提交/已审核等） |
| 创建人 | creator | 用户 | 是 | 系统自动携带当前用户 |
| 创建时间 | createtime | 日期时间 | 是 | 系统自动携带当前时间 |
| 修改人 | modifier | 用户 | 是 | 系统自动携带当前用户 |
| 修改时间 | modifytime | 日期时间 | 是 | 系统自动携带当前时间 |
| 审核人 | auditor | 用户 | 否 | 审核操作人 |
| 审核日期 | auditdate | 日期时间 | 否 | 审核时间 |
| 组织 | org | 组织 | 是 | 业务组织 |

说明：单据状态为系统预置字段，本需求不启用工作流，不定义审批流转；审核人、审核日期仅作为字段保留，非必填。

### 3.2 资产领用单明细分录

记录每项领用资产的详细信息，一行一条资产记录：

| 字段名称 | 字段编码 | 字段类型 | 必填 | 说明 |
|----------|----------|----------|------|------|
| 资产名称 | asset_name | 文本 | 是 | 领用资产的名称 |
| 资产编码 | asset_code | 文本 | 否 | 资产的唯一编码（如有） |
| 规格型号 | spec_model | 文本 | 否 | 资产的规格型号 |
| 数量 | qty | 数量 | 是 | 领用数量，默认 1 |
| 单位 | unit | 计量单位 | 否 | 计量单位（如台、套、个） |
| 存放位置 | location | 文本 | 否 | 资产存放或领取位置 |
| 备注 | line_remark | 多行文本 | 否 | 分录行备注 |
| 修改人 | modifierfield | 用户 | 是 | 系统自动携带 |
| 修改时间 | modifydatefield | 日期时间 | 是 | 系统自动携带 |

分录业务规则：
- 明细分录至少有一条记录，不允许空分录提交。
- 同一分录中，资产名称不能为空。

### 3.3 单据自动编号

- 系统自动生成唯一的领用单号。
- 编号格式：前缀 `LY` + 日期 `yyyyMMdd` + 4 位递增流水号，示例 `LY202505050001`（PRD 标注为建议规则，按此执行；单号唯一性为用户明确要求）。

### 3.4 打印模板

提供领用单打印模板，支持套打输出纸质单据。打印内容：

- 主表信息：领用单号、领用日期、领用人、领用部门、用途说明、备注。
- 分录信息：资产名称、资产编码、规格型号、数量、单位、存放位置。
- 签章区域：领用人签字、部门负责人签字、资产管理员签字、日期。

### 3.5 保存校验

在单据保存时执行校验，确保数据完整性：

1. 分录非空校验：保存前校验明细分录是否为空，为空则阻止保存并提示「明细分录不能为空」。
2. 资产名称必填校验：保存前逐条校验分录中资产名称是否为空，为空则阻止保存并提示「资产名称不能为空」。

### 3.6 数据查询

支持按领用单号、领用人、领用日期等条件查询已保存的资产领用单。

## 5. 非功能要求（用户明确约束）

- 性能：单据保存响应时间 ≤ 2 秒（纳入 AC-01 验收）。
- 可用性：界面操作直观，表单布局清晰合理。
- 兼容性：支持主流浏览器访问。

## 6. 验收场景

### AC-01：资产管理员可创建并保存资产领用单

- 验收条件：填写主表必填信息和至少一条分录后保存成功，主表与分录数据完整保存并可读回，保存响应时间不超过 2 秒。
- 入口类型：用户界面
- 验证动作：在资产领用单界面填写领用日期、领用人、领用部门、组织等主表必填字段，在明细分录中录入至少一条资产信息（含资产名称、数量），执行保存；随后重新打开该单据查看数据。
- 预期结果：保存成功；重新打开后主表与分录字段数据与录入内容一致、完整无丢失；保存操作在 2 秒内完成响应。
- 证据类型：runtime-render, session-persistence

### AC-02：无效数据被阻止保存并给出明确提示

- 验收条件：主表必填字段为空、明细分录为空或分录资产名称为空时，保存被阻止，并给出对应的明确提示。
- 入口类型：用户界面
- 验证动作：
  1. 主表必填字段（如领用人、领用部门、领用日期）留空，录入有效分录，执行保存；
  2. 主表必填字段填写完整，但未录入任何明细分录，执行保存；
  3. 主表必填字段填写完整并录入分录，但其中某行资产名称为空，执行保存。
- 预期结果：三种情况均保存失败且不生成单据数据；分别给出明确提示：主表必填字段为空的必填提示、「明细分录不能为空」、「资产名称不能为空」。
- 证据类型：error-feedback

### AC-03：保存后自动生成符合规则的唯一领用单号

- 验收条件：保存成功后系统自动生成领用单号，格式为 `LY` + `yyyyMMdd` + 4 位流水号，且单号唯一。
- 入口类型：用户界面
- 验证动作：连续保存两张内容有效的资产领用单，查看系统生成的领用单号。
- 预期结果：每张单据自动生成领用单号，格式符合 `LYyyyyMMdd` + 4 位流水号（如 `LY202505050001`）；两张单据的单号互不相同；单号在单据上可见，并可用于追溯查询。
- 证据类型：runtime-render

### AC-04：可通过打印模板输出纸质领用单

- 验收条件：打印输出包含主表信息和分录信息并带签章区域的领用单。
- 入口类型：用户界面
- 验证动作：打开一张已保存的资产领用单，通过打印模板执行打印。
- 预期结果：打印输出包含领用单号、领用日期、领用人、领用部门、用途说明、备注等主表信息，以及每行的资产名称、资产编码、规格型号、数量、单位、存放位置等分录信息，并包含领用人签字、部门负责人签字、资产管理员签字、日期的签章区域。
- 证据类型：interaction, visual-style

### AC-05：支持按条件查询领用单

- 验收条件：可按领用单号、领用人、领用日期等条件查询到已保存的资产领用单。
- 入口类型：用户界面
- 验证动作：保存资产领用单后，分别按领用单号、领用人、领用日期条件执行查询。
- 预期结果：查询结果包含目标领用单，且单据数据与保存内容一致；不满足条件的单据不出现在查询结果中。
- 证据类型：interaction
