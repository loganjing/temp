# Bug fix / 缺陷修复

Status / 状态: fixed

修复三处界面与数据不一致的缺陷：抽屉关闭时保留当前模式与记录，收起过程不再闪成“新增教师”空壳；Form.List 行改为显式传 key、不再把 key 展开进 Form.Item；手机输入去掉硬截断，改由既有校验规则拦截超长号码。同时补充手机 12 位用例与表单取值往返的单元测试。

## Investigation / 调查
- 原始任务只给出项目路径，没有描述具体现象；目标项目自带的验证记录（docs/wi-t1000008/verification.md）结论为 pass-with-risk 且未登记缺陷，因此按“先实际运行复现，再定位修复”推进。
- 当前工作项分支（kteam/23684738304708608/T1000011，提交 a04f4ceb）的基线里没有应用源码，只有 docs/ 与 .gitignore；被引用的项目在同一仓库的 wi-t1000008 工作树（提交 8dcb294e）。为了在本次授权的写范围内交付，把该项目的 src、tests、index.html、package.json、package-lock.json、vite.config.js、README.md 原样带入当前工作项作为修复基线，带入时未修改其内容。
- 基线单元测试 15 项通过；启动开发服务器后在页面实测新增、编辑、删除、刷新持久化以及名称/手机/邮箱校验，均能按需求工作，没有复现出既有验证记录之外的业务流程阻断。
- 页面实测发现三处缺陷：抽屉保存后收起动画期间标题和引导文案已经变成“新增教师”，表单里却仍是刚保存那位教师的数据；打开含有课程/年级条目的表单时控制台出现 React 报错（key 通过对象展开传进 JSX）；手机输入框输入 12 位号码会被静默截断成 11 位，并按截断后的号码保存。
- 三处缺陷的共同点是“界面显示与真实数据不一致”：一处把上一条记录当成新表单内容展示，一处污染运行期控制台并妨碍表单行增删的稳定渲染，一处让用户输入的值在没有提示的情况下被改写。

## Root cause / 根因
1) src/App.jsx 的 closeDrawer 把抽屉状态重置为模块常量 CLOSED_DRAWER（mode 固定为 'create'），而 TeacherFormDrawer 只在 open 变为 true 时重置表单，于是收起动画期间面板已切到“新增教师”文案，字段却仍渲染上一条记录的 store 值。2) src/components/TeacherFormDrawer.jsx 的 Form.List 行把整个 {...field} 展开到 <Form.Item>，field 中含 key，React 会报“key 通过对象展开传入 JSX”，并使行 meta 与 JSX 属性来源混杂。3) 手机 Input 上的 maxLength={11} 让浏览器在输入或粘贴时静默截断，校验器随后校验的是被截断后的值，于是保存了用户从未输入的号码。
