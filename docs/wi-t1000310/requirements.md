# 工单系统需求文档

> 工作项：wi-t1000310　|　阶段：requirements　|　业务任务：125-ticket
> 来源标注约定：**〔用户〕** = 用户明确提出；**〔推荐〕** = 闭合核心目标所必需的最小推荐基线，可后续调整；未标注来源的描述是对用户需求的组织与展开，不引入新的产品决定。

---

## 1. 目标与范围概览

构建一个多公司工单管理系统：员工提交工单，工单按公司隔离、按分类自动分配到业务组；处理人通过工作台处理工单并进行协作（多轮回复、转派）；工单完成后系统记录处理信息并发送邮件通知，提交人随后进行满意度评价；系统提供按公司/部门维度的工单分布统计与运营指标仪表盘，并记录工单相关操作日志。

| 功能域 | 内容 | 来源 |
|---|---|---|
| 工单管理 | 工单创建（完整字段、SLA优先级 P0-P4、问题分类）、多轮回复、公司隔离、生命周期状态 | 〔用户〕 |
| 工单分配 | 公司/业务组/成员管理、按分类自动分配 | 〔用户〕 |
| 工单协作 | 工单转派 | 〔用户〕 |
| 工单处理 | 提交人完整信息查看、处理记录、完成邮件通知 | 〔用户〕 |
| 用户评价 | 满意度评价 | 〔用户〕 |
| 统计分析 | 按公司、部门维度统计工单分布；运营指标仪表盘（工单量、平均响应时间、满意度、热点问题） | 〔用户〕 |
| 工单工作台 | 待处理工单列表：筛选、搜索、排序、按公司维度筛选 | 〔用户〕 |
| 操作日志 | 记录工单相关日志 | 〔用户〕 |

## 2. 参与方与公司隔离

### 2.1 参与方

| 参与方 | 职责 | 来源 |
|---|---|---|
| 提交人 | 提交工单、多轮回复补充信息、接收完成邮件通知、进行满意度评价 | 〔用户〕（"提交人""用户收到工单后进行满意度评价"） |
| 处理人 | 处理分配到本业务组的工单、回复、转派、执行完成操作 | 〔用户〕（"在处理工单时""记录处理人"） |
| 业务组与分配规则配置方 | 为公司创建业务组、设置业务组成员、配置分类自动分配规则 | 用户功能点的操作主体，用户未为其命名具体角色 |
| 运营统计查看方 | 查看统计分析与运营仪表盘、在工作台按公司维度筛选跟踪工单 | 〔推荐〕（按公司维度统计与筛选隐含跨公司查看视角） |

### 2.2 公司隔离

- 工单数据按公司隔离：任一公司的工单对其他公司不可见——其他公司的用户无法在工单列表、搜索结果或工单详情中访问〔用户〕。
- 业务组、业务组成员与分配规则均归属某个公司，不跨公司共享〔用户〕。
- 跨公司查看视角仅存在于运营/统计场景：按公司维度统计汇总、工作台按公司筛选，面向运营统计查看方开放〔推荐〕。提交人与处理人的日常操作均在其所属公司范围内。

## 4. 工单生命周期

状态集：**创建 → 待分配 → 待处理 → 完成 / 取消**〔用户〕。其中「完成」「取消」为终态。

```
创建 ──自动流转──> 待分配 ──分配到业务组──> 待处理 ──处理完成──> 完成（终态）
                     │                       │
                     └────── 取消 ──────────┘
                                             v
                                          取消（终态）
```

| 编号 | 转换规则 | 来源 |
|---|---|---|
| LC-01 | 工单提交后处于「创建」状态，随即自动流转为「待分配」 | 状态集〔用户〕；自动流转〔推荐〕 |
| LC-02 | 「待分配」工单被分配到业务组（自动或手动）后流转为「待处理」 | 状态集〔用户〕；分配触发流转〔推荐〕 |
| LC-03 | 「待处理」工单处理完成后流转为「完成」 | 〔用户〕 |
| LC-04 | 工单在「创建」「待分配」「待处理」状态下可被取消，流转为「取消」；提交人可取消其提交的未终态工单 | 状态集〔用户〕；可取消范围与操作者〔推荐〕 |
| LC-05 | 转派不改变工单状态，仅变更工单归属的业务组 | 〔推荐〕 |
| LC-06 | 「完成」「取消」为终态，工单进入终态后不可再流转到其他状态 | 〔推荐〕 |

## 5. 端到端用户旅程

### 5.1 提交人旅程

1. 提交人填写主题、描述，选择问题分类与SLA优先级（P0-P4），提交工单（6.1.1）〔用户〕
2. 系统生成工单ID，记录提交人信息（姓名、邮箱、公司、部门）与创建时间〔用户〕
3. 工单进入「创建」状态并流转「待分配」（LC-01）
4. 工单按分类自动分配到业务组（6.2.2）〔用户〕
5. 处理过程中，提交人可进行多轮回复补充信息（6.1.2）〔用户〕
6. 工单完成后，系统发送完成邮件通知到提交人邮箱（6.4.3）〔用户〕
7. 提交人收到通知后对工单进行满意度评价（6.5）〔用户〕

### 5.2 处理人旅程

1. 处理人在工作台查看待处理工单列表，筛选、搜索、排序定位工单（6.7）〔用户〕
2. 打开工单详情，查看主题、描述、分类、SLA优先级与当前状态
3. 查看提交人完整信息面板：姓名、公司、部门、历史工单（6.4.1）〔用户〕
4. 通过多轮回复与提交人沟通（6.1.2）
5. 工单不属于本组职责时，转派给其他业务组（6.3）〔用户〕
6. 处理完成后执行完成操作，系统记录处理人、处理时间（6.4.2）〔用户〕

### 5.3 配置旅程

1. 配置方为某公司创建多个业务组（6.2.1）〔用户〕
2. 为每个业务组设置成员（6.2.1）〔用户〕
3. 配置该公司的「问题分类 → 业务组」自动分配规则（6.2.2）〔用户〕
4. 新工单按分类自动匹配分配规则；无匹配的待分配工单由配置方手动分配〔推荐〕

### 5.4 运营旅程

1. 运营统计查看方查看按公司、部门维度的工单分布统计（6.6.1）〔用户〕
2. 查看运营指标仪表盘：工单量、平均响应时间、满意度、热点问题（6.6.2）〔用户〕
3. 在工作台按公司维度筛选、跟踪待处理工单（6.7）〔用户〕

## 6. 分模块功能需求

### 6.1 工单管理

#### 6.1.1 工单创建

**行为**：提交人创建工单，系统记录完整信息。

**字段**：

| 字段 | 说明 | 来源 |
|---|---|---|
| 工单ID | 系统生成的唯一标识 | 〔用户〕 |
| 主题 | 工单标题，必填 | 〔用户〕 |
| 描述 | 工单详细内容，必填 | 〔用户〕 |
| 分类 | 从系统已有问题分类中选择 | 〔用户〕 |
| SLA优先级 | P0 / P1 / P2 / P3 / P4 | 〔用户〕 |
| 提交人信息 | 姓名、邮箱、公司、部门，自动取自提交人用户资料 | 含邮箱〔用户〕；部门与自动填充〔推荐〕 |
| 创建时间 | 系统记录的提交时刻 | 〔用户〕 |

**规则**：
- 主题或描述为空时不能提交〔推荐〕
- 提交人必须有所属公司，否则无法创建工单（公司隔离的前提）〔推荐〕
- 提交人信息由系统填充，提交人不能修改其公司归属〔推荐〕
- 创建成功后按 LC-01 进入状态流转

#### 6.1.2 工单多轮回复

**行为**：工单处理过程中，提交人与处理方对工单进行多轮回复。

**字段**：回复内容（必填）、回复人（系统记录）、回复时间（系统生成）。

**规则**：
- 工单支持多轮回复，回复按时间顺序排列〔用户〕
- 每条回复记录回复人与回复时间〔用户〕
- 回复主体为提交人与工单当前处理侧（业务组处理人）〔推荐〕
- 回复操作记录于操作日志（6.8）〔推荐〕

#### 6.1.3 SLA优先级与问题分类

- SLA优先级取值 P0-P4，P0 为最高〔用户〕
- 创建工单时必须选择一个问题分类与一个SLA优先级〔用户要求支持设置；必填为推荐〕
- 系统支持维护问题分类列表（新增、查看），作为工单创建与分配规则配置的前置数据〔推荐〕

#### 6.1.4 工单列表与详情

- 提交人可查看其提交的工单列表与详情（回复与评价的必要入口）〔推荐〕
- 处理人可查看其所在业务组承接的工单〔推荐〕
- 工单详情展示：主题、描述、分类、SLA优先级、提交人信息（含邮箱）、创建时间、当前状态、回复记录与操作记录〔用户（字段清单）+推荐（展示组织）〕
- 可见范围受公司隔离约束（2.2）〔用户〕

### 6.2 工单分配

#### 6.2.1 业务组管理

**行为**：为公司创建多个业务组，并为每个业务组设置成员。

**规则**：
- 每个公司下可创建多个业务组〔用户〕
- 每个业务组可设置多个成员，成员为该公司内用户〔用户；成员限于公司内为推荐〕
- 业务组成员可被添加与移除〔推荐〕
- 业务组、成员、分配规则按公司归属，不跨公司共享〔用户（隔离）〕

#### 6.2.2 分类自动分配

**行为**：为某公司配置「问题分类 → 业务组」分配规则，该公司新工单按分类自动分配到业务组。

**规则**：
- 分配规则以公司为范围：某公司的某问题分类映射到该公司的一个业务组〔用户〕
- 同一公司内一个问题分类最多映射到一个业务组；一个业务组可承接多个分类的工单〔推荐〕
- 工单进入「待分配」后，系统按其公司+分类匹配分配规则；匹配成功时工单自动归属对应业务组并流转「待处理」〔用户〕
- 无匹配规则时，工单保持「待分配」，由配置方手动分配到某业务组后流转「待处理」〔推荐〕
- 自动分配与手动分配均记录分配结果（分配方式、目标业务组、时间）于操作日志（6.8）〔推荐〕

### 6.3 工单协作：转派

**行为**：处理人可将工单转派给其他业务组。

**流程**：处理人在「待处理」工单上发起转派，选择目标业务组并确认，工单归属业务组变更。

**规则**：
- 转派目标为同公司内的其他业务组〔推荐〕
- 转派后工单状态保持「待处理」，归属业务组变更为目标业务组〔推荐〕
- 转派记录包含转派人、目标业务组、转派时间；可填写转派原因〔推荐〕
- 「待处理」工单可多次转派；终态工单不可转派〔推荐〕

### 6.4 工单处理

#### 6.4.1 提交人完整信息查看

**行为**：处理人在处理工单时可查看提交人的完整信息。

**内容**：姓名、公司、部门，以及提交人的历史工单列表（含主题、状态、创建时间）〔用户〕。

**规则**：
- 历史工单按创建时间倒序排列〔推荐〕
- 历史工单范围限于提交人所属公司（公司隔离的自然结果）〔用户（隔离推导）〕

#### 6.4.2 工单处理完成

**行为**：处理人完成处理后，对工单执行完成操作。

**记录**：处理人（执行完成操作的用户）、处理时间（完成操作时刻）；工单状态变更为「完成」〔用户〕。

**规则**：
- 完成后工单进入终态，不再接受状态变更（LC-06）〔推荐〕
- 完成操作记录于操作日志（6.8）〔推荐〕

#### 6.4.3 完成邮件通知

**行为**：工单完成时，系统向提交人发送邮件通知〔用户〕。

**规则**：
- 通知发送至提交人邮箱（取自工单上的提交人信息）〔用户（"提交人信息（含邮箱）"与完成通知的衔接）〕
- 邮件内容至少可识别对应工单（含工单标识）及其完成状态〔推荐〕
- 通知发送记录于操作日志（6.8）〔推荐〕

### 6.5 用户满意度评价

**行为**：工单完成后（提交人收到完成通知后），提交人对该工单进行满意度评价〔用户〕。

**规则**：
- 仅「完成」状态的工单可被评价；仅提交人本人可评价其提交的工单〔用户（"用户收到工单后"）；资格与状态限定为推荐补充〕
- 评价形式为量化评分（1-5 星或等价形式）〔推荐：仪表盘满意度指标需要量化口径〕
- 每个工单可评价一次，评价提交后不可修改〔推荐：统计口径一致性〕
- 评价记录包含评价人、评价时间与评分〔推荐：满足统计与追溯的最小记录〕
- 评价操作记录于操作日志（6.8）〔推荐〕

### 6.6 统计分析

#### 6.6.1 工单分布统计

**行为**：按公司、部门维度统计工单分布〔用户〕。

**规则**：
- 公司维度：统计各公司的工单量分布〔用户〕
- 部门维度：按提交人所属部门统计工单量分布〔用户〕
- 统计结果可查看；查看者为运营统计查看方（2.1）〔推荐〕

#### 6.6.2 运营指标仪表盘

**行为**：统计与分析仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标〔用户〕。用户以"等"开放式列举，下表四项为必须提供的最小指标集。

| 指标 | 口径 | 来源 |
|---|---|---|
| 工单量 | 工单数量统计，支持按公司维度查看 | 〔用户〕 |
| 平均响应时间 | 从工单创建到处理侧首次回复的平均耗时 | 〔推荐〕（用户要求该指标但未定义口径；由工单创建时间与首条处理侧回复时间计算） |
| 满意度 | 已评价工单的平均满意度评分 | 〔用户〕；平均值口径〔推荐〕 |
| 热点问题 | 按问题分类聚合的工单量排名 | 〔推荐〕（用户要求该指标但未定义口径） |

- 仪表盘展示基于当前工单业务数据计算的统计结果〔推荐〕

### 6.7 工单工作台

**行为**：查看待处理工单列表，支持筛选、搜索、排序〔用户〕。

| 能力 | 说明 | 来源 |
|---|---|---|
| 列表 | 展示状态为「待处理」的工单，含工单ID、主题、分类、SLA优先级、所属公司、创建时间等基础信息 | 待处理列表〔用户〕；列表列〔推荐〕 |
| 筛选 | 按公司维度筛选；补充按问题分类、SLA优先级筛选 | 按公司筛选〔用户〕；补充维度〔推荐〕 |
| 搜索 | 按主题关键词或工单ID搜索 | 〔推荐〕（用户要求搜索能力，目标字段未规定） |
| 排序 | 按创建时间、SLA优先级（P0 在前）排序 | 〔推荐〕（用户要求排序能力，排序字段未规定） |

**规则**：
- 工作台面向处理侧：处理人查看其有权处理的待处理工单（公司内）；运营统计查看方可跨公司查看并按公司筛选（2.2）〔推荐〕

### 6.8 操作日志

**行为**：记录工单相关操作的日志〔用户〕。

**规则**：
- 记录范围为工单生命周期与协作中的关键操作：创建、回复、分配（自动/手动）、转派、完成、邮件通知发送、取消、评价〔推荐：对"相关日志"的最小闭合〕
- 每条日志记录操作类型、操作人、操作时间〔推荐：最小可追溯字段〕
- 日志随操作产生，可供追溯查询，业务用户不可修改〔推荐〕

## 7. 验收场景

每条验收场景（AC）描述一个独立可观察的产品结果；`AC-xx` 编号在本文档内唯一。

### AC-01：创建工单并记录完整信息
- 验收条件：提交人可创建工单，系统记录工单全部字段信息并进入初始状态流转。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份新建工单，填写主题与描述，选择问题分类与SLA优先级（P0-P4），提交。
- 预期结果：系统生成唯一工单ID；工单记录主题、描述、分类、SLA优先级、提交人信息（姓名、邮箱、公司、部门）与创建时间；工单初始状态为「创建」，随后流转为「待分配」；提交人可查看该工单。
- 证据类型：runtime-render, interaction

### AC-02：工单多轮回复
- 验收条件：工单参与方可对工单进行多轮回复，系统记录回复人与回复时间。
- 入口类型：用户界面
- 验证动作：打开一个「待处理」工单详情，以提交人身份添加一条回复，再以处理人身份连续添加两条回复。
- 预期结果：三条回复均成功保存并按时间顺序展示；每条回复显示回复人、回复时间与回复内容。
- 证据类型：interaction, runtime-render

### AC-03：工单按公司隔离
- 验收条件：一个公司的用户无法访问其他公司的工单。
- 入口类型：用户界面
- 验证动作：以公司A提交人身份登录，在工单列表与搜索中查找公司B已存在的工单，并尝试通过其工单ID直接访问。
- 预期结果：公司B的工单不出现在公司A用户的工单列表与搜索结果中；直接访问被拒绝且不展示公司B工单内容。
- 证据类型：authorization, error-feedback

### AC-04：业务组与成员管理
- 验收条件：可为公司创建多个业务组，并为每个业务组设置成员。
- 入口类型：用户界面
- 验证动作：为某公司创建两个业务组，分别向两个业务组添加多名成员，再从其中一个业务组移除一名成员。
- 预期结果：业务组创建成功且归属该公司；成员添加与移除成功；业务组与成员列表正确展示各组成员。
- 证据类型：interaction, runtime-render

### AC-05：工单按分类自动分配
- 验收条件：配置分配规则后，公司内新工单按其分类自动分配到对应业务组。
- 入口类型：后台任务
- 验证动作：为公司C配置「分类X → 业务组G」分配规则；以公司C提交人身份创建分类为X的工单；再创建一个未配置规则的其他分类工单。
- 预期结果：分类为X的工单自动归属业务组G，状态由「待分配」流转为「待处理」；无匹配规则的工单保持「待分配」。
- 证据类型：other

### AC-06：工单转派
- 验收条件：处理人可将「待处理」工单转派给其他业务组，转派记录可追溯。
- 入口类型：用户界面
- 验证动作：处理人对其业务组承接的「待处理」工单执行转派，选择同公司另一业务组并确认。
- 预期结果：工单归属业务组变更为目标业务组；工单状态保持「待处理」；转派记录（转派人、目标业务组、转派时间）可在工单中查看。
- 证据类型：interaction, runtime-render

### AC-07：查看提交人完整信息
- 验收条件：处理人处理工单时可查看提交人完整信息，包括历史工单。
- 入口类型：用户界面
- 验证动作：处理人打开「待处理」工单详情，查看提交人信息面板。
- 预期结果：面板展示提交人姓名、公司、部门；展示该提交人在本公司的历史工单列表（含主题、状态、创建时间），按创建时间倒序排列。
- 证据类型：runtime-render

### AC-08：工单处理完成
- 验收条件：处理人完成处理后，系统记录处理人与处理时间，工单进入完成终态。
- 入口类型：用户界面
- 验证动作：处理人对「待处理」工单执行完成操作，随后查看工单详情并尝试再次执行转派、取消类操作。
- 预期结果：系统记录处理人与处理时间；工单状态变为「完成」；完成后的工单不再接受状态变更操作，操作入口不可用或被拒绝。
- 证据类型：interaction, runtime-render

### AC-09：工单完成邮件通知
- 验收条件：工单完成时，系统向提交人发送邮件通知。
- 入口类型：后台任务
- 验证动作：处理人完成某工单后，检查该工单提交人的邮箱。
- 预期结果：提交人邮箱收到完成通知邮件，邮件内容可识别对应工单（含工单标识）及其完成状态。
- 证据类型：other

### AC-10：满意度评价
- 验收条件：工单完成后，提交人可对工单进行一次满意度评价，评价被记录。
- 入口类型：用户界面
- 验证动作：提交人打开其已完成工单并提交满意度评分；再次尝试对同一工单评价；检查一个未完成工单的评价入口。
- 预期结果：首次评价成功保存，记录评价人、评价时间与评分；对同一工单的第二次评价被拒绝；未完成工单不提供评价入口。
- 证据类型：interaction, error-feedback

### AC-11：工单分布统计
- 验收条件：支持按公司、部门维度统计工单分布。
- 入口类型：用户界面
- 验证动作：在统计分析中分别选择公司维度与部门维度查看工单分布。
- 预期结果：公司维度展示各公司的工单量分布；部门维度按提交人所属部门展示工单量分布；统计结果与当前实际工单数据一致。
- 证据类型：runtime-render

### AC-12：运营指标仪表盘
- 验收条件：统计与分析仪表盘可查看工单量、平均响应时间、满意度、热点问题四类运营指标。
- 入口类型：用户界面
- 验证动作：打开统计与分析仪表盘，查看四类指标。
- 预期结果：仪表盘展示工单量、平均响应时间（工单创建到处理侧首次回复的平均耗时）、满意度（已评价工单平均评分）、热点问题（按分类的工单量排名）；指标值基于当前工单数据计算（如工单量与当前工单总数一致）。
- 证据类型：runtime-render

### AC-13：工单工作台
- 验收条件：工作台可查看待处理工单列表，支持筛选、搜索、排序与按公司维度筛选。
- 入口类型：用户界面
- 验证动作：在工作台依次执行按公司筛选、按分类或SLA优先级筛选、按主题关键词或工单ID搜索、按创建时间与SLA优先级排序。
- 预期结果：列表仅展示「待处理」状态的工单；每次筛选、搜索、排序操作后列表结果相应正确变化（按公司筛选后仅显示所选公司工单）。
- 证据类型：interaction, runtime-render

### AC-14：操作日志记录
- 验收条件：工单相关关键操作均产生日志记录，可供追溯。
- 入口类型：内部
- 验证动作：依次执行工单创建、回复、分配、转派、完成、取消、评价操作，然后查询工单操作日志。
- 预期结果：日志包含上述操作记录；每条日志含操作类型、操作人、操作时间。
- 证据类型：other

### AC-15：生命周期状态与终态
- 验收条件：工单状态沿定义的生命周期流转，「完成」与「取消」为不可逆终态。
- 入口类型：用户界面
- 验证动作：对「待处理」工单执行取消；对「完成」工单尝试执行转派、取消、完成操作；对「取消」工单尝试执行处理类操作。
- 预期结果：取消后工单状态为「取消」并进入终态；「完成」「取消」工单的状态变更操作被拒绝或入口不可用，状态不再变化。
- 证据类型：interaction, error-feedback
