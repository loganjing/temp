# 工单系统（123-ticket）产品需求说明

> 工作项：wi-t1000305 · 阶段：requirements · 来源：用户业务任务"123-ticket"

标注约定：
- （用户明确）= 用户在业务任务中明确提出的要求；
- （推荐）= 为闭合核心验收而补充的最小推荐基线，保守、可逆、可观察；
- （未规定）= 用户未规定，本基线保持开放，不替用户决定。

## 1. 目标与范围

构建一个面向多公司的工单系统：公司成员提交工单，服务侧按业务组承接并处理，完成后邮件通知提交人并由其进行满意度评价；系统同时提供工单工作台、统计分析与运营仪表盘，并记录关键操作日志。

范围（用户明确）：

| 能力域 | 内容 |
|---|---|
| 工单管理 | 工单信息记录、多轮回复、按公司隔离、SLA 优先级（P0–P4）与问题分类、生命周期状态 |
| 工单分配 | 公司级业务组与成员配置、按分类自动分配 |
| 工单协作 | 工单转派 |
| 工单处理 | 提交人完整信息查看、处理记录、完成邮件通知 |
| 用户评价 | 满意度评价 |
| 统计分析 | 按公司/部门维度统计工单分布、运营仪表盘 |
| 工单工作台 | 待处理工单列表与筛选、搜索、排序 |
| 日志 | 记录相关操作日志 |

核心旅程（端到端）：

1. 提交人创建工单：系统记录工单信息，工单进入待分配。
2. 系统按分类将该公司的工单自动分配到对应业务组（进入待处理）；未命中规则时停留待分配等待人工分配；处理过程中可转派调整归属。
3. 处理人查看提交人完整信息（姓名、公司、部门、历史工单），与提交人多轮回复沟通并处理。
4. 处理人完成工单：系统记录处理人、处理时间，状态变为完成，并向提交人邮箱发送通知邮件。
5. 提交人收到通知后对工单进行满意度评价。
6. 全程关键操作记录日志；工单数据进入工作台列表、统计与仪表盘。

## 2. 角色与数据隔离

| 角色 | 说明 | 来源 |
|---|---|---|
| 提交人 | 公司成员，创建工单、参与多轮回复、接收完成通知邮件、进行满意度评价 | 用户明确 |
| 处理人 | 承接并处理工单，可回复、转派；完成工单时被记录为处理人 | 用户明确 |
| 业务组成员 | 处理人归属业务组，业务组承接归属公司的工单 | 用户明确 |
| 运营/管理方 | 配置业务组与分类自动分配规则；使用支持按公司筛选的工作台与统计分析 | 由"可按公司维度筛选""按公司维度统计"要求推断 |

数据隔离（用户明确）：

- 每张工单归属提交人所在公司；工单及其回复、处理、评价等数据按公司隔离。
- 公司内的用户（提交人侧）仅能看到本公司的工单，不同公司之间互不可见对方的工单数据。
- 工作台"按公司筛选"与"按公司维度统计"面向可跨公司查看的服务侧（运营/管理方）视图，用于兼顾公司隔离与跨公司运营要求。

## 3. 工单数据与生命周期

### 3.1 工单信息

工单创建时记录（用户明确）：

| 字段 | 说明 |
|---|---|
| 工单ID | 系统生成的唯一标识 |
| 主题 / 描述 | 工单标题与正文 |
| 问题分类 | 用于组织工单并驱动自动分配 |
| SLA 优先级 | P0–P4 枚举（用户明确范围；各优先级的响应/解决时限目标未规定，不在本基线内） |
| 提交人信息 | 姓名、公司、部门、邮箱 |
| 创建时间 | 工单提交时刻 |

### 3.2 生命周期状态

（用户明确）主流程：创建 → 待分配 → 待处理 → 完成；取消为分支终态。

```
创建 → 待分配 →（分配到业务组/处理人）→ 待处理 →（处理完成）→ 完成
                                        └────────完成前可取消────────→ 取消
```

| 状态 | 定义 |
|---|---|
| 创建 | 工单生成时刻的初始状态，信息落库 |
| 待分配 | 已提交，尚未分配到业务组或处理人 |
| 待处理 | 已分配到业务组/处理人，等待或正在进行处理 |
| 完成 | 处理结束，已记录处理信息并触发邮件通知（终态） |
| 取消 | 工单被取消（终态） |

- 提交后工单进入待分配；命中分类自动分配规则时分配到业务组并进入待处理。
- 取消：完成前可将工单置为取消（推荐：允许取消的前置状态为未完成；取消操作的发起角色未规定）。

### 3.3 多轮回复

（用户明确）工单支持多轮回复：提交人与处理方可对同一工单进行多轮回复沟通；每条回复记录回复人、回复时间与内容，按时间顺序保留并可查看。

## 4. 工单分配与协作

### 4.1 业务组配置

（用户明确）

- 每个公司可配置多个业务组。
- 每个业务组可设置成员（处理人）。
- 业务组归属公司，承接归属公司的工单。

### 4.2 按分类自动分配

（用户明确）公司维度的自动分配规则：将某问题分类映射到该公司某业务组；该公司新建该分类的工单时，自动分配到对应业务组，无需人工选择。

- 推荐：未命中分配规则的分类，工单停留在待分配等待人工分配（用于闭合"待分配"状态的可观察行为）。

### 4.3 工单转派

（用户明确）支持工单转派操作：处理人可将工单转派给其他业务组或处理人；转派后工单的处理归属变更为转派目标，转派操作留痕（转派人、时间、目标），并计入日志。

## 5. 工单处理与通知

### 5.1 提交人完整信息

（用户明确）处理人处理工单时，可查看提交人的完整信息：姓名、公司、部门、历史工单（该提交人此前提交的工单列表）。

### 5.2 处理完成与邮件通知

（用户明确）

- 工单处理完成后，记录处理人、处理时间等处理信息。
- 工单完成时，向提交人发送邮件通知（收件地址为工单记录的提交人邮箱；邮件内容与模板未规定）。

### 5.3 用户满意度评价

（用户明确）提交人收到已完成工单后，可对工单进行满意度评价；评价结果记录在工单上（含评价人、评价时间），并纳入满意度统计。

- 评价量表形式（星级/等级/分数）未规定，以系统提供的评价输入为准。

## 6. 工单工作台

（用户明确）面向处理侧的工单工作台：

- 展示待处理工单列表。
- 支持筛选、搜索、排序。
- 支持按公司维度筛选。

推荐最小基线（闭合可验收的具体维度）：筛选维度含公司、优先级、分类；搜索支持按工单ID或主题关键字；排序支持按创建时间、优先级。其余维度以系统实际提供为准。

## 7. 统计分析与仪表盘

（用户明确）

- 工单分布统计：支持按公司、部门（提交人所在部门）维度统计工单分布。
- 运营仪表盘：查看工单量、平均响应时间、满意度、热点问题等运营指标。

指标口径（推荐最小基线）：

- 平均响应时间 = 工单创建时间至首次处理回复的平均时长。
- 满意度 = 已完成工单的评价结果汇总。
- 热点问题 = 工单量最高的问题分类。

## 8. 操作日志

（用户明确）系统记录工单相关操作的日志。

推荐最小基线：日志覆盖工单创建、分配、转派、回复、处理、完成、取消、评价等关键操作；每条日志包含操作类型、操作人、操作时间与所涉工单标识。日志的查看入口与保留期限未规定。

## 9. 验收场景

### AC-01：工单创建与信息记录
- 验收条件：提交人可创建工单，系统完整记录工单信息（含 SLA 优先级）并纳入生命周期管理。
- 入口类型：用户界面
- 验证动作：使用带有姓名、公司、部门、邮箱的提交人账号创建工单，填写主题、描述、选择问题分类、设置 SLA 优先级（如 P2），提交后查看工单详情。
- 预期结果：工单创建成功并生成唯一工单ID；详情中可见主题、描述、问题分类、SLA 优先级（可选项覆盖 P0–P4）、提交人姓名/公司/部门/邮箱、创建时间；工单处于生命周期初始状态（创建/待分配）。
- 证据类型：runtime-render, interaction

### AC-02：工单生命周期状态流转
- 验收条件：工单按"创建 → 待分配 → 待处理 → 完成"主流程流转，并支持取消为终态。
- 入口类型：用户界面
- 验证动作：创建一张工单并观察初始状态；将其分配到业务组后观察状态；处理后执行完成操作；另创建一张工单执行取消操作；分别查看工单状态。
- 预期结果：工单创建后可见初始状态；分配到业务组/处理人后状态变为待处理；处理完成后状态变为完成（终态）；取消操作后状态变为取消（终态）；每次状态变化均可在工单详情中观察到。
- 证据类型：runtime-render, interaction

### AC-03：工单按公司隔离
- 验收条件：工单数据按公司隔离，公司A的用户无法查看公司B的工单。
- 入口类型：用户界面
- 验证动作：分别在两个公司各创建一张工单；以公司A用户身份查看工单列表，并尝试搜索公司B工单的ID/主题。
- 预期结果：公司A用户仅能看到本公司工单；公司B的工单不出现在其列表、搜索结果与详情中。
- 证据类型：runtime-render, authorization

### AC-04：工单多轮回复
- 验收条件：工单支持多轮回复，每条回复记录回复人与回复时间。
- 入口类型：用户界面
- 验证动作：在一张已分配的工单中，由处理人回复一次，再由提交人回复一次，形成两轮以上回复；查看该工单的回复区。
- 预期结果：各轮回复按时间顺序排列展示；每条回复显示回复人、回复时间与内容；多轮回复均被保留。
- 证据类型：runtime-render, interaction

### AC-05：公司业务组配置
- 验收条件：每个公司可配置多个业务组，业务组可设置成员。
- 入口类型：用户界面
- 验证动作：为公司A配置两个业务组（如"技术支持组""账务组"），并分别为两个业务组添加成员；查看公司A的业务组列表。
- 预期结果：公司A下存在两个业务组且归属公司A；各业务组的成员列表正确保存并可再次查看。
- 证据类型：runtime-render, interaction

### AC-06：工单按分类自动分配到业务组
- 验收条件：配置公司的分类→业务组自动分配规则后，该公司新建该分类的工单被自动分配到对应业务组。
- 入口类型：用户界面
- 验证动作：为公司A配置映射"分类X → 业务组G"；以公司A提交人身份创建分类为X的工单（不做人工分配）；以业务组G成员身份查看工作台待处理列表。
- 预期结果：新工单无需人工选择即分配到业务组G，出现在G成员的工作台待处理列表中，工单状态进入待处理。
- 证据类型：runtime-render, interaction

### AC-07：工单转派
- 验收条件：处理人可将工单转派给其他业务组或处理人，转派结果与记录可观察。
- 入口类型：用户界面
- 验证动作：处理人打开一张待处理工单，执行转派到另一业务组/处理人的操作；查看工单的处理归属。
- 预期结果：工单处理归属变更为转派目标（出现在目标方的工作台列表中）；转派操作被记录（含转派人、时间、目标）；原处理方不再持有该工单的处理责任。
- 证据类型：runtime-render, interaction

### AC-08：处理时查看提交人完整信息
- 验收条件：处理人处理工单时可查看提交人完整信息，包括姓名、公司、部门、历史工单。
- 入口类型：用户界面
- 验证动作：使用已提交过工单的提交人新建一张工单并分配给处理人；处理人打开该工单的处理视图，查看提交人信息区。
- 预期结果：处理视图中显示提交人姓名、公司、部门，以及该提交人的历史工单列表（含其此前提交的工单）。
- 证据类型：runtime-render

### AC-09：工单完成处理与邮件通知
- 验收条件：工单处理完成时记录处理人与处理时间，并向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：处理人对一张待处理工单执行完成操作；查看工单详情中的处理信息；检查提交人邮箱。
- 预期结果：工单状态变为完成；工单上记录处理人与处理时间；提交人邮箱收到该工单的完成通知邮件。
- 证据类型：interaction, other

### AC-10：用户满意度评价
- 验收条件：工单完成后，提交人可对其进行满意度评价，评价结果被记录并纳入满意度统计。
- 入口类型：用户界面
- 验证动作：提交人打开一张已完成工单，提交满意度评价；查看工单上的评价记录；查看统计中的满意度指标。
- 预期结果：评价提交成功，工单上记录评价人与评价结果；该评价体现在满意度统计指标中。
- 证据类型：interaction, runtime-render

### AC-11：工单工作台列表操作
- 验收条件：工作台展示待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：进入工单工作台查看待处理列表；按公司维度筛选；按工单ID或主题关键字搜索；切换排序方式。
- 预期结果：列表展示待处理工单；选择某公司后仅显示该公司工单；输入关键字后列表过滤为匹配结果；切换排序后列表顺序相应变化。
- 证据类型：runtime-render, interaction

### AC-12：统计分析与运营仪表盘
- 验收条件：统计支持按公司、部门维度查看工单分布；仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：在两个公司、不同部门、不同分类下积累若干工单（含已回复、已完成与已评价的工单）后，打开统计分析页面与运营仪表盘。
- 预期结果：可按公司、部门维度查看工单分布（各维度的工单数量）；仪表盘显示工单量、平均响应时间（创建至首次处理回复的平均时长）、满意度（评价汇总）、热点问题（工单量最高的问题分类），且数值与积累的测试数据一致。
- 证据类型：runtime-render

### AC-13：关键操作日志记录
- 验收条件：系统记录工单相关关键操作日志，包含操作类型、操作人、操作时间与所涉工单。
- 入口类型：内部
- 验证动作：依次执行工单创建、分配、转派、回复、处理、完成、取消、评价等关键操作，随后查询系统日志记录。
- 预期结果：每项关键操作均产生对应日志记录，日志包含操作类型、操作人、操作时间与所涉工单标识。
