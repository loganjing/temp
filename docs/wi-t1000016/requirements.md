# 工单系统需求文档

> 业务任务：154-ticket  
> Work Item：wi-t1000016

## 1. 目标

构建一个工单管理系统，支持按公司隔离的工单创建、分配、处理、协作、评价和统计分析全生命周期。系统面向多公司场景，每家公司独立管理其工单、业务组和成员，提交人可通过工单发起问题，处理人按业务组分工处理并闭环反馈。

## 2. 角色与权限

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单、查看自己提交的工单及回复、收到完成工单后进行满意度评价 | 用户明确提出 |
| 处理人 | 所属某公司某业务组的成员，接收分配的工单并处理、回复、转派 | 用户明确提出 |
| 管理员 | 为公司配置业务组及成员、设置分类自动分配规则 | 用户明确提出（隐含于工单分配功能） |

> 权限粒度：工单按公司隔离，用户只能查看和操作所属公司的工单数据。未规定具体 RBAC 模型或权限矩阵。

## 3. 核心实体

### 3.1 工单（Ticket）

| 字段 | 说明 | 来源 |
|------|------|------|
| 工单ID | 系统唯一标识 | 用户明确提出 |
| 主题 | 工单标题 | 用户明确提出 |
| 描述 | 工单详细内容 | 用户明确提出 |
| 分类 | 问题分类，用于自动分配 | 用户明确提出 |
| 提交人信息 | 姓名、邮箱、公司、部门 | 用户明确提出 |
| 创建时间 | 工单创建时间戳 | 用户明确提出 |
| SLA优先级 | P0-P4 五级 | 用户明确提出 |
| 状态 | 生命周期状态（见第4节） | 用户明确提出 |
| 处理人 | 当前处理该工单的人 | 用户明确提出 |
| 处理时间 | 处理完成时间记录 | 用户明确提出 |
| 所属公司 | 工单所属公司，用于隔离 | 用户明确提出 |

### 3.2 工单回复（Ticket Reply）

- 支持多轮回复，每轮记录回复人、回复时间、回复内容。
- 来源：用户明确提出。

### 3.3 业务组（Business Group）

- 一个公司可配置多个业务组。
- 每个业务组可设置成员（处理人）。
- 支持按工单分类配置自动分配规则，将工单自动分配到对应业务组。
- 来源：用户明确提出。

### 3.4 工单日志

- 记录工单生命周期中的关键操作日志，包括但不限于：创建、分配、转派、处理、完成、取消。
- 来源：用户明确提出。

## 4. 生命周期

工单状态流转：

```
创建 → 待分配 → 待处理 → 完成
                ↘ 取消
```

| 状态 | 说明 | 来源 |
|------|------|------|
| 创建 | 工单刚提交后的初始状态 | 用户明确提出 |
| 待分配 | 等待分配到业务组或处理人 | 用户明确提出 |
| 待处理 | 已分配，等待或正在处理中 | 用户明确提出 |
| 完成 | 工单处理完毕，触发邮件通知 | 用户明确提出 |
| 取消 | 工单被取消，终止流程 | 用户明确提出 |

> 转派操作在"待处理"状态下进行，将工单转派给其他处理人或业务组，状态保持"待处理"。

## 5. 功能需求

### 5.1 工单管理

- **创建工单**：提交人填写主题、描述、分类、优先级，系统自动填充提交人信息（姓名、邮箱、公司、部门）和创建时间，生成唯一工单ID。
- **多轮回复**：工单创建后支持提交人和处理人进行多轮回复，每轮记录回复人、回复时间。
- **公司隔离**：所有工单、业务组、成员数据按公司隔离，用户只能访问所属公司数据。
- **SLA优先级**：支持 P0、P1、P2、P3、P4 五级优先级设置。
- **问题分类**：工单按分类归类，分类同时作为自动分配的依据。

### 5.2 工单分配

- **业务组管理**：允许给某个公司增加多个业务组，每个业务组可设置成员。
- **自动分配规则**：允许某个公司的工单按照分类自动分配到某个业务组。
  - 管理员配置"分类 → 业务组"映射规则。
  - 工单创建后，系统根据其分类自动匹配规则并分配到对应业务组。
  - 未匹配到规则的工单进入"待分配"状态，等待人工分配。
  - 来源：用户明确提出。

### 5.3 工单协作

- **转派操作**：处理人可将工单转派给同公司其他处理人或业务组。
  - 转派记录处理人、转派目标、转派时间。
  - 转派后工单处理权移交目标处理人。
  - 来源：用户明确提出。

### 5.4 工单处理

- **提交人信息查看**：处理人在处理工单时可查看提交人的完整信息，包括姓名、公司、部门、历史工单列表。
- **处理记录**：工单处理完成后，记录处理人、处理时间。
- **完成通知**：工单完成后，系统向提交人发送邮件通知。

### 5.5 用户评价

- **满意度评价**：用户收到完成的工单后，可对工单处理进行满意度评价。
  - 评价在工单完成后触发。
  - 来源：用户明确提出。

### 5.6 统计分析

- **工单分布统计**：支持按公司、部门维度统计工单分布。
- **运营仪表盘**：展示以下运营指标：
  - 工单量
  - 平均响应时间
  - 满意度
  - 热点问题
- 来源：用户明确提出。

### 5.7 工单工作台

- **待处理工单列表**：处理人可查看待处理工单列表。
- **筛选**：支持按公司维度筛选。
- **搜索**：支持按主题、工单ID等搜索工单。
- **排序**：支持按创建时间、优先级等排序。
- 来源：用户明确提出。

### 5.8 操作日志

- 记录工单生命周期中的关键操作日志，包括创建、分配、转派、处理、完成、取消等操作。
- 来源：用户明确提出。

## 6. 验收场景

### AC-01：提交人创建工单并按分类自动分配到业务组

- 验收条件：提交人填写主题、描述、分类、优先级后提交工单，系统生成唯一工单ID，自动填充提交人信息（姓名、邮箱、公司、部门）和创建时间，并根据分类自动分配规则将工单分配到对应业务组，状态流转为"待处理"。
- 入口类型：用户界面
- 验证动作：提交人登录后创建一张工单，填写必要字段并提交。
- 预期结果：工单创建成功，生成工单ID，提交人信息和创建时间自动填充，工单按分类自动分配到已配置规则的业务组，状态为"待处理"。
- 证据类型：runtime-render, interaction

### AC-02：工单多轮回复

- 验收条件：工单创建后，提交人和处理人可对工单进行多轮回复，每轮回复记录回复人、回复时间和回复内容，回复按时间顺序展示。
- 入口类型：用户界面
- 验证动作：在已创建的工单中，提交人和处理人分别进行回复。
- 预期结果：回复成功保存，每轮回复显示回复人、回复时间和内容，按时间顺序排列。
- 证据类型：runtime-render, interaction

### AC-03：工单按公司隔离

- 验收条件：不同公司的用户只能查看和操作本公司工单数据，无法访问其他公司的工单。
- 入口类型：用户界面
- 验证动作：用A公司用户登录查看工单列表，切换为B公司用户登录查看工单列表。
- 预期结果：A公司用户只看到A公司工单，B公司用户只看到B公司工单，两者数据互不可见。
- 证据类型：runtime-render, authorization

### AC-04：SLA优先级设置与生命周期状态流转

- 验收条件：工单创建时可设置P0-P4优先级，工单状态按"创建→待分配→待处理→完成"或"取消"流转，状态变更记录在操作日志中。
- 入口类型：用户界面
- 验证动作：创建工单时选择优先级为P1，观察工单状态从创建流转到待处理，再完成或取消。
- 预期结果：工单优先级显示为P1，状态流转路径正确，每次状态变更在操作日志中有记录。
- 证据类型：runtime-render, interaction

### AC-05：业务组配置与成员管理

- 验收条件：管理员可为某公司增加多个业务组，每个业务组可设置成员。
- 入口类型：用户界面
- 验证动作：管理员登录后为某公司创建两个业务组，分别为每个业务组添加成员。
- 预期结果：业务组创建成功，成员添加成功，可在业务组列表中查看各组及其成员。
- 证据类型：runtime-render, interaction

### AC-06：工单按分类自动分配到业务组

- 验收条件：管理员配置"分类→业务组"映射规则后，新创建的工单根据其分类自动匹配规则并分配到对应业务组；未匹配规则的工单进入"待分配"状态。
- 入口类型：用户界面
- 验证动作：管理员配置分类A→业务组X的规则，提交人创建一张分类为A的工单，再创建一张分类为B（无规则）的工单。
- 预期结果：分类A的工单自动分配到业务组X，状态为"待处理"；分类B的工单状态为"待分配"。
- 证据类型：runtime-render, interaction

### AC-07：工单转派

- 验收条件：处理人可将"待处理"状态的工单转派给同公司其他处理人或业务组，转派后处理权移交目标，转派操作记录在日志中。
- 入口类型：用户界面
- 验证动作：处理人在待处理工单中执行转派操作，选择目标处理人。
- 预期结果：工单处理人变更为目标处理人，转派记录（转派人、目标、时间）写入操作日志，工单状态保持"待处理"。
- 证据类型：runtime-render, interaction

### AC-08：处理工单时查看提交人完整信息含历史工单

- 验收条件：处理人在处理工单页面可查看提交人的完整信息，包括姓名、公司、部门和历史工单列表。
- 入口类型：用户界面
- 验证动作：处理人打开一张待处理工单，查看提交人信息区域。
- 预期结果：页面展示提交人姓名、公司、部门信息，以及该提交人的历史工单列表。
- 证据类型：runtime-render

### AC-09：工单完成记录处理信息并发送邮件通知

- 验收条件：处理人完成工单后，系统记录处理人和处理时间，工单状态变为"完成"，并向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：处理人将待处理工单标记为完成。
- 预期结果：工单状态变为"完成"，处理人和处理时间已记录，提交人邮箱收到完成通知邮件。
- 证据类型：runtime-render, interaction

### AC-10：用户满意度评价

- 验收条件：工单完成后，提交人可对该工单进行满意度评价，评价结果记录在工单上。
- 入口类型：用户界面
- 验证动作：工单完成后，提交人查看该工单并进行满意度评价。
- 预期结果：评价成功保存并关联到该工单，工单详情中可见评价结果。
- 证据类型：runtime-render, interaction

### AC-11：按公司/部门维度统计工单分布

- 验收条件：统计分析页面支持按公司、部门维度查看工单分布数据。
- 入口类型：用户界面
- 验证动作：进入统计分析页面，选择按公司维度查看工单分布，再切换按部门维度查看。
- 预期结果：页面正确展示各公司或各部门的工单数量分布。
- 证据类型：runtime-render

### AC-12：运营仪表盘展示工单量、平均响应时间、满意度、热点问题

- 验收条件：运营仪表盘展示工单量、平均响应时间、满意度评分、热点问题分类等运营指标。
- 入口类型：用户界面
- 验证动作：进入运营仪表盘页面。
- 预期结果：页面展示工单总量、平均响应时间数值、满意度指标、热点问题排名，数据与实际工单数据一致。
- 证据类型：runtime-render

### AC-13：工单工作台筛选、搜索、排序

- 验收条件：工单工作台展示待处理工单列表，支持按公司筛选、按主题/工单ID搜索、按创建时间/优先级排序。
- 入口类型：用户界面
- 验证动作：进入工单工作台，使用筛选条件筛选某公司工单，搜索特定主题工单，按优先级排序。
- 预期结果：列表按筛选、搜索、排序条件正确展示符合条件的工单。
- 证据类型：runtime-render, interaction

### AC-14：操作日志记录

- 验收条件：工单生命周期中的关键操作（创建、分配、转派、处理、完成、取消）均记录在操作日志中，包含操作人、操作类型、操作时间。
- 入口类型：用户界面
- 验证动作：执行工单创建、分配、转派、完成操作后，查看工单操作日志。
- 预期结果：每步操作在日志中有对应记录，包含操作人、操作类型和操作时间。
- 证据类型：runtime-render, interaction

### AC-15：工单取消

- 验收条件：工单可被取消，取消后状态为"取消"，终止后续处理流程，取消操作记录在日志中。
- 入口类型：用户界面
- 验证动作：对一张待分配或待处理状态的工单执行取消操作。
- 预期结果：工单状态变为"取消"，无法再进行处理操作，取消操作记录在日志中。
- 证据类型：runtime-render, interaction

## 7. 未规定事项

- **邮件发送方式**：用户要求完成工单后发送邮件通知，未规定邮件服务技术选型、模板格式或重试策略。
- **评价形式**：用户要求满意度评价，未规定评分制式（星级/分数/选项），实现时可选择常见方式。
- **热点问题定义**：用户要求展示热点问题，未规定具体计算方式（按分类频次/增长率等），实现时可选择合理方式。
- **平均响应时间定义**：用户要求展示平均响应时间，未规定起止时间点（创建→首次回复/创建→完成），实现时可选择合理方式。
- **部署平台与技术栈**：未规定。
- **RBAC 权限矩阵**：用户明确角色和公司隔离，未规定细粒度权限矩阵。
- **历史工单范围**：处理人可查看提交人的历史工单，未规定是否仅限同公司历史工单；按公司隔离原则，推荐仅展示同公司历史工单。
