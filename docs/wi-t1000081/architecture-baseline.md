# 教师管理系统架构基线

> 对应需求基线：[requirements.md](./requirements.md)
> 路线：simple-frontend（单用户浏览器 CRUD）

## 架构决策

采用 React + Vite 单页应用（SPA），数据存储于浏览器 `localStorage`。不引入服务端、数据库、认证、后台任务或外部集成。

### 选型理由

需求为单用户教师 CRUD，持久化边界为刷新或重开页面后数据仍在（AC-01），未规定服务端权威数据、认证/权限、跨设备共享等能力（见需求「未规定事项」）。`localStorage` 即可满足全部验收场景。

## 页面与交互范围

单页面包含两个区域：

1. **教师列表区**：以表格展示全部已录入教师记录，每行含教师名称、教授课程、年级、手机、邮箱五个字段及「编辑」「删除」操作按钮。
2. **教师表单区**：用于新增和编辑教师。新增时表单为空，编辑时预填选中记录的当前值。表单字段：教师名称（必填）、教授课程、年级、手机、邮箱。提交后写入 `localStorage` 并刷新列表。

交互流程覆盖三条验收场景：
- AC-01（增）：填写表单提交 → 记录写入 localStorage → 列表读回。
- AC-02（改）：点击「编辑」→ 表单预填当前值 → 修改提交 → 列表更新。
- AC-03（删）：点击「删除」→ 确认 → 记录从 localStorage 移除 → 列表移除。

## 数据归属

- 存储介质：浏览器 `localStorage`，键名如 `teachers`，值为 JSON 数组。
- 数据生命周期：同一浏览器配置文件内刷新或重开页面后保留；清除浏览器存储或切换浏览器/设备后不保留。
- 不承诺跨浏览器、跨设备或跨用户同步。

## 接口与校验边界

- 教师名称为必填字段，提交时校验非空，空值不允许提交。
- 手机与邮箱按推荐基线做轻量格式校验（常见手机号/邮箱格式），不通过时提示用户但不阻塞核心流程。
- 教授课程与年级为选填字段，无校验约束。
- 每条记录分配唯一标识（如自增 id 或 UUID），用于编辑和删除时定位记录。

## 实现入口与运行方式

- 框架：React + Vite（SPA）。
- 包管理：npm。
- 开发运行：`npm run dev`，通过 Vite 开发服务器启动。
- 入口页面：单个 HTML 页面挂载 React 应用，列表区与表单区在同一页面内切换状态。
