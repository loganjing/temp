# 工单系统需求文档

## 1. 目标

为用户提供工单管理与服务支持系统，覆盖工单从创建、分配、处理到完成评价的完整生命周期，支持按分类自动分配到业务组、工单转派协作、处理时查看提交人完整信息以及用户满意度评价。

## 2. 角色与权限边界

| 角色 | 说明 |
|------|------|
| 提交人 | 创建工单、回复工单、收到处理结果后进行满意度评价 |
| 处理人 | 业务组成员，查看分配给自己的工单、处理工单、回复工单、转派工单 |
| 管理员 | 为公司配置业务组及成员、配置分类到业务组的自动分配规则 |

> 用户未明确指定更细的权限粒度（如只读、仅回复等），保持未规定。

## 3. 核心实体

### 3.1 工单

- **工单ID**：系统生成的唯一标识。
- **主题**：工单标题。
- **描述**：工单详细内容。
- **分类**：问题分类，用于自动分配路由。
- **提交人信息**：包括提交人姓名、邮箱、所属公司、所属部门。
- **SLA优先级**：P0（最高）至 P4（最低），用于区分处理紧急程度。
- **创建时间**：工单提交时记录。
- **状态**：工单当前生命周期状态。
- **处理人**：当前分配到的处理人（待分配后填写）。
- **处理时间**：处理完成时记录。

### 3.2 工单回复

- **回复人**：提交人或处理人。
- **回复时间**：回复提交时记录。
- **回复内容**：文本内容。

一条工单可包含多条回复，按时间顺序排列，构成多轮对话。

### 3.3 公司与业务组

- **公司**：工单提交人所属组织，一个公司可配置多个业务组。
- **业务组**：公司下的处理单元，每个业务组可设置多名成员（处理人）。

### 3.4 分类分配规则

- 为公司配置「分类 → 业务组」的映射规则。
- 工单创建后，根据其分类匹配该公司对应的分配规则，自动将工单分配到目标业务组。

### 3.5 用户评价

- **满意度评分**：用户对工单处理结果的满意度评价。
- **评价内容**：用户可填写文字评价（可选）。

## 4. 工单生命周期

```
创建 → 待分配 → 待处理 → 完成
  │                        ↑
  └──→ 取消              处理人完成处理
```

| 状态 | 说明 | 进入条件 |
|------|------|----------|
| 创建 | 工单刚提交 | 提交人创建工单 |
| 待分配 | 等待自动分配到业务组 | 工单提交成功后自动进入 |
| 待处理 | 已分配到业务组/处理人，等待处理 | 自动分配完成或手动分配后 |
| 完成 | 处理人完成处理 | 处理人提交处理结果 |
| 取消 | 工单被取消 | 提交人或管理员取消工单 |

> 工单从「待分配」到「待处理」的自动分配：系统根据分类分配规则匹配业务组后，工单进入待处理状态。若未匹配到规则，工单保持待分配，需手动处理。

## 5. 用户旅程

### 旅程一：提交人创建工单到完成评价

1. 提交人填写主题、描述、分类，设置SLA优先级，提交工单。
2. 系统根据分类自动分配到对应业务组，工单进入待处理。
3. 处理人在工单中回复或处理，提交人与处理人可多轮回复。
4. 处理人完成处理，工单状态变为完成。
5. 提交人收到处理结果后进行满意度评价。

### 旅程二：处理人查看提交人信息并处理工单

1. 处理人查看分配给自己的待处理工单。
2. 处理人查看提交人完整信息：姓名、公司、部门、历史工单列表。
3. 处理人进行回复或处理，记录处理人和处理时间。
4. 如需其他业务组处理，处理人执行转派操作。

### 旅程三：管理员配置业务组和分配规则

1. 管理员为公司增加多个业务组。
2. 为每个业务组设置成员。
3. 配置分类到业务组的自动分配规则。

## 6. 功能模块

### 6.1 工单管理

- **创建工单**：提交人填写主题、描述、分类、SLA优先级，系统自动记录提交人信息和创建时间。
- **查看工单**：查看工单详情、回复记录、处理记录、当前状态。
- **回复工单**：提交人和处理人均可回复，记录回复人和回复时间，支持多轮。
- **取消工单**：提交人或管理员可取消未完成的工单，状态变为取消。

### 6.2 工单分配

- **业务组管理**：管理员可为公司增加多个业务组，每个业务组可设置成员。
- **自动分配规则**：管理员配置「分类 → 业务组」映射。工单创建后按分类自动匹配并分配到对应业务组，工单从待分配转为待处理。
- **未匹配处理**：若工单分类无对应分配规则，工单保持待分配状态，需手动分配。

### 6.3 工单协作

- **转派**：处理人可将工单转派给其他业务组或处理人。转派后工单仍处于待处理状态，处理人变更为新的接收方。转派记录应可追溯。

### 6.4 工单处理

- **查看提交人信息**：处理人在处理工单时可查看提交人完整信息，包括姓名、公司、部门、历史工单列表。
- **处理记录**：处理人完成处理后，系统记录处理人、处理时间，工单状态更新为完成。
- **历史工单**：展示该提交人之前提交的工单列表，供处理人参考。

### 6.5 用户评价

- **评价入口**：工单完成后，提交人收到通知并可进行满意度评价。
- **评价内容**：满意度评分 + 可选文字评价。
- **评价记录**：评价结果关联到工单，可查看。

## 7. 验收场景

### AC-01：提交人创建工单并设置分类和优先级

- 验收条件：提交人能创建包含完整信息的工单，工单记录核心字段并进入初始生命周期状态。
- 入口类型：用户界面
- 验证动作：提交人填写主题、描述、分类、SLA优先级并提交工单。
- 预期结果：工单创建成功，系统记录工单ID、主题、描述、分类、SLA优先级、提交人信息（含邮箱）和创建时间，工单状态为创建或待分配。
- 证据类型：interaction, session-persistence

### AC-02：工单支持多轮回复

- 验收条件：提交人和处理人可在同一工单下进行多轮回复，每条回复记录回复人和回复时间。
- 入口类型：用户界面
- 验证动作：在已创建的工单中，不同用户依次添加多条回复。
- 预期结果：所有回复按时间顺序展示，每条回复显示回复人和回复时间，回复内容正确。
- 证据类型：interaction, session-persistence

### AC-03：管理员配置业务组并实现分类自动分配

- 验收条件：管理员能为公司配置业务组和成员，工单按分类自动分配到对应业务组。
- 入口类型：用户界面
- 验证动作：管理员为公司添加业务组并设置成员，配置分类到业务组的分配规则，提交人创建对应分类的工单。
- 预期结果：工单创建后自动匹配分配规则，分配到对应业务组，工单状态从待分配变为待处理；未配置规则的分类工单保持待分配。
- 证据类型：interaction, session-persistence

### AC-04：处理人转派工单

- 验收条件：处理人可将工单转派给其他业务组或处理人，转派后新处理人可继续处理。
- 入口类型：用户界面
- 验证动作：处理人在待处理工单中执行转派操作，指定新的业务组或处理人。
- 预期结果：工单处理人变更为新接收方，新接收方可在该工单中进行回复和处理操作，转派记录可追溯。
- 证据类型：interaction, session-persistence

### AC-05：处理人查看提交人完整信息并处理工单

- 验收条件：处理人在处理工单时可查看提交人完整信息（姓名、公司、部门、历史工单），完成处理后记录处理人和处理时间。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息面板和历史工单列表，执行处理完成操作。
- 预期结果：提交人信息面板显示姓名、公司、部门和历史工单列表；处理完成后工单状态变为完成，处理记录中包含处理人和处理时间。
- 证据类型：interaction, session-persistence

### AC-06：用户对完成工单进行满意度评价

- 验收条件：工单完成后提交人能进行满意度评价，评价结果关联到工单。
- 入口类型：用户界面
- 验证动作：工单状态为完成后，提交人对该工单进行满意度评分和文字评价。
- 预期结果：评价提交成功，满意度评分和评价内容关联到该工单，可在工单详情中查看评价记录。
- 证据类型：interaction, session-persistence

## 8. 未规定事项

- 工单ID的具体生成规则未规定。
- 满意度评分的具体分值范围（如1-5星或百分制）未规定，由后续设计确定。
- 转派是否限制次数、是否需要审批未规定。
- 历史工单列表的展示数量上限和排序方式未规定。
- 通知方式（邮件、站内信等）未规定。
- 工单取消的具体权限范围（仅提交人、仅管理员或两者均可）未规定。
- 多公司场景下的跨公司工单处理未规定。
