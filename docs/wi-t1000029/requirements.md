# 165-农业采摘 需求文档

## 1. 目标

为农业采摘作业搭建管理系统，覆盖作物成熟度识别、采摘任务规划、作业进度监控、异常上报和产量统计五大功能，支撑从"判定可采摘"到"采摘产出统计"的完整作业闭环。

## 2. 角色

| 角色 | 职责 |
|------|------|
| 农场管理者 | 成熟度评估、采摘任务规划与分配、进度监控、异常处理、产量统计查看 |
| 采摘作业人员 | 接收并执行采摘任务、上报采摘进度、上报作业异常 |

## 3. 用户旅程

### 旅程 A：成熟度评估 → 任务规划 → 执行 → 产量统计

1. 农场管理者对各地块作物进行成熟度评估，记录成熟度等级和评估信息。
2. 系统根据成熟度评估结果标识"可采摘"地块。
3. 管理者基于可采摘地块创建采摘任务，分配作业人员并设定计划日期。
4. 作业人员接收任务后执行采摘，期间上报进度。
5. 遇到异常时，作业人员或管理者上报异常并跟踪处理。
6. 任务完成后系统汇总产量数据，管理者查看统计。

### 旅程 B：异常上报与处理

采摘过程中任意环节发现异常（如天气突变、病虫害、设备故障、人员不足等），由发现人上报异常报告，管理者跟踪处理直至关闭。

## 4. 功能需求

### 4.1 成熟度识别

- 管理者可对地块创建成熟度评估记录，包含：关联地块、成熟度等级（如未成熟 / 接近成熟 / 成熟 / 过熟）、评估时间、评估人、备注。
- 同一地块可有多条评估记录，最新一条为当前有效评估。
- 系统根据成熟度等级为"成熟"及以上（含"接近成熟"）的地块标记"可采摘"状态。
- 可按地块编号、品种、成熟度等级或可采摘状态筛选评估记录。

### 4.2 采摘任务规划

- 管理者可基于"可采摘"地块创建采摘任务，包含：任务编号（系统生成）、关联地块、计划采摘量、分配的作业人员、计划采摘日期、优先级（普通 / 紧急）、备注。
- 任务状态生命周期：待执行 → 执行中 → 已完成；支持取消（已取消）。
- 管理者可查看任务列表并按状态、地块、作业人员、计划日期筛选。
- 紧急任务在列表中有视觉标识区分。

### 4.3 作业进度监控

- 作业人员可将任务状态从"待执行"切换为"执行中"，开始采摘。
- 作业人员可上报进度，记录：已采摘量、进度时间、备注。
- 同一任务可多次上报进度，系统累计已采摘量。
- 管理者可查看所有进行中任务的整体进度，包括已分配、进行中、已完成任务的数量和采摘量汇总。
- 任务采摘完成后，作业人员将状态切换为"已完成"。

### 4.4 异常上报

- 作业人员和管理者均可提交异常报告，包含：关联采摘任务（可选）、异常类型（天气、病虫害、设备故障、人员、其他）、描述、上报人、上报时间。
- 异常报告状态：待处理 → 处理中 → 已解决。
- 管理者可查看异常列表并更新处理状态和添加处理说明。
- 待处理异常在采摘进度监控界面有提示标识。

### 4.5 产量统计

- 系统根据已完成任务的采摘量自动汇总产量数据。
- 管理者可按地块、品种、时间范围查看产量统计。
- 统计包含：总采摘量、完成任务数、参与作业人员数。
- 可按地块维度查看各地块累计产量。

## 5. 数据对象与状态

### 地块

| 字段 | 说明 |
|------|------|
| 地块编号 | 唯一标识 |
| 地块名称 | 显示名称 |
| 品种 | 种植作物品种 |
| 面积 | 地块面积 |
| 当前成熟度 | 取最新评估记录的等级 |
| 可采摘状态 | 成熟度等级达到"成熟"及以上为可采摘 |

### 采摘任务状态流转

```
待执行 → 执行中 → 已完成
  ↓        ↓
 已取消   已取消
```

### 异常报告状态流转

```
待处理 → 处理中 → 已解决
```

## 6. 验收场景

### AC-01：管理者可对地块记录成熟度评估并标识可采摘

- 验收条件：管理者能对指定地块创建成熟度评估记录，系统根据成熟度等级自动标识该地块是否可采摘。
- 入口类型：用户界面
- 验证动作：管理者选择一个地块，填写成熟度等级为"成熟"并提交评估记录。
- 预期结果：评估记录保存成功，该地块在列表中显示"可采摘"状态；查看该地块可看到最新评估记录。
- 证据类型：interaction, runtime-render

### AC-02：管理者可基于可采摘地块创建并分配采摘任务

- 验收条件：管理者能选择可采摘地块创建采摘任务，分配作业人员并设定计划日期，任务保存后出现在任务列表。
- 入口类型：用户界面
- 验证动作：管理者选择一个可采摘地块，填写计划采摘量、分配作业人员、设定计划日期，提交创建任务。
- 预期结果：任务创建成功，生成任务编号，状态为"待执行"，在任务列表中可见该任务及分配信息。
- 证据类型：interaction, runtime-render

### AC-03：作业人员可上报采摘进度，管理者可监控整体进度

- 验收条件：作业人员能将任务切换为"执行中"并多次上报采摘进度，管理者能在进度监控界面查看各任务进度和汇总数据。
- 入口类型：用户界面
- 验证动作：作业人员将一个待执行任务切换为"执行中"，上报已采摘量 50kg；再上报已采摘量 30kg。
- 预期结果：任务状态变为"执行中"，累计已采摘量显示 80kg；管理者在进度监控界面能看到该任务状态为执行中、累计采摘量 80kg，以及整体进行中任务数量。
- 证据类型：interaction, runtime-render, session-persistence

### AC-04：用户可上报异常并跟踪处理状态

- 验收条件：作业人员或管理者能提交异常报告，管理者能更新异常处理状态，待处理异常在进度监控界面有提示。
- 入口类型：用户界面
- 验证动作：作业人员对某采摘任务提交一条异常报告（类型：设备故障，描述内容），管理者查看异常列表并将状态更新为"处理中"。
- 预期结果：异常报告保存成功，状态为"待处理"；管理者更新后状态变为"处理中"；进度监控界面显示存在待处理异常的提示标识。
- 证据类型：interaction, runtime-render

### AC-05：管理者可查看产量统计数据

- 验收条件：已完成任务的采摘量被汇总，管理者可按地块或时间范围查看产量统计。
- 入口类型：用户界面
- 验证动作：管理者打开产量统计页面，选择某地块并查看统计。
- 预期结果：页面显示该地块的总采摘量、完成任务数、参与作业人员数；数据与已完成任务上报的采摘量一致。
- 证据类型：interaction, runtime-render
