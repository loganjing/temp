# 园区安防系统需求文档（k05-园区安防）

## 1. 目标

为园区安防管理提供一体化的巡逻路线配置、视频事件识别、实时告警、人工处置和事件留痕能力，所有业务数据需持久化存储到数据库，确保数据在写入后可通过相应读取行为读回。

### 用户明确提出的需求

- 巡逻路线配置：支持配置园区内的巡逻路线。
- 视频事件识别：系统对视频画面进行事件识别。
- 实时告警：识别到事件时生成实时告警。
- 人工处置：对告警进行人工处置。
- 事件留痕：对事件及处置过程进行留痕记录。
- 数据持久化：业务数据需存储到数据库。

### 推荐基线

- 巡逻路线与巡逻点位关联，巡逻路线包含多个有序巡逻点位。（推荐：闭合核心目标"巡逻路线配置"所必需的结构化描述，可逆、可观察。）
- 告警具备生命周期状态流转（如待处置 → 处置中 → 已处置），以支撑"人工处置"流程的可观察结果。（推荐：闭合"人工处置"所必需的状态可观察性。）
- 数据库持久化的验收以"成功写入后可通过读取行为读回"为可观察结果，不指定具体数据库技术选型。（推荐基线，可逆。）

### 未规定事项

- 用户角色、权限体系、受众范围未由用户明确，保持未规定。
- 视频事件识别的具体识别类型、算法和准确率阈值未由用户明确，保持未规定。
- 巡逻路线的地图展示方式、巡逻人员执行方式未由用户明确，保持未规定。
- 部署平台、技术栈、前端/后端框架未由用户明确，保持未规定。

---

## 2. 用户旅程

### 旅程 A：巡逻路线配置 → 视频识别 → 告警 → 人工处置 → 留痕

1. 用户在系统中创建巡逻路线，配置路线关联的巡逻点位及顺序。
2. 系统对接入的视频画面进行事件识别。
3. 系统识别到事件时，生成实时告警，告警信息可供查看。
4. 处置人员对告警进行人工处置（确认、处理并记录处置结果）。
5. 系统对事件及处置全过程进行留痕记录，留痕信息可查询回读。

---

## 3. 模块需求

### 3.1 巡逻路线配置

- 支持创建巡逻路线，每条路线可关联多个巡逻点位，点位之间有顺序。
- 支持查看已有巡逻路线列表及路线详情。
- 支持编辑已有巡逻路线（修改路线名称、增删调整巡逻点位及顺序）。
- 支持删除巡逻路线。
- 路线配置数据需持久化到数据库，写入后可通过读取行为读回。

### 3.2 视频事件识别

- 系统对视频画面进行事件识别。
- 识别到事件时，生成事件记录，记录包含事件发生的时间、关联的视频来源等基本信息。
- 事件记录需持久化到数据库。

### 3.3 实时告警

- 视频事件识别产生事件时，系统生成实时告警。
- 告警包含关联的事件信息、告警时间和告警状态。
- 告警状态支持流转：待处置 → 处置中 → 已处置。
- 告警信息可供实时查看，告警数据需持久化到数据库。

### 3.4 人工处置

- 处置人员可查看待处置的告警。
- 处置人员可对告警进行处置操作：确认接收（状态变更为处置中）、记录处置结果并完成处置（状态变更为已处置）。
- 处置操作需记录处置人、处置时间和处置结果说明。
- 处置记录需持久化到数据库。

### 3.5 事件留痕

- 系统对以下关键节点进行留痕记录：事件产生、告警生成、告警处置操作。
- 留痕记录包含操作时间、操作类型和关联的业务对象。
- 留痕记录可供查询，留痕数据需持久化到数据库。

## 4. 验收场景

### AC-01：巡逻路线可配置并持久化读取

- 验收条件：用户可创建、查看、编辑、删除巡逻路线，且配置数据持久化后可通过读取行为读回。
- 入口类型：用户界面
- 验证动作：用户创建一条包含多个有序巡逻点位的巡逻路线并保存；随后查看路线列表和路线详情；编辑路线的点位及顺序并保存后再次查看；删除路线后再次查看列表。
- 预期结果：创建后可在列表和详情中读回路线及其点位顺序；编辑后读取的内容与修改一致；删除后列表中不再包含该路线。
- 证据类型：interaction,session-persistence

### AC-02：视频事件识别产生事件记录并持久化

- 验收条件：系统对视频进行事件识别，识别到事件时生成事件记录并持久化到数据库，可通过读取行为读回。
- 入口类型：后台任务
- 验证动作：系统对视频画面执行事件识别；识别到事件后，查询事件记录。
- 预期结果：事件记录包含事件发生时间和关联的视频来源信息，且持久化后可通过读取行为读回。
- 证据类型：session-persistence

### AC-03：事件识别产生实时告警并可供查看

- 验收条件：视频事件识别产生事件时，系统生成实时告警，告警可在系统中被查看，初始状态为待处置。
- 入口类型：用户界面
- 验证动作：视频事件识别产生事件后，用户查看告警列表。
- 预期结果：告警列表中出现与该事件关联的告警，告警状态为待处置，告警包含告警时间和关联事件信息。
- 证据类型：interaction,session-persistence

### AC-04：人工处置告警并记录处置结果

- 验收条件：处置人员可对待处置告警进行人工处置，告警状态随处置流程流转，处置记录持久化并可读回。
- 入口类型：用户界面
- 验证动作：处置人员查看待处置告警，确认接收告警（状态变为处置中），记录处置结果说明并完成处置（状态变为已处置）；随后查看该告警的处置记录。
- 预期结果：告警状态依次流转为处置中、已处置；处置记录包含处置人、处置时间和处置结果说明，且持久化后可通过读取行为读回。
- 证据类型：interaction,session-persistence

### AC-05：事件及处置全过程留痕可查询

- 验收条件：系统对事件产生、告警生成、告警处置操作进行留痕，留痕记录可查询并读回。
- 入口类型：用户界面
- 验证动作：完成一次从事件识别到告警处置的完整流程后，查询留痕记录。
- 预期结果：留痕记录包含事件产生、告警生成、告警处置操作各节点，每条记录包含操作时间、操作类型和关联的业务对象，且持久化后可通过读取行为读回。
- 证据类型：interaction,session-persistence
