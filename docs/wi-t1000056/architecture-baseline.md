## 1. 范围与页面

一个单页面实时时钟，居中展示当前时间，格式 `HH:MM:SS`，每秒自动更新一次，用户无需手动刷新。

- 唯一页面：时钟页（根路径 `/`）。
- 唯一交互：无。页面打开即开始走时，持续显示与系统时钟一致的时分秒。
- 不存在导航、表单、列表、详情、设置等其它视图。

## 2. 数据与状态归属

- 时间来源：客户端系统时钟（`Date` 对象 / `new Date()`），由浏览器宿主提供。
- 数据归属：纯运行时展示，无业务数据持久化。不使用 `localStorage`、`IndexedDB` 或任何本地存储；刷新或重开后仅重新读取当前系统时钟。
- 不涉及服务端权威数据、认证/权限、后台任务、外部服务或跨用户/跨设备共享。

## 3. 实现入口与运行方式

- 技术栈：React + Vite 静态 SPA（npm）。
- 入口：`src/main.jsx` → `src/App.jsx`。
- 时钟实现：`App` 组件挂载后通过 `setInterval` 每 1000ms 读取一次 `new Date()`，将 `HH`、`MM`、`SS` 写入 React state 并渲染；组件卸载时清除定时器，避免泄漏。
- 开发运行：`npm run dev`（Vite 开发服务器）。
- 构建：`npm run build`，产物输出到 `dist/`，作为静态资源部署。
- 部署基线：`deploy/Dockerfile` 与根目录 `.dockerignore` 由前端部署初始化器生成，构建 SPA 静态产物并对外提供。

## 4. UI 视觉方向

时钟为纯展示型单页，不采用管理工作台风格。视觉方向：

- 居中布局，单一大字号等宽时间显示 `HH:MM:SS`。
- 深色背景、浅色文字，保证可读性。
- 不引入 Ant Design 等组件体系；使用原生 CSS 或内联样式实现最小视觉。
- 不使用 emoji 或 Unicode 图标作为标识。

## 5. 验证控制入口

AC-01 涉及定时自动更新（每秒推进），属于"定时任务/动画"类，需简述可重复验证方式：

- 时间值由 `new Date()` 确定，秒数逐秒递增，可在测试中固定系统时钟或断言「相邻两次渲染差值为 1 秒」来验证。
- 页面验收：打开 `/`，观察初始时间与系统时间一致，持续数秒后秒数逐秒递增；无需预置状态，刷新即恢复为当前系统时间，无初态需还原。
- 不为该展示流程新增产品侧测试控制入口；正常运行即按每秒更新执行。
