# 教师管理系统 需求基线（142-teachers）

## 目标

用户明确提出：建设一个教师管理系统，支持对教师信息的增、删、改、查；每位教师至少包含以下五个字段：教师名称、教授课程、年级、手机、邮箱。

## 核心行为与规则

1. **教师信息字段（用户明确提出）**：教师名称、教授课程、年级、手机、邮箱。
2. **新增（用户明确提出）**：用户可录入一名教师并保存；保存成功后，可通过教师列表或详情读回与提交内容一致的字段值。
   - 说明：本条只承诺“保存后可在同一使用过程中读回”，不约定刷新、重开、重启或重新部署后的数据持久性，也不指定存储方式。
3. **查看（用户明确提出）**：用户可查看教师列表，并可查看单条教师记录的详细信息。
4. **修改（用户明确提出）**：用户可编辑已有教师的字段并保存；保存后再次查看该记录，显示更新后的值。
5. **删除（用户明确提出）**：用户可删除教师记录；删除后该记录不再出现于教师列表。
6. **取值范围口径（未规定）**：教授课程、年级是单值还是多值、是自由文本还是预置选项，用户未规定，本基线不约束，保持未规定。
7. **录入校验（推荐基线，保守、可逆、可观察）**：教师名称为必填；手机、邮箱按基本格式校验。不满足时阻止保存并提示对应字段。此为闭合录入可用性缺口的最小补充，用户可调整或取消。
8. **角色与权限（未规定）**：各操作涉及的角色划分与权限控制用户未规定，本基线不约束。

## 验收场景

### AC-01：新增教师并可读回
- 共享流程组：教师管理主流程
- 验收条件：用户可新增一条教师记录，填写教师名称、教授课程、年级、手机、邮箱后保存，并能在教师列表或详情中读回与提交一致的五个字段值。
- 入口类型：用户界面
- 验证动作：进入教师管理界面，触发新增，填写教师名称「张老师」、教授课程「数学」、年级「三年级」、手机「13800000000」、邮箱「zhang@example.com」，执行保存；随后在同一使用过程中重新打开教师列表并查看该条记录。
- 预期结果：保存成功并出现成功反馈；列表中新增该教师记录；读回的五个字段值与提交内容一致。
- 证据类型：interaction, session-persistence

### AC-02：查看教师列表与详情
- 共享流程组：教师管理主流程
- 验收条件：教师列表展示已存在教师及其字段，用户可查看单条教师记录的详情，且详情内容与列表一致。
- 入口类型：用户界面
- 验证动作：在已有至少两名教师数据的情况下打开教师列表，记录展示内容；再打开其中一名教师的详情。
- 预期结果：列表展示全部已存在的教师记录及其字段；所选教师的详情展示内容与列表一致，无缺失或错位字段。
- 证据类型：runtime-render, interaction

### AC-03：修改教师信息并读回
- 共享流程组：教师管理主流程
- 验收条件：用户可编辑已有教师记录并保存，保存后读回更新后的值。
- 入口类型：用户界面
- 验证动作：编辑一名已有教师的手机号与邮箱，执行保存；重新打开该教师记录查看。
- 预期结果：保存成功；读回手机号与邮箱为更新后的值；该教师其他字段未被意外改动。
- 证据类型：interaction

### AC-04：删除教师记录
- 共享流程组：教师管理主流程
- 验收条件：用户可删除已有教师记录，删除后该记录不再出现在教师列表中。
- 入口类型：用户界面
- 验证动作：在教师列表中删除一名已有教师，随后重新打开教师列表。
- 预期结果：该教师记录不再出现在列表中；其他教师记录不受影响。
- 证据类型：interaction

### AC-05：录入必填与格式校验（推荐基线）
- 共享流程组：教师管理主流程
- 验收条件：教师名称为空时不允许保存；手机、邮箱不符合基本格式时不允许保存，并提示对应字段。
- 入口类型：用户界面
- 验证动作：分别尝试保存「教师名称留空」、「手机填写 123」、「邮箱填写 abc」三种输入，每次检查反馈与列表。
- 预期结果：三次尝试均保存失败，提示对应字段的校验信息，且列表中没有产生新的教师记录。
- 证据类型：interaction, error-feedback
