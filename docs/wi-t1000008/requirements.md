# 教师管理系统需求（k01-teacher）

判断：需求可落地，决策为 **ready**。核心范围是一个教师信息管理页面，围绕单一业务对象（教师记录）完成新增、查看、编辑、删除，记录包含教师名称、教授课程、年级、手机、邮箱五项信息。课程与年级的数量口径已由用户确认：均允许多个。

## 目标

提供教师信息管理能力，让管理者可以录入教师、查看教师清单、修改教师信息、删除不再需要的教师记录。

## 教师记录字段

| 字段 | 内容 | 数量 | 必填 | 来源 |
| --- | --- | --- | --- | --- |
| 教师名称 | 文本 | 单值 | 是 | 用户提出字段；必填为推荐基线（无名称无法识别记录） |
| 教授课程 | 文本 | 多值 | 否 | 用户提出字段；多值口径用户已确认 |
| 年级 | 文本 | 多值 | 否 | 用户提出字段；多值口径用户已确认 |
| 手机 | 文本 | 单值 | 否 | 用户提出字段；11 位手机号格式校验为推荐基线 |
| 邮箱 | 文本 | 单值 | 否 | 用户提出字段；常规邮箱格式校验为推荐基线 |

多值字段规则（推荐基线）：课程与年级均可添加、移除单个条目，每个条目独立填写；一旦填写，至少保留一个非空条目；整体留空视为未填写。

## 核心行为

1. **查看**：教师管理页面列出全部教师记录，每条记录可读到五项信息；多值字段逐条展示，不压缩为单值。无记录时显示空状态说明（推荐基线）。
2. **新增**：在教师管理页面填写并提交新建表单，校验通过后该教师出现在清单中，字段与提交内容一致。
3. **编辑**：从清单进入某条教师记录的编辑，保存后清单中该条显示更新后的值，记录条数不变。
4. **删除**：删除一条教师记录需二次确认（推荐基线：删除不可逆），确认后该记录从清单消失，其他记录不受影响。
5. **校验与反馈**（推荐基线）：教师名称为空、或填写了的手机/邮箱格式不符时阻止保存，并在对应字段给出可见提示；已填写的其他内容不丢失。手机与邮箱留空不触发格式错误。

## 未规定事项

以下事项用户未提出、也不影响本次核心验收，当前保持不约束，实现时不作为需求：

- 教师名称、手机、邮箱的唯一性：未规定，不做唯一性限制。
- 用户角色与权限边界（谁可以管理教师）：未规定。
- 清单的排序、分页、搜索筛选：未纳入本次范围。
- 部署形态与跨重启的数据保留要求：未规定；增删改查以保存后能通过清单读回为准。

## 验收场景

### AC-01：可查看教师清单及五项信息
- 验收条件：教师管理页面展示当前全部教师记录，每条记录可读到教师名称、教授课程、年级、手机、邮箱；多值字段的每个条目都完整可见。
- 入口类型：用户界面
- 验证动作：打开教师管理页面，查看已存在至少一条含两门课程、两个年级的教师记录时的清单展示。
- 预期结果：每条记录的五项信息均可读到，课程与年级的全部条目都显示出来，不出现空白或只显示首项的情况。
- 证据类型：runtime-render
- 共享流程组：教师管理流程

### AC-02：新增教师记录后可在清单读回
- 验收条件：提交一条包含五项信息（课程两项、年级两项）的新教师记录后保存成功，并能在清单中读回，各字段值与提交内容一致。
- 入口类型：用户界面
- 验证动作：在教师管理页面填写并提交一条完整教师记录，随后查看清单。
- 预期结果：清单中出现该教师，名称、两门课程、两个年级、手机、邮箱与提交内容一致。
- 证据类型：interaction, session-persistence
- 共享流程组：教师管理流程

### AC-03：编辑教师记录后更新可见
- 验收条件：修改已有教师的课程、年级、手机或邮箱后保存，清单中该教师显示修改后的值，且不产生重复记录。
- 入口类型：用户界面
- 验证动作：从清单打开一条教师记录，调整课程与年级条目并修改手机号，保存后回到清单查看该记录。
- 预期结果：该记录显示更新后的课程、年级和手机号，清单记录条数不变。
- 证据类型：interaction, session-persistence
- 共享流程组：教师管理流程

### AC-04：删除教师记录后不再出现
- 验收条件：删除一条教师记录并经确认后，该记录从清单移除，其余记录保持原样。
- 入口类型：用户界面
- 验证动作：在清单中对一条教师记录执行删除并确认。
- 预期结果：清单中不再出现该教师，其他教师记录仍存在且内容未变。
- 证据类型：interaction, session-persistence
- 共享流程组：教师管理流程

### AC-05：不合法输入被阻止并给出字段提示
- 验收条件：教师名称为空，或填写了的手机、邮箱格式不符合校验规则时，保存被阻止，并在对应字段显示可见提示。
- 入口类型：用户界面
- 验证动作：新建或编辑教师记录时清空教师名称，并在手机、邮箱中填入格式错误的内容后提交保存。
- 预期结果：记录未被保存（清单中不新增记录，也不被改成无效值），教师名称、手机、邮箱字段旁出现可见错误提示，已填写的课程与年级等内容仍保留。
- 证据类型：interaction, error-feedback
- 共享流程组：教师管理流程
