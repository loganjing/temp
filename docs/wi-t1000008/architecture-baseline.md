# 教师管理系统架构基线（k01-teacher）

依据批准的需求基线 `docs/wi-t1000008/requirements.md`（sha256:e43704bc…e67456）确立的最小可行架构。路线分类为 `simple-frontend`：单用户教师记录增删改查，数据只在当前浏览器可用，不承诺跨设备、跨浏览器或跨用户共享。本文只给出承载方式，不改变需求中的字段、规则与验收语义。

## 技术形态

| 项 | 结论 |
| --- | --- |
| 应用形态 | 单页应用（SPA），无服务端、无数据库、无认证、无后台任务、无外部集成 |
| 技术栈 | React + Vite，JavaScript（除非实现阶段需要类型约束再引入 TS，不改变数据边界） |
| 数据归属 | 浏览器 `localStorage`，由应用独占读写 |
| 组件体系 | Ant Design（`antd`、`@ant-design/icons`） |
| 运行方式 | 本工作项工作区内新建项目；开发预览通过 Vite 开发服务器（`npm install` 后 `npm run dev`） |

## 页面与交互范围

单一页面「教师管理」承载全部能力：

- 顶部上下文区：页面标题、记录总数等基本上下文，以及唯一的「新增教师」主操作。
- 内容区：教师记录清单，以表格呈现五项信息；教授课程、年级按条目逐项展示，不压缩为首项。
- 表单：新增与编辑复用同一个教师表单（抽屉或弹窗形式），包含五项字段；课程与年级以可增删的条目列表编辑。
- 删除：从清单触发的记录级操作，执行前弹出二次确认，确认后才写入数据并刷新清单。
- 空状态：无记录时清单区域显示说明性空状态，并保留新增入口。

校验发生在提交前、写入数据之前：名称为空，或已填写的手机、邮箱格式不符时阻止写入，并在对应字段旁显示可见提示，表单中其余已填内容保持不变；留空的手机、邮箱不触发格式错误。

## 数据边界

- 由一个应用内的数据模块独占 `localStorage` 访问，键名固定（如 `k01-teacher:teachers:v1`），上层页面只调用该模块的列表、新增、更新、删除方法，不直接读写存储。
- 单条记录结构：`id`（应用内生成的稳定标识）、`name`、`courses`（字符串数组）、`grades`（字符串数组）、`mobile`、`email`；写入前对多值字段去空白并丢弃空条目。
- 持久化范围：同一浏览器配置文件内刷新或重新打开页面后记录仍可读回；首次访问无数据时以空清单启动，不预置演示数据。
- 编辑按 `id` 原地更新，删除按 `id` 移除，两者都不改变其他记录。

## 实现入口

- 新建 React/Vite 项目在工作项工作区内初始化，入口为 Vite 约定的 `index.html` → `src/main.jsx` → `src/App.jsx`，页面与表单组件放在 `src/` 下，数据模块单独成文件。
- 视觉方向按默认工作台样式：深色侧栏或等价的强对比导航区、浅色工作区、清晰的标题与主操作、以表格为主的内容表面；不引入需求之外的功能、指标或筛选能力。
- 实现参考可用团队包内的 Ant Design 工作台示例（`general-app-implementation/assets/antd-workbench/example.jsx` 与 `example.css`），其示例数据与文案不构成业务需求。

## 验证承载

本应用无自动推进、随机结果、定时或外部异步依赖，验收状态可由确定的数据与交互直接复现；因此不增设测试专用控制入口，验证入口为常规页面操作与刷新后的清单读回。
