## 缺陷

- DEFECT-01 (blocking, T02): 前端 App.tsx:65 检查 typeof result.user.id !== "number"，但后端 authkit/userkit 返回 UUID 字符串作为用户 ID。同理 App.tsx:31 对 GET /api/auth/me 的检查也会失败。技术契约第 2 节声明 user.id 类型为 number，但实际实现为 string。; 预期: 登录成功后应跳转到工单工作台主界面; 实际: 页面停留在登录表单，token 未存入 localStorage; 要求修改: 统一前端与后端的 user.id 类型：或将前端类型定义和运行时检查改为接受 string（UUID），或将后端响应中的 user.id 转为数字。前者更符合 authkit/userkit 的实际设计。; 复现步骤: 1. 打开 http://127.0.0.1:3001/ 显示登录表单 → 2. 填写 alice@acme.com / user-pass-1234 并点击登录 → 3. POST /api/auth/login 返回 200 且包含有效 token → 4. 页面未跳转，停留在登录表单
