## 1. 目标与结果

### 1.1 目标 **[用户提出]**

构建一个工单系统，支撑企业内工单的提交、分配、处理、协作、评价与统计分析，实现工单从提交到完成的全过程可追溯，并让工单能按公司内的分类规则自动流转到对应业务组。

### 1.2 核心结果 **[用户提出]**

1. 工单被完整记录并可被跟踪：工单 ID、主题、描述、分类、提交人信息（含邮箱）、创建时间。
2. 工单支持多轮往来回复，每条回复可追溯回复人与回复时间。
3. 工单数据按公司隔离。
4. 工单具备 SLA 优先级（P0–P4）与问题分类。
5. 工单具备「创建、待分配、待处理、完成、取消」的生命周期。
6. 公司下可维护多个业务组及其成员，工单可按分类自动分配到业务组。
7. 支持工单转派协作。
8. 处理人处理工单时可查看提交人完整信息（姓名、公司、部门、历史工单），处理完成后记录处理人与处理时间，并向提交人发送完成邮件通知。
9. 提交人在工单完成后可进行满意度评价。
10. 支持按公司、部门维度统计工单分布，并提供统计与分析仪表盘（工单量、平均响应时间、满意度、热点问题等运营指标）。
11. 提供工单工作台：待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选。
12. 记录相关日志。

## 2. 角色 **[推荐基线]**

用户原文未显式定义角色清单，但明确描述了「提交人」「回复人」「处理人」以及「为某个公司增加业务组并设置成员、配置按分类自动分配」这类维护动作。为闭合目标，按最小集合约定以下角色，均可由人工调整：

| 角色 | 职责 | 依据 |
|---|---|---|
| 提交人 | 提交工单、追加回复、查看自己工单的进度、对已完成工单进行满意度评价 | **[用户提出]**（提交人、回复人、评价） |
| 工单处理人 | 处理分配到本业务组的工单、回复、转派、完成工单 | **[用户提出]**（回复人、处理人、转派、完成） |
| 业务组维护者 | 在所属公司下新增业务组、设置业务组成员、配置「分类 → 业务组」的自动分配规则 | **[推荐基线]**（用户要求实现这些维护能力，但未指明由谁执行） |

**[未规定]**：角色与账号如何产生、是否可以叠加、是否存在跨公司角色；跨公司可见性规则除「按公司隔离」外不作规定。

## 3. 用户旅程

### 3.1 提交人旅程 **[用户提出]**

1. 提交人填写工单主题与描述，选择分类，设置 SLA 优先级（P0–P4）。
2. 系统生成工单 ID，记录提交人信息（姓名、邮箱、公司、部门）与创建时间。
3. 工单进入「创建」后流转为「待分配」。
4. 系统按分类自动将工单分配到对应业务组，工单进入「待处理」。
5. 提交人可多次追加回复，并可查看工单回复记录（回复人、回复时间）。
6. 处理完成后工单进入「完成」，提交人收到完成邮件通知。
7. 提交人对工单进行满意度评价。

### 3.2 处理人旅程 **[用户提出]**

1. 处理人在工单工作台查看待处理工单列表，按公司、分类、SLA 优先级等条件筛选、搜索、排序。
2. 进入工单详情，查看工单主题、描述、分类、SLA 优先级与往来回复。
3. 查看提交人完整信息：姓名、公司、部门、历史工单。
4. 追加回复完成多轮沟通。
5. 若工单不属于本业务组职责，执行转派。
6. 处理完成后执行完成操作，系统记录处理人、处理时间，并向提交人发送完成邮件通知。

### 3.3 业务组与分配规则维护旅程 **[用户提出]**

1. 为某个公司新增多个业务组。
2. 为每个业务组设置成员。
3. 配置该公司内「某分类 → 某业务组」的自动分配关系。
4. 新建工单按分类自动匹配到对应业务组。

## 4. 工单对象与状态

### 4.1 工单字段 **[用户提出]**

| 字段 | 说明 |
|---|---|
| 工单 ID | 系统生成的唯一标识 |
| 主题 | 工单标题 |
| 描述 | 问题或请求的详细说明 |
| 分类 | 问题分类，来自系统维护的分类列表 |
| SLA 优先级 | P0、P1、P2、P3、P4 |
| 提交人信息 | 姓名、邮箱、公司、部门 |
| 创建时间 | 工单创建的时间点 |
| 归属业务组 | 工单当前分配到的业务组（分配后具备） |
| 处理人 | 完成处理的人员（完成后具备） |
| 处理时间 | 完成处理的时间点（完成后具备） |

### 4.2 回复记录 **[用户提出]**

每条回复记录包含：回复内容、回复人、回复时间。一个工单可承载多轮回复。

### 4.3 生命周期 **[用户提出]**

状态集合：`创建`、`待分配`、`待处理`、`完成`、`取消`。

允许的流转：

| 起始状态 | 目标状态 | 触发 |
|---|---|---|
| 创建 | 待分配 | 工单创建完成 |
| 待分配 | 待处理 | 工单被分配到业务组 |
| 待处理 | 完成 | 处理人完成工单 |
| 创建 / 待分配 / 待处理 | 取消 | 工单被取消 |

- `完成` 与 `取消` 为终态。
- 转派只变更工单归属（业务组/处理人），不改变状态。 **[推荐基线]**（用户要求「转派」协作能力，未说明其对状态的影响）
- **[未规定]**：各状态下可取消的操作人范围、取消是否需要理由、状态回退（如由「待处理」退回「待分配」）。

### 4.4 公司隔离 **[用户提出]**

工单按公司隔离：同一公司内的工单可被该公司范围内的人员查看与操作，其他公司的工单不可见、不可操作。

- **[推荐基线]**：业务组、自动分配规则同样限定在所属公司内生效，跨公司不匹配。
- **[未规定]**：公司、部门基础数据的来源与维护方式。

## 5. 模块需求

### 5.1 工单管理 **[用户提出]**

- 创建工单：录入主题、描述、分类、SLA 优先级；系统补全工单 ID、提交人信息（含邮箱）、创建时间。
- 查看工单：可查看工单完整字段、当前状态与全部往来回复。
- 回复工单：提交人与处理人均可追加回复，形成多轮沟通，回复记录包含回复人与回复时间。
- 按公司隔离：工单的可见范围受公司边界约束。

### 5.2 工单分配 **[用户提出]**

- 业务组维护：可为某个公司新增多个业务组，并为每个业务组设置成员（成员数量不限）。
- 自动分配规则维护：可为某个公司配置「工单分类 → 业务组」的映射关系。
- 自动分配生效：该公司内新建工单按其分类自动分配到对应业务组，工单由「待分配」进入「待处理」。
- **[推荐基线]**：当工单无匹配的自动分配规则时，工单可停留在「待分配」，并可由业务组维护者手动指定业务组完成分配；同一公司内同一分类至多命中一个业务组，重复配置以最新配置为准。

### 5.3 工单协作（转派） **[用户提出]**

- 处理工单时可执行转派，将工单交给其他业务组或处理人。
- 转派记录可追溯转派人、转派目标与转派时间；工单状态不因转派改变。

### 5.4 工单处理 **[用户提出]**

- 处理人在处理工单时，可查看提交人完整信息：姓名、公司、部门，以及该提交人的历史工单列表。
- 完成处理时记录处理人与处理时间，工单进入「完成」。
- 工单完成时向提交人发送邮件通知（使用提交人邮箱）。
- **[推荐基线]**：历史工单列表按创建时间倒序展示，并展示主题、状态与创建时间。
- **[未规定]**：邮件服务提供方、邮件模板样式、重发与投递失败处理策略。

### 5.5 用户评价 **[用户提出]**

- 提交人在工单完成后可提交满意度评价。
- 评价记录包含评价人、评价时间与评价内容，可被统计分析引用。
- **[推荐基线]**：每个工单至多一条满意度评价，提交后不可修改；评价采用 1–5 星评分并可选填文字说明。
- **[未规定]**：评价开放时限、评价是否必填。

### 5.6 统计分析 **[用户提出]**

- 按公司、部门维度统计工单分布。
- 统计与分析仪表盘展示运营指标：工单量、平均响应时间、满意度、热点问题等。
- **[推荐基线]**：平均响应时间定义为「工单创建时间」到「该工单首条处理方回复时间」的平均时长；热点问题按分类工单量降序呈现；满意度指标基于工单满意度评价结果汇总。
- **[未规定]**：统计的时间范围口径（默认区间、自定义区间）、SLA 时限与超时率的计算规则、数据刷新频率。

### 5.7 工单工作台 **[用户提出]**

- 展示待处理工单列表。
- 支持筛选（含按公司维度筛选）、搜索、排序。

### 5.8 日志与通知 **[用户提出]**

- 记录工单相关日志，覆盖关键操作。
- **[推荐基线]**：日志至少记录工单创建、分配（自动或手动）、转派、回复、完成、取消、评价等操作，每条包含操作类型、操作人、操作时间与工单标识；日志与工单同样遵守公司隔离。
- **[未规定]**：日志保留期限与导出能力。

## 7. 验收场景

### AC-01：创建工单并记录完整工单信息

- 验收条件：提交人可创建工单，成功后该工单具备唯一工单 ID，并保存主题、描述、分类、SLA 优先级、提交人信息（姓名与邮箱）、创建时间，初始状态为「创建」并流转为「待分配」。
- 入口类型：用户界面
- 验证动作：以某公司的提交人身份新建工单，填写主题、描述，选择分类与 SLA 优先级后提交；提交后打开该工单详情，并查看该公司工单列表。
- 预期结果：工单创建成功并显示唯一工单 ID；详情中主题、描述、分类、SLA 优先级、提交人姓名与邮箱、创建时间均与提交内容一致；工单当前状态为「待分配」；工单列表中可检索到该工单。
- 证据类型：runtime-render, session-persistence

### AC-02：工单支持多轮回复并记录回复人、回复时间

- 验收条件：工单可承载多轮回复，每条回复记录回复内容、回复人与回复时间，并可按时间顺序完整回看。
- 入口类型：用户界面
- 验证动作：在处于「待处理」的工单详情中，以提交人身份提交一条回复；再以处理人身份提交第二条回复；重新打开该工单详情查看回复记录。
- 预期结果：两次回复均提交成功并出现在回复列表中；每条回复都显示回复内容、回复人和回复时间；回复按时间顺序排列；重新打开后回复记录仍然完整。
- 证据类型：interaction, session-persistence

### AC-03：工单按公司隔离

- 验收条件：工单仅在所属公司范围内可见与可操作，其他公司的人员无法查看或操作该公司的工单。
- 入口类型：用户界面
- 验证动作：以 A 公司人员身份创建一条工单；以 B 公司人员身份检索该公司工单列表并尝试通过工单标识直接打开 A 公司工单。
- 预期结果：B 公司人员的工单列表与搜索/筛选结果中不出现 A 公司的工单；直接访问 A 公司工单时被拒绝或不可见，且不暴露工单内容。
- 证据类型：authorization, runtime-render

### AC-04：设置 SLA 优先级与问题分类

- 验收条件：工单具备 SLA 优先级与问题分类，优先级可选 P0、P1、P2、P3、P4，分类取自系统维护的分类列表，且选择结果被正确保存与展示。
- 入口类型：用户界面
- 验证动作：创建工单时打开优先级选项与分类选项，分别选择一项（如 P1 与某分类）并提交；随后在工单详情与工作台列表中查看该工单的优先级与分类。
- 预期结果：优先级选项包含 P0–P4；提交后工单详情与列表中的优先级、分类与所选内容一致。
- 证据类型：runtime-render, interaction

### AC-05：工单生命周期流转与终态约束

- 验收条件：工单状态仅在「创建 → 待分配 → 待处理 → 完成」与到「取消」的路径上流转，「完成」与「取消」为终态且不可再变更。
- 入口类型：用户界面
- 验证动作：对同一条工单依次观察创建后的状态、分配后的状态、完成后的状态；在「完成」的工单上再次尝试执行取消或重新分配；另创建一条工单并执行取消。
- 预期结果：新建工单由「创建」进入「待分配」；分配后进入「待处理」；完成后进入「完成」；处于「完成」的工单不再提供可改变状态的可用操作，状态保持不变；被取消的工单状态为「取消」且同样不可再变更。
- 证据类型：runtime-render, interaction

### AC-06：公司下可维护多个业务组及其成员

- 验收条件：可为某个公司新增多个业务组，并为每个业务组设置成员。
- 入口类型：用户界面
- 验证动作：为同一公司新增两个业务组，分别向两个业务组添加成员；查看该公司业务组列表及各业务组成员列表。
- 预期结果：两个业务组均创建成功并出现在该公司的业务组列表中；每个业务组分别展示其已添加的成员；一个业务组可包含多个成员。
- 证据类型：runtime-render, session-persistence

### AC-07：按分类配置自动分配规则并使新工单自动分配

- 验收条件：可为某个公司配置「工单分类 → 业务组」的分配规则；该公司新建工单按分类自动分配到对应业务组，工单由「待分配」进入「待处理」。
- 入口类型：用户界面
- 验证动作：为某公司配置「分类 A → 业务组 X」的规则；以该公司提交人身份创建一条分类为 A 的工单；查看该工单的归属业务组与状态。
- 预期结果：规则保存成功并可在规则列表中查看；新建的分类 A 工单自动归属于业务组 X；工单状态为「待处理」；该分配动作可在工单日志中查到。
- 证据类型：runtime-render, session-persistence

### AC-08：工单转派并记录转派痕迹

- 验收条件：处理人可将工单转派到其他业务组或处理人，转派后工单归属变更且转派过程可追溯。
- 入口类型：用户界面
- 验证动作：在「待处理」工单上执行转派，指定目标业务组或处理人；随后查看该工单的当前归属与操作日志。
- 预期结果：工单当前归属变更为所选目标；工单状态仍为「待处理」；操作日志中出现一条转派记录，包含转派人、转派目标与转派时间。
- 证据类型：interaction, session-persistence

### AC-09：处理人可查看提交人完整信息

- 验收条件：处理人在处理工单时，可查看提交人姓名、公司、部门以及该提交人的历史工单。
- 入口类型：用户界面
- 验证动作：以处理人身份打开分配到本业务组的待处理工单，查看提交人信息区域；对照该提交人在系统中的公司、部门以及其历史工单记录。
- 预期结果：提交人信息区域展示姓名、公司、部门；同时展示该提交人的历史工单列表，列表项包含主题、状态与创建时间，并与系统中该提交人的实际工单一致。
- 证据类型：runtime-render

### AC-10：完成工单并记录处理信息、发送完成邮件通知

- 验收条件：处理人完成工单后，系统记录处理人与处理时间，工单进入「完成」，并向提交人邮箱发送完成通知。
- 入口类型：用户界面
- 验证动作：以处理人身份对「待处理」工单执行完成操作；查看该工单详情中的处理人、处理时间与状态；查看该系统发出的通知记录中该工单完成通知的收件人与发送结果。
- 预期结果：工单状态为「完成」；详情中显示实际执行完成操作的处理人与处理时间；存在一条发往该工单提交人邮箱的完成通知记录，且发送状态为已发出。
- 证据类型：interaction, other

### AC-11：提交人对已完成工单进行满意度评价

- 验收条件：提交人可对「完成」状态的工单提交满意度评价，评价被保存并关联到该工单。
- 入口类型：用户界面
- 验证动作：以提交人身份打开一条已完成的工单，提交满意度评价；重新打开该工单查看评价记录，并再次尝试提交评价。
- 预期结果：评价提交成功；工单中展示评价内容、评价人与评价时间；重新打开后评价仍然存在；同一工单不再允许重复提交第二条评价。
- 证据类型：interaction, session-persistence

### AC-12：按公司、部门维度统计工单分布

- 验收条件：可基于现有工单数据按公司维度、部门维度查看工单分布统计，统计结果与实际工单数据一致。
- 入口类型：用户界面
- 验证动作：在已有的多条不同公司、不同部门的工单数据下，打开统计视图，分别查看按公司维度与按部门维度的工单分布；与工单列表核对数量与归属。
- 预期结果：统计视图按公司、部门给出工单分布结果，各分组工单数与工单列表中的实际数量一致；统计结果遵循公司隔离范围。
- 证据类型：runtime-render, other

### AC-13：统计与分析仪表盘展示运营指标

- 验收条件：仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标，指标值可追溯到具体工单数据。
- 入口类型：用户界面
- 验证动作：在存在已完成工单、回复记录与满意度评价的数据下打开仪表盘，读取工单量、平均响应时间、满意度、热点问题；用工单数据人工核对其中至少一项指标的取值。
- 预期结果：仪表盘同时展示工单量、平均响应时间、满意度、热点问题；指标项有明确数值或排行，且与工单数据核对一致（例如热点问题按分类工单量排序、满意度与该范围内评价结果一致）。
- 证据类型：runtime-render, other

### AC-14：工单工作台支持筛选、搜索、排序与公司维度筛选

- 验收条件：工单工作台展示待处理工单列表，并支持筛选、搜索、排序以及按公司维度筛选。
- 入口类型：用户界面
- 验证动作：在存在多个公司、多个分类、不同优先级的待处理工单时打开工作台：输入关键字搜索；按分类或优先级筛选；选择某个公司进行筛选；切换排序方式。
- 预期结果：列表默认展示待处理工单；搜索按关键字缩小结果为匹配项；筛选条件生效且可叠加；按公司筛选后仅展示该公司工单；排序切换后列表顺序按所选字段相应变化。
- 证据类型：interaction, runtime-render

### AC-15：工单关键操作日志可追溯

- 验收条件：工单相关关键操作被记录为日志，日志包含操作类型、操作人、操作时间与对应工单，并可被查看。
- 入口类型：用户界面
- 验证动作：对一条工单依次执行创建、分配、回复、转派、完成、评价等操作；查看该工单的日志记录并逐条核对。
- 预期结果：日志中可看到上述操作对应的记录；每条记录包含操作类型、操作人、操作时间，并与实际操作和工单对应；日志内容遵守公司隔离范围。
- 证据类型：session-persistence, runtime-render
