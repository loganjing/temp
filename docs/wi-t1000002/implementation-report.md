# 开发实现报告

> 工作项：wi-t1000002 ｜ 业务任务：140-ticket ｜ 阶段：implementation

## 1. 概述

工单系统按批准的技术契约 `docs/wi-t1000002/technical-contract.md` 完成开发实现，采用前后端并行两个任务：

- **T01 服务端**：在 `app/ticket-system/src/server/` 实现数据模型、领域接口、公司隔离授权、自动分配、邮件通知、审计日志与统计分析。
- **T02 浏览器端**：在 `app/ticket-system/src/client/` 实现工单工作台、工单详情与协作、管理与配置页、统计仪表盘。

两个任务依据同一份技术契约并行推进、各自独立验证，互不等待。

## 2. 实现内容

### 2.1 服务端（T01）

**数据模型与迁移**（`src/server/migrations/sqlite/`）：新增工单业务表，覆盖公司、部门、分类、用户业务属性、业务组、业务组成员、分配规则、工单、工单回复、工单转派、满意度评价，并保留既有平台迁移。

**领域路由**（`src/server/tickets/routes.ts` 及 `service.ts`、`repository.ts`、`http.ts`）：

- 认证与用户：`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/me`、用户与 profile 创建/更新。
- 基础数据：公司、部门、分类的列表与创建。
- 业务组与分配规则：业务组列表（含成员）、创建业务组、添加/移除成员、分配规则列表与创建/更新、手动分配。
- 工单：创建（触发自动分配）、列表（筛选/搜索/排序/分页/公司隔离）、详情（含回复、转派记录、评价）、回复、转派、完成、取消、提交人完整信息（含历史工单）、工单日志。
- 评价：`POST /api/tickets/:id/rating`（仅完成态、每工单一条、不可修改）。
- 统计分析：按公司/部门维度分布、仪表盘运营指标（工单量、平均响应时间、满意度、热点分类）。

**关键行为**：

- 公司隔离：所有业务查询以服务端可信的当前用户公司为权威来源，跨公司访问返回 403 且不返回内容。
- 生命周期：`created → pending_assignment → pending_processing → completed`，及到 `cancelled` 的流转；`completed`/`cancelled` 为终态，终态上的状态变更/回复/转派/分配返回 409。
- 自动分配：创建工单时按 `(company_id, category_id)` 匹配规则，命中则设归属业务组并流转至待处理，未命中停留待分配。
- 完成处理：记录处理人与处理时间，成功后发送完成通知邮件（emailkit），邮件发送结果记入审计日志，邮件不可用时不阻塞完成。
- 审计日志：覆盖创建、分配（自动/手动）、转派、回复、完成、取消、评价，含操作类型、操作人、操作时间与工单标识，并遵守公司隔离。

**缺陷修复**：修复认证中间件包装层丢弃认证失败响应的既有缺陷，使未认证请求正确返回 401（此前因缺陷退化为 500）。

### 2.2 浏览器端（T02）

**应用壳与路由**（`src/client/App.tsx`、`src/client/app/AppShell.tsx`）：左侧导航（工单工作台、统计分析、业务组管理、分类管理、用户管理）与顶部上下文栏（当前用户、邮箱、所属公司），沿用既有本地账号登录流程。

**工单工作台**（`src/client/tickets/WorkbenchPage.tsx`）：待处理工单列表，默认状态待处理；关键字搜索（防抖）、按状态/分类/SLA 优先级/公司筛选、排序字段与升降序、分页；列表与右侧详情通过 `?ticket=` 协作（split-master-detail），`?new=1` 打开新建面板。

**工单详情与协作**（`src/client/tickets/TicketDetailPanel.tsx`）：完整字段与状态、多轮回复录入与记录（回复人/时间）、转派（业务组或处理人）、无规则工单手动分配、完成/取消、提交人完整信息面板（姓名/公司/部门/历史工单）、满意度评价、工单操作日志查看。

**管理与配置页**：业务组新增与成员设置、分类→业务组分配规则维护、公司/部门/分类基础数据维护、用户业务属性维护。

**统计分析**：按公司/部门维度的工单分布视图，以及展示工单量、平均响应时间、满意度、热点分类的运营仪表盘。

**请求接线**：契约类型与调用集中在 `src/client/api/`，所有业务请求经既有 `src/client/platform/api-client.ts` 作为唯一请求边界，未新增契约外接口。

**状态反馈**：加载态、空态、表单内联错误、操作失败提示，跨公司访问被拒绝时给出明确提示且不暴露他公司内容。视觉遵循 Modern SaaS 紧凑可扫读布局。

## 5. 遗留事项

以下为后续验证阶段或产品决策需关注的事项，不影响本实现阶段交付：

1. **未认证未知路径状态码**：修复认证缺陷后，未认证时未知 `/api/*` 路径返回 401（此前因缺陷返回 500）。若验收要求未认证未知路径为 404，需调整认证挂载顺序，属产品决策。
2. **邮件发送**：未配置 `SMTP_HOST` 时按设计降级为记录日志，真实 SMTP 发送未验证。
3. **认证契约缺口**：技术契约第 2 节只定义 `login`/`logout`/`me`；客户端沿用的首账户初始化与临时密码修改端点不在契约内，需产品/契约补充明确路径。
4. **端到端验收**：面向用户的完整端到端验收由后续验证阶段在真实前后端联调环境下负责。
