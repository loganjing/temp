# 工单系统需求文档

> Work Item: wi-t1000022 | 业务任务: 159-ticket | 阶段: requirements

---

## 1. 目标与范围

### 1.1 目标

构建一个面向多公司的工单管理系统，支持工单从创建到完成的完整生命周期，涵盖工单分配、协作转派、处理通知、用户评价、统计分析和工作台等能力。

### 1.2 用户明确提出的范围

- **工单管理**：工单信息记录、多轮回复、公司隔离、SLA 优先级（P0-P4）、问题分类、生命周期状态管理
- **工单分配**：为公司配置多个业务组及成员、按分类自动分配到业务组
- **工单协作**：工单转派
- **工单处理**：处理时查看提交人完整信息、记录处理人与处理时间、完成后邮件通知
- **用户评价**：满意度评价
- **统计分析**：按公司/部门维度统计工单分布、运营指标仪表盘
- **工单工作台**：待处理工单列表、筛选/搜索/排序、按公司维度筛选
- **操作日志**：记录相关日志

### 1.3 未规定事项

- 部署方式、技术选型、数据库方案、具体页面布局
- 角色权限模型的完整定义（用户仅描述了操作行为，未显式命名角色）
- MVP 优先级划分与迭代排期
- 日志记录的具体操作范围（用户仅说"记录相关日志"）
- 邮件通知的内容模板与发送方式

## 2. 角色说明

以下角色由用户描述的操作行为推导，非用户显式命名：

| 角色 | 推导来源 |
|------|----------|
| 提交人 | 创建工单、提交工单信息（含邮箱）、回复工单、接收完成通知、满意度评价 |
| 处理人 | 处理工单、回复工单、转派工单 |
| 管理员 | 为公司增加业务组、设置业务组成员、配置分类自动分配规则 |

## 3. 核心实体与状态

### 3.1 工单状态

用户明确的生命周期状态：

| 状态 | 说明 |
|------|------|
| 创建 | 工单新建后的初始状态 |
| 待分配 | 工单等待分配到业务组或处理人 |
| 待处理 | 工单已分配，等待处理人处理 |
| 完成 | 工单处理完毕 |
| 取消 | 工单被取消 |

状态流转路径：创建 → 待分配 → 待处理 → 完成 | 取消

> **推荐基线**：工单创建后默认进入「待分配」状态，经自动分配或手动分配后流转至「待处理」。取消可从待分配或待处理状态触发。此为闭合生命周期流转缺口的最小推荐，可由后续设计调整。

### 3.2 工单信息字段

用户明确要求的工单字段：

- 工单 ID
- 主题
- 描述
- 分类（用户同时提及"分类"和"问题分类"，本需求将其视为同一分类概念）
- 提交人信息（含邮箱）
- 创建时间
- SLA 优先级（P0-P4）
- 问题分类

### 3.3 工单回复

- 支持多轮回复
- 每条回复记录回复人和回复时间

### 3.4 公司隔离

工单按公司隔离，不同公司的工单数据互不可见。此规则贯穿工单管理、工作台、统计分析等所有模块。

## 4. 功能需求

### 4.1 工单管理

#### 4.1.1 工单创建

- 用户可创建工单，填写主题、描述、分类、SLA 优先级（P0-P4）、问题分类
- 系统记录提交人信息（含邮箱）和创建时间
- 系统自动生成工单 ID
- 工单创建后进入生命周期初始状态

#### 4.1.2 工单回复

- 支持对工单进行多轮回复
- 每条回复记录回复人和回复时间
- 回复人和提交人均可回复工单

#### 4.1.3 SLA 优先级与问题分类

- 工单支持设置 SLA 优先级，级别为 P0、P1、P2、P3、P4
- 工单支持设置问题分类

### 4.2 工单分配

#### 4.2.1 业务组管理

- 允许为某个公司增加多个业务组
- 每个业务组可以设置成员
- 业务组归属于特定公司

#### 4.2.2 分类自动分配

- 允许配置某个公司的工单按分类自动分配到对应业务组
- 工单创建后，系统根据工单分类匹配分配规则，将工单自动分配到对应业务组
- 分配规则按公司维度配置

> **未规定**：当工单分类未匹配到任何分配规则时的处理方式（如保持待分配、通知管理员等），保留为未规定。

### 4.3 工单协作

#### 4.3.1 工单转派

- 支持将工单转派操作
- 转派后工单的处理方变更，接收方成为新的处理方

### 4.4 工单处理

#### 4.4.1 提交人信息查看

- 在处理工单时，可查看提交人的完整信息，包括：
  - 姓名
  - 公司
  - 部门
  - 历史工单

#### 4.4.2 处理记录与完成通知

- 处理工单后，记录处理人、处理时间
- 工单完成后，发送邮件通知提交人

### 4.5 用户评价

#### 4.5.1 满意度评价

- 用户在工单完成后，可进行满意度评价

### 4.6 统计分析

#### 4.6.1 工单分布统计

- 支持按公司维度统计工单分布
- 支持按部门维度统计工单分布

#### 4.6.2 运营指标仪表盘

- 展示工单量
- 展示平均响应时间
- 展示满意度
- 展示热点问题

### 4.7 工单工作台

#### 4.7.1 待处理工单列表

- 查看待处理工单列表
- 支持筛选
- 支持搜索
- 支持排序
- 支持按公司维度筛选

### 4.8 操作日志

- 记录工单相关操作日志

## 5. 验收场景

### AC-01：工单创建与基础信息记录

- 验收条件：用户可创建工单，系统记录全部要求的字段信息并生成工单 ID。
- 入口类型：用户界面
- 验证动作：提交人填写主题、描述、分类、SLA 优先级（P0-P4）、问题分类，提交创建工单。
- 预期结果：工单创建成功，系统生成工单 ID，记录提交人信息（含邮箱）和创建时间，工单进入初始生命周期状态；创建后可通过查看工单详情读回全部字段信息。
- 证据类型：interaction, session-persistence

### AC-02：工单多轮回复

- 验收条件：工单支持多轮回复，每条回复记录回复人和回复时间。
- 入口类型：用户界面
- 验证动作：在工单详情中添加多条回复，包括提交人和处理人分别回复。
- 预期结果：每条回复成功保存并显示回复内容和回复时间；回复列表按时间顺序展示多轮回复记录，可读回全部回复。
- 证据类型：interaction, session-persistence

### AC-03：工单公司隔离

- 验收条件：工单按公司隔离，不同公司的工单数据互不可见。
- 入口类型：用户界面
- 验证动作：在 A 公司创建工单后，以 B 公司用户身份查看工单列表和工作台。
- 预期结果：B 公司用户无法看到 A 公司的工单数据，工单列表和工作台中均不展示 A 公司工单。
- 证据类型：authorization, session-persistence

### AC-04：工单生命周期状态流转

- 验收条件：工单按照「创建 → 待分配 → 待处理 → 完成 / 取消」的生命周期流转。
- 入口类型：用户界面
- 验证动作：创建工单后观察初始状态，触发分配使工单进入待处理，完成处理后标记完成；另创建一个工单执行取消操作。
- 预期结果：工单状态依次经过创建、待分配、待处理后到达完成；取消操作可使工单进入取消状态；每次状态变更后可通过查看工单详情读回当前状态。
- 证据类型：interaction, session-persistence

### AC-05：业务组与成员管理

- 验收条件：可为公司增加多个业务组，并为每个业务组设置成员。
- 入口类型：用户界面
- 验证动作：管理员为某公司创建多个业务组，为每个业务组添加成员。
- 预期结果：业务组创建成功并归属对应公司，成员设置成功后可通过查看业务组详情读回成员列表；不同业务组的成员独立管理。
- 证据类型：interaction, session-persistence

### AC-06：工单按分类自动分配

- 验收条件：配置分类与业务组的分配规则后，工单按分类自动分配到对应业务组。
- 入口类型：用户界面
- 验证动作：管理员为某公司配置分类→业务组的分配规则，提交人创建该分类的工单。
- 预期结果：工单创建后系统根据分类规则自动匹配并分配到对应业务组，工单状态从待分配流转至待处理，工单详情中可读回分配的业务组信息。
- 证据类型：interaction, session-persistence

### AC-07：工单转派

- 验收条件：支持将工单转派给其他处理方。
- 入口类型：用户界面
- 验证动作：处理人对一个待处理工单执行转派操作，指定新的接收方。
- 预期结果：转派成功后工单的处理方变更为新接收方，工单详情中可读回转派后的处理方信息。
- 证据类型：interaction, session-persistence

### AC-08：处理工单时查看提交人完整信息

- 验收条件：处理工单时可查看提交人的完整信息，包括姓名、公司、部门、历史工单。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息面板。
- 预期结果：展示提交人的姓名、公司、部门信息，并列出该提交人的历史工单记录。
- 证据类型：runtime-render, interaction

### AC-09：工单完成记录与邮件通知

- 验收条件：处理工单后记录处理人和处理时间，工单完成后发送邮件通知提交人。
- 入口类型：用户界面
- 验证动作：处理人完成工单处理并标记完成。
- 预期结果：工单状态变为完成，系统记录处理人和处理时间，可通过查看工单详情读回处理人信息；系统向提交人邮箱发送完成通知邮件。
- 证据类型：interaction, session-persistence

### AC-10：用户满意度评价

- 验收条件：用户在工单完成后可进行满意度评价。
- 入口类型：用户界面
- 验证动作：提交人在已完成的工单上进行满意度评价。
- 预期结果：评价提交成功后，工单详情中可读回满意度评价结果。
- 证据类型：interaction, session-persistence

### AC-11：统计分析与运营仪表盘

- 验收条件：支持按公司、部门维度统计工单分布，并通过仪表盘查看工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：进入统计分析页面，分别按公司维度和部门维度查看工单分布；查看运营指标仪表盘。
- 预期结果：工单分布统计按所选维度正确展示数据；仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标，数据与实际工单数据一致。
- 证据类型：runtime-render, session-persistence

### AC-12：工单工作台

- 验收条件：工作台展示待处理工单列表，支持筛选、搜索、排序，可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：进入工单工作台，使用筛选条件过滤工单、输入关键词搜索、切换排序方式，并使用公司维度筛选。
- 预期结果：工单列表按所选筛选、搜索、排序条件正确展示符合条件的待处理工单；按公司维度筛选后仅展示对应公司的工单。
- 证据类型：interaction, session-persistence

### AC-13：操作日志记录

- 验收条件：工单相关操作被记录为日志。
- 入口类型：内部
- 验证动作：执行工单创建、分配、转派、完成等操作后，查看工单操作日志。
- 预期结果：相关操作在日志中有对应记录，可通过日志查看操作信息。
- 证据类型：session-persistence
