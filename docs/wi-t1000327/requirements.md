# 工单系统需求（业务任务 131-ticket）

## 1. 目标

【用户明确提出】构建一套面向多公司的工单系统，覆盖工单从创建、分配、处理、完成到满意度评价的完整生命周期，并支持业务组分配、工单转派协作、完成邮件通知、统计分析与工单工作台。

## 2. 角色与核心对象

以下角色名称由用户描述的操作推导（用户未指定角色命名）：

- **提交人**：创建工单、参与工单多轮回复、在工单完成后进行满意度评价。提交人属于某家公司，具有姓名、邮箱、部门属性。
- **处理人**：业务组成员，处理分配到本组的工单，可回复、转派、完成工单。
- **管理者**：为公司创建业务组、设置业务组成员、配置分类分配规则。用户未指定该管理权限的具体归属，见第 7 节未规定事项。

核心对象：

- **公司**：工单数据隔离、业务组与分配规则的边界。
- **工单**：核心业务对象，见第 4 节。
- **业务组**：公司内的工单处理单元，包含成员。
- **工单分类**：用于自动分配与统计分析。

## 3. 端到端旅程

### 3.1 提交人旅程
提交人创建工单（主题、描述、分类、SLA 优先级）→ 系统记录工单 ID、提交人信息与创建时间 → 工单待分配 → 按分类自动分配到业务组 → 处理人处理并与提交人多轮回复沟通 → 处理人完成工单 → 提交人邮箱收到完成通知邮件 → 提交人进行满意度评价。

### 3.2 处理人旅程
处理人在工作台查看待处理工单列表（筛选、搜索、排序）→ 打开工单查看提交人完整信息（姓名、公司、部门、历史工单）→ 回复并处理 → 必要时转派给其他业务组 → 完成工单（系统记录处理人、处理时间并发送邮件通知）。

### 3.3 管理配置旅程
管理者为公司创建业务组并设置成员 → 配置"工单分类 → 业务组"的自动分配规则 → 该公司新工单按分类自动进入对应业务组。

## 4. 工单数据与生命周期

### 4.1 工单字段【用户明确提出】

- 工单 ID（【推荐】系统自动生成、唯一）
- 主题
- 描述
- 分类（问题分类）
- SLA 优先级：P0–P4（【推荐】P0 为最高优先级）
- 提交人信息：姓名、邮箱、公司、部门
- 创建时间
- 当前状态
- 回复记录（多轮）：回复人、回复时间
- 处理记录：处理人、处理时间

### 4.2 生命周期状态【用户明确提出】

状态集合：创建、待分配、待处理、完成、取消。

【推荐】流转规则：

- 工单提交成功后处于"创建"状态，随即进入"待分配"；
- 分配到业务组（自动或人工）后进入"待处理"；
- 处理人完成处理后进入"完成"；
- "取消"可在工单完成前的状态发起；
- "完成"与"取消"为终态，终态工单不再出现在待处理列表。

### 4.3 公司隔离【用户明确提出】

工单、业务组、分配规则与统计数据均以公司为隔离边界：任何用户只能查看和操作所属公司的数据。工单转派、自动分配、统计、工作台筛选中的"公司"维度均在该边界内生效。

## 5. 功能需求

### 5.1 工单管理

- **FR-01 工单创建**：提交人填写主题、描述、分类、SLA 优先级（P0–P4）创建工单；系统记录工单 ID、提交人信息（姓名、邮箱、公司、部门）与创建时间。
- **FR-02 多轮回复**：工单支持多轮回复，每轮记录回复人与回复时间；提交人与处理人均可参与回复。
- **FR-03 公司隔离**：见 4.3。

### 5.2 工单分配

- **FR-04 业务组管理**：可为某个公司增加多个业务组；每个业务组可以设置成员。
- **FR-05 分类自动分配**：可配置某个公司"工单分类 → 业务组"的分配规则；该公司新工单按分类自动分配到对应业务组。

### 5.3 工单协作

- **FR-06 工单转派**：待处理工单可转派到其他业务组；转派后工单仍处于待处理状态（【推荐】），原处理流程可继续。

### 5.4 工单处理

- **FR-07 提交人完整信息**：处理工单时可查看提交人的完整信息，包括姓名、公司、部门、历史工单等。
- **FR-08 处理记录与完成通知**：工单完成时记录处理人、处理时间等；工单完成后系统向提交人邮箱发送通知邮件。

### 5.5 用户评价

- **FR-09 满意度评价**：提交人在收到（完成通知后的）工单后可进行满意度评价。

### 5.6 统计分析

- **FR-10 工单分布统计**：支持按公司、部门维度统计工单分布。
- **FR-11 运营指标仪表盘**：查看工单量、平均响应时间、满意度、热点问题等运营指标。指标口径见第 6 节推荐基线。

### 5.7 工单工作台

- **FR-12 工作台列表**：查看待处理工单列表；支持筛选、搜索、排序；可按公司维度筛选。

### 5.8 操作日志

- **FR-13 相关日志**：记录工单相关操作日志，覆盖工单创建、回复、分配、转派、状态变更、完成、评价等关键操作（【推荐】含操作人、操作时间、操作内容）。

## 6. 推荐基线

以下为闭合核心目标所必需的保守默认口径，可被后续阶段或用户调整：

1. 工单 ID 由系统自动生成且唯一，作为工单的对外标识。
2. SLA 优先级 P0 为最高、P4 为最低，仅作为优先级分级；各优先级对应的具体响应时限未规定。
3. 状态流转规则见 4.2；取消仅可在工单完成前发起。
4. 平均响应时间 = 工单创建时间至首次回复时间的平均时长。
5. 满意度指标 = 工单满意度评价的平均值。
6. 热点问题 = 按工单量排序的问题分类（最高的分类排在前列）。
7. 操作日志含操作人、操作时间、操作内容，用于审计追溯。
8. 历史工单 = 该提交人在当前系统内提交过的全部工单列表（含各状态）。

## 7. 未规定事项

- 技术栈、存储方案、部署方式。
- 邮件发送的实现渠道与邮件内容模板。
- 满意度评价的具体形式（分值范围、等级数、是否可修改）。
- P0–P4 对应的具体 SLA 时限数值与超时处理。
- 业务组管理、分配规则配置等管理权限的具体角色归属与权限模型。
- 业务组数量、成员数量等配置上限。

## 8. 验收场景

### AC-01：提交人可创建工单并记录完整信息
- 验收条件：提交人创建的工单包含全部必填信息，创建后可查看。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份创建工单，填写主题、描述、分类、SLA 优先级（P0–P4 任选一档），提交后打开该工单详情查看。
- 预期结果：工单具有唯一工单 ID；主题、描述、分类、优先级与填写内容一致；提交人姓名、邮箱、公司、部门及创建时间被记录；工单初始状态为待分配。
- 证据类型：runtime-render, interaction, session-persistence

### AC-02：工单支持多轮回复
- 验收条件：同一工单可进行多轮回复，每轮记录回复人、回复时间。
- 入口类型：用户界面
- 验证动作：对一张已创建的工单，由处理人和提交人先后各回复至少 2 次，然后查看工单的回复列表。
- 预期结果：全部回复按时间顺序完整保留；每条回复显示对应的回复人与回复时间；不同角色的回复被正确归属。
- 证据类型：runtime-render, interaction, session-persistence

### AC-03：工单按公司隔离
- 验收条件：任一公司的用户无法查看或操作其他公司的工单。
- 入口类型：用户界面
- 验证动作：公司 A 的提交人创建一张工单后，分别以公司 B 的提交人和处理人身份，在工作台列表中浏览、按该工单的主题或 ID 搜索，并查看统计页面。
- 预期结果：公司 B 用户在列表、搜索结果和统计中均看不到公司 A 的工单；公司 A 用户可正常访问自己的工单。
- 证据类型：runtime-render, authorization

### AC-04：工单生命周期状态流转
- 验收条件：工单按"创建 → 待分配 → 待处理 → 完成"流转，且可在完成前取消。
- 入口类型：用户界面
- 验证动作：操作两张新工单：第 1 张依次完成创建、分配、处理并完成；第 2 张在待处理状态下执行取消。分别查看各阶段工单状态及工作台待处理列表。
- 预期结果：第 1 张工单依次呈现待分配、待处理、完成状态；第 2 张工单呈现取消状态且不再进入处理流程；完成与取消的工单均不再出现在待处理工单列表中。
- 证据类型：runtime-render, interaction, session-persistence

### AC-05：业务组与成员管理
- 验收条件：可为某个公司增加多个业务组，并为每个业务组设置成员。
- 入口类型：用户界面
- 验证动作：使用具备业务组管理权限的账号，为公司 A 创建两个业务组，并分别为其添加不同成员。
- 预期结果：两个业务组独立存在且归属公司 A；各业务组成员归属正确；业务组可被该公司的分配规则引用。
- 证据类型：runtime-render, interaction, session-persistence

### AC-06：工单按分类自动分配到业务组
- 验收条件：配置分配规则后，该公司新工单按分类自动进入对应业务组。
- 入口类型：用户界面
- 验证动作：为公司 A 配置"分类 X → 业务组 G1"的自动分配规则，随后以公司 A 提交人身份创建分类为 X 的工单。
- 预期结果：新工单无需人工操作即归属于业务组 G1，状态进入待处理；G1 成员可在工作台待处理列表中看到该工单。
- 证据类型：runtime-render, interaction

### AC-07：工单转派
- 验收条件：待处理工单可转派给其他业务组，转派后可继续处理。
- 入口类型：用户界面
- 验证动作：将业务组 G1 名下的一张待处理工单转派给业务组 G2，随后以 G2 成员身份查看并处理该工单。
- 预期结果：转派后工单归属变更为 G2；G2 成员可在工作台看到该工单并继续回复、处理；转派操作被记录。
- 证据类型：runtime-render, interaction, session-persistence

### AC-08：处理工单时可查看提交人完整信息
- 验收条件：处理人打开待处理工单时，可查看提交人姓名、公司、部门及历史工单。
- 入口类型：用户界面
- 验证动作：处理人打开一张由提交人（其此前已提交过其他工单）创建的待处理工单，查看提交人信息区域。
- 预期结果：显示提交人姓名、公司、部门；历史工单列表包含该提交人此前提交的工单并可查看。
- 证据类型：runtime-render

### AC-09：工单完成记录处理信息并发送邮件通知
- 验收条件：工单完成时系统记录处理人、处理时间，并向提交人邮箱发送通知。
- 入口类型：用户界面
- 验证动作：处理人完成一张待处理工单后，查看工单的处理记录，并核对提交人邮箱的收件情况。
- 预期结果：工单状态变为完成；处理人与处理时间被记录在工单上；提交人邮箱收到工单完成的通知邮件。
- 证据类型：interaction, other

### AC-10：工单完成后用户进行满意度评价
- 验收条件：提交人可对已完成的工单进行满意度评价。
- 入口类型：用户界面
- 验证动作：提交人对一张已完成的工单提交满意度评价，然后查看该工单的评价结果。
- 预期结果：评价成功并记录在该工单上；评价结果可在工单详情中查看，并反映到统计中的满意度指标。
- 证据类型：runtime-render, interaction, session-persistence

### AC-11：按公司、部门维度统计工单分布
- 验收条件：统计分析支持按公司、部门维度查看工单分布。
- 入口类型：用户界面
- 验证动作：由多家公司、多个部门的提交人分别创建数量已知的工单后，在统计分析中分别按公司维度、部门维度查看工单分布。
- 预期结果：按公司查看时，各公司工单数量与实际创建数据一致；按部门查看时，各部门工单数量与实际创建数据一致；统计范围遵守公司隔离。
- 证据类型：runtime-render

### AC-12：运营指标仪表盘
- 验收条件：仪表盘可查看工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：准备数据基础：创建数量已知、分类分布已知、完成与评价状态已知，且各工单的创建时间与首次回复时间间隔已知的工单集合；打开统计与分析仪表盘查看各项指标。
- 预期结果：工单量与实际数量一致；平均响应时间与已知间隔的计算结果一致；满意度与评价的平均值一致；热点问题呈现工单量最多的分类；指标数据遵守公司隔离。
- 证据类型：runtime-render

### AC-13：工单工作台列表的筛选、搜索与排序
- 验收条件：工作台可查看待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：在待处理工单列表中依次执行：按 SLA 优先级/分类筛选、按主题关键词搜索、按创建时间排序、按公司维度筛选，并组合其中若干条件再次查询。
- 预期结果：每次操作后列表仅显示满足条件的工单且排序正确；筛选、搜索、排序可单独或组合使用，结果准确。
- 证据类型：runtime-render, interaction

### AC-14：关键操作日志记录
- 验收条件：工单关键操作被记录为相关日志。
- 入口类型：内部
- 验证动作：依次执行工单创建、回复、分配、转派、完成、评价等操作后，查看工单相关日志记录。
- 预期结果：每个关键操作均有对应日志条目，包含操作人、操作时间、操作内容；日志与实际操作一一对应。
