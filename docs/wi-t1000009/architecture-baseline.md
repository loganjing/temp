# 教师管理系统架构基线

## 需求引用

本设计基于已批准的需求基线 `docs/wi-t1000009/requirements.md`（SHA-256: `0f4cf043e2d15278d35db164093974c4249a95d1ca6c998a682c6f27840e42c9`），不扩展或重裁产品语义。

## 路由结论

应用类型为 **simple-frontend**（精简前端路线）。理由：需求为单用户 CRUD 应用，验收场景入口类型均为用户界面，证据类型为 interaction 和 session-persistence，仅要求页面刷新或重开后数据仍保留；需求未提及服务端权威数据、认证、后台任务、外部集成或跨用户/设备共享。

## 页面与交互范围

单个 SPA 页面承载教师管理全部交互：

- **教师列表视图**：以表格展示全部教师记录，每行包含教师名称、教授课程、年级、手机、邮箱五个字段，每行提供编辑和删除操作入口。
- **新增/编辑表单**：表单包含五个字段输入控件，提交后保存到本地存储并刷新列表；编辑时预填充已有值。
- **删除确认**：删除操作前向用户确认，确认后移除记录并刷新列表。

## 浏览器状态与数据归属

- 使用浏览器 `localStorage` 作为唯一持久化层，键名约定为 `teacher-mgmt:teachers`，存储 JSON 数组。
- 数据在同一浏览器配置文件中刷新或重新打开页面后仍保留；不与其他浏览器、设备或用户共享。
- 无服务端 API、数据库、认证、后台任务或外部集成。字段格式校验规则（手机号位数、邮箱格式）需求未规定，不作为当前基线正式验收项。

## 实现入口与运行方式

- 新建 React + Vite SPA 项目作为前端实现入口。
- 开发环境使用 Vite 开发服务器（`npm run dev`），生产构建使用 `npm run build`。
- 应用负责 `localStorage` 的读写边界：新增、修改、删除操作直接读写本地存储，查询操作从本地存储读取并渲染。

## 适用边界

- 本设计仅覆盖前端页面与本地数据持久化，不包含服务端、数据库或跨设备同步。
- 架构结论冻结后复用于后续实现和验证阶段。
