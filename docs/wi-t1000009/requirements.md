# 工单系统需求基线（k02-ticket）

## 1. 目标

为多公司场景提供统一的工单受理与处理能力：公司内用户提交工单，系统按分类自动分配到本公司业务组，由业务组处理、协作与转派，完成后向提交人发送邮件通知并收集满意度评价；公司管理员可维护业务组与分配规则，管理者可查看本公司的工单分布与运营指标、追溯工单操作日志。

本基线覆盖：工单管理、业务组与自动分配、转派协作、工单处理与邮件通知、满意度评价、统计分析与仪表盘、工单工作台、操作日志。

## 2. 角色

| 角色 | 职责与可见范围 |
| --- | --- |
| 提交人（普通用户） | 提交工单；查看、回复、取消自己的工单；对自己的已完成工单评价。仅可见本人提交的工单。 |
| 处理人（业务组成员） | 查看所属业务组名下的工单；回复、转派、完成工单。可见范围限于所在公司的工单，可处理范围为其所在业务组名下的工单。 |
| 公司管理员 | 维护本公司的业务组、业务组成员和按分类的自动分配规则；查看本公司工作台、统计与日志；可取消本公司未完结工单。 |

来源说明：提交人与处理人的能力来自用户明确提出的功能项；“公司管理员”以及其可见范围属于**推荐基线**（用户未指定配置操作人，而“给某个公司增加业务组、按分类自动分配”必须由本公司某个角色维护），可调整。

## 3. 核心对象

### 3.1 工单

用户明确要求的字段：

- 工单ID：系统生成的全局唯一编号，不可修改。
- 主题：必填。
- 描述：必填。
- 分类：必填，取值来自本公司的分类清单（公司隔离）。
- 优先级：P0–P4，必填；P0 为最高优先级、P4 为最低（推荐基线）。
- 提交人信息：姓名、邮箱、公司、部门（部门用于按维度统计）。
- 创建时间：系统记录的提交时间。
- 回复记录：多轮回复，含回复人、回复时间、回复内容。

推荐基线补充的字段：当前状态、当前业务组、当前处理人、完成人、完成时间、取消人、取消时间、最近更新时间。

未规定：主题与描述的长度限制、附件、自定义字段、内部私有备注、抄送人。

### 3.2 状态模型

状态集合（用户明确提出）：创建、待分配、待处理、完成、取消。

| 状态 | 含义 |
| --- | --- |
| 创建 | 提交过程中的瞬时初始状态：提交后立即完成校验与自动分配判定，不在此状态停留。 |
| 待分配 | 已提交但未确定承办业务组，等待分配。 |
| 待处理 | 已归属某个业务组（或指定处理人），等待回复与处理。 |
| 完成 | 已处理完毕，记录完成人与完成时间（终态）。 |
| 取消 | 未完成即终止（终态）。 |

允许的流转（推荐基线，依据用户给出的状态集合与功能项推导）：

- 创建 → 待分配：提交成功且未命中自动分配规则。
- 创建 → 待处理：提交成功且命中自动分配规则。
- 待分配 → 待处理：管理员或处理人将工单指派到业务组/成员。
- 待处理 → 待处理：转派到其他业务组或成员（状态不变）。
- 待分配、待处理 → 取消。
- 待处理 → 完成。
- 完成、取消为终态，不可再回复、转派、取消或变更状态。

### 3.3 业务组

- 属于某一个公司，同一公司可建立多个业务组（用户明确提出）。
- 业务组包含名称、所属公司、成员列表；成员为本公司的用户（用户明确提出“每个业务组可以设置成员”）。
- 业务组及其成员只对本公司可见。

### 3.4 自动分配规则

- 规则由“公司 + 分类 → 业务组”组成（用户明确提出“某个公司的工单按照分类自动分配到某个业务组”）。
- 同一公司同一分类至多一条生效规则；重复配置时以最新保存的规则生效，不产生多条并发规则（推荐基线）。
- 规则可启用与停用；停用后该分类的新工单不再自动分配，按未命中规则处理（推荐基线）。
- 规则只影响规则保存后创建的工单，不回溯已存在的工单（推荐基线）。

### 3.5 回复、评价、通知与日志

- 回复：回复内容、回复人、回复时间；按回复时间正序展示；工单完成后不允许新增回复（推荐基线）。
- 评价：评分（1–5 分，推荐基线）+ 可选评语 + 评价时间；每条工单由提交人评价一次，评价后不可修改（推荐基线）。
- 邮件通知：工单完成时向提交人邮箱发送完成通知；记录发送时间与发送结果（成功/失败）。发送失败不阻塞工单完成，失败结果需可查看并可重试（推荐基线）。
- 操作日志：记录创建、状态变更、分配、转派、回复、完成、取消、评价、通知发送等动作，含操作人、操作时间、动作类型与变更摘要；日志只读，不可编辑或删除（推荐基线）。

## 4. 业务规则

- **R-01 公司隔离**：工单、业务组、分配规则、工作台、统计和日志均按公司隔离。用户只能看到本公司数据；访问其他公司的工单或配置不返回数据并给出无权限提示。
- **R-02 提交**：提交人可提交工单，提交时必须填写主题、描述、分类、优先级；提交人姓名、邮箱、公司、部门取自其账号信息，不由提交人逐单填写。
- **R-03 自动分配**：工单提交时，按工单所属公司与分类匹配生效中的分配规则；命中则归属对应业务组并进入待处理，未命中进入待分配。
- **R-04 手工分配**：待分配工单可由公司管理员或该业务组处理人指派到业务组，或直接指定本公司成员为处理人（推荐基线）；指派后进入待处理。
- **R-05 转派**：待处理工单可转派到本公司其他业务组或成员（用户明确提出）；转派需记录转派前后归属、转派人与转派时间，工单状态保持待处理。
- **R-06 处理信息可见**：处理人在工单处理界面可查看提交人完整信息：姓名、公司、部门、邮箱，以及该提交人的历史工单列表（含工单ID、主题、分类、状态、创建时间）。
- **R-07 完成与通知**：工单完成时记录完成人与完成时间，并向提交人邮箱发送完成通知；同一工单不重复发送完成通知（重试发送失败的通知除外）。
- **R-08 评价**：仅已完成工单可评价，且只能由提交人评价；评分必填、评语可选；每条工单最多一条评价。
- **R-09 取消**：提交人可取消自己未完结的工单；公司管理员可取消本公司未完结工单（推荐基线）；取消需记录取消人与取消时间。
- **R-10 数据保留**：工单、回复、评价、日志在工单取消或完成后仍可查看，不做物理删除（推荐基线）。

## 5. 核心旅程

1. **提交**：提交人选择分类与优先级，填写主题、描述后提交；系统生成工单ID与创建时间，并按 R-03 判定归属。
2. **分配到处理**：未命中规则的工单进入待分配，由管理员/处理人指派；命中规则的工单直接进入待处理，由业务组成员查看并处理。
3. **处理与协作**：处理人查看提交人信息与历史工单，通过多轮回复沟通；必要时转派给其他业务组或成员。
4. **完成与通知**：处理人完成工单，系统记录完成人与完成时间，并向提交人邮箱发送完成通知。
5. **评价与回顾**：提交人收到通知后对工单满意度评价；管理员在工作台与统计中查看本公司工单量与运营指标，并通过操作日志追溯工单过程。

## 6. 统计与工作台

### 6.1 工单工作台

用户明确提出：查看待处理工单列表，支持筛选、搜索、排序，可按公司维度筛选。

推荐基线的具体能力：

- 默认展示当前用户可处理范围内的待处理工单（业务组成员为其业务组工单，管理员为本公司工单）。
- 筛选：状态、优先级、分类、业务组、所属公司、提交人、创建时间范围。
- 搜索：按工单ID或主题关键字。
- 排序：创建时间、优先级、最近更新时间，支持升序与降序。
- 列表至少展示：工单ID、主题、分类、优先级、状态、提交人、所属公司、部门、业务组、创建时间、最近更新时间。

### 6.2 统计分析与仪表盘

用户明确提出：按公司、部门维度统计工单分布；仪表盘查看工单量、平均响应时间、满意度、热点问题等运营指标。

指标口径（推荐基线，取用户未定义的可观察口径）：

| 指标 | 口径 |
| --- | --- |
| 工单量 | 统计期内创建的工单数量；取消数量单独显示以便区分。 |
| 平均响应时间 | 统计期内已产生首次回复的工单，从创建到首次回复的平均时长。 |
| 满意度 | 已完成且已评价工单的平均评分，同时显示已评价数量。 |
| 热点问题 | 统计期内按分类汇总工单量并取前若干名。 |
| 分布统计 | 按提交人所属公司、所属部门分组统计工单量，可选择时间范围。 |

未规定：统计时间范围的默认值与粒度、热点问题的具体名次数、SLA 响应/解决时限与超时告警（用户仅提出 P0–P4 优先级设置，未提出时限阈值），均不作为本期验收条件。

## 7. 验收场景

### AC-01：提交工单生成完整工单信息
- 验收条件：提交人填写必填项提交后，系统生成唯一工单ID，并保存主题、描述、分类、P0–P4 优先级、提交人姓名/邮箱/公司/部门及创建时间；必填项缺失时不生成工单并提示。
- 入口类型：用户界面
- 验证动作：以某个提交人身份提交一条包含主题、描述、分类和优先级的工单，随后打开该工单详情。
- 预期结果：工单详情展示全部上述字段，工单ID唯一且不可编辑，创建时间与提交时间一致；再次提交缺少必填项的工单被拒绝并给出提示。
- 证据类型：interaction,error-feedback
- 共享流程组：工单提交与处理

### AC-02：生命周期状态按规则流转
- 验收条件：工单提交后进入待分配（未命中分配规则）或待处理（命中分配规则）；待分配可被指派为待处理；待处理可完成为完成、可取消为取消；完成与取消后不可再变更状态。
- 入口类型：用户界面
- 验证动作：分别为“未命中规则”和“命中规则”的分类各提交一条工单，观察初始状态；对待分配工单执行指派；对一条待处理工单执行完成，对另一条执行取消；再尝试对已完成与已取消工单回复或变更状态。
- 预期结果：两条工单初始状态分别为待分配与待处理；指派后变为待处理；完成后为完成、取消后为取消；终态工单不再提供回复、转派、取消操作，直接调用也不改变状态。
- 证据类型：interaction,session-persistence
- 共享流程组：工单提交与处理

### AC-03：多轮回复完整留痕
- 验收条件：工单支持多轮回复，每条回复记录回复人、回复时间与内容，按时间正序展示并在重新打开后保持。
- 入口类型：用户界面
- 验证动作：由处理人回复两次、提交人回复一次，然后重新打开该工单详情。
- 预期结果：三条回复按时间正序展示，回复人与回复时间各自正确对应，内容未被覆盖或丢失。
- 证据类型：interaction,session-persistence
- 共享流程组：工单提交与处理

### AC-04：工单数据按公司隔离
- 验收条件：不同公司的用户无法看到、搜索到或访问对方的工单与业务组；工作台与统计只含本公司数据。
- 入口类型：用户界面
- 验证动作：以公司A用户提交工单并登录公司B的处理人账号，查看工作台、搜索该工单ID、直接打开其详情链接，并查看业务组列表。
- 预期结果：公司B用户的工作台、搜索结果与统计均不含公司A工单；打开公司A工单详情被拒绝并提示无权限；业务组列表只显示本公司业务组。
- 证据类型：authorization
- 共享流程组：公司隔离

### AC-05：公司可维护多个业务组及成员
- 验收条件：同一公司可创建多个业务组，每个业务组可设置与调整成员；成员来自本公司用户。
- 入口类型：用户界面
- 验证动作：管理员为公司A创建两个业务组并分别添加不同成员，移除其中一个成员后重新打开业务组详情。
- 预期结果：两个业务组同时存在且独立展示；成员设置与移除结果正确保存并回显；无法将其他公司用户加入本公司业务组。
- 证据类型：interaction,session-persistence
- 共享流程组：业务组与分配配置

### AC-06：工单按分类自动分配到业务组
- 验收条件：公司管理员为某分类配置业务组后，该分类新提交的工单自动归属对应业务组并进入待处理；无规则或规则停用时工单进入待分配。
- 入口类型：用户界面
- 验证动作：为公司A的“账务问题”分类配置业务组“财务支持组”，保存后以公司A提交人提交该分类工单；再停用该规则后提交一条同分类工单。
- 预期结果：配置生效后的工单在详情中显示所属业务组为“财务支持组”且状态为待处理；停用规则后提交的工单状态为待分配、无业务组；规则变更前已创建的工单归属不变。
- 证据类型：interaction,session-persistence
- 共享流程组：业务组与分配配置

### AC-07：待分配工单可指派到业务组或成员
- 验收条件：待分配工单可被指派到本公司业务组，或直接指定本公司成员为处理人，指派后进入待处理并记录归属。
- 入口类型：用户界面
- 验证动作：对一条待分配工单执行指派，选择目标业务组与成员，保存后查看详情与工作台。
- 预期结果：工单状态变为待处理，详情显示目标业务组与处理人，工作台中该工单从待分配范围移入待处理范围。
- 证据类型：interaction,session-persistence
- 共享流程组：工单提交与处理

### AC-08：工单转派记录前后归属
- 验收条件：待处理工单可转派到本公司其他业务组或成员，转派后状态仍为待处理，并保留转派前归属、转派人、转派时间。
- 入口类型：用户界面
- 验证动作：处理人将工单从“财务支持组”转派到“技术支持组”，填写转派说明后保存，再打开工单详情与操作日志。
- 预期结果：工单当前业务组为“技术支持组”、状态为待处理；详情或日志中可看到转派前后的业务组、转派人与转派时间；原业务组处理人不再可处理该工单。
- 证据类型：interaction,session-persistence
- 共享流程组：工单提交与处理

### AC-09：处理人可查看提交人完整信息与历史工单
- 验收条件：工单处理界面展示提交人姓名、公司、部门、邮箱，以及该提交人的历史工单（含工单ID、主题、分类、状态、创建时间）。
- 入口类型：用户界面
- 验证动作：为同一提交人提交两条工单后，由处理人打开其中一条工单详情查看提交人信息区域。
- 预期结果：提交人四项信息完整展示；历史工单列表中包含该提交人的两条工单，字段齐全且不含其他提交人的工单。
- 证据类型：interaction
- 共享流程组：工单提交与处理

### AC-10：完成工单记录处理结果并发送邮件通知
- 验收条件：处理人完成工单后，工单记录完成人与完成时间，系统向提交人邮箱发送完成通知并记录通知结果；通知发送失败不改变完成状态且失败可查看。
- 入口类型：用户界面
- 验证动作：处理人完成一条待处理工单，随后查看工单详情中的完成信息与通知记录；分别使用可正常投递与不可投递的提交人邮箱各验证一次。
- 预期结果：工单状态为完成，完成人与完成时间正确；通知记录显示发送时间与结果；可投递邮箱收到完成通知邮件；不可投递邮箱不阻塞完成，通知结果标记失败并可查看/重试。
- 证据类型：interaction,session-persistence
- 共享流程组：工单提交与处理

### AC-11：提交人完成满意度评价
- 验收条件：已完成工单可由提交人提交一次满意度评价（1–5 分，评语可选），评价记录评分、评语与评价时间；未完成工单不可评价，重复评价被拒绝。
- 入口类型：用户界面
- 验证动作：提交人对一条已完成工单提交评分与评语，再次尝试评价；并对一条待处理工单尝试评价。
- 预期结果：首次评价成功并在详情中展示评分、评语与时间；再次评价被拒绝或仅显示已有评价不可修改；待处理工单不提供评价入口。
- 证据类型：interaction,session-persistence
- 共享流程组：工单提交与处理

### AC-12：工单工作台支持筛选、搜索、排序
- 验收条件：工作台展示当前用户可处理范围内的待处理工单，支持按状态、优先级、分类、业务组、公司、创建时间筛选，按工单ID或主题搜索，按创建时间/优先级/最近更新时间排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：在待处理工单列表中依次按公司筛选、按优先级筛选、输入主题关键字搜索，并按创建时间降序与优先级排序切换。
- 预期结果：每次条件变更后列表只包含符合条件的工单，结果数量与状态提示一致；排序切换后列表顺序随之变化；清空条件后恢复默认待处理列表。
- 证据类型：interaction
- 共享流程组：工作台与统计

### AC-13：按公司与部门维度统计工单分布
- 验收条件：统计视图可按提交人所属公司和部门维度展示统计期内的工单量分布，并可与公司/部门明细对应。
- 入口类型：用户界面
- 验证动作：在存在多公司、多部门工单数据的情况下，打开按公司维度的分布并切换到按部门维度，选择统计时间范围。
- 预期结果：公司维度显示各公司工单量；部门维度显示对应部门工单量；分组合计与统计期内工单总量一致；修改时间范围后结果随之更新。
- 证据类型：interaction
- 共享流程组：工作台与统计

### AC-14：仪表盘展示运营指标
- 验收条件：仪表盘展示工单量、平均响应时间、满意度、热点问题四类指标，且指标值与工单数据一致。
- 入口类型：用户界面
- 验证动作：使用已完成的工单、含首次回复的工单和已评价工单的数据集打开仪表盘，核对各项指标。
- 预期结果：工单量与统计期内创建的工单数一致并单独显示取消数量；平均响应时间等于已首次回复工单的创建到首次回复平均时长；满意度显示平均评分与评价数量；热点问题按分类显示工单量排名。
- 证据类型：interaction
- 共享流程组：工作台与统计

### AC-15：工单操作日志可追溯
- 验收条件：工单的创建、分配、转派、回复、完成、取消、评价与通知发送均写入操作日志，日志含操作人、操作时间、动作类型与变更摘要，且不可编辑删除。
- 入口类型：用户界面
- 验证动作：对一条工单依次执行指派、转派、回复、完成、评价，然后打开该工单的操作日志。
- 预期结果：日志按时间顺序包含上述全部动作，每条记录的操作人与时间正确，可看出对应动作的关键变更（如状态、业务组变化）；日志不提供编辑或删除入口。
- 证据类型：interaction,session-persistence
- 共享流程组：工单提交与处理

## 8. 未规定与范围外

未规定（不纳入本期验收）：SLA 响应/解决时限与超时提醒、工单附件、内部备注、工单合并/拆分、邮件模板自定义、移动端专属适配、多语言、外部系统集成、数据导出、通知渠道（除邮件外）。

明确排除：无。用户未提出排除项，本基线不擅自设定非目标。
