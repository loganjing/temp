# 验证报告

## 验证结论

pass-with-risk

## 摘要

按验收条件核对 k02-ticket 工单管理系统 15 项验收条件（AC-01…AC-15）的浏览器可用性与数据一致性。

变更行为：本轮为验收执行，未修改产品代码；验证范围为工单全生命周期、业务组与自动分配、公司隔离、通知邮件、评价、工作台筛选排序、统计分布与仪表盘。

非目标：
- SLA 响应/解决时限与超时提醒
- 工单附件与内部备注
- 工单合并/拆分
- 邮件模板自定义
- 移动端专属适配与多语言
- 外部系统集成与数据导出
- 邮件之外的通知渠道

## 验证环境

本地开发环境（Vite dev server + Hono 后端 + SQLite） 工作区当前 HEAD，node/npm workspace app/ticket；本轮独立临时数据库执行 npm run seed（2 公司、9 用户、3 业务组、5 分类、8 条种子工单，幂等复核两次一致），并在验收过程中新增 7 条工单、2 个业务组与 1 条分配规则；完成通知由本地 SMTP 收件桩承接。

## 剩余风险

- 工作台“按优先级 + 降序”时低优先级在前（P3 先于 P0），只有切到“升序”才是 P0 在前；与契约“排序时 P0 最高”的直觉不一致，AC-12 仅要求排序切换生效，故记为非阻断风险，建议明确 asc/desc 与优先级的映射。
- 工单详情首次进入时，操作日志区在异步加载完成前渲染为“暂无操作日志”，随后正确显示 7 条；重载后无数据丢失，建议补充加载态区分以避免误判为空。
- 统计页统计时间为原生日期输入，自动化工具无法驱动其改值，时间范围生效改用接口证据（同范围 volume 11、部门合计 11）佐证，UI 默认范围与接口返回值一致。
