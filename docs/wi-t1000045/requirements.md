# 教师管理系统需求

## 目标

为教师管理提供一个增删改查（CRUD）能力，使用户可以在统一入口中创建、查看、编辑和删除教师记录。

## 字段

| 字段 | 说明 |
|------|------|
| 教师名称 | 教师的姓名 |
| 教授课程 | 该教师教授的课程 |
| 年级 | 教师所带的年级 |
| 手机 | 教师的手机号码 |
| 邮箱 | 教师的电子邮箱 |

## 核心行为

1. **新增教师**：用户可填写上述全部字段并保存，生成一条教师记录。
2. **查看教师列表**：用户可查看已保存的教师记录列表，列表中展示各教师的关键信息。
3. **编辑教师**：用户可对已有教师记录的字段进行修改并保存。
4. **删除教师**：用户可删除已有教师记录，删除后该记录不再出现在列表中。

## 验收场景

### AC-01：新增教师后可通过列表读回

- 验收条件：用户填写全部字段保存后，可在教师列表中读回该记录，且各字段值与录入一致。
- 入口类型：用户界面
- 验证动作：在教师管理界面填写教师名称、教授课程、年级、手机、邮箱并保存，然后查看教师列表。
- 预期结果：列表中包含刚新增的教师记录，五个字段值与录入内容一致。
- 证据类型：interaction, runtime-render

### AC-02：编辑教师信息后可读回更新

- 验收条件：用户对已有教师记录修改任意字段并保存后，再次读取该记录时显示更新后的值。
- 入口类型：用户界面
- 验证动作：选中一条已有教师记录，修改其中一个或多个字段（如教师名称、手机）并保存，然后查看该记录。
- 预期结果：记录显示为修改后的值，未被修改的字段保持原值。
- 证据类型：interaction, runtime-render

### AC-03：删除教师后列表不再包含该记录

- 验收条件：用户删除一条教师记录后，该记录不再出现在教师列表中。
- 入口类型：用户界面
- 验证动作：在教师列表中选中一条已有教师记录并执行删除，然后刷新或重新查看列表。
- 预期结果：被删除的教师记录不再出现在列表中。
- 证据类型：interaction, runtime-render

## 未规定事项

- 教师列表的排序、分页、筛选方式：用户未明确要求，保持未规定。
- 权限与角色控制：用户未明确要求，保持未规定。
- 数据持久化方式与存储技术：用户未明确要求，保持未规定。
