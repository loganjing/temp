# 教师管理系统架构基线

## 范围来源

本设计基于已批准的需求基线 `docs/wi-t1000045/requirements.md`（sha256: e94aa118b04638aa446af77c845ca95b1d9d2aa5b20cfffcec8979e51bf0cc08）。需求范围为单用户教师记录增删改查（CRUD），字段为教师名称、教授课程、年级、手机、邮箱。验收场景 AC-01/AC-02/AC-03 均为用户界面交互验证。本设计不扩展或重裁产品语义。

## 应用类型

simple-frontend。需求未要求服务端权威数据、数据库、认证/权限、后台任务、外部服务集成或跨用户/跨设备数据共享。数据归属为当前浏览器配置文件，不承诺跨浏览器、跨设备或跨用户同步。

## 页面与交互范围

单一 SPA 页面承载教师管理的全部 CRUD 能力：

- **教师列表视图**：展示已保存教师记录的关键字段（教师名称、教授课程、年级、手机、邮箱），并提供新增、编辑、删除入口。
- **新增/编辑表单**：在同一页面内通过模态或内联表单呈现，包含教师名称、教授课程、年级、手机、邮箱五个字段；保存后写回存储并刷新列表。
- **删除操作**：在列表项上触发删除，删除后记录不再出现在列表中。

交互边界由应用自身负责读写，无服务端 API 调用。

## 浏览器状态与数据归属

- 教师记录持久化于浏览器 `localStorage`，键名由应用负责定义。
- 数据在同一浏览器配置文件中刷新或重新打开页面后仍保留；不会与其他浏览器、设备或用户共享。
- 无服务端权威数据源，无认证层，无同步层。
- 字段值均为本地展示字符串，当前基线不强制手机/邮箱格式校验（与需求未规定事项一致）。

## 实现入口与运行方式

新建 React + Vite 单页应用：

- 技术栈：React + Vite SPA。
- 开发运行：通过 Vite 开发服务器启动（如使用 npm，则 `npm run dev`）。
- 构建：`npm run build` 产出静态资源。
- 应用通过单一入口加载，读写 `localStorage` 完成教师记录的增、删、改、查。

## 接口与校验边界

- 读写边界：应用直接读写 `localStorage`，无外部接口。
- 校验边界：五个字段均为必填项以保证 CRUD 语义完整；手机和邮箱格式校验未在需求中规定，当前基线不强制格式约束。若后续需求明确格式规则，应在需求基线更新后纳入设计。
