# 访客系统需求文档

## 1. 项目目标

开发一套访客管理系统，包含微信小程序端（访客登记）和移动端适配的审批后端系统。访客通过微信小程序录入访客信息并提交访问申请，审批人员通过移动端审批系统审核来访人员，系统将所有数据持久化到数据库中。

> 用户明确提出：微信小程序、后端和数据库、审批后端系统适配移动端。

## 2. 角色与入口

| 角色 | 入口 | 说明 |
|------|------|------|
| 访客 | 微信小程序 | 填写访客信息并提交访问申请 |
| 审批人员 | 移动端审批系统（Web） | 审核访客申请，通过或驳回 |

> 角色由用户描述的流程推导（访客登记 + 审批审核），用户未指定具体受众范围。

## 3. 访客信息字段

### 用户明确提出（必填）

| 字段 | 说明 | 录入方式 |
|------|------|----------|
| 手机号码 | 访客手机号 | 优先从微信获取；获取不到时手工填写 |
| 身份证号 | 访客身份证号码 | 手工填写 |
| 公司信息 | 访客所属公司 | 手工填写 |
| 人名 | 访客姓名 | 手工填写 |
| 访问事由 | 来访目的 | 手工填写 |

### 推荐基线（补充核心流程必要字段）

以下字段为推荐补充，用于闭合访客系统核心流程。标注为推荐基线，可在后续阶段调整或排除。

| 字段 | 说明 | 是否必填 | 推荐理由 |
|------|------|----------|----------|
| 被访人姓名 | 接待访客的内部人员 | 必填 | 访客系统需明确访问对象，审批需据此判断 |
| 预计到访时间 | 访客计划到达时间 | 必填 | 审批需有时间参照，便于管理来访时段 |
| 访客照片 | 访客现场或上传照片 | 选填 | 安全管理常见需求，辅助审批人员核对身份 |

> 用户明确授权"其他的你可以发挥"，推荐基线仅闭合核心流程缺口，不代替用户决定。

## 4. 核心流程

### 4.1 访客登记流程

1. 访客打开微信小程序，进入访客登记页面
2. 系统尝试从微信获取手机号码；若获取失败，访客手工填写
3. 访客填写其余必填字段（身份证号、公司信息、人名、访问事由、被访人、预计到访时间）
4. 访客提交登记申请，系统将记录写入数据库，状态为"待审批"
5. 提交成功后，访客收到提交成功反馈

### 4.2 审批流程

1. 审批人员通过移动端审批系统进入
2. 系统展示待审批的访客申请列表
3. 审批人员查看访客详细信息
4. 审批人员操作"通过"或"驳回"，可填写审批意见
5. 审批结果写入数据库，访客申请状态更新为"已通过"或"已驳回"

### 4.3 状态流转

访客申请状态：`待审批` → `已通过` / `已驳回`

> 状态流转由用户描述的审批行为推导，用户未指定驳回后重新提交或超时自动处理等扩展流程，暂不规定。

## 5. 审批系统移动端适配

- 审批系统需适配移动端屏幕，在手机浏览器中可正常浏览和操作
- 审批列表、详情页、操作按钮在移动端布局下可用且不溢出

> 用户明确要求"审批系统要适配移动端"，此为产品入口约束，不指定具体前端框架。

## 6. 数据持久化

- 用户明确要求：访客信息需记录到数据库
- 访客登记提交成功后，数据可通过审批系统的列表和详情读取回
- 审批操作结果需持久化，重新打开审批系统后状态保持一致

## 7. 验收场景

### AC-01：访客可通过微信小程序提交访客登记申请

- 验收条件：访客在小程序中填写全部必填信息后提交，系统成功保存记录并返回提交成功反馈；手机号支持微信获取与手工填写两种路径。
- 入口类型：用户界面
- 验证动作：访客打开小程序登记页面，通过微信授权获取手机号（或获取失败时手工填写），填写身份证号、公司信息、人名、访问事由、被访人、预计到访时间，点击提交。
- 预期结果：系统提示提交成功；该访客记录在审批系统中可见，状态为"待审批"，各字段值与录入一致。
- 证据类型：interaction,session-persistence

### AC-02：审批人员可在移动端审核访客申请

- 验收条件：审批人员在移动端审批系统中对待审批申请执行通过或驳回操作，操作结果持久化保存。
- 入口类型：用户界面
- 验证动作：审批人员在手机浏览器中打开审批系统，查看待审批列表，进入一条申请详情，点击"通过"或"驳回"（可填写审批意见）。
- 预期结果：该申请状态更新为"已通过"或"已驳回"；刷新或重新打开审批系统后状态保持一致。
- 证据类型：interaction,session-persistence

### AC-03：审批系统在移动端布局下可用

- 验收条件：审批系统的列表、详情和操作页面在移动端屏幕下正常显示且可操作。
- 入口类型：用户界面
- 验证动作：在手机尺寸视口下打开审批系统的申请列表页和申请详情页。
- 预期结果：页面元素在移动端宽度下不溢出、不重叠，列表可滚动浏览，详情信息可查看，操作按钮可点击。
- 证据类型：runtime-render,visual-style
