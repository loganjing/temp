# 工单系统 需求文档（wi-t1000007）

标注说明：**用户明确提出**＝工单原文直接要求；**推荐基线**＝为闭合用户目标所必需的最小、可逆、可观察默认值，用户可随时纠正；**未规定**＝原文未说明且本次不推断，不构成验收条件。

## 1. 目标

为公司内部及跨部门的问题受理提供统一的工单系统（**用户明确提出**）：提交人以工单形式提出问题，系统按公司隔离数据；通过业务组配置与按分类自动分配完成工单派发；处理人在处理过程中可查看提交人完整背景、可转派协作，处理完成后记录处理结果并向提交人发送邮件通知；提交人可对处理结果进行满意度评价；管理者可通过工作台与统计仪表盘掌握工单量、响应时效、满意度与热点问题，并保留相关操作日志。

## 2. 操作者

| 操作者 | 能力 | 来源 |
| --- | --- | --- |
| 提交人 | 创建工单、查看本人公司的工单、多轮回复、取消工单、接收完成邮件通知、提交满意度评价 | 用户明确提出 |
| 处理人（业务组成员） | 查看待处理工单、查看提交人完整信息、回复、转派、处理完成 | 用户明确提出 |
| 业务组配置者 | 为公司配置多个业务组、设置业务组成员、维护"分类→业务组"的分配规则 | 用户明确提出能力；**该角色身份与授权方式未规定**，不作为验收条件 |

角色的具体权限模型（谁能取消、谁能转派给谁、配置入口由谁使用）**未规定**；本次验收只覆盖上表已列出的能力与公司隔离要求。

## 3. 端到端旅程

1. **受理**：提交人填写主题、描述、问题分类、SLA 优先级并提交 → 系统生成工单 ID、记录提交人信息（含邮箱）与创建时间，工单进入创建/待分配状态。
2. **派发**：系统按该公司的"分类→业务组"规则自动分配 → 命中规则则送达对应业务组并进入待处理；未命中则保持待分配，等待人工处理。已分配的工单可被转派。
3. **处理**：处理人在处理页面查看提交人完整信息（姓名、公司、部门、历史工单）与工单回复线程 → 回复、转派或完成；完成时记录处理人与处理时间。
4. **闭环**：工单完成后系统向提交人邮箱发送通知 → 提交人对本次处理结果提交满意度评价。
5. **运营观察**：管理者/支持人员在工单工作台查看与筛选待处理工单，在统计与分析仪表盘查看工单量、平均响应时间、满意度与热点问题；上述操作均写入日志。

## 4. 功能需求与业务规则

### 4.1 工单管理

- 工单包含：工单 ID、主题、描述、问题分类、SLA 优先级、提交人信息（姓名、邮箱、公司、部门）、创建时间（**用户明确提出**）。工单 ID 由系统生成并唯一；生成规则**未规定**。
- SLA 优先级取值为 P0–P4（**用户明确提出**）。
- 工单支持多轮回复；每轮回复记录回复人、回复时间与回复内容（**用户明确提出**）。
- 工单按公司隔离：工单及其回复、评价、日志仅在所属公司的可见范围内可查、可操作（**用户明确提出**）。跨公司可见范围（如平台级支持人员）**未规定**。
- 工单所属公司取自提交人所属公司（**推荐基线**，用于闭合"按公司隔离"与"按公司维度统计"）。

### 4.2 工单分配

- 允许为同一公司增加多个业务组，每个业务组可设置成员（**用户明确提出**）。一个业务组成员可属于多个业务组、工单可分配至业务组——**未规定**，不生成验收条件。
- 允许按"问题分类→业务组"的规则将本公司的工单自动分配到某个业务组（**用户明确提出**）。
- 自动分配在工单提交时触发；命中规则时工单进入待处理并归属该业务组；未命中规则时工单保持待分配（**推荐基线**，用于闭合未配置公司的可观察行为）。
- 分配结果（目标业务组、分配时间、分配方式：自动/人工）需可查看（**推荐基线**，用于验证"自动分配到某个业务组"这一结果）。

### 4.3 工单协作（转派）

- 处理人可将工单转派给同一公司范围内的其他业务组或成员，转派后由新的处理方继续处理（**用户明确提出**；转派的候选范围限制为同一公司属公司隔离的直接推论）。
- 每次转派记录转派人、转派时间与转派目标（**推荐基线**，用于验证转派已生效且可追溯）。

### 4.4 工单处理

- 处理工单时可查看提交人的完整信息：姓名、公司、部门、历史工单（**用户明确提出**）。
- 处理完成后记录处理人与处理时间（**用户明确提出**）。
- 工单完成时向提交人邮箱发送完成通知邮件（**用户明确提出**）。邮件服务与模板**未规定**；验收只要求"完成动作触发了面向提交人邮箱的通知发送"这一可观察结果。

### 4.5 用户评价

- 工单完成后，提交人可对本次处理结果提交满意度评价（**用户明确提出**）。
- 评价包含满意度评分，取值为 1–5，并记录评价人、评价时间与工单 ID（**推荐基线**，用于使"满意度"可统计、可观察）；是否允许文字评论**未规定**。
- 每张工单允许提交一次评价（**推荐基线**）。

### 4.6 统计分析

- 支持按公司、部门维度统计工单分布（**用户明确提出**：计数与分布）。
- 统计与分析仪表盘展示运营指标：工单量、平均响应时间、满意度、热点问题（**用户明确提出**）。
- 平均响应时间＝工单创建时间到首次处理方回复时间的时长均值；无处理方回复的工单不计入该均值（**推荐基线**，用于使该指标可计算、可核对）。
- 满意度＝已评价工单评分的平均值（**推荐基线**）。
- 热点问题＝按问题分类统计工单量并按数量排序取前列（**推荐基线**）。
- 统计范围遵循公司隔离；跨公司汇总**未规定**。

### 4.7 工单工作台

- 工作台展示待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选（**用户明确提出**）。
- 工作台待处理列表默认限定在当前操作者所属公司的可见范围内（**推荐基线**，用于与公司隔离一致）；跨公司查看能力**未规定**。
- 列表至少可按问题分类、SLA 优先级筛选，按创建时间排序（**推荐基线**，用于使筛选/排序可执行、可判断）。

### 4.8 操作日志

- 记录相关日志（**用户明确提出**）。
- 日志至少覆盖：工单创建、自动/人工分配、转派、回复、状态变更（含取消）、处理完成、评价提交，并记录操作类型、操作人、操作时间与工单 ID（**推荐基线**，用于使日志可核对）。
- 是否提供日志查看界面**未规定**；验收通过操作记录或日志存储核对。

## 5. 状态模型

状态集合：创建、待分配、待处理、完成、取消（**用户明确提出**）。

流转规则（**推荐基线**，用于闭合生命周期语义）：

| 流转 | 触发 |
| --- | --- |
| 创建 → 待分配 | 工单提交后进入分配流程 |
| 待分配 → 待处理 | 命中"分类→业务组"规则自动分配成功 |
| 待处理 → 待处理 | 转派给同一公司内的其他业务组或成员（状态不变，处理方变更） |
| 待处理 → 完成 | 处理人完成处理，并触发完成通知邮件 |
| 创建 / 待分配 / 待处理 → 取消 | 工单被取消 |
| 完成、取消 | 终态，不可再流转 |

不满足上述规则的流转（例如对已完成或被取消的工单再次回复、转派、完成或取消）应被拒绝并给出反馈（**推荐基线**）。

## 6. 非功能要求

- 邮件通知为外部依赖能力（**用户明确提出**），不指定邮件服务与技术选型。
- 其余非功能要求（性能、并发、可用性、部署方式）**未规定**，不生成验收条件。

## 7. 未规定事项（不参与验收）

- 技术选型、存储结构、部署形式、多端适配（Web/移动/桌面）。
- 角色权限模型细节、跨公司可见范围、配置入口的使用者与授权方式。
- 分类字典与 SLA 时限的具体清单、邮件模板内容、工单 ID 生成规则。
- 评价文字评论、统计的跨公司汇总、日志查看界面。

## 8. 验收场景

### AC-01：提交人可创建工单并在工单中读回完整信息
- 验收条件：提交人提交工单后，系统生成唯一工单 ID，并完整保存与展示主题、描述、问题分类、SLA 优先级（P0–P4）、提交人信息（姓名、邮箱、公司、部门）与创建时间。
- 入口类型：用户界面
- 验证动作：以提交人身份打开工单提交入口，填写主题、描述、问题分类并选择优先级 P2，提交；随后在工单列表和该工单详情中查看上述字段。
- 预期结果：工单创建成功并返回唯一工单 ID；详情中主题、描述、分类、优先级 P2、提交人姓名/邮箱/公司/部门、创建时间与提交内容一致且非空。
- 证据类型：runtime-render, interaction, session-persistence
- 共享流程组：G1（工单受理）

### AC-02：工单支持多轮回复并记录回复人与回复时间
- 验收条件：同一工单可进行多轮回复，每轮回复可读回回复人、回复时间与回复内容，并按时间顺序完整呈现。
- 入口类型：用户界面
- 验证动作：在 AC-01 的工单中由处理方连续回复两次，再由提交人回复一次；查看工单回复线程。
- 预期结果：三条回复按时间顺序全部显示，每条均带有正确的回复人身份与回复时间，无覆盖或丢失，重开该工单后仍可读回。
- 证据类型：interaction, session-persistence
- 共享流程组：G1（工单受理）

### AC-03：工单按公司隔离
- 验收条件：公司 A 的工单及其回复、评价、日志不出现在公司 B 的可见范围内，且公司 B 的操作者无法对该工单执行查看、回复、转派、完成、取消等操作。
- 入口类型：用户界面
- 验证动作：在公司 A 创建工单后，以公司 B 的操作者身份在工单列表、工作台与工单详情入口检索该工单，并尝试打开与操作。
- 预期结果：公司 B 的列表中不出现该工单；直接访问该工单时被拒绝或不可见，不返回其详情、回复或日志内容。
- 证据类型：authorization, runtime-render

### AC-04：工单生命周期状态按规则流转且非法流转被拒绝
- 验收条件：工单状态在 创建、待分配、待处理、完成、取消 之间按规则流转，完成与被取消为终态；不满足规则的流转被拒绝并给出反馈。
- 入口类型：用户界面
- 验证动作：提交一张未命中分配规则的工单，观察状态为待分配；为其配置分类分配规则后重新提交一张同类工单，观察状态；对该工单执行取消并尝试再次回复、转派与取消；另提交一张工单走完待处理到完成，再尝试回复与转派。
- 预期结果：未命中规则的工单为待分配；命中规则的工单为待处理；待处理工单可被取消；对已取消、已完成工单的回复/转派/完成/取消操作被拒绝并给出可见反馈，状态保持不变。
- 证据类型：interaction, error-feedback
- 共享流程组：G2（工单派发与处理）

### AC-05：可为公司配置多个业务组并设置成员
- 验收条件：同一公司下可新增多个业务组，每个业务组可设置一名以上成员，且配置结果可读回。
- 入口类型：用户界面
- 验证动作：在业务组配置入口为公司新增至少两个业务组，分别设置成员并保存；重新打开配置列表查看。
- 预期结果：两个业务组均存在并归属于该公司，各自显示已设置的全部成员；重开后配置仍可读回。
- 证据类型：interaction, session-persistence
- 共享流程组：G3（业务组与分配规则配置）

### AC-06：按问题分类自动分配工单到业务组
- 验收条件：为某公司配置"问题分类→业务组"规则后，该公司提交的该类工单在提交时自动分配到指定业务组并进入待处理；未配置规则的分类不自动分配。
- 入口类型：用户界面
- 验证动作：先配置"分类 X → 业务组 G1"规则，再以该公司提交人身份提交一张分类为 X 的工单，查看其分配结果与状态；随后提交一张分类为 Y（无规则）的工单并查看状态。
- 预期结果：分类 X 的工单归属业务组 G1、状态为待处理，且可读回分配时间与分配方式为自动；分类 Y 的工单未被分配、状态为待分配。
- 证据类型：interaction, runtime-render
- 共享流程组：G3（业务组与分配规则配置）

### AC-07：处理人可转派工单且转派可追溯
- 验收条件：处理人可将工单转派给同一公司范围内的其他业务组或成员，转派后由新处理方继续处理，并记录转派人、转派时间与转派目标。
- 入口类型：用户界面
- 验证动作：在待处理工单上执行转派，选择同一公司内的另一业务组或成员并确认；以新处理方身份查看该工单，并查看转派记录。
- 预期结果：工单处理方变更为所选目标，仍处于待处理状态；转派记录显示转派人、转派时间与目标；新处理方可对该工单回复与完成。
- 证据类型：interaction, session-persistence
- 共享流程组：G2（工单派发与处理）

### AC-08：处理工单时可查看提交人完整信息与历史工单
- 验收条件：处理人在处理工单的入口可查看提交人的姓名、公司、部门以及该提交人的历史工单。
- 入口类型：用户界面
- 验证动作：先以同一提交人身份创建两张工单，再以处理人身份打开其中一张的处理入口，查看提交人信息区与历史工单区。
- 预期结果：显示提交人姓名、公司、部门，且历史工单区列出该提交人在同一公司下的其他工单（含本张之外的工单），信息与实际数据一致。
- 证据类型：runtime-render, interaction
- 共享流程组：G2（工单派发与处理）

### AC-09：完成工单时记录处理人与处理时间并发送完成通知邮件
- 验收条件：处理人完成工单后，工单状态为完成，并记录处理人与处理时间；同时触发面向提交人邮箱的完成通知发送。
- 入口类型：用户界面
- 验证动作：以处理人身份完成一张待处理工单，查看工单详情中的处理人、处理时间与状态，并核对面向该提交人邮箱的通知发送结果。
- 预期结果：工单状态为完成，处理人为执行操作的处理人，处理时间为完成时刻且不早于创建时间；存在一条指向提交人邮箱的完成通知发送记录/结果。
- 证据类型：interaction, session-persistence, other
- 共享流程组：G2（工单派发与处理）

### AC-10：提交人可对已完成工单提交满意度评价
- 验收条件：工单完成后，提交人可提交 1–5 分的满意度评分，评价被保存并记录评价人、评价时间与工单 ID；未完成或被取消的工单不可评价，重复评价被拒绝。
- 入口类型：用户界面
- 验证动作：以提交人身份对已完成工单提交评分 5；重新打开该工单查看评价；对该工单再次提交评分；对一张未完成工单尝试提交评分。
- 预期结果：首次评分保存成功并可读回评分值、评价人与评价时间；重复评价被拒绝并给出反馈；未完成工单不提供或拒绝评价入口。
- 证据类型：interaction, error-feedback, session-persistence
- 共享流程组：G4（评价闭环）

### AC-11：可按公司、部门维度统计工单分布
- 验收条件：统计视图可按公司、部门维度给出工单数量分布，结果与实际工单数据一致。
- 入口类型：用户界面
- 验证动作：在已知数据的公司/部门下创建若干工单（含不同分类与优先级），打开按公司、按部门的工单分布统计并逐项核对数量。
- 预期结果：按公司维度与按部门维度的分布数量与已创建工单一致，切换维度后数值随之变化且不串数据。
- 证据类型：runtime-render, interaction
- 共享流程组：G5（统计与分析）

### AC-12：统计与分析仪表盘展示运营指标
- 验收条件：仪表盘展示工单量、平均响应时间、满意度、热点问题四类指标，取数口径与工单数据一致。
- 入口类型：用户界面
- 验证动作：构造已知样本（若干工单：其中部分有处理方回复且首条回复时间可确定，部分已评价，分类分布已知，另有已完成工单），打开统计与分析仪表盘，逐项核对工单量、平均响应时间、满意度、热点问题。
- 预期结果：工单量与样本总数一致；平均响应时间等于有处理方回复工单的创建到首次处理方回复时长均值（无处理方回复的工单不计入）；满意度等于已评价工单评分均值；热点问题按分类工单量降序取前列且与样本分布一致。
- 证据类型：runtime-render
- 共享流程组：G5（统计与分析）

### AC-13：工单工作台支持待处理列表与筛选、搜索、排序
- 验收条件：工作台展示待处理工单列表，支持关键字搜索、按问题分类与 SLA 优先级筛选、按创建时间排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：在存在多张不同分类、优先级、公司的待处理工单时打开工作台，依次：输入关键字搜索；按某一分类筛选；按优先级 P1 筛选；切换创建时间升序/降序；使用公司维度筛选条件。
- 预期结果：列表仅显示当前操作者可见范围内处于待处理的工单；每次筛选/搜索后的结果集合与条件一致；排序切换后顺序按创建时间相应变化；公司维度筛选对不同公司返回对应结果，不一致的工单不出现在结果中。
- 证据类型：runtime-render, interaction
- 共享流程组：G6（工作台）

### AC-14：关键操作产生可核对的操作日志
- 验收条件：工单创建、分配、转派、回复、状态变更（含取消）、处理完成、评价提交均产生日志记录，日志含操作类型、操作人、操作时间与工单 ID。
- 入口类型：内部
- 验证动作：对一张工单依次执行创建、自动分配、转派、回复、取消，对另一张工单执行创建、分配、回复、完成、评价，随后核对这两张工单的操作记录/日志。
- 预期结果：两类工单的每一项已执行操作均有对应日志条目，且操作类型、操作人、操作时间、工单 ID 与实际操作一致；未执行的操作没有日志条目。
- 证据类型：other
