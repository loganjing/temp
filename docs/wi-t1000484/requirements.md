# 工单系统需求文档

> Work Item: wi-t1000484 | Issue: T1000484 | 项目: jlg-ticket

## 1. 目标

构建一个工单管理系统，支持工单从创建、分配、处理到完成/取消的完整生命周期，涵盖多轮回复、SLA 优先级管理、按分类自动分配业务组、工单转派协作、提交人信息查看与处理记录、以及用户满意度评价等核心能力。

## 2. 角色与对象

| 角色 | 说明 |
|------|------|
| 提交人 | 创建工单的用户，提供姓名、邮箱、公司、部门等信息 |
| 处理人 | 业务组成员，接收并处理分配到本组的工单 |
| 管理员 | 配置公司业务组及成员、设置分类分配规则 |

> 角色名称用于描述职责边界，不指定权限模型或实现方式。

## 3. 核心流程

### 3.1 工单生命周期

工单从创建到终态经历以下状态：

```
创建 → 待分配 → 待处理 → 完成
                ↘ 取消（可从待分配/待处理状态取消）
```

- **创建**：提交人填写工单信息后提交，工单进入待分配状态。
- **待分配**：系统按分类规则自动分配到业务组，或由管理员手动分配；分配后进入待处理。
- **待处理**：业务组处理人接收工单并进行处理；处理完成后进入完成状态。
- **完成**：工单处理结束，等待用户评价。
- **取消**：提交人或管理员在待分配/待处理阶段取消工单，工单终止。

### 3.2 工单分配流程

1. 管理员为公司创建多个业务组，并为每个业务组设置成员。
2. 管理员配置公司的分类分配规则：将工单分类映射到业务组。
3. 工单创建后系统根据分类自动匹配规则，将工单分配到对应业务组。
4. 若无匹配规则，工单保持待分配状态等待手动分配。

### 3.3 工单处理流程

1. 处理人在待处理工单中查看提交人完整信息（姓名、公司、部门、历史工单）。
2. 处理人通过多轮回复与提交人沟通。
3. 处理人可将工单转派给其他业务组或处理人。
4. 处理完成后记录处理人、处理时间、工单状态。
5. 工单完成后，提交人收到通知并进行满意度评价。

## 4. 模块需求

### 4.1 工单管理

- **工单字段**（用户明确提出）：工单 ID、主题、描述、分类、提交人信息（含邮箱）、创建时间。
- **SLA 优先级**（用户明确提出）：支持 P0、P1、P2、P3、P4 五个优先级等级。
- **问题分类**（用户明确提出）：工单可按问题分类进行归类，分类用于自动分配匹配。
- **多轮回复**（用户明确提出）：工单支持多轮回复，每轮回复记录回复人和回复时间。
- **生命周期状态**（用户明确提出）：创建、待分配、待处理、完成、取消。

### 4.2 工单分配

- **业务组管理**（用户明确提出）：允许为某个公司增加多个业务组，每个业务组可以设置成员。
- **分类自动分配**（用户明确提出）：允许某个公司的工单按照分类自动分配到某个业务组。通过配置分类与业务组的映射规则实现。

### 4.3 工单协作

- **工单转派**（用户明确提出）：支持将工单转派给其他业务组或处理人，转派后工单仍处于待处理状态，由新接收方继续处理。

### 4.4 工单处理

- **提交人信息查看**（用户明确提出）：处理工单时可查看提交人的完整信息，包括姓名、公司、部门、历史工单。
- **处理记录**（用户明确提出）：处理工单后，记录处理人、处理时间、工单状态等信息。

### 4.5 用户评价

- **满意度评价**（用户明确提出）：工单完成后，用户收到工单可进行满意度评价。

## 5. 验收场景

### AC-01：提交人可创建工单并包含完整信息
- 验收条件：提交人能创建工单，工单包含工单 ID、主题、描述、分类、提交人信息（含邮箱）、创建时间、SLA 优先级和问题分类，创建后工单进入待分配状态。
- 入口类型：用户界面
- 验证动作：提交人填写工单主题、描述、分类、SLA 优先级等字段并提交工单。
- 预期结果：工单创建成功，可查看工单 ID、主题、描述、分类、提交人姓名与邮箱、创建时间、SLA 优先级和问题分类，工单状态为待分配。
- 证据类型：runtime-render, interaction

### AC-02：工单支持多轮回复
- 验收条件：工单支持多次回复，每轮回复记录回复人和回复时间，回复按时间顺序展示。
- 入口类型：用户界面
- 验证动作：在已创建的工单中添加多条回复。
- 预期结果：每条回复显示回复人、回复时间和回复内容，多条回复按时间顺序排列。
- 证据类型：runtime-render, interaction, session-persistence

### AC-03：工单按生命周期状态流转
- 验收条件：工单经历创建→待分配→待处理→完成的状态流转，并支持从待分配或待处理状态取消。
- 入口类型：用户界面
- 验证动作：创建工单后触发分配使工单进入待处理，处理完成后标记完成；在待分配或待处理状态下执行取消操作。
- 预期结果：工单状态依次经过待分配、待处理、完成；取消操作后工单状态变为取消，且已完成的工单不可再取消。
- 证据类型：runtime-render, interaction, session-persistence

### AC-04：可为公司创建多个业务组并设置成员
- 验收条件：管理员能为某个公司增加多个业务组，每个业务组可设置成员，成员信息可查看。
- 入口类型：用户界面
- 验证动作：管理员为公司创建多个业务组，为每个业务组添加成员。
- 预期结果：公司下显示多个业务组，每个业务组可查看其成员列表。
- 证据类型：runtime-render, interaction, session-persistence

### AC-05：工单按分类自动分配到业务组
- 验收条件：配置公司工单分类与业务组的映射规则后，新建工单根据分类自动分配到对应业务组，工单状态从待分配变为待处理。
- 入口类型：用户界面
- 验证动作：管理员配置分类到业务组的分配规则，提交人创建该分类的工单。
- 预期结果：工单创建后自动匹配规则并分配到对应业务组，工单状态变为待处理；未配置匹配规则的分类工单保持待分配状态。
- 证据类型：runtime-render, interaction, session-persistence

### AC-06：支持工单转派操作
- 验收条件：处理人可将待处理工单转派给其他业务组或处理人，转派后工单仍为待处理状态，新接收方可继续处理。
- 入口类型：用户界面
- 验证动作：在待处理工单中执行转派操作，选择目标业务组或处理人。
- 预期结果：工单转派成功，工单分配到新的业务组或处理人，状态保持待处理，新接收方可见该工单。
- 证据类型：runtime-render, interaction, session-persistence

### AC-07：处理工单时可查看提交人完整信息
- 验收条件：处理人在处理工单时，可查看提交人的完整信息，包括姓名、公司、部门和历史工单列表。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息区域。
- 预期结果：显示提交人姓名、公司、部门信息，以及该提交人的历史工单列表。
- 证据类型：runtime-render, interaction

### AC-08：工单处理后记录处理人和处理时间
- 验收条件：工单处理完成后，系统记录处理人、处理时间和工单最终状态。
- 入口类型：用户界面
- 验证动作：处理人完成工单处理并标记完成。
- 预期结果：工单记录处理人、处理时间和完成状态，信息可查看。
- 证据类型：runtime-render, interaction, session-persistence

### AC-09：工单完成后用户可进行满意度评价
- 验收条件：工单完成后，提交人收到工单并可进行满意度评价，评价结果可查看。
- 入口类型：用户界面
- 验证动作：提交人在已完成的工单上进行满意度评价。
- 预期结果：评价提交成功，满意度评价结果在工单中可查看。
- 证据类型：runtime-render, interaction, session-persistence
