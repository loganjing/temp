# 工单系统需求基线（135-ticket）

> 业务任务：135-ticket。本基线将用户提出的目标整理为可实施、可验收的产品需求。
> 标注约定：无标注 = 用户明确提出；【推荐】= 为闭合核心目标所补的保守默认，用户可调整；【未规定】= 用户未提出且本基线不擅自决定。

## 1. 目标概述

面向多公司环境提供工单服务：公司用户提交工单，工单按公司隔离；由各公司配置的业务组按问题分类自动接收，支持多轮回复、转派协作、处理完成与邮件通知、满意度评价；并提供待处理工单工作台与按公司/部门维度的统计分析仪表盘；全程记录操作日志。

## 2. 角色与参与方

| 角色 | 说明 | 来源 |
|---|---|---|
| 提交人 | 提交工单的公司用户，信息含姓名、邮箱、公司、部门；参与回复，收到完成通知后进行满意度评价 | 用户明确提出 |
| 处理人 | 业务组成员，处理分配到本组的工单；可回复、转派、完成工单 | 用户明确提出（业务组成员、处理人） |
| 公司配置管理员 | 为本公司维护业务组、成员与"分类→业务组"自动分配规则 | 【推荐】（用户未指定该配置操作者） |

处理端工作台与统计视图的使用者为处理人/运营侧，可跨公司查看待处理工单并按公司筛选（见第 5 节）。【推荐】

## 3. 核心对象与生命周期

### 3.1 工单
- 工单ID：系统生成的唯一标识。
- 主题、描述：文本。
- 问题分类：用于统计与自动分配。
- SLA 优先级：P0、P1、P2、P3、P4 五级；具体 SLA 时限与升级规则【未规定】。
- 提交人信息：姓名、邮箱、公司、部门。
- 创建时间。
- 处理信息：处理人、处理时间（完成处理时记录，见 4.5）。
- 所属公司：工单归属提交人所在公司，是数据隔离与统计维度的基础。【推荐】

### 3.2 工单生命周期
状态：已创建 → 待分配 → 待处理 → 已完成；待分配/待处理 → 已取消。
- 提交人创建工单后，工单进入待分配（"创建"对应提交动作及初始记录）。
- 工单分配到业务组后进入待处理。
- 处理人完成处理后进入已完成，同时发送邮件通知（见 4.5）。
- 完成前的工单可被取消，进入已取消【推荐：用户未规定允许取消的状态范围，取"完成前均可取消"的保守口径】。
- 已完成、已取消为终态；满意度评价仅在完成后进行（见 4.6）。

### 3.3 工单回复
- 工单支持多轮回复；每条回复记录回复内容、回复人、回复时间。
- 参与该工单沟通的提交人与处理方可回复。

### 3.4 业务组与分配规则
- 业务组隶属于某个公司，含组名称与成员列表。
- 自动分配规则：公司级"问题分类 → 业务组"映射。

### 3.5 满意度评价
- 工单完成后由提交人提交；评价结果与工单关联，纳入满意度统计。
- 评价形式【推荐】：评分档位（如 1-5 级），用户未规定具体形式。

### 3.6 操作日志
- 系统自动记录工单相关操作：操作类型、操作人、操作时间、关联工单。
- 覆盖范围【推荐】：创建、分配、转派、回复、完成、取消、评价（用户仅要求"记录相关日志"）。

## 4. 功能需求

### 4.1 工单创建
- 提交人填写主题、描述、问题分类、SLA 优先级（P0-P4）创建工单。
- 系统自动记录：工单ID、提交人信息（姓名、邮箱、公司、部门）、创建时间。
- 创建成功后工单进入待分配。
- 提交人邮箱用于接收完成通知邮件（见 4.5）。

### 4.2 工单回复
- 工单详情中可查看历史回复并新增回复。
- 每条回复显示回复人、回复时间，按时间排列，支持多轮。

### 4.3 工单分配
- 公司可增加多个业务组，并为每个业务组设置成员。
- 公司可配置"问题分类 → 业务组"的自动分配规则。
- 新工单按其问题分类自动分配到对应业务组，分配后进入待处理，该组成员可在工作台看到。
- 无匹配分类规则时【推荐】：工单保持待分配，等待人工处理（保守可逆）。

### 4.4 工单转派
- 处理人可将待处理工单转派给其他业务组【推荐：转派目标为业务组，与分配模型一致；用户未规定目标粒度】。
- 转派后工单仍为待处理，归属目标业务组；转派操作记入操作日志。

### 4.5 工单处理与完成通知
- 处理工单时，处理人可查看提交人完整信息：姓名、公司、部门、历史工单（该提交人过往提交的工单列表）。
- 完成处理时，系统记录处理人、处理时间；工单进入已完成。
- 工单完成时，向提交人邮箱发送完成通知邮件。邮件内容【推荐】：包含工单ID、主题与完成时间；用户未规定邮件内容。

### 4.6 用户满意度评价
- 工单完成后，提交人可对该工单进行满意度评价。
- "用户收到工单后"解读为：提交人收到完成通知（工单完成）后进行评价【推荐解读】。
- 评价结果与工单关联记录，作为满意度统计来源。

### 4.7 工单工作台
- 提供待处理工单列表视图，面向处理端。
- 支持筛选、搜索、排序：
  - 公司维度筛选（用户明确要求）。
  - 搜索字段【推荐】：工单ID、主题、提交人。
  - 排序字段【推荐】：创建时间、SLA 优先级。

### 4.8 统计分析与仪表盘
- 维度统计：按公司、按部门（提交人部门）统计工单分布。
- 运营指标仪表盘，至少包含：
  - 工单量：统计范围内工单数量。
  - 平均响应时间【推荐口径】：工单创建至处理端首次回复的时间均值。
  - 满意度【推荐口径】：已完成且已评价工单的满意度汇总（如平均评分）。
  - 热点问题【推荐口径】：按问题分类的工单量排名。
- 指标统计的时间范围【未规定】。

### 4.9 操作日志
- 工单相关关键操作发生时，系统自动记录日志（操作类型、操作人、操作时间、关联工单）。
- 日志用于运营审计与问题追溯。【推荐】

## 5. 数据隔离与权限

- 工单按公司隔离：提交人只能查看与操作本公司的工单及其回复、评价。
- 业务组与自动分配规则按公司维护，仅作用于本公司工单。
- 处理端工作台与统计视图汇聚多公司工单数据，通过公司维度筛选区分【推荐：该跨公司处理视图是"公司隔离"与"按公司筛选"并存的闭合解释】。

## 6. 推荐基线与未规定事项

| 事项 | 处理 | 说明 |
|---|---|---|
| 公司配置管理员角色 | 推荐 | 配置业务组/成员/分配规则的操作者 |
| 允许取消的状态范围 | 推荐 | 完成前均可取消 |
| 无匹配分配规则的兜底 | 推荐 | 保持待分配，等待人工处理 |
| 转派目标粒度 | 推荐 | 转派到业务组 |
| 满意度评价形式 | 推荐 | 评分档位 |
| 完成通知邮件内容 | 推荐 | 工单ID、主题、完成时间 |
| 响应时间/满意度/热点问题口径 | 推荐 | 见 4.8 |
| 工作台搜索/排序字段 | 推荐 | 见 4.7 |
| SLA 时限与升级规则 | 未规定 | 仅有 P0-P4 优先级分级 |
| 统计指标时间范围 | 未规定 | |
| 评价修改/撤销 | 未规定 | |

## 7. 验收场景

### AC-01：提交人可创建工单并完整记录信息
- 验收条件：提交人创建工单后，系统生成唯一工单ID，并记录主题、描述、问题分类、SLA 优先级（P0-P4）、提交人信息（姓名、邮箱、公司、部门）与创建时间，工单进入待分配。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份新建工单，填写主题、描述、分类并选择优先级 P1，提交后打开该工单详情。
- 预期结果：详情显示系统生成的工单ID、所填主题/描述/分类/优先级、提交人姓名、邮箱、公司、部门与创建时间，状态为待分配。
- 证据类型：runtime-render, interaction
- 共享流程组：工单全流程

### AC-02：工单支持多轮回复
- 验收条件：工单详情中的沟通支持多轮回复，每条回复记录回复人、回复时间并按时间排列。
- 入口类型：用户界面
- 验证动作：在已创建的工单中，由提交人和处理人先后各提交一条回复。
- 预期结果：工单详情显示两条回复，各自标明回复人与回复时间，按时间先后排列，且可继续追加回复。
- 证据类型：runtime-render, interaction
- 共享流程组：工单全流程

### AC-03：工单按公司隔离
- 验收条件：提交人只能查看本公司的工单，无法通过列表、搜索或详情访问其他公司的工单。
- 入口类型：用户界面
- 验证动作：公司B提交人创建一个工单；切换为公司A提交人身份，在工单列表与搜索中查找该工单并尝试直接访问。
- 预期结果：公司A的列表与搜索结果均不出现公司B的工单，直接访问不可见。
- 证据类型：authorization, runtime-render

### AC-04：工单生命周期状态正确流转
- 验收条件：工单随业务动作在 待分配 → 待处理 → 已完成 之间流转，并支持在完成前取消进入已取消。
- 入口类型：用户界面
- 验证动作：创建工单确认状态为待分配；自动分配后确认状态为待处理；完成处理后确认状态为已完成。另取一个待处理工单执行取消。
- 预期结果：各时点状态与动作一致；取消后工单为已取消，不再进入待处理/已完成。
- 证据类型：interaction, runtime-render
- 共享流程组：工单全流程

### AC-05：业务组配置与分类自动分配
- 验收条件：公司可维护多个业务组及成员，并配置"分类→业务组"规则；新工单按分类自动分配到对应业务组并进入待处理，该组成员可见。
- 入口类型：用户界面
- 验证动作：为公司A创建两个业务组并设置成员，配置"分类X→业务组G1"规则；以公司A提交人创建分类X的工单。
- 预期结果：工单自动分配至G1，状态为待处理；以G1成员身份在工作台可见该工单；G2成员不可见。
- 证据类型：interaction, runtime-render
- 共享流程组：工单全流程

### AC-06：工单转派
- 验收条件：待处理工单可转派到其他业务组，转派后由目标业务组处理，转派操作被记录。
- 入口类型：用户界面
- 验证动作：将待处理工单从业务组G1转派至G2。
- 预期结果：工单归属G2且状态仍为待处理，G2成员在工作台可见；操作日志含转派记录。
- 证据类型：interaction, runtime-render
- 共享流程组：工单全流程

### AC-07：工单处理、完成记录与邮件通知
- 验收条件：处理人处理工单时可查看提交人完整信息（姓名、公司、部门、历史工单）；完成时记录处理人与处理时间，并向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息区与历史工单列表后完成处理；检查提交人邮箱。
- 预期结果：处理页显示提交人姓名、公司、部门及历史工单；完成后工单状态为已完成，记录处理人、处理时间；提交人邮箱收到完成通知邮件。
- 证据类型：runtime-render, interaction, other
- 共享流程组：工单全流程

### AC-08：完成后满意度评价
- 验收条件：工单完成后，提交人可对该工单提交满意度评价，评价与工单关联记录。
- 入口类型：用户界面
- 验证动作：工单完成后，以提交人身份对该工单提交满意度评价。
- 预期结果：评价提交成功，工单上可查看该评价结果。
- 证据类型：interaction, runtime-render
- 共享流程组：工单全流程

### AC-09：统计分析与运营仪表盘
- 验收条件：统计支持按公司、部门维度查看工单分布；仪表盘展示工单量、平均响应时间、满意度、热点问题指标。
- 入口类型：用户界面
- 验证动作：准备跨公司、跨部门的多条工单数据（含已完成与已评价），打开统计与仪表盘视图。
- 预期结果：可按公司维度与部门维度查看工单分布；仪表盘显示工单量、平均响应时间、满意度、热点问题四项指标，数值与准备的数据一致。
- 证据类型：runtime-render

### AC-10：待处理工单工作台
- 验收条件：工作台展示待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：准备多个公司、不同状态的工单；在工作台分别使用公司筛选、关键字搜索与排序。
- 预期结果：列表默认为待处理工单；公司筛选后仅显示所选公司的待处理工单；搜索命中目标工单；排序按所选字段生效；非待处理状态工单不出现在列表。
- 证据类型：runtime-render, interaction

### AC-11：工单操作日志记录
- 验收条件：工单关键操作发生时，系统自动记录含操作类型、操作人、操作时间、关联工单的日志。
- 入口类型：内部
- 验证动作：依次执行创建、自动分配、转派、回复、完成操作，随后检索这些工单的操作日志记录。
- 预期结果：日志包含上述每一步操作，记录操作类型、操作人、操作时间与关联工单。
