# k06-robot 设备管理平台需求

## 1. 目标

为机器人设备建立管理平台，覆盖设备状态监测、故障诊断、远程升级、维修工单和设备履历五个功能模块。用户明确提出所有设备相关数据需要数据库存储。

- **项目名称**：jlgrobot
- **需求来源**：用户明确提出设备状态监测、故障诊断、远程升级、维修工单、设备履历功能及数据库存储约束。

## 2. 功能模块

### 2.1 设备状态监测

用户可查看机器人设备的当前运行状态。

**行为与规则**：

- 系统记录每台设备的当前状态（用户明确提出）。
- 用户可查看设备列表及各设备当前状态（用户明确提出）。
- 状态数据须持久化存储，系统重启后可读取（用户明确提出数据库存储约束）。

**未规定**：

- 具体状态类型（如在线/离线、运行/待机/故障等）未明确。
- 状态更新方式（设备自动上报或人工录入）未明确。

### 2.2 故障诊断

用户可对设备记录和查看故障诊断信息。

**行为与规则**：

- 系统支持记录设备的故障信息及诊断结果（用户明确提出）。
- 用户可查看设备的故障诊断记录（用户明确提出）。
- 故障诊断数据须持久化存储（用户明确提出数据库存储约束）。

**未规定**：

- 诊断方式（自动诊断或人工录入诊断结论）未明确。
- 故障分级标准未明确。

### 2.3 远程升级

用户可对机器人设备发起远程软件或固件升级。

**行为与规则**：

- 系统支持向指定设备发起远程升级操作（用户明确提出）。
- 升级过程和结果须记录并持久化存储（用户明确提出数据库存储约束）。

**未规定**：

- 升级包格式和来源未明确。
- 升级失败后的回滚策略未明确。

### 2.4 维修工单

用户可创建和管理设备维修工单。

**行为与规则**：

- 用户可创建维修工单并关联指定设备（用户明确提出）。
- 工单记录维修内容和处理结果（用户明确提出）。
- 工单数据须持久化存储（用户明确提出数据库存储约束）。

**未规定**：

- 工单状态流转规则（如待处理→处理中→已完成）未明确。
- 工单分配和审批流程未明确。

### 2.5 设备履历

用户可查看设备的完整履历记录。

**行为与规则**：

- 系统汇总设备的历史记录，包括状态变更、故障诊断、升级记录和维修工单（用户明确提出）。
- 用户可按设备查看其完整履历（用户明确提出）。
- 履历数据须持久化存储（用户明确提出数据库存储约束）。

**未规定**：

- 履历记录的保留期限未明确。
- 履历导出格式未明确。

## 3. 数据存储约束

用户明确提出需要数据库存储。所有设备状态、故障诊断、升级记录、维修工单和设备履历数据须写入数据库，系统重启后可通过相应读取行为读回。

- **用户明确提出**：需要数据库存储。
- **未规定**：具体数据库技术选型未指定。

## 4. 验收场景

### AC-01：设备状态监测与持久化

- 验收条件：用户可查看设备列表及各设备当前状态，状态数据持久化存储，重启后可读回。
- 入口类型：用户界面
- 验证动作：查看设备状态列表；重启系统后再次查看。
- 预期结果：设备列表显示各设备当前状态；重启后状态数据仍可读取。
- 证据类型：runtime-render, session-persistence

### AC-02：故障诊断记录与持久化

- 验收条件：用户可记录和查看设备故障诊断信息，数据持久化存储，重启后可读回。
- 入口类型：用户界面
- 验证动作：录入一条设备故障诊断记录；重启系统后查看该记录。
- 预期结果：故障诊断记录成功保存并可在设备下查看；重启后记录仍存在。
- 证据类型：runtime-render, session-persistence

### AC-03：远程升级与结果持久化

- 验收条件：用户可对设备发起远程升级，升级结果记录持久化存储，重启后可读回。
- 入口类型：用户界面
- 验证动作：对一台设备发起远程升级，查看升级结果记录；重启系统后再次查看。
- 预期结果：升级操作及结果记录保存；重启后升级记录仍可读取。
- 证据类型：runtime-render, session-persistence

### AC-04：维修工单创建与持久化

- 验收条件：用户可创建维修工单并关联设备，工单数据持久化存储，重启后可读回。
- 入口类型：用户界面
- 验证动作：创建一条维修工单并关联指定设备；重启系统后查看该工单。
- 预期结果：工单成功创建并关联设备；重启后工单数据仍可读取。
- 证据类型：runtime-render, session-persistence

### AC-05：设备履历汇总与持久化

- 验收条件：用户可查看设备完整履历，履历汇总各模块历史记录并持久化存储，重启后可读回。
- 入口类型：用户界面
- 验证动作：在一台设备上产生状态记录、故障诊断、升级记录和维修工单后，查看该设备履历；重启系统后再次查看。
- 预期结果：设备履历汇总显示该设备的状态、故障、升级和工单记录；重启后履历数据仍可读取。
- 证据类型：runtime-render, session-persistence
