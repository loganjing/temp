# 工单系统需求文档

> WorkItem: wi-t1000077 | 标题: 221-ticket

## 1. 目标

构建一个面向多公司的工单系统，支持工单的全生命周期管理、按业务组自动分配、协作转派、处理与通知、用户满意度评价，以及运营统计分析。

## 2. 用户角色

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单并跟踪处理进度，完成后可评价 | 用户明确提出 |
| 处理人 | 业务组成员，接收并处理工单，记录处理结果 | 用户明确提出 |
| 管理员 | 管理公司业务组与成员配置、分类分配规则 | 用户明确提出（业务组管理隐含） |

## 3. 核心实体与状态

### 3.1 工单

工单包含以下属性（用户明确提出）：

- 工单ID：唯一标识
- 主题、描述
- 分类（问题分类）
- 提交人信息：姓名、公司、部门、邮箱
- 创建时间
- SLA 优先级：P0、P1、P2、P3、P4（用户明确提出）
- 当前状态
- 所属业务组（分配后）

### 3.2 工单回复

- 支持多轮回复（用户明确提出）
- 每条回复记录：回复人、回复内容、回复时间（用户明确提出）

### 3.3 工单生命周期

用户明确提出以下状态（用户明确提出）：

```
创建 → 待分配 → 待处理 → 完成
                                   ↘ 取消
```

| 状态 | 含义 | 转移触发 |
|------|------|----------|
| 创建 | 工单刚提交，尚未分配 | 提交人创建工单 |
| 待分配 | 等待分配到业务组 | 创建后进入；或转派后回到此状态（推荐基线） |
| 待处理 | 已分配业务组，等待/正在处理 | 分配到业务组后进入 |
| 完成 | 工单已处理完毕 | 处理人标记完成 |
| 取消 | 工单被取消 | 提交人或处理人取消 |

> **推荐基线**：转派操作后工单回到"待分配"状态，由新业务组重新分配处理人。此为保守可逆的处理方式，可由用户调整。

### 3.4 公司与业务组

- 工单按公司隔离（用户明确提出）
- 一个公司可配置多个业务组，每个业务组可设置成员（用户明确提出）
- 可配置分类与业务组的映射规则，实现工单按分类自动分配到对应业务组（用户明确提出）

### 3.5 工单处理记录

- 处理工单后记录：处理人、处理时间（用户明确提出）
- 工单完成时发送邮件通知提交人（用户明确提出）

### 3.6 用户评价

- 工单完成后，提交人可进行满意度评价（用户明确提出）

### 3.7 操作日志

- 记录工单相关操作日志（用户明确提出）
- 覆盖范围：工单创建、分配、转派、处理、完成、取消、评价等关键操作（推荐基线）

## 4. 功能模块

### 4.1 工单管理

- 创建工单：填写主题、描述、分类、SLA 优先级，自动记录提交人信息（含邮箱）和创建时间（用户明确提出）
- 查看工单：查看工单详情、多轮回复列表（用户明确提出）
- 回复工单：提交人和处理人均可回复，记录回复人和回复时间（用户明确提出）
- 取消工单：可取消未完成的工单（用户明确提出）
- 公司隔离：工单数据按公司隔离，不跨公司可见（用户明确提出）

### 4.2 工单分配

- **业务组管理**：为某个公司增加多个业务组，为每个业务组设置成员（用户明确提出）
- **自动分配规则**：配置某个公司的"分类 → 业务组"映射规则，工单创建后按分类自动分配到对应业务组（用户明确提出）
- 分配后工单状态从"待分配"变为"待处理"（推荐基线）

### 4.3 工单协作（转派）

- 支持工单转派到其他业务组或处理人（用户明确提出）
- 转派后工单状态回到"待分配"（推荐基线）
- 转派操作记录在日志中（推荐基线）

### 4.4 工单处理

- **查看提交人信息**：处理工单时可查看提交人完整信息，包括姓名、公司、部门、历史工单列表（用户明确提出）
- **记录处理结果**：处理完成后记录处理人、处理时间（用户明确提出）
- **完成通知**：工单完成时发送邮件通知提交人（用户明确提出）

### 4.5 用户评价

- 工单完成后，提交人收到工单可进行满意度评价（用户明确提出）
- 评价结果纳入统计指标（推荐基线）

### 4.6 工单工作台

- 查看待处理工单列表（用户明确提出）
- 支持筛选：按公司维度筛选（用户明确提出）
- 支持搜索：按关键词搜索工单（用户明确提出）
- 支持排序：按工单字段排序（用户明确提出）

### 4.7 统计分析

- **工单分布统计**：按公司、部门维度统计工单分布（用户明确提出）
- **运营仪表盘**：查看以下运营指标（用户明确提出）：
  - 工单量
  - 平均响应时间
  - 满意度
  - 热点问题（按分类聚合的高频问题）

### 4.8 操作日志

- 记录工单生命周期中的关键操作日志（用户明确提出）
- 日志可查询（推荐基线）

## 5. 验收场景

### AC-01：提交人创建工单并按分类自动分配到业务组

- 验收条件：提交人创建工单后，工单按预设的分类规则自动分配到对应业务组，状态变为待处理。
- 入口类型：用户界面
- 验证动作：提交人在工单创建页面填写主题、描述、分类、SLA 优先级并提交。
- 预期结果：工单创建成功，自动记录提交人信息（含邮箱）和创建时间；按分类映射规则分配到对应业务组；工单状态为待处理；分配操作记入日志。
- 证据类型：interaction, session-persistence

### AC-02：处理人查看提交人完整信息并处理工单

- 验收条件：处理人在处理工单时可查看提交人的完整信息（姓名、公司、部门、历史工单），完成后记录处理人和处理时间并发送邮件通知。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息面板，执行处理并标记完成。
- 预期结果：提交人信息面板显示姓名、公司、部门和历史工单列表；工单状态变为完成；记录处理人和处理时间；提交人邮箱收到完成通知邮件。
- 证据类型：interaction, session-persistence

### AC-03：工单多轮回复

- 验收条件：提交人和处理人可对同一工单进行多轮回复，每条回复记录回复人和回复时间。
- 入口类型：用户界面
- 验证动作：在工单详情页中，提交人和处理人交替添加多条回复。
- 预期结果：回复列表按时间排列显示所有回复，每条回复包含回复人、回复内容和回复时间。
- 证据类型：interaction, session-persistence

### AC-04：工单按公司隔离

- 验收条件：不同公司的工单数据互不可见，工单工作台和统计均按公司隔离。
- 入口类型：用户界面
- 验证动作：使用 A 公司用户查看工单工作台和工单列表，确认看不到 B 公司的工单。
- 预期结果：工单列表仅显示当前用户所属公司的工单；统计仪表盘仅统计当前公司数据。
- 证据类型：authorization, session-persistence

### AC-05：业务组管理与分类自动分配规则配置

- 验收条件：管理员可为公司配置多个业务组及其成员，并设置分类与业务组的映射规则。
- 入口类型：用户界面
- 验证动作：管理员进入业务组管理页面，创建业务组、添加成员，然后配置分类到业务组的映射规则。
- 预期结果：业务组和成员保存成功；分类映射规则保存成功；新创建的工单按分类自动分配到对应业务组。
- 证据类型：interaction, session-persistence

### AC-06：工单转派

- 验收条件：处理人可将工单转派到其他业务组，转派后工单回到待分配状态。
- 入口类型：用户界面
- 验证动作：处理人在待处理工单上执行转派操作，选择目标业务组。
- 预期结果：工单转派成功，状态变为待分配，归属变更到目标业务组；转派操作记入日志。
- 证据类型：interaction, session-persistence

### AC-07：工单取消

- 验收条件：未完成的工单可被取消，状态变为取消。
- 入口类型：用户界面
- 验证动作：在待分配或待处理状态的工单上执行取消操作。
- 预期结果：工单状态变为取消；取消操作记入日志。
- 证据类型：interaction, session-persistence

### AC-08：用户满意度评价

- 验收条件：工单完成后，提交人可对工单进行满意度评价。
- 入口类型：用户界面
- 验证动作：提交人在已完成的工单上进行满意度评价。
- 预期结果：评价提交成功并记录；评价结果可在统计仪表盘中查看。
- 证据类型：interaction, session-persistence

### AC-09：工单工作台筛选、搜索、排序

- 验收条件：工单工作台支持按公司筛选、关键词搜索和字段排序查看待处理工单列表。
- 入口类型：用户界面
- 验证动作：在工单工作台中使用公司筛选、输入关键词搜索、点击列头排序。
- 预期结果：工单列表根据筛选、搜索、排序条件实时刷新，仅显示符合条件的待处理工单。
- 证据类型：interaction, session-persistence

### AC-10：统计分析仪表盘

- 验收条件：统计仪表盘展示工单量、平均响应时间、满意度和热点问题等运营指标，支持按公司、部门维度统计工单分布。
- 入口类型：用户界面
- 验证动作：进入统计分析仪表盘页面，切换公司、部门维度查看统计。
- 预期结果：仪表盘展示工单量、平均响应时间、满意度指标和热点问题（按分类聚合）；工单分布可按公司、部门维度统计。
- 证据类型：interaction, session-persistence

### AC-11：操作日志记录

- 验收条件：工单生命周期中的关键操作（创建、分配、转派、处理、完成、取消、评价）均有日志记录。
- 入口类型：内部
- 验证动作：执行工单创建、分配、转派、处理、完成、取消、评价等操作后，查询操作日志。
- 预期结果：每项关键操作在日志中均有记录，包含操作类型、关联工单、操作人、操作时间。
- 证据类型：session-persistence
