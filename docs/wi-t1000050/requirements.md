# 工单系统需求文档

## 1. 目标

构建一个按公司隔离的工单管理系统，支持工单全生命周期管理（创建、待分配、待处理、完成、取消）、基于分类的自动分配、工单转派协作、提交人信息查看、完成邮件通知、满意度评价、统计分析仪表盘和工单工作台。

## 2. 角色与权限

| 角色 | 说明 |
|------|------|
| 提交人 | 创建工单、回复工单、收到完成后进行满意度评价 |
| 管理员 | 配置公司业务组及成员、配置分类自动分配规则 |
| 处理人 | 被分配到业务组的成员，处理工单、回复工单、转派工单 |

> 角色划分由用户明确提出；具体权限模型（RBAC 细粒度）未规定，保持未规定。

## 3. 实体与状态

### 3.1 工单属性

- 工单 ID：唯一标识
- 主题
- 描述
- 分类（问题分类）
- SLA 优先级：P0 / P1 / P2 / P3 / P4
- 提交人信息：姓名、公司、部门、邮箱
- 创建时间
- 当前状态：创建 → 待分配 → 待处理 → 完成 / 取消
- 处理人：记录最终处理人
- 处理时间：记录处理完成时间
- 满意度评价：完成后由提交人填写

### 3.2 工单回复

- 每条回复记录：回复人、回复内容、回复时间
- 工单支持多轮回复

### 3.3 公司与业务组

- 公司：工单按公司隔离，工单只能被同公司用户可见和处理
- 业务组：一个公司可拥有多个业务组，每个业务组可设置成员
- 分类自动分配规则：按工单分类将工单自动分配到对应业务组

### 3.4 操作日志

- 系统记录关键操作日志，包括工单创建、分配、转派、状态变更、处理完成等操作

## 4. 生命周期

```
创建 → 待分配 → 待处理 → 完成
                  ↘ 取消
```

- **创建**：提交人创建工单，初始状态为创建
- **待分配**：工单进入待分配状态，按分类自动分配规则匹配业务组；若无匹配规则，由管理员手动分配
- **待处理**：工单分配到业务组后进入待处理，处理人可查看、回复、转派或处理完成
- **完成**：处理人标记完成，记录处理人和处理时间，发送邮件通知提交人
- **取消**：工单可被取消，终止流程

## 5. 功能需求

### 5.1 工单管理

- 工单创建时必填：主题、描述、分类、SLA 优先级；提交人信息从当前登录用户获取（含邮箱）
- 工单支持多轮回复，每轮回复记录回复人和回复时间
- 工单按公司隔离：用户只能查看和处理本公司工单
- 工单可设置 SLA 优先级 P0-P4 和问题分类

### 5.2 工单分配

- 管理员可给公司增加多个业务组，每个业务组可设置成员
- 管理员可配置"分类 → 业务组"自动分配规则
- 工单创建后按分类自动匹配规则并分配到对应业务组
- 无匹配规则时工单保持待分配，等待手动分配

### 5.3 工单协作

- 处理人可将工单转派给同公司其他业务组或处理人
- 转派操作记录在操作日志中

### 5.4 工单处理

- 处理工单时，处理人可查看提交人完整信息：姓名、公司、部门、历史工单列表
- 处理完成后记录处理人和处理时间
- 工单完成后向提交人邮箱发送邮件通知

### 5.5 用户评价

- 工单完成后，提交人收到通知后可对工单进行满意度评价
- 满意度评价为一次性提交，提交后不可修改

### 5.6 统计分析

- 支持按公司维度统计工单分布
- 支持按部门维度统计工单分布
- 仪表盘展示：工单量、平均响应时间、满意度、热点问题（按分类统计工单量排序）

### 5.7 工单工作台

- 查看待处理工单列表
- 支持按主题/工单 ID 搜索
- 支持按状态、分类、SLA 优先级筛选
- 支持按创建时间、SLA 优先级排序
- 支持按公司维度筛选

### 5.8 操作日志

- 记录工单生命周期关键操作：创建、分配、转派、状态变更、完成
- 每条日志包含操作人、操作时间、操作类型、工单 ID

## 6. 验收场景

### AC-01：提交人创建工单并按分类自动分配

- 验收条件：提交人创建工单后，系统按工单分类自动分配到对应业务组，工单进入待处理状态，同公司用户可查看该工单。
- 入口类型：用户界面
- 验证动作：提交人填写主题、描述、分类和 SLA 优先级后提交工单。
- 预期结果：工单创建成功，状态从创建流转到待处理（经待分配自动分配），工单出现在被分配业务组成员的待处理列表中；本公司以外用户不可见该工单。
- 证据类型：runtime-render, interaction, authorization

### AC-02：工单多轮回复

- 验收条件：工单创建后，提交人和处理人可对工单进行多轮回复，每条回复记录回复人和回复时间。
- 入口类型：用户界面
- 验证动作：在工单详情中，不同用户依次添加回复。
- 预期结果：所有回复按时间顺序展示，每条回复显示回复人姓名和回复时间。
- 证据类型：runtime-render, interaction, session-persistence

### AC-03：管理员配置业务组与自动分配规则

- 验收条件：管理员可为公司添加多个业务组并设置成员，配置"分类→业务组"自动分配规则后，新建工单按分类自动分配到对应业务组。
- 入口类型：用户界面
- 验证动作：管理员添加业务组并设置成员，配置分类自动分配规则，提交人创建对应分类工单。
- 预期结果：工单自动分配到规则配置的业务组，该业务组成员可在待处理列表中看到工单；未配置规则的分类，工单保持待分配状态。
- 证据类型：runtime-render, interaction, session-persistence

### AC-04：工单转派

- 验收条件：处理人可将工单转派给同公司其他业务组或处理人，转派记录在操作日志中，工单仍处于待处理状态。
- 入口类型：用户界面
- 验证动作：处理人在工单详情中选择转派操作，选择目标业务组或处理人并确认。
- 预期结果：工单被分配到新目标，原处理人不再在待处理列表中看到该工单，新目标处理人可看到；操作日志记录转派人、目标和时间。
- 证据类型：runtime-render, interaction, session-persistence

### AC-05：查看提交人完整信息

- 验收条件：处理人在处理工单时可查看提交人完整信息，包括姓名、公司、部门和历史工单列表。
- 入口类型：用户界面
- 验证动作：处理人打开工单详情，查看提交人信息区域。
- 预期结果：页面显示提交人姓名、公司、部门，以及该提交人的历史工单列表（含工单 ID、主题、状态）。
- 证据类型：runtime-render, interaction

### AC-06：工单完成并发送邮件通知

- 验收条件：处理人将工单标记为完成后，系统记录处理人和处理时间，向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：处理人在工单详情中选择完成操作并确认。
- 预期结果：工单状态变为完成，记录处理人姓名和处理时间；提交人邮箱收到包含工单信息的完成通知邮件。
- 证据类型：runtime-render, interaction, session-persistence

### AC-07：用户满意度评价

- 验收条件：工单完成后，提交人可对工单进行满意度评价，评价提交后不可修改。
- 入口类型：用户界面
- 验证动作：提交人在已完成工单详情中选择满意度评分并提交。
- 预期结果：评价保存成功，工单详情展示已评价的满意度结果；再次提交评价被拒绝。
- 证据类型：runtime-render, interaction, session-persistence

### AC-08：工单取消

- 验收条件：工单可被取消，取消后工单状态为取消，不再进入处理流程。
- 入口类型：用户界面
- 验证动作：对处于待分配或待处理状态的工单执行取消操作。
- 预期结果：工单状态变为取消，不出现在待处理列表中；操作日志记录取消操作。
- 证据类型：runtime-render, interaction, session-persistence

### AC-09：统计仪表盘

- 验收条件：仪表盘展示工单量、平均响应时间、满意度和热点问题（按分类统计工单量排序），支持按公司维度筛选。
- 入口类型：用户界面
- 验证动作：打开统计仪表盘，切换公司筛选条件。
- 预期结果：页面显示当前筛选范围内的工单总量、平均响应时间、满意度（平均评分），以及热点问题列表（按分类工单量降序）；切换公司后数据对应更新。
- 证据类型：runtime-render, interaction

### AC-10：按公司和部门维度统计工单分布

- 验收条件：支持按公司和部门维度统计工单分布，展示各维度下的工单数量。
- 入口类型：用户界面
- 验证动作：在统计页面选择公司或部门维度查看工单分布。
- 预期结果：页面按所选维度展示工单数量分布，不同公司/部门的工单数量与实际数据一致。
- 证据类型：runtime-render, interaction

### AC-11：工单工作台筛选搜索排序

- 验收条件：工单工作台展示待处理工单列表，支持搜索、筛选、排序和按公司维度筛选。
- 入口类型：用户界面
- 验证动作：在工作台输入搜索关键词、选择筛选条件（状态、分类、SLA 优先级、公司）、切换排序方式。
- 预期结果：列表按筛选条件和排序方式更新，仅显示符合条件且当前用户有权限查看的工单。
- 证据类型：runtime-render, interaction

### AC-12：操作日志记录

- 验收条件：系统记录工单生命周期关键操作（创建、分配、转派、状态变更、完成、取消），每条日志包含操作人、操作时间、操作类型和工单 ID。
- 入口类型：内部
- 验证动作：执行工单创建、分配、转派、完成等操作后查看操作日志。
- 预期结果：日志中包含每次操作的完整记录，操作人、操作时间、操作类型和工单 ID 字段齐全。
- 证据类型：session-persistence
