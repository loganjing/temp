# 会话流程轨迹可视化 — 实现报告

## 1. 变更概述

本次实现新建了一个 React + Vite 单页应用，提供会话流程轨迹可视化功能。用户打开页面后，可看到一条自上而下的纵向时间线，按发生顺序完整呈现一次会话的全部步骤，无需展开即可在概览层面理解整条执行流程。

实现依据：`docs/wi-t1000073/requirements.md`（已批准需求）与 `docs/wi-t1000073/architecture-baseline.md`（已批准架构基线）。

## 3. 需求实现映射

### AC-01：完整轨迹按发生顺序呈现
- 全部 8 个步骤在同一视图中纵向排列，编号由数组顺序派生（1~8），连续无跳号。
- 首步为用户输入，末步为模型最终回复；中间步骤为模型回复与工具调用交替。
- 轨迹超出视口时纵向滚动，仍属同一视图。

### AC-02：每个步骤直接看懂"做了什么"
- 每个步骤条目包含：步骤编号（"第 N 步"）、类型标识（蓝色"用户输入" / 紫色"模型回复" / 橙色"工具调用"）、一句话动作摘要。
- 用户输入步骤显示输入内容要点；模型回复步骤显示返回内容要点（最终回复为终点）；工具调用步骤显示工具名称（等宽字体标签）。

### AC-03：顺序与衔接关系清晰
- 相邻步骤之间由纵向时间线连接，形成"上一步 → 下一步"的视觉衔接。
- 起点（用户输入）左侧蓝色边框 + "起点"标签；终点（模型最终回复）左侧紫色边框 + "终点"标签；中间步骤视觉权重一致。

### AC-04：概览保持粗粒度
- 默认状态即为完整概览，不存在"点击展开"的信息层级。
- 长文本内容通过 `-webkit-line-clamp` 收敛为两行可读摘要，保留可辨识要点。
- 不提供下钻、原始报文或日志视图。

## 4. 示例数据集

会话共 8 步，满足"不少于 5 个中间步骤，含至少 1 次工具调用"的基线要求：

| 步 | 类型 | 摘要 |
|----|------|------|
| 1 | 用户输入 | 用户请求分析季度销售数据并生成报告 |
| 2 | 模型回复 | 模型确认任务并规划执行步骤 |
| 3 | 工具调用 | 查询数据库中的季度销售记录 (`querySalesDatabase`) |
| 4 | 模型回复 | 确认数据已获取，准备进行趋势分析 |
| 5 | 工具调用 | 对销售数据进行多维度趋势分析 (`analyzeDataTrends`) |
| 6 | 模型回复 | 分析完成，准备生成可视化报告 |
| 7 | 工具调用 | 生成包含图表的可视化报告 (`generateReport`) |
| 8 | 模型回复 | 汇总分析结果并输出最终报告 |

## 5. 数据边界校验

`sessionRepository.js` 在数据装载处进行一次性校验：
- 首步必须为 `user` 类型
- 末步必须为 `model` 类型
- 工具调用步骤必须带 `toolName`
- 类型必须为 `user` / `model` / `tool` 之一
- 编号由数组顺序派生，渲染层不做兜底推断

## 8. 遗留与边界

- 本功能使用内置示例数据集，不涉及真实会话数据源接入（需求第 4 节排除）。
- 不含单步详情下钻、导出、分享、多会话对比（需求第 5 节排除）。
- 浏览器界面验收（视觉渲染、滚动、交互）由 QA 阶段执行。
