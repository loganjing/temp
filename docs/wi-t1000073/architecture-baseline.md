# 会话流程轨迹可视化 — 架构基线

需求来源：`docs/wi-t1000073/requirements.md`（已批准基线，sha256:3c35460f…672bc）。本文件只说明技术承载方式，不新增或改写产品语义。

## 1. 路线选择

- 应用类型：`simple-frontend`（紧凑路线）。
- 依据：验收全部落在界面渲染与浏览交互；需求第 4 节不要求真实会话数据源接入，第 5 节排除详情下钻、原始报文与日志；无服务端权威数据、认证、后台任务或跨用户共享要求。
- 形式：React + Vite 单页应用（SPA），纯客户端运行，无服务端、无数据库、无认证、无外部集成。

## 2. 页面与交互范围

单一视图「会话轨迹」承载全部内容：

- **纵向时间线**：一条会话对应一条自上而下的轨迹，步骤按发生顺序排列。选择纵向而非横向，是因为步骤数量可变（含第 2 至第 6 步等中间步骤），纵向排列在窄屏与长文本摘要下更易逐条通读，且天然形成"上一步 → 下一步"的阅读方向。
- **步骤条目（粗粒度、结构一致）**：每条包含步骤编号、类型标识（用户输入 / 模型回复 / 工具调用）、一句话动作摘要；工具调用步骤显示工具名称，用户输入与模型最终回复显示可辨识的要点内容。条目默认呈现即为完整概览，不存在"点击展开才可见"的信息层级。
- **首尾区分**：起点（用户输入）与终点（模型最终回复）使用与中间步骤不同的视觉处理（如强调色边框与位置标识），中间步骤视觉权重一致，以体现"起 → 中段交替 → 终"的结构。
- **衔接指示**：相邻步骤之间以连续的时间线连接呈现先后关系，不使用并行分栏，避免用户误判中间步骤发生在输入之前或最终回复之后。
- **滚动**：轨迹超出视口时整条轨迹纵向滚动，全部步骤仍属同一视图。
- **概览摘要收敛**：长文本在条目内按展示需要收敛为可读摘要（单行或限定行数），保留可辨识要点；不提供展开、下钻、原始报文或日志视图（范围外）。

## 3. 数据归属与读写边界

- 本次无真实会话数据源（需求第 4 节），轨迹内容由应用内的示例会话数据集提供，验收以该数据集呈现完整流程。
- 应用只有一个数据访问边界（`sessionRepository`）：对外暴露当前会话的轨迹（会话标识 + 有序步骤列表），页面只读取该边界，不直接散落引用示例数据常量。
- 该边界为**只读**；本功能不产生用户写入的记录，验收不涉及持久化。示例数据作为应用内置数据集随构建发布；后续接入真实数据源时仅替换该边界实现，页面与步骤模型不变。
- 不使用 `localStorage` 保存业务记录：本次没有需要跨刷新保留的写入型数据；若后续增加会话选择等界面偏好，再作为独立的界面状态处理，不进入轨迹模型。

## 4. 步骤模型与校验边界

渲染以单一有序数组驱动，编号由数组顺序派生，避免"编号与顺序不一致"：

- 步骤字段：顺序号（派生）、类型（`user` | `model` | `tool`）、一句话摘要、可选的要点内容（用户输入与模型回复）、可选的工具名称（工具调用）。
- 边界校验（仅在数据装载处进行一次）：首步必须为用户输入、末步必须为模型最终回复；工具调用步骤必须带工具名称；类型与显示字段的对应关系在此处收敛，渲染层不做兜底推断。
- 工具调用为**展示记录**，应用不发起、不执行任何工具调用，也不还原其入参与返回明细。

## 5. 实现入口与运行方式

- 入口：Vite 单页入口加载轨迹页面组件，组件内部拆分为"轨迹容器"与"步骤条目"两级，样式由应用自身的样式入口提供。
- 运行：开发态使用 Vite 开发服务器（`npm run dev`）；构建产物为静态资源，可直接静态托管。
- 工作区落位与初始脚手架由实现阶段按执行契约初始化，本文件不预设具体工作区路径。

## 6. 可重复验证说明

- 本功能无自动推进、随机结果、动画、定时任务或外部异步事件，交互仅为浏览与滚动，因此**不设置测试控制入口**，也不需要预置状态或固定结果。
- 页面验收可直接以示例数据集渲染后的初始视图进行：首末步骤与编号连续、各步骤概览文本、衔接与首尾视觉差异、滚动后仍属同视图，均为确定性结果；刷新即回到初态。

## 7. 范围边界

- 不做：单步详情下钻、原始报文与日志、导出、分享、多会话对比、会话列表与历史检索（需求第 5 节及第 4 节排除项）。
- 不引入：服务端接口、数据库、认证与权限、后台任务、跨设备/跨用户同步、第三方服务。
- 不生成：技术契约、工作区初始化清单、ADR、实现计划（紧凑路线不产出）。
