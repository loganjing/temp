# 工单系统需求文档

## 1. 目标与范围

构建一个工单系统，支持工单的创建、分配、处理、协作、评价和统计分析全生命周期管理。系统按公司隔离数据，支持 SLA 优先级和问题分类，面向多公司、多业务组的工单运营场景。

**范围外（用户未提及）：** 用户管理、公司/部门组织架构管理本身不属于本次工单系统范围，工单系统消费已有的公司、部门、用户数据。

---

## 2. 角色

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单、查看工单进度、对完成工单进行满意度评价的用户 | 用户明确提出 |
| 处理人 | 业务组成员，接收分配的工单并处理 | 用户明确提出（业务组成员） |
| 管理员 | 配置公司业务组及成员、配置分类-业务组自动分配规则 | 用户明确提出（工单分配功能隐含） |

## 4. 业务规则与流程

### 4.1 工单生命周期

工单状态流转如下：

```
创建 → 待分配 → 待处理 → 完成
                                 ↑
                任意状态 → 取消（取消操作）

待处理 → 待处理（转派后仍为待处理，处理人变更）
```

**状态规则：**
- **创建**：提交人创建工单后，工单进入"待分配"状态。
- **待分配**：根据分类-业务组规则自动分配到业务组后，工单进入"待处理"状态。若无匹配规则，工单停留在"待分配"状态等待手动分配。（**推荐基线**：无匹配自动分配规则时停留在待分配等待手动分配，因用户未明确说明无规则时的行为）
- **待处理**：处理人接收并开始处理工单。处理人可将工单转派给同公司其他业务组成员，转派后工单仍为"待处理"状态但处理人变更。
- **完成**：处理人完成处理，记录处理人和处理时间，系统发送邮件通知提交人。
- **取消**：工单可被取消。取消操作的具体权限边界未规定。

### 4.2 工单分配规则

1. 管理员可给某个公司增加多个业务组，每个业务组设置成员。
2. 管理员可配置公司的"分类→业务组"自动分配规则。
3. 工单创建后，系统按工单分类匹配该公司下的分配规则，自动将工单分配到对应业务组。
4. 工单按公司隔离：提交人只能查看本公司工单，处理人只能处理其所属业务组接收的工单。

### 4.3 工单协作（转派）

- 处理人可将待处理工单转派给同公司其他业务组的成员。
- 转派后工单状态保持"待处理"，处理人变更为被转派人。
- 转派操作记录操作日志。

### 4.4 工单处理

1. 处理人在处理工单时可查看提交人的完整信息，包括：姓名、公司、部门、历史工单列表。
2. 处理工单后，系统记录处理人和处理时间。
3. 工单完成后，系统向提交人邮箱发送完成通知邮件。

### 4.5 用户评价

- 工单完成后，提交人可对该工单进行满意度评价。
- 评价结果纳入统计指标。

## 5. 功能模块

### 5.1 工单工作台

- 查看待处理工单列表
- 支持筛选（含按公司维度筛选）、搜索、排序
- 处理人可查看分配给自己的待处理工单

### 5.2 统计分析仪表盘

- **工单量统计**：按公司、部门维度统计工单分布
- **平均响应时间**：统计工单从创建到分配处理的时间指标
- **满意度统计**：汇总用户评价数据
- **热点问题**：按分类统计高频工单问题
- 仪表盘展示上述运营指标

### 5.3 日志记录

- 记录工单全生命周期的关键操作日志，包括创建、分配、转派、处理、完成、取消、评价等操作。
- 日志记录操作人、操作时间和操作详情。

## 6. 验收场景

### AC-01：提交人创建工单并按分类自动分配到业务组

- 验收条件：提交人创建工单后，系统按分类规则自动将工单分配到对应业务组，工单状态从"待分配"流转为"待处理"。
- 入口类型：用户界面
- 验证动作：提交人在工单创建页面填写主题、描述、分类、SLA优先级后提交工单。
- 预期结果：工单创建成功，状态为"待分配"；系统按该公司该分类的分配规则将工单分配到目标业务组，工单状态变为"待处理"，分配操作记录到日志。
- 证据类型：interaction, session-persistence

### AC-02：处理人查看提交人完整信息并处理工单

- 验收条件：处理人在处理工单时可查看提交人的完整信息（姓名、公司、部门、历史工单），完成处理后记录处理人和处理时间。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息面板，执行完成处理操作。
- 预期结果：工单详情页显示提交人姓名、公司、部门和历史工单列表；完成处理后工单状态变为"完成"，处理人和处理时间被记录，操作日志中记录完成操作。
- 证据类型：interaction, session-persistence

### AC-03：工单完成后发送邮件通知提交人

- 验收条件：工单完成时系统向提交人邮箱发送完成通知邮件。
- 入口类型：后台任务
- 验证动作：处理人将工单状态置为"完成"。
- 预期结果：系统向提交人登记的邮箱发送工单完成通知邮件。
- 证据类型：other

### AC-04：处理人转派工单给同公司其他业务组成员

- 验收条件：处理人可将待处理工单转派给同公司其他业务组成员，转派后处理人变更且工单保持"待处理"状态。
- 入口类型：用户界面
- 验证动作：处理人在待处理工单上执行转派操作，选择目标业务组成员。
- 预期结果：工单处理人变更为被转派人，工单状态仍为"待处理"，转派操作记录到日志。
- 证据类型：interaction, session-persistence

### AC-05：提交人对完成工单进行满意度评价

- 验收条件：工单完成后，提交人可对该工单进行满意度评价，评价结果被记录。
- 入口类型：用户界面
- 验证动作：提交人在已完成工单上提交满意度评价。
- 预期结果：评价结果（满意度和评价时间）被保存并关联到该工单，评价操作记录到日志。
- 证据类型：interaction, session-persistence

### AC-06：管理员配置公司业务组和分类自动分配规则

- 验收条件：管理员可为公司增加业务组并设置成员，配置分类→业务组的自动分配规则。
- 入口类型：用户界面
- 验证动作：管理员进入业务组管理页面，为公司新增业务组并添加成员；进入分配规则页面，配置某分类自动分配到某业务组。
- 预期结果：业务组和成员被保存，分配规则被保存；后续该公司该分类的新工单自动分配到指定业务组。
- 证据类型：interaction, session-persistence

### AC-07：工单按公司隔离

- 验收条件：提交人和处理人只能访问本公司工单，无法查看或操作其他公司工单。
- 入口类型：用户界面
- 验证动作：分别以不同公司用户身份登录，查看工单列表和工单详情。
- 预期结果：用户只能看到本公司工单，无法访问其他公司工单。
- 证据类型：authorization, session-persistence

### AC-08：工单工作台支持筛选、搜索和排序

- 验收条件：工单工作台展示待处理工单列表，支持按公司维度筛选、关键词搜索和排序。
- 入口类型：用户界面
- 验证动作：处理人在工单工作台使用筛选条件（含公司筛选）、搜索框和排序功能操作工单列表。
- 预期结果：工单列表按筛选、搜索和排序条件正确显示匹配的工单。
- 证据类型：interaction

### AC-09：统计分析仪表盘展示运营指标

- 验收条件：统计分析仪表盘展示工单量、平均响应时间、满意度和热点问题等运营指标，支持按公司、部门维度查看工单分布。
- 入口类型：用户界面
- 验证动作：用户进入统计分析仪表盘页面，查看各运营指标和按公司/部门维度的工单分布。
- 预期结果：仪表盘展示工单量、平均响应时间、满意度评分、热点问题（按分类统计高频工单）以及按公司/部门维度的工单分布数据。
- 证据类型：interaction

### AC-10：工单多轮回复

- 验收条件：工单支持多轮回复，每条回复记录回复人和回复时间，回复按时间顺序形成回复链。
- 入口类型：用户界面
- 验证动作：不同用户对同一工单多次回复。
- 预期结果：工单详情页展示所有回复，每条回复显示回复人和回复时间，按时间顺序排列。
- 证据类型：interaction, session-persistence

### AC-11：操作日志记录工单生命周期关键操作

- 验收条件：工单的创建、分配、转派、处理、完成、取消、评价等操作均记录到操作日志，包含操作人、操作时间和操作详情。
- 入口类型：内部
- 验证动作：对工单执行创建、分配、转派、处理、完成、取消、评价等操作后查看操作日志。
- 预期结果：每一步操作在日志中均有对应记录，包含操作类型、操作人、操作时间和操作详情。
- 证据类型：session-persistence

### AC-12：工单取消

- 验收条件：工单可被取消，取消后状态为"取消"，取消操作记录到日志。
- 入口类型：用户界面
- 验证动作：对非完成状态的工单执行取消操作。
- 预期结果：工单状态变为"取消"，取消操作记录到日志。
- 证据类型：interaction, session-persistence
