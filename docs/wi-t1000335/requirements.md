# 工单系统需求（137-ticket）

> 来源标注约定：无标注条目为用户明确提出；`[推荐]` 为闭合核心目标所必需的最小推荐基线（保守、可逆、可观察）；`[假设]` 为可纠正的默认取值；`[未规定]` 为本次不决定、留待后续的事项。

## 1. 目标

构建一个按公司隔离的工单系统，覆盖工单完整生命周期：提交人创建工单（含 SLA 优先级 P0–P4 与问题分类）、系统按分类自动分配到公司业务组、处理人多轮回复与转派协作、处理完成并邮件通知提交人、提交人满意度评价；并配套待处理工单工作台、按公司/部门维度的统计分布与运营仪表盘（工单量、平均响应时间、满意度、热点问题），全程记录相关日志。

## 2. 涉及对象

以下对象均来自需求原文，不新增角色或权限模型：

| 对象 | 在本需求中的职责 |
| --- | --- |
| 公司 | 工单的隔离边界；业务组的挂靠单位；统计维度 |
| 提交人 | 创建工单并留下姓名、邮箱、公司、部门等信息；参与工单回复；工单完成后进行满意度评价 |
| 业务组 | 挂在某公司下，可设置成员；承接按分类自动分配的工单 |
| 处理人 | 处理工单的业务组成员；处理记录中的处理人 |
| 工单 | 核心业务对象，归属于一个公司 |

## 3. 端到端旅程（唯一完整描述，模块需求与 AC 均引用此处）

1. **创建**：提交人创建工单，填写主题、描述、问题分类，设置 SLA 优先级（P0–P4）；系统生成唯一工单 ID，记录创建时间与提交人信息（含邮箱）。
2. **分配**：工单进入分配队列（待分配），系统按该公司"问题分类 → 业务组"的自动分配规则将其分配到对应业务组；工单转为待处理，出现在该组成员的工单工作台待处理列表中。
3. **处理**：业务组成员在工作台接单处理：可查看提交人完整信息（姓名、公司、部门、历史工单），与提交人多轮回复（每条回复记录回复人、回复时间）；必要时将工单转派到同公司其他业务组。
4. **完成与通知**：处理完成时系统记录处理人、处理时间；工单转为完成，并向提交人邮箱发送邮件通知。
5. **评价**：提交人在收到完成通知后对该工单进行满意度评价。
6. **统计与留痕**：统计分析持续提供按公司、部门维度的工单分布，以及工单量、平均响应时间、满意度、热点问题等运营指标；工单关键操作记录日志。

**生命周期状态**（用户原文五态）：`创建 → 待分配 → 待处理 → 完成`；未完成状态下可发起 `取消` `[假设：可在创建/待分配/待处理状态发起取消，取消后不再参与分配与处理]`。

## 4. 模块需求

### 4.1 工单管理
- 工单字段：工单 ID（系统生成、唯一）、主题、描述、问题分类、SLA 优先级（P0–P4）、提交人信息（姓名、邮箱、公司、部门）、创建时间。
- 多轮回复：工单内可进行多轮回复；每条回复记录回复人、回复时间。
- 公司隔离：工单归属于提交人所在公司；跨公司用户不可见、不可操作对方公司的工单（覆盖详情、回复、列表、工作台与统计）。
- 生命周期状态：创建、待分配、待处理、完成、取消（流转见第 3 节）。

### 4.2 工单分配
- 业务组管理：允许给某个公司增加多个业务组，每个业务组可设置成员（成员即该公司内可承接工单的处理人）。
- 自动分配规则：允许为某个公司配置"问题分类 → 业务组"映射；该公司的新工单按问题分类自动分配到对应业务组。`[假设：无匹配规则时工单停留在待分配，不自动分配；该默认可调整]`

### 4.3 工单协作（转派）
- 支持将工单转派到同公司的其他业务组；转派后工单仍处于待处理并出现在新业务组的工作台。`[假设：转派目标限于同公司业务组，以维持公司隔离]`
- 转派作为关键操作记录日志（见 4.8）。

### 4.4 工单处理
- 处理视图：处理工单时可查看提交人完整信息，包括姓名、公司、部门、历史工单（该提交人既往提交的工单列表）。
- 处理记录：处理完成后记录处理人、处理时间等处理信息，并随工单保存可查。
- 完成通知：工单完成时向该工单提交人的邮箱发送邮件通知。`[假设：邮件在完成动作触发时发送一次，收件人为该工单记录的提交人邮箱；发送通道与服务商未规定]`

### 4.5 用户评价
- 提交人可对已完成的工单进行满意度评价。`[假设：评价入口在工单完成后对提交人开放，仅可评价本公司的已完成工单]`

### 4.6 统计分析
- 维度统计：支持按公司、按部门两个维度统计工单分布。
- 运营仪表盘：可查看工单量、平均响应时间、满意度、热点问题等运营指标。指标口径 `[推荐]`：
  - 平均响应时间 = 工单创建时间到处理方首次回复时间的平均间隔；
  - 满意度 = 已完成且已评价工单的平均满意度评分；
  - 热点问题 = 按问题分类聚合的工单量排名；
  - 工单量 = 统计范围内的工单数量。
  - 以上口径可调整，但每个指标必须可观察、可核算。

### 4.7 工单工作台
- 查看待处理工单列表；
- 支持筛选（含按公司维度筛选）、关键字搜索、排序；
- 列表范围遵守公司隔离：用户仅能看到其有权查看公司的待处理工单。

### 4.8 操作日志 `[推荐：闭合"记录相关日志"所需的最小范围]`
- 对工单的关键操作留痕：创建、分配、回复、转派、处理、完成、取消、评价；
- 每条日志至少记录操作类型、操作人、操作时间、相关工单；
- 日志可查询（查询入口形式未规定）。

## 5. 未规定事项（本次不决定）

## 6. 验收场景

### AC-01：工单创建与信息完整性
- 验收条件：提交人可创建工单，系统生成唯一工单 ID，工单字段完整保存并可查看。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份创建一张工单，填写主题、描述，选择问题分类与 SLA 优先级（如 P1），提交后打开该工单详情查看。
- 预期结果：工单创建成功；详情页可见工单 ID、主题、描述、问题分类、SLA 优先级 P1、提交人姓名与邮箱、公司、部门、创建时间；工单处于初始生命周期状态（创建/待分配）。
- 证据类型：runtime-render, interaction

### AC-02：工单按公司隔离
- 验收条件：工单归属其提交人所在公司，跨公司用户不可见、不可操作。
- 入口类型：用户界面
- 验证动作：公司 A 提交人创建工单 T1；随后以公司 B 用户身份在工单列表、工作台搜索/筛选 T1 的工单 ID 与主题，并尝试直接访问其详情。
- 预期结果：公司 B 用户在列表、工作台、搜索结果中均看不到工单 T1；直接访问其详情时无法查看或操作该工单；公司 A 提交人仍可正常查看 T1。
- 证据类型：authorization, interaction

### AC-03：工单生命周期状态流转
- 验收条件：工单按"创建 → 待分配 → 待处理 → 完成"流转，未完成状态下可取消。
- 入口类型：用户界面
- 验证动作：在已配置分配规则的公司按第 3 节旅程创建并处理一张工单，依次观察状态；另创建一张工单在未完成状态下执行取消。
- 预期结果：工单创建后依次出现创建/待分配、待处理状态；处理完成后状态为完成；取消操作后状态为取消且不再出现在待处理列表；状态变化均有记录。
- 证据类型：interaction, runtime-render
- 共享流程组：工单端到端流程

### AC-04：工单多轮回复
- 验收条件：工单内可进行多轮回复，每条回复记录回复人、回复时间。
- 入口类型：用户界面
- 验证动作：打开一张工单，由提交人与处理人先后进行至少两轮回复，随后查看工单的回复记录。
- 预期结果：每条回复均保存成功并按时间展示；每条回复可观察其回复人与回复时间；多轮回复顺序完整不丢失。
- 证据类型：interaction, runtime-render

### AC-05：业务组与成员管理
- 验收条件：可为某公司增加多个业务组，并为每个业务组设置成员。
- 入口类型：用户界面
- 验证动作：为公司 A 新增两个业务组（如"技术支持组""财务组"），分别添加成员；随后查看该公司业务组配置。
- 预期结果：两个业务组创建成功并归属于公司 A；每个业务组的成员列表与所设置成员一致；不同公司的业务组互不混淆。
- 证据类型：interaction, runtime-render

### AC-06：工单按分类自动分配到业务组
- 验收条件：为公司配置"问题分类 → 业务组"映射后，该公司新工单按分类自动分配到对应业务组。
- 入口类型：用户界面
- 验证动作：为公司 A 配置规则"分类 X → 业务组 G1"；以公司 A 提交人身份创建一张分类为 X 的工单；查看该工单的分配结果与状态，并以 G1 成员身份查看工作台。
- 预期结果：新工单自动分配到业务组 G1，状态转为待处理；G1 成员的工作台待处理列表出现该工单；同公司未命中规则的分类工单停留在待分配。
- 证据类型：interaction, runtime-render
- 共享流程组：工单端到端流程

### AC-07：工单转派
- 验收条件：处理中的工单可转派到同公司其他业务组，转派后由新业务组承接。
- 入口类型：用户界面
- 验证动作：将公司 A 一张待处理工单从业务组 G1 转派到业务组 G2；分别查看工单当前归属与两个业务组成员的工作台列表。
- 预期结果：转派成功后工单归属业务组 G2，状态仍为待处理；G2 成员工作台可见该工单，G1 成员工作台不再显示；跨公司业务组不可作为转派目标；转派操作记录在日志中。
- 证据类型：interaction, runtime-render

### AC-08：工单处理、处理记录与完成邮件通知
- 验收条件：处理人可查看提交人完整信息；处理完成后记录处理人、处理时间，并向提交人邮箱发送邮件通知。
- 入口类型：用户界面
- 验证动作：处理人打开一张待处理工单，查看提交人完整信息（姓名、公司、部门、历史工单）；执行多轮沟通后完成处理；随后查看工单的处理记录与完成通知结果。
- 预期结果：处理视图中可见提交人姓名、公司、部门及其历史工单列表；工单完成后详情中可见处理人与处理时间；系统向该工单提交人邮箱发起完成通知邮件，发送记录可观察（收件人邮箱与提交人邮箱一致）；工单状态转为完成。
- 证据类型：interaction, other
- 共享流程组：工单端到端流程

### AC-09：用户满意度评价
- 验收条件：工单完成后，提交人可对该工单进行满意度评价，评价结果被记录。
- 入口类型：用户界面
- 验证动作：工单完成并收到通知后，以提交人身份对该工单提交满意度评价；再次查看该工单。
- 预期结果：评价提交成功；工单详情中可查看该满意度评价结果与评价人；未完成的工单不可评价。
- 证据类型：interaction, runtime-render

### AC-10：统计分析与运营仪表盘
- 验收条件：支持按公司、部门维度统计工单分布；仪表盘可查看工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：准备多公司、多部门、多分类、含已完成与已评价的工单数据；打开统计分析，分别按公司维度与部门维度查看工单分布；打开仪表盘查看四项运营指标。
- 预期结果：按公司维度与按部门维度的工单分布均正确反映各维度工单数量；仪表盘展示工单量、平均响应时间、满意度、热点问题四项指标，且数值与底层工单/回复/评价数据一致（口径见 4.6）。
- 证据类型：runtime-render, interaction

### AC-11：工单工作台
- 验收条件：工作台展示待处理工单列表，支持筛选（含按公司维度）、搜索、排序。
- 入口类型：用户界面
- 验证动作：打开工单工作台待处理列表；分别执行按公司维度筛选、按主题关键字搜索、按创建时间排序；对照底层数据核对结果。
- 预期结果：列表仅展示待处理工单；公司筛选结果只含所选公司的工单；搜索结果匹配关键字；排序结果符合所选排序方式；列表不出现其他公司或非待处理状态的工单。
- 证据类型：interaction, runtime-render

### AC-12：工单关键操作日志
- 验收条件：工单的创建、分配、回复、转派、处理、完成、取消、评价等关键操作被记录为日志，日志含操作类型、操作人、操作时间、相关工单。
- 入口类型：内部
- 验证动作：按第 3 节旅程完成一张工单的创建、自动分配、回复、转派（可选）、处理、完成与评价操作，另对一张工单执行取消；随后查询工单相关日志。
- 预期结果：上述每类关键操作均存在对应日志记录；每条日志可观察操作类型、操作人、操作时间与相关工单；日志时间与操作顺序一致。
- 证据类型：other
