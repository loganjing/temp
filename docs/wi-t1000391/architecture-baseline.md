# 架构基线：贪吃蛇游戏（193-snake）

> 需求来源：`docs/wi-t1000391/requirements.md`（SHA-256 已校验）
> 路线：`simple-frontend`（精简路线）

## 1. 页面与交互范围

- 单页应用，整个游戏在一个浏览器视口内完成。
- 页面包含三个可见区域：
  1. **游戏画布**：渲染网格、蛇身、食物。
  2. **分数显示**：当前分数（吃食物计数）。
  3. **游戏结束提示**：撞墙或撞自身后显示最终分数和重新开始入口。
- 玩家交互仅限键盘方向控制（↑↓←→ 或 WASD）和重新开始触发（按键或点击）。
- 蛇以固定速度自动推进，玩家只改变方向，不控制逐帧移动。

## 2. 技术栈与实现入口

- **框架**：React + Vite SPA（新建应用）。
- **渲染**：HTML `<canvas>` + 2D Canvas API 绘制网格、蛇身、食物。Canvas 在固定时间间隔重绘，与游戏逻辑帧同步。
- **游戏循环**：使用 `setInterval`（或 `requestAnimationFrame` + 时间累积）以固定 tick 速率驱动蛇移动；每个 tick 计算一次移动、碰撞和进食。
- **方向输入**：监听 `window` 的 `keydown` 事件，将方向请求缓存到队列中，每个 tick 消费一个，防止连续快速输入导致瞬时反向。
- **状态管理**：React `useState` / `useRef` 管理蛇身坐标数组、食物坐标、方向、分数、游戏状态（running / game-over）。
- **运行方式**：`npm run dev`（Vite 开发服务器），浏览器访问 `localhost` 预览。

## 3. 浏览器状态与数据归属

- 所有游戏状态（蛇身、食物位置、方向、分数、游戏状态）均为单局内存状态，存在 React 组件树中。
- **不使用 localStorage**：需求基线未要求刷新后保留数据或跨会话持久化；AC-03 明确重新开始时分数归零、蛇恢复初始长度，数据仅在单局有效。
- **不涉及服务端、数据库、认证、后台任务或外部服务**。
- 数据不跨浏览器、设备或用户共享。

## 4. 核心逻辑边界

### 4.1 网格与坐标

- 游戏区域为 `cols × rows` 的离散网格（如 20×20），每个单元格用一个整数坐标 `(x, y)` 表示。
- 蛇身为有序坐标数组，索引 0 为蛇头。
- 食物为单个坐标，始终位于蛇身以外的空单元格。

### 4.2 移动与方向

- 每个 tick：蛇头沿当前方向前进一格，新头部坐标加入数组前端。
- 方向不可直接反向（当前向右时不能变为向左）。
- 若未吃到食物，蛇尾移除一节（长度不变）；若吃到食物，蛇尾保留（长度 +1）。

### 4.3 碰撞检测

- **撞墙**：新头部坐标超出网格边界 → 游戏结束。
- **撞自身**：新头部坐标与蛇身（排除当前尾节，因尾节在同一 tick 移除）任一坐标重合 → 游戏结束。

### 4.4 食物与分数

- 蛇头移动到食物坐标时：分数 +1，蛇身增长，在剩余空单元格中随机选取新食物坐标。
- 若网格已满（蛇身占满所有单元格），不再生成食物，游戏以胜利状态或自然结束。

### 4.5 重新开始

- 游戏结束状态下触发重新开始：蛇身重置为初始长度与位置，分数归零，方向重置，食物重新生成，蛇立即开始移动。

## 5. 验证可重复性说明

贪吃蛇的验收涉及自动推进（定时器驱动）和随机结果（食物位置），需在验收时控制状态以保持可重复：

- **AC-01（吃食物增长得分）**：蛇自动推进是定时器驱动的，验收时可通过预置蛇头与食物相邻的确定状态、手动推进一个 tick 来验证进食增长和分数变化，避免依赖随机食物刷新时机。
- **AC-02（撞墙/撞自身结束）**：可预置蛇头贴近边界或贴近自身的确定状态，手动推进一个 tick 触发碰撞，验证游戏结束和分数显示。
- **AC-03（重新开始）**：在游戏结束态触发重新开始，验证状态重置。
- **随机食物控制**：测试时可将食物随机生成替换为确定性坐标（注入固定种子或直接设置食物位置），使进食和碰撞场景可重复执行。该控制入口仅限测试环境使用，正常运行按产品逻辑执行。
- **tick 控制**：测试时可将游戏循环的 tick 间隔调大或改为手动步进（调用单次推进函数），避免依赖实时定时器。该控制入口仅限测试环境使用。
