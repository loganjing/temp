# 教师管理系统需求

## 目标

提供一个教师管理系统，支持对教师信息的增删改查操作。

## 核心行为与规则

### 教师信息字段

教师记录包含以下字段（用户明确提出）：

| 字段 | 说明 |
|------|------|
| 教师名称 | 教师的姓名 |
| 教授课程 | 该教师教授的课程 |
| 年级 | 该教师所教授的年级 |
| 手机 | 教师的手机号码 |
| 邮箱 | 教师的电子邮箱地址 |

### 增删改查操作（用户明确提出）

- **新增**：用户可录入上述字段信息，创建一条新的教师记录。
- **查看**：用户可查看已保存的教师记录列表及单条记录的详细信息。
- **编辑**：用户可修改已有教师记录的字段内容并保存。
- **删除**：用户可删除指定的教师记录，删除后该记录不再出现在列表中。

### 推荐基线

以下内容为推荐基线，非用户明确提出，仅用于闭合核心目标必需的缺口：

- 手机号与邮箱字段在保存时进行基本格式校验（手机号为合理手机号格式，邮箱为合理邮箱格式），以保证管理系统中联系信息的数据可用性。此校验为保守、可逆、可观察的规则，用户可在后续阶段调整具体格式要求。

### 未规定事项

- 用户未规定具体平台（Web / 桌面端 / 移动端），不在此推断。
- 用户未规定教师列表的分页、排序、搜索等辅助功能。
- 用户未规定权限角色或操作者身份限制。
- 用户未规定数据持久化方式或存储技术。

## 验收场景

### AC-01：用户可新增并查看教师记录

- 验收条件：用户能够创建包含全部字段（教师名称、教授课程、年级、手机、邮箱）的教师记录，且创建后可通过查看操作读回已保存的信息。
- 入口类型：用户界面
- 验证动作：在教师管理界面中执行新增操作，填写全部字段并保存；随后查看教师列表及该条记录详情。
- 预期结果：教师列表中出现新创建的记录，且详情中各字段内容与录入时一致。
- 证据类型：interaction, runtime-render

### AC-02：用户可编辑并删除教师记录

- 验收条件：用户能够修改已有教师记录的字段内容并保存，修改后可通过查看操作确认变更；用户能够删除已有教师记录，删除后该记录不再出现在列表中。
- 入口类型：用户界面
- 验证动作：在教师管理界面中选择一条已有记录，修改部分字段后保存并查看；随后删除该记录并查看教师列表。
- 预期结果：编辑保存后，查看到的记录内容反映最新修改；删除后，教师列表中不再出现该记录。
- 证据类型：interaction, runtime-render
