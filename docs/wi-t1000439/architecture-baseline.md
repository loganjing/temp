# 教师管理系统 — 架构基线

> 关联需求：`docs/wi-t1000439/requirements.md`（SHA-256 已校验）
> 应用类型：simple-frontend（compact 路线）

## 设计范围

本设计将教师管理系统实现为单页应用（SPA），支持教师记录的新增、查看、编辑和删除。产品语义以批准的需求基线为准，不扩展或重裁字段定义、操作语义和验收条件。

## 页面与交互范围

应用呈现一个教师管理主界面，包含以下交互区域：

- **教师列表**：以表格形式展示已保存的教师记录，列出教师名称、教授课程、年级、手机、邮箱字段。每行提供"编辑"和"删除"操作入口。列表上方提供"新增教师"按钮。
- **新增/编辑表单**：弹出或内联的表单，包含教师名称、教授课程、年级、手机、邮箱五个输入字段。新增模式提交后创建记录；编辑模式预填已有数据，提交后更新记录。
- **删除确认**：删除操作前提示用户确认，确认后移除该记录。

所有操作在同一页面内完成，不涉及路由跳转或多页面导航。

## 浏览器状态与数据归属

- 教师记录存储在浏览器 `localStorage` 中，键名为 `teachers`，值为 JSON 数组。
- 数据在同一浏览器配置文件中刷新或重新打开页面后仍然保留。
- 数据不与其他浏览器、设备或用户共享；无服务端权威数据源，无同步层。
- 每条教师记录包含字段：`id`（内部生成，用于标识）、`name`（教师名称）、`course`（教授课程）、`grade`（年级）、`phone`（手机）、`email`（邮箱）。

## 校验边界

- **手机号**：保存时进行基本格式校验，要求符合合理手机号格式（数字为主，长度合理）。
- **邮箱**：保存时进行基本格式校验，要求包含 `@` 及合理域名结构。
- 校验失败时在表单中提示用户，不保存无效数据。
- 教师名称为必填字段。

以上校验为前端可逆规则，用户可在后续阶段调整具体格式要求。

## 实现入口与运行方式

- 技术栈：React + Vite SPA。
- 应用入口为 `src/main.jsx`（或 `src/main.tsx`），渲染根组件 `src/App.jsx`。
- 数据读写通过一个应用负责的 `localStorage` 读写模块封装，提供 `getTeachers`、`saveTeacher`、`updateTeacher`、`deleteTeacher` 方法。
- 开发运行：使用 Vite 开发服务器（`npm run dev`），在浏览器中访问开发服务器地址。
- 构建产物：`npm run build`，输出静态文件可部署至任意静态托管服务。

## 技术边界

- 不涉及服务端 API、数据库、认证/权限、后台任务、外部服务集成或跨设备同步。
- 不生成 `technical-contract.md`、`workspace-bootstrap.json` 或 ADR。
