# 教师管理系统需求基线

## 1. 目标

提供一个教师管理系统，支持对教师信息的增加、删除、修改、查询（CRUD）。教师信息包含以下字段：教师名称、教授课程、年级、手机、邮箱。

> 来源说明：本章目标与字段由用户明确提出。

## 2. 核心行为与规则

### 2.1 教师信息字段

每条教师记录包含以下字段：

| 字段 | 说明 |
| --- | --- |
| 教师名称 | 教师姓名，必填 |
| 教授课程 | 该教师教授的课程，必填 |
| 年级 | 教师所授课对应的年级，必填 |
| 手机 | 教师联系电话，必填 |
| 邮箱 | 教师电子邮箱，必填 |

> 来源：字段清单由用户明确提出。各字段“必填”为推荐基线：核心 CRUD 的写入与读回需要这些字段均有有效值才能形成可观察的完整记录，未规定时默认必填，用户可调整。

### 2.2 增加（创建教师）

- 用户可填写上述全部字段创建一条教师记录。
- 创建成功后，该记录可通过查询行为被读回。

### 2.3 查询（列表与查看）

- 用户可查看已创建的教师列表。
- 用户可在列表中查看某条教师记录的完整字段信息。

### 2.4 修改（编辑）

- 用户可对已有教师记录的任一字段进行修改。
- 修改成功后，再次查询该记录应返回更新后的字段值。

### 2.5 删除

- 用户可删除一条已有的教师记录。
- 删除成功后，该记录不再出现在教师列表中。

> 来源：增删改查四类操作由用户明确提出；“写入后可读回”为推荐基线，用于闭合核心 CRUD 的可观察验收，不指定存储技术或持久化周期。

## 3. 未规定事项

- 未规定用户角色、权限与登录鉴权。
- 未规定界面布局、产品载体（Web/桌面/移动）及设备适配。
- 未规定数据存储技术、部署方式与持久化周期。
- 未规定列表分页、排序、筛选规则。
- 未规定手机号与邮箱的格式校验强度（推荐基线：至少做基本非空校验，格式校验规则用户可调整）。
- 未规定教师与课程/年级的多对多关联约束（当前按单条记录上的字段值处理）。

## 4. 验收场景

### AC-01：用户可完成教师的增删改查闭环

- 验收条件：用户能够创建、查看、修改、删除一条教师记录，且每一步操作的结果可在后续查询中被观察到。
- 入口类型：用户界面
- 验证动作：在教师管理界面中，填写教师名称、教授课程、年级、手机、邮箱并创建一条教师记录；随后在列表中查看该记录；修改其中任一字段并保存；最后删除该记录。
- 预期结果：
  - 创建后，教师列表中出现包含所填各字段值的记录；
  - 查看时显示该记录完整的五个字段；
  - 修改保存后，再次查看该记录对应字段显示为更新后的值；
  - 删除后，该记录不再出现在教师列表中。
- 证据类型：interaction,session-persistence
