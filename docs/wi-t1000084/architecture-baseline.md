# 教师管理系统架构基线

> 引用已批准需求基线：`docs/wi-t1000084/requirements.md`（sha256: 69d002d2…960928d）

## 1. 路由结论

本应用归类为 **simple-frontend**（纯前端 SPA）。已批准需求仅要求单用户教师信息增删改查，未规定服务端权威数据、认证/权限、后台任务、外部服务或跨用户/跨设备共享。浏览器本地持久化即可闭合全部验收场景。

## 2. 技术选型

| 维度 | 选择 | 说明 |
| --- | --- | --- |
| 应用形态 | React + Vite 单页应用（SPA） | 新建应用，使用 TypeScript |
| UI 组件库 | Ant Design（`antd` + `@ant-design/icons`） | 适用于管理后台类界面，提供表格、表单、弹窗等开箱即用组件 |
| 数据存储 | 浏览器 `localStorage` | 同一浏览器配置文件内刷新或重新打开后数据仍保留 |
| 构建工具 | Vite | 开发服务器与生产构建 |
| 运行方式 | `npm run dev`（Vite 开发服务器） | 生产构建使用 `npm run build` |

## 3. 数据归属与持久化边界

- 教师记录存储于浏览器 `localStorage`，键名约定为 `teacher-management/teachers`，值为 JSON 数组。
- 数据仅在同一浏览器、同一用户下可用；不与其他浏览器、设备或用户共享。
- 不承诺跨设备同步；清空浏览器存储后数据将丢失。
- 每条教师记录包含唯一标识（`id`，字符串，创建时生成）及需求规定的五个字段。

## 4. 数据模型

```typescript
interface Teacher {
  id: string;          // 唯一标识，创建时自动生成
  name: string;        // 教师名称，必填
  course: string;      // 教授课程，必填
  grade: string;       // 年级，必填
  phone: string;       // 手机，必填
  email: string;       // 邮箱，必填
}
```

## 5. 页面与交互范围

应用为单页面布局，包含以下交互区域：

- **页面标题与主操作**：顶部显示"教师管理"标题，主操作为"新增教师"按钮。
- **教师列表**：以表格形式展示已创建的教师记录，列包括教师名称、教授课程、年级、手机、邮箱，每行提供"编辑"和"删除"操作。
- **新增/编辑表单**：通过模态框（Modal）或抽屉（Drawer）呈现，包含五个必填字段的表单输入，支持提交与取消。
- **删除确认**：删除操作前弹出确认对话框，确认后执行删除。

视觉方向：浅色工作区、清晰的页面标题与主操作、表格行内操作按钮。布局适应实际内容，不增设无依据的功能或指标。

## 6. 读写边界

所有读写操作由应用在前端完成，直接操作 `localStorage`：

- **创建**：生成唯一 `id`，组装教师对象，追加到存储数组并写入 `localStorage`。
- **查询列表**：从 `localStorage` 读取全部教师记录，渲染至表格。
- **查询详情**：按 `id` 从存储数组中查找对应记录。
- **修改**：按 `id` 定位记录，更新对应字段值后写回 `localStorage`。
- **删除**：按 `id` 从存储数组中移除对应记录后写回 `localStorage`。

## 7. 校验边界

- 五个字段均为必填，提交前做非空校验。
- 手机与邮箱做基本格式校验（手机号基本数字格式、邮箱基本 `@` 格式）；校验强度可由用户后续调整。
- 校验失败时在表单对应字段显示错误提示，不执行写入。

## 8. 实现入口与运行

- 应用入口：React 应用从 `src/main.tsx` 挂载，根组件渲染教师管理页面。
- 开发运行：`npm run dev`，由 Vite 开发服务器提供本地预览。
- 生产构建：`npm run build`，输出静态资源。

## 9. 边界声明

- 不涉及服务端 API、数据库、认证鉴权、后台任务、外部服务集成或数据同步层。
- 数据持久化范围限于当前浏览器 `localStorage`，不承诺持久化周期之外的可靠性。
- 不涉及分页、排序、筛选等扩展功能（需求未规定），实现阶段可按最小可验收范围处理。
