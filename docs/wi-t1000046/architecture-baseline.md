# 架构基线：日常专注时段记录系统（168-timeling）

> 本设计基于已批准的需求基线 `docs/wi-t1000046/requirements.md`（sha256: e91632a9e92a799bca0e9e76ad0cbade15b666557d9e7dd76af636ab9b272fba）。产品语义以需求基线为唯一来源，本文档不扩展或重裁业务规则与验收场景。

## 路线结论

应用分类为 `simple-frontend`，走 compact 架构路线。所有功能在浏览器单页面内完成，无需服务端权威数据、认证、后台任务、外部集成或跨用户/设备共享。

## 技术选型

- **框架**：React + Vite SPA。
- **运行方式**：Vite 开发服务器（`npm run dev`），浏览器加载单个 HTML 入口。
- **数据存储**：浏览器 `localStorage`，同一浏览器配置文件中刷新或重新打开后当日记录仍保留；不与其他浏览器、设备或用户共享。
- **不引入**：后端服务/API、数据库、认证/权限、后台任务、外部第三方集成、跨设备同步层。

## 页面与交互范围

单页面包含三个核心区域，自上而下：

1. **累计专注时长区**（页面上方）：实时显示当日累计专注时长，累计值 = 当日已完成番茄钟数 × 25 分钟。每完成一个番茄钟后更新。
2. **番茄钟倒计时区**（页面中部）：
   - 专注阶段从 25:00 倒计时至 00:00。
   - 专注阶段完成后自动切换到休息阶段，从 05:00 倒计时至 00:00。
   - 休息阶段结束后进入可启动下一轮专注的状态，不自动开始专注。
   - 一个专注阶段倒计时完成（到达 00:00）即视为完成一个番茄钟，触发自动记录。
3. **当日专注热力图区**（页面下方）：按当日时间区间（按小时分桶）统计该小时内完成的专注分钟数/番茄钟数，以颜色深浅反映专注强度。完成番茄钟后更新对应时段。

## 浏览器状态与数据归属

### 状态结构

应用运行时的核心状态：

- **番茄钟状态**：当前阶段（专注/休息/待启动）、剩余时间（秒）、是否运行中。
- **当日专注记录列表**：每条记录包含完成时间（时间戳）和专注时长（25 分钟）。
- **累计专注时长**：由当日记录列表派生（记录数 × 25 分钟），无需单独持久化。
- **热力图数据**：由当日记录列表按完成时间的小时分桶派生，无需单独持久化。

### 数据归属

- 当日专注记录列表持久化到 `localStorage`，key 按日期区分（如 `timeling.sessions.YYYY-MM-DD`）。
- 番茄钟运行状态（当前阶段、剩余时间）为会话内状态，不持久化；刷新后重置为待启动。
- 数据仅在当前浏览器配置文件中有效，不跨浏览器、跨设备或跨用户同步。
- 需求基线将跨天/刷新后保留历史排除在基线之外；当前实现以当日记录为最小可观察结果，`localStorage` 仅用于同一日内刷新后保留当日数据。

## 实现入口与运行方式

- **入口**：Vite SPA 标准入口（`index.html` → React 根组件）。
- **开发运行**：`npm run dev`，Vite 开发服务器提供本地预览。
- **构建**：`npm run build`，产出静态资源可由任意静态服务器托管。
- 倒计时由 `setInterval` 驱动，每秒更新剩余时间；验收时可使用可控/加速时钟驱动渲染以避免长时间等待（对应需求 AC-01 验证动作）。

## 接口与校验边界

- 无外部 API 接口。所有数据读写发生在浏览器内：`localStorage` 读写当日记录，组件间通过 React state 传递。
- 校验边界：专注阶段倒计时到达 00:00 时才产生记录；休息阶段完成不产生记录。累计时长与热力图均由记录列表派生，保证三者数据一致。
