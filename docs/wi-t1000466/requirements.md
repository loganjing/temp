# 工单系统需求文档

## 1. 目标

构建一个工单管理系统，支持工单从创建到完成的全生命周期管理，覆盖工单创建与信息记录、多轮回复、SLA优先级与问题分类、按分类自动分配到业务组、工单转派协作、处理过程提交人信息查看与处理记录、以及用户满意度评价。

## 2. 工单生命周期

工单具有以下五个状态（用户明确提出）：

| 状态 | 说明 |
|------|------|
| 创建 | 工单刚创建，尚未进入分配流程 |
| 待分配 | 工单等待分配到业务组 |
| 待处理 | 工单已分配到业务组/处理人，等待或正在处理 |
| 完成 | 工单处理结束 |
| 取消 | 工单被取消，为终态 |

状态流转方向（用户明确提出）：

```
创建 → 待分配 → 待处理 → 完成
```

- 工单创建后依次经历 待分配、待处理，最终到达 完成。
- 取消 为可选终态，具体可在哪些状态下执行取消操作：未规定。

## 3. 功能需求

### 3.1 工单管理

#### 3.1.1 工单创建与信息记录（用户明确提出）
- 创建工单时填写：主题、描述、分类、SLA优先级（P0-P4）。
- 系统自动生成工单ID，记录提交人信息（含邮箱）和创建时间。
- 工单ID 为唯一标识。

#### 3.1.2 多轮回复（用户明确提出）
- 同一工单支持多轮回复。
- 每轮回复记录回复人和回复时间。
- 回复按时间顺序排列。

#### 3.1.3 SLA优先级与问题分类（用户明确提出）
- SLA优先级支持 P0、P1、P2、P3、P4 五个等级。
- 工单的分类即问题分类。

### 3.2 工单分配

#### 3.2.1 业务组管理（用户明确提出）
- 允许给某个公司增加多个业务组。
- 每个业务组可以设置成员。

#### 3.2.2 按分类自动分配（用户明确提出）
- 允许配置某个公司的"分类→业务组"分配规则。
- 工单创建后，根据其分类匹配该公司的分配规则，自动分配到对应业务组。
- 工单分配后状态从待分配变为待处理。
- 若无匹配的分配规则时工单的处理方式：未规定。

### 3.3 工单协作

#### 3.3.1 工单转派（用户明确提出）
- 支持工单转派操作，将工单重新指派给其他处理人或业务组。
- 转派后工单归属更新为新的处理人或业务组。

### 3.4 工单处理

#### 3.4.1 提交人完整信息查看（用户明确提出）
- 在处理工单时，可查看提交人的完整信息，包括：
  - 姓名
  - 公司
  - 部门
  - 历史工单

#### 3.4.2 处理记录（用户明确提出）
- 工单处理后记录：
  - 处理人
  - 处理时间
  - 工单状态

### 3.5 用户评价

#### 3.5.1 满意度评价（用户明确提出）
- 工单完成后，用户可对该工单进行满意度评价。
- 评价的具体维度和评分方式：未规定。

## 4. 未规定事项

以下事项用户未明确，不影响核心流程的实现，保留为未规定：

- 取消操作可在哪些状态下执行、由谁执行。
- 无匹配分类分配规则时的工单处理方式。
- 满意度评价的具体维度和评分方式。
- 工单转派后工单的具体状态（是否回退到待分配或保持待处理）。
- 业务组和成员管理由谁执行。

## 5. 验收场景

### AC-01：创建工单并记录完整信息
- 验收条件：用户创建工单后，系统生成唯一工单ID，并完整记录主题、描述、分类、SLA优先级（P0-P4）、提交人信息（含邮箱）和创建时间，工单进入初始状态。
- 入口类型：用户界面
- 验证动作：填写工单主题、描述、分类和SLA优先级后提交创建。
- 预期结果：工单创建成功，可查看到系统生成的工单ID、提交人信息（含邮箱）和创建时间，工单状态为初始状态。
- 证据类型：interaction, session-persistence

### AC-02：工单支持多轮回复
- 验收条件：同一工单可进行多轮回复，每轮回复记录回复人和回复时间，回复按时间顺序排列。
- 入口类型：用户界面
- 验证动作：对同一工单依次提交多条回复。
- 预期结果：所有回复均被保存，每条回复显示回复人和回复时间，回复按提交顺序排列。
- 证据类型：interaction, session-persistence

### AC-03：工单生命周期状态流转
- 验收条件：工单可在创建、待分配、待处理、完成、取消这五个状态之间按照定义的生命周期流转，状态变更可被观察到。
- 入口类型：用户界面
- 验证动作：创建工单后，触发分配、处理、完成等操作，观察工单状态变化；在可取消的时机执行取消操作。
- 预期结果：工单状态按"创建 → 待分配 → 待处理 → 完成"方向流转，取消操作将工单置为"取消"状态，各状态变更均可被观察到。
- 证据类型：interaction, session-persistence

### AC-04：为公司配置业务组和成员
- 验收条件：可以为某个公司增加多个业务组，每个业务组可设置成员，配置后可查询到该公司下所有业务组及各组成员。
- 入口类型：用户界面
- 验证动作：选择一个公司，新增多个业务组，为每个业务组添加成员。
- 预期结果：业务组和成员配置成功，可查询到该公司下所有业务组及各组成员。
- 证据类型：interaction, session-persistence

### AC-05：按分类自动分配工单到业务组
- 验收条件：为某个公司配置"分类→业务组"分配规则后，该公司创建的工单根据分类自动分配到对应业务组，工单状态从待分配变为待处理。
- 入口类型：用户界面
- 验证动作：配置某分类与某业务组的分配规则，创建一个匹配该分类的工单。
- 预期结果：工单自动分配到规则指定的业务组，工单状态变为待处理，可查看到分配到的业务组。
- 证据类型：interaction, session-persistence

### AC-06：工单转派
- 验收条件：工单可被转派给其他处理人或业务组，转派后工单归属更新，转派操作可被观察到。
- 入口类型：用户界面
- 验证动作：对一个待处理状态的工单执行转派操作，选择新的处理人或业务组。
- 预期结果：工单归属更新为新的处理人或业务组，转派操作被记录且可被观察到。
- 证据类型：interaction, session-persistence

### AC-07：处理工单时查看提交人完整信息
- 验收条件：在处理工单时，可查看提交人的完整信息，包括姓名、公司、部门和该提交人的历史工单。
- 入口类型：用户界面
- 验证动作：打开一个待处理工单的处理界面，查看提交人信息区域。
- 预期结果：显示提交人的姓名、公司、部门信息，并可查看该提交人的历史工单列表。
- 证据类型：interaction, visual-style

### AC-08：工单处理记录
- 验收条件：工单处理后，系统记录处理人、处理时间和工单状态，处理记录可被查询。
- 入口类型：用户界面
- 验证动作：对一个待处理工单执行处理完成操作。
- 预期结果：工单状态更新为完成，处理记录中包含处理人、处理时间，该记录可被查询到。
- 证据类型：interaction, session-persistence

### AC-09：用户满意度评价
- 验收条件：工单完成后，用户可对该工单进行满意度评价，评价结果被保存并可与工单关联查询。
- 入口类型：用户界面
- 验证动作：以提交人身份打开一个已完成的工单，提交满意度评价。
- 预期结果：评价被保存，可在工单详情中查看到该满意度评价结果。
- 证据类型：interaction, session-persistence
