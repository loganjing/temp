# 132-ticket 工单系统需求

## 1. 目标与范围

构建面向多公司的工单系统：公司用户提交并跟踪工单，处理团队按业务组承接、处理并完成工单，完成后通知提交人并进行满意度评价，运营侧可进行工单分布统计与运营指标仪表盘分析。〔用户明确提出〕

范围包含：工单管理、工单分配、工单协作（转派）、工单处理、用户评价、统计分析、工单工作台、相关日志。〔用户明确提出〕

## 2. 使用者

以下操作主体由用户描述推导得出，命名与权限体系未由用户明确规定〔未规定〕：

- **提交人**：公司内提交工单的用户；提交工单、参与多轮回复、在工单完成后进行满意度评价。
- **处理人**：业务组成员；在工作台查看并处理本业务组承接的工单，回复、转派并完成工单。
- **配置管理人员**：为公司配置业务组、成员与分类自动分配规则。〔操作主体未规定，功能操作本身为用户明确提出〕
- **统计查看者**：查看工单分布统计与运营仪表盘。〔操作主体未规定〕

## 3. 核心旅程

### 旅程A：工单端到端（提交 → 分配 → 处理 → 完成 → 通知 → 评价）

1. 提交人填写主题、描述、问题分类并设置 SLA 优先级（P0-P4），提交创建工单；系统记录工单 ID、提交人信息（含邮箱、公司、部门）与创建时间。
2. 工单进入分配流程；系统按该公司"问题分类 → 业务组"规则自动分配到对应业务组，工单进入待处理状态；无匹配规则时保持待分配。〔无匹配规则时的行为为推荐基线〕
3. 业务组成员（处理人）在工作台看到该工单，可查看提交人完整信息（姓名、公司、部门、历史工单），与提交人多轮回复沟通；必要时将工单转派给同公司其他业务组。〔转派目标范围为推荐基线〕
4. 处理完成后，处理人将工单标记完成；系统记录处理人与处理时间，并向提交人邮箱发送完成通知邮件。〔收件人为提交人属推荐基线；发送邮件为用户明确提出〕
5. 提交人收到通知后，在工单上提交满意度评价，评价结果计入满意度统计。
6. 工单在未完成阶段可被取消，进入取消终态。〔可执行取消的状态范围为推荐基线〕

### 旅程B：分配配置（公司 → 业务组 → 成员 → 分类规则）

1. 配置管理人员为某公司创建多个业务组。
2. 为每个业务组设置成员（处理人）。
3. 为该公司配置"问题分类 → 业务组"的自动分配规则。

## 4. 状态模型

工单生命周期包含五个状态〔用户明确提出〕：**创建、待分配、待处理、完成、取消**。

流转规则〔状态集合为用户明确提出；以下流转条件为推荐基线〕：

| 当前状态 | 事件 | 目标状态 |
|---|---|---|
| 创建 | 工单提交成功（初始态） | — |
| 创建 | 进入分配队列（推荐：提交后立即） | 待分配 |
| 待分配 | 分类规则自动分配到业务组 | 待处理 |
| 待处理 | 处理人完成处理 | 完成 |
| 创建 / 待分配 / 待处理 | 取消操作 | 取消 |
| 完成 / 取消 | 终态，不再流转 | — |

## 5. 模块需求

### 5.1 工单管理

**工单字段**〔用户明确提出〕：

- 工单 ID：系统生成，全局唯一
- 主题、描述
- 问题分类
- 提交人信息：姓名、邮箱、公司、部门〔邮箱为用户明确提出；公司、部门来自提交人所属组织，为处理与统计所需〕
- 创建时间
- SLA 优先级：P0-P4〔用户明确提出〕

**回复**〔用户明确提出〕：

- 工单支持多轮回复；每轮回复记录回复人、回复时间与回复内容
- 提交人与处理人均可回复

**公司隔离**〔用户明确提出〕：

- 每张工单归属于提交人所在公司
- 不同公司之间的工单数据相互隔离：公司 A 的用户不能查看或访问公司 B 的工单
- 提交人仅能查看自己提交的工单〔推荐基线〕

生命周期见第 4 节。

### 5.2 工单分配〔用户明确提出〕

- 业务组：可为某个公司配置多个业务组；每个业务组可设置成员
- 自动分配：公司可配置"问题分类 → 业务组"规则；该公司新工单按分类自动分配到匹配的业务组
- 无匹配规则时工单保持待分配，等待人工处理〔推荐基线〕

### 5.3 工单协作：转派〔用户明确提出〕

- 处于待处理状态的工单支持转派操作
- 转派目标：同公司内的其他业务组〔推荐基线〕
- 转派后工单保持待处理状态，转派操作计入日志〔推荐基线〕

### 5.4 工单处理〔用户明确提出〕

- **提交人完整信息**：处理人处理工单时可查看提交人的姓名、公司、部门及该提交人的历史工单列表
- **处理记录**：工单完成时记录处理人与处理时间
- **完成通知**：工单完成后系统向提交人邮箱发送通知邮件〔发送邮件为用户明确提出；收件人为提交人为推荐基线〕

### 5.5 用户评价〔用户明确提出〕

- 工单完成后，提交人可对该工单进行满意度评价
- 评价结果被记录，并计入满意度统计
- 评价形式为满意度评分；具体刻度未规定〔推荐基线：1-5 星〕

### 5.6 统计分析〔用户明确提出〕

- **工单分布统计**：支持按公司维度、按部门维度（提交人所属部门）统计工单分布
- **统计与分析仪表盘**，运营指标包括：
  - 工单量：展示工单数量〔具体口径未规定；推荐基线：工单总量及按状态分布〕
  - 平均响应时间：〔口径未规定；推荐基线：工单创建时间到业务组首次回复的平均间隔〕
  - 满意度：已评价工单的平均满意度评分
  - 热点问题：〔口径未规定；推荐基线：按问题分类聚合的工单量排名〕

### 5.7 工单工作台〔用户明确提出〕

- 查看待处理工单列表（状态为待处理的工单）
- 筛选：支持按公司维度筛选〔用户明确提出〕；推荐补充状态、优先级、分类等筛选维度
- 搜索：〔推荐基线：按工单 ID、主题搜索〕
- 排序：〔推荐基线：按创建时间、优先级排序〕

### 5.8 操作日志〔记录日志为用户明确提出；日志范围与查看方式为推荐基线〕

- 记录工单关键操作：创建、分配、状态变更、转派、回复、完成、取消、评价等，每条日志含操作人与操作时间
- 日志可按工单查看

## 6. 验收场景

### AC-01：提交人可创建工单并读回完整信息
- 验收条件：公司用户提交工单后，工单被持久保存，工单详情可读回全部关键字段，且具备 SLA 优先级与问题分类。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份新建工单，填写主题、描述、问题分类并设置 SLA 优先级（P0-P4），提交；随后打开该工单详情。
- 预期结果：详情页显示系统生成的工单 ID、主题、描述、分类、优先级、提交人信息（含邮箱）、公司归属与创建时间，与提交内容一致。
- 证据类型：interaction, session-persistence
- 共享流程组：工单端到端流程

### AC-02：工单支持多轮回复并记录回复人与时间
- 验收条件：提交人与处理人可在同一工单上进行多轮回复，每轮回复可追溯回复人与回复时间。
- 入口类型：用户界面
- 验证动作：在已创建的工单详情中，由提交人和处理人先后各回复两次。
- 预期结果：工单回复区按时间顺序展示 4 条回复，每条显示回复人、回复时间与回复内容。
- 证据类型：interaction, session-persistence

### AC-03：工单数据按公司隔离
- 验收条件：不同公司的用户不能查看对方公司的工单。
- 入口类型：用户界面
- 验证动作：公司 A 提交人创建工单后，以公司 B 用户身份登录，尝试通过工单列表及工单详情访问公司 A 的工单。
- 预期结果：公司 B 用户在工单列表中看不到公司 A 的工单，直接访问公司 A 工单详情也无法获得其内容。
- 证据类型：authorization, runtime-render

### AC-04：工单生命周期状态按规则流转
- 验收条件：工单在创建、待分配、待处理、完成、取消五个状态间按第 4 节规则流转，终态不再变更。
- 入口类型：用户界面
- 验证动作：创建并提交一张工单，依次观察进入分配队列后的状态、分配到业务组后的状态、处理人完成后的状态；另建一张工单在待处理状态执行取消。
- 预期结果：各阶段工单当前状态与第 4 节流转表一致（创建 → 待分配 → 待处理 → 完成，以及待处理 → 取消）；完成与取消的工单不再发生状态变更。
- 证据类型：interaction
- 共享流程组：工单端到端流程

### AC-05：公司业务组配置与按分类自动分配
- 验收条件：为公司配置业务组与成员后，该公司按问题分类自动分配的新工单进入对应业务组的处理范围。
- 入口类型：用户界面
- 验证动作：为公司 A 配置两个业务组（各设置成员），配置"分类 X → 业务组 1"规则；以公司 A 提交人创建分类为 X 的工单；再创建一张分类无匹配规则的工单。
- 预期结果：分类为 X 的工单自动分配至业务组 1 并进入待处理状态，业务组 1 成员在工作台可见该工单；无匹配分类规则的工单保持待分配。
- 证据类型：interaction, runtime-render
- 共享流程组：工单端到端流程

### AC-06：工单支持转派
- 验收条件：待处理工单可转派给同公司其他业务组，转派后目标业务组可见该工单。
- 入口类型：用户界面
- 验证动作：处理人对一张待处理工单执行转派，选择同公司另一业务组。
- 预期结果：转派成功后该工单出现在目标业务组成员的工作台列表中，且该工单记录了转派操作。
- 证据类型：interaction

### AC-07：处理工单时可查看提交人完整信息
- 验收条件：处理人在处理工单时，可查看提交人的姓名、公司、部门及历史工单。
- 入口类型：用户界面
- 验证动作：处理人打开一张工单，查看提交人信息区。
- 预期结果：显示提交人姓名、公司、部门，以及该提交人此前提交的历史工单列表。
- 证据类型：runtime-render

### AC-08：完成工单记录处理信息并发送邮件通知
- 验收条件：处理人完成工单后，系统记录处理人与处理时间，并向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：处理人将一张待处理工单标记完成。
- 预期结果：工单状态变为完成；工单上记录处理人与处理时间；提交人邮箱收到完成通知邮件（或系统可查到该邮件的发送记录）。
- 证据类型：interaction, other
- 共享流程组：工单端到端流程

### AC-09：提交人可进行满意度评价
- 验收条件：工单完成后，提交人可提交满意度评价，评价结果被记录并计入统计。
- 入口类型：用户界面
- 验证动作：提交人打开已完成工单，提交满意度评分；再次查看该工单。
- 预期结果：评价提交成功后，工单显示已评价及评分值；评价结果可被满意度统计读取。
- 证据类型：interaction, session-persistence
- 共享流程组：工单端到端流程

### AC-10：按公司与部门维度统计工单分布
- 验收条件：统计功能可分别按公司维度、部门维度展示工单分布。
- 入口类型：用户界面
- 验证动作：在统计分析页分别切换公司维度与部门维度查看工单分布。
- 预期结果：两个维度下的工单分布数据与实际工单数据的聚合结果一致（如各公司工单数、各部门工单数）。
- 证据类型：runtime-render

### AC-11：运营仪表盘展示核心运营指标
- 验收条件：仪表盘展示工单量、平均响应时间、满意度、热点问题四类指标，数值与底层数据一致。
- 入口类型：用户界面
- 验证动作：打开统计与分析仪表盘，查看四项指标。
- 预期结果：工单量、平均响应时间（按 5.6 节推荐口径：创建到业务组首次回复的平均间隔）、满意度（已评价工单平均分）、热点问题（按问题分类聚合的工单量排名）均有数值展示，且与已知工单数据的计算结果一致。
- 证据类型：runtime-render

### AC-12：工单工作台支持筛选、搜索、排序
- 验收条件：工作台展示待处理工单列表，支持按公司维度筛选，并支持搜索与排序。
- 入口类型：用户界面
- 验证动作：处理人进入工作台，对待处理列表分别执行：按公司筛选；按工单 ID / 主题搜索；按创建时间、优先级排序。
- 预期结果：列表展示状态为待处理的工单；公司筛选后仅显示所选公司的工单；搜索仅命中匹配的工单；排序按所选字段正确排列。
- 证据类型：interaction, runtime-render

### AC-13：关键操作记录日志
- 验收条件：工单的关键操作（创建、分配、状态变更、转派、回复、完成、评价等）被记录，含操作人与时间，且可查看。
- 入口类型：用户界面
- 验证动作：对一张工单依次执行创建、自动分配、回复、转派、完成、评价等操作后，查看该工单的日志。
- 预期结果：日志完整列出上述操作，每条日志含操作人、操作时间与操作类型。
- 证据类型：runtime-render
