# 教师管理系统架构基线（WorkItem: wi-t1000325）

## 需求基线引用

- 批准需求基线：`docs/wi-t1000325/requirements.md`（sha256: `b3081a8dab7f1b9fb73a8ebb65500afef006ffb10fb2798a92acaf25e253ddd5`）。
- 路由分类：`simple-frontend`（compact 路线）。依据：需求为单用户教师信息 CRUD 界面应用，未提出服务端权威数据、认证/权限、后台任务、外部服务或跨用户/设备共享要求。

## 架构决策

- 应用形态：React + Vite 单页应用（SPA），一个页面承载全部教师管理交互。
- 数据承载：浏览器 `localStorage` 作为唯一持久化边界；全部读写经由应用内单一数据存取模块（teacher store）完成，界面组件不直接操作存储键。
- 数据归属：教师数据仅在当前浏览器配置文件中保留，刷新或重开页面后仍存在；不与其他浏览器、设备或用户共享，不做任何同步。
- 明确不引入：服务端 API、数据库、认证、后台任务、外部集成与同步层。

## 页面与交互范围

单页视图内提供以下交互（覆盖需求声明的增删改查四类管理操作）：

- **教师列表**（默认视图）：以表格呈现已保存的教师记录，展示教师名称、教授课程、年级、手机、邮箱五个字段，并提供记录的编辑与删除入口。
- **新增/编辑表单**：弹出或内嵌表单，录入/修改五个字段后保存；新增初始为空表单，编辑时预填该教师当前字段值。
- **删除确认**：删除前弹出确认操作，确认后移除该记录并回到列表视图。
- **查看**：列表行内即完整展示单个教师的五个字段值，无需独立详情页。

视图状态（列表 / 表单）由应用内状态管理切换，不引入路由库。

## 数据与读写边界

- 存储键：`teacher-management.teachers.v1`，取值为教师记录的 JSON 数组。
- 记录结构（字段语义与需求基线一致）：

| 属性 | 说明 |
| --- | --- |
| `id` | 应用生成的唯一标识（`crypto.randomUUID()`），用于编辑与删除时定位记录 |
| `name` | 教师名称 |
| `course` | 教授课程 |
| `grade` | 年级 |
| `phone` | 手机 |
| `email` | 邮箱 |

- 读写边界：新增、修改、删除均为先在内存中变更记录数组，再整体写回存储键；查询直接读取该键并渲染。异常输入（存储内容损坏或为空）时按空列表处理，不阻塞页面加载。

## 校验边界（最小必要）

需求未规定字段必填性与格式规则，实现采用最小必要校验，不扩展产品语义：

- 教师名称为必填（空值不允许保存）；
- 手机按基本手机号格式、邮箱按基本邮箱格式做提示性校验；
- 教授课程、年级不做强制约束，仅去除首尾空白后保存。
- 校验失败时在表单内提示，不执行写入。

## 实现入口与运行方式

- 新建 React + Vite SPA（TypeScript 模板），依赖 Node/npm 工具链。
- 开发运行：`npm install` 后执行 `npm run dev`，由 Vite 开发服务器启动本地访问入口。
- 生产构建：`npm run build` 产出静态资源，可直接以静态方式部署运行。
