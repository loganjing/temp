# 仓储搬运系统需求文档

> **工作项**：wi-t1000025  
> **业务任务**：161-仓储搬运  
> **阶段**：requirements

---

## 1. 项目目标

为仓储场景开发搬运管理系统，覆盖搬运任务分配、路径规划、交通避让、执行监控和任务统计五项核心能力。系统接收搬运需求后，自动或手动将任务分配给可用搬运设备，为每台设备规划可行路径，在多设备同时作业时进行交通避让调度，实时监控执行过程，并对历史任务进行统计汇总。

---

## 2. 用户角色

| 角色 | 说明 |
|---|---|
| 仓库调度员 | 创建和分配搬运任务，监控执行进度，查看任务统计，处理异常 |
| 系统管理员 | 配置仓库地图、搬运设备、交通规则等基础数据 |

> 用户未明确角色划分，以上为基于业务目标推断的最小角色集。若实际使用场景存在更细粒度的角色分工，可在后续阶段调整。

---

## 3. 核心实体与术语

| 实体 | 说明 |
|---|---|
| **搬运任务 (Transport Task)** | 核心业务对象，记录从源库位到目标库位的搬运需求，包含货物信息、优先级、状态等 |
| **搬运设备 (Transport Resource)** | 执行搬运任务的资源，如 AGV、叉车等；具有类型、当前状态、当前位置等属性 |
| **库位 (Location)** | 仓库地图上的位置节点，有唯一编码，分为源库位和目标库位 |
| **仓库地图 (Warehouse Map)** | 由库位和通道构成的拓扑图，描述可行走路径网络 |
| **路径 (Route)** | 为某搬运设备规划的从起点到终点的通道序列 |
| **交通冲突 (Traffic Conflict)** | 多台设备在同时段经过同一通道节点或相向通行时产生的冲突 |
| **避让策略 (Yield Strategy)** | 解决交通冲突的调度规则，如优先级避让、等待让行、绕行替代路径 |
| **执行事件 (Execution Event)** | 搬运执行过程中的关键事件，如出发、到达中间点、到达终点、异常暂停等 |
| **任务统计记录 (Task Statistics)** | 完成任务后生成的统计数据，含搬运时长、设备利用率等 |

## 4. 状态模型与业务规则

### 4.1 搬运任务状态

| 状态 | 说明 |
|---|---|
| **待分配 (Pending)** | 任务已创建，等待分配搬运设备 |
| **已分配 (Assigned)** | 已分配到搬运设备，等待路径规划完成 |
| **搬运中 (In Transit)** | 设备已出发，正在执行搬运 |
| **已完成 (Completed)** | 搬运任务已到达目标库位并确认完成 |
| **已取消 (Cancelled)** | 任务被取消，不再执行 |
| **异常 (Error)** | 执行过程中出现异常，需要人工介入 |

### 4.2 任务状态转换

```
待分配 ──分配设备──> 已分配
已分配 ──路径规划完成/设备出发──> 搬运中
搬运中 ──到达目标库位/确认完成──> 已完成
搬运中 ──设备故障/超时/受阻无法恢复──> 异常
待分配 ──取消──> 已取消
已分配 ──取消──> 已取消
搬运中 ──取消（需人工确认）──> 已取消
异常 ──人工介入恢复──> 搬运中
异常 ──人工关闭/取消──> 已取消
已完成 ──（终态）
已取消 ──（终态）
```

### 4.3 搬运设备状态

| 状态 | 说明 |
|---|---|
| **空闲 (Idle)** | 设备在线且无任务，可被分配 |
| **作业中 (Busy)** | 设备正在执行搬运任务 |
| **离线 (Offline)** | 设备不在线，不可被分配 |
| **故障 (Fault)** | 设备报告故障，不可被分配，需人工处理 |

### 4.4 通用业务规则

| 编号 | 规则描述 | 来源 |
|---|---|---|
| BR-01 | 搬运任务创建后进入「待分配」状态；任务须包含源库位、目标库位和货物信息 | 用户明确提出 |
| BR-02 | 仅状态为「空闲」的设备可被分配搬运任务 | 推荐基线 |
| BR-03 | 任务分配可由系统按设备可用性和距离自动分配，也可由调度员手动指定设备 | 用户明确提出（任务分配） |
| BR-04 | 每台设备同一时间仅执行一个搬运任务；任务完成后设备恢复「空闲」 | 推荐基线 |
| BR-05 | 路径规划在任务分配后、设备出发前完成；规划结果为通道节点序列 | 用户明确提出（路径规划） |
| BR-06 | 当多台设备的规划路径存在时空冲突时，系统按避让策略进行调度，避免碰撞和死锁 | 用户明确提出（交通避让） |
| BR-07 | 执行过程中设备实时上报位置和状态；系统记录关键执行事件 | 用户明确提出（执行监控） |
| BR-08 | 任务完成后系统自动统计搬运时长、完成率等指标，并纳入任务统计 | 用户明确提出（任务统计） |
| BR-09 | 进入「已完成」或「已取消」终态的任务不可再变更状态 | 推荐基线 |
| BR-10 | 处于「异常」状态的任务需调度员人工介入处理；恢复后可继续执行或取消 | 推荐基线 |

## 5. 用户旅程

### 5.1 搬运任务执行旅程

1. 调度员创建搬运任务，指定源库位、目标库位、货物信息和优先级
2. 任务进入「待分配」状态
3. 系统自动分配空闲设备（或调度员手动指定设备）
4. 任务进入「已分配」状态，系统为设备规划路径
5. 路径规划完成后设备出发，任务进入「搬运中」状态
6. 执行过程中，设备上报位置和状态；若检测到交通冲突，系统按避让策略调度
7. 设备到达目标库位，调度员或系统确认完成，任务进入「已完成」状态
8. 系统自动记录任务统计数据

### 5.2 异常处理旅程

1. 搬运过程中设备报告故障或长时间受阻，任务进入「异常」状态
2. 调度员收到异常通知，查看异常详情
3. 调度员判断是否可恢复：可恢复则处理后恢复执行；不可恢复则取消任务
4. 异常处理过程记录在任务执行事件中

## 6. 分模块功能需求

### 6.1 搬运任务分配模块

#### 6.1.1 任务创建

**行为**：调度员创建搬运任务，填写搬运需求信息。

**输入字段**：

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|:---:|---|
| 任务ID | 系统生成 | - | 全局唯一标识 |
| 源库位 | 选择 | ✅ | 货物当前位置 |
| 目标库位 | 选择 | ✅ | 货物目标位置 |
| 货物名称 | 文本 | ✅ | 搬运货物标识 |
| 货物数量 | 数值 | ✅ | 搬运数量 |
| 优先级 | 选择 | ✅ | 普通/紧急/最高 |
| 备注 | 文本 | ❌ | 补充说明 |
| 创建时间 | 系统生成 | - | 任务提交时刻 |
| 创建人 | 系统记录 | - | 当前操作用户 |

**业务规则**：
- 源库位和目标库位不能相同
- 源库位和目标库位须在已配置的仓库地图中存在
- 创建后自动生成任务ID，状态为「待分配」

**不应发生的行为**：
- 源库位与目标库位相同时创建成功
- 选择不存在的库位

#### 6.1.2 任务分配

**行为**：将待分配任务分配给可用搬运设备，支持自动分配和手动分配两种方式。

**自动分配规则**：
- 系统从「空闲」状态设备中选择候选设备
- 优先选择距离源库位最近的空闲设备（推荐基线）
- 按任务优先级高低决定分配顺序：最高 > 紧急 > 普通（推荐基线）

**手动分配规则**：
- 调度员查看待分配任务列表，手动选择目标设备
- 仅可选择「空闲」状态的设备

**业务规则**：
- 分配后任务状态变为「已分配」
- 记录分配方式（自动/手动）、分配设备和分配时间
- 每台设备同一时间仅分配一个任务

**不应发生的行为**：
- 将任务分配给非空闲状态的设备
- 同一设备同时被分配多个任务

#### 6.1.3 任务取消

**行为**：调度员取消未完成的搬运任务。

**业务规则**：
- 「待分配」和「已分配」状态可直接取消
- 「搬运中」状态取消需人工确认
- 取消后任务进入「已取消」终态
- 若设备已在执行中，取消后设备状态恢复为「空闲」（推荐基线）
- 记录取消人和取消时间

---

### 6.2 路径规划模块

#### 6.2.1 路径规划

**行为**：任务分配到设备后，系统为设备规划从当前位置到源库位、再从源库位到目标库位的可行走路径。

**规划输入**：
- 设备当前位置
- 任务源库位
- 任务目标库位
- 仓库地图（库位和通道拓扑）

**规划输出**：
- 路径节点序列（通道节点有序列表）
- 预计搬运距离和预计时长

**业务规则**：
- 路径须由仓库地图中实际存在的通道节点构成
- 路径起点为设备当前位置，终点为目标库位，中间经过源库位
- 若存在多条可行路径，优先选择距离最短的路径（推荐基线）
- 路径规划失败（无可行路径）时，任务进入「异常」状态并通知调度员

**不应发生的行为**：
- 规划出地图中不存在的路径
- 设备当前位置不明确时强行规划路径

#### 6.2.2 路径重规划

**行为**：当搬运过程中原路径因故障、阻塞等原因无法继续通行时，系统为设备重新规划替代路径。

**业务规则**：
- 路径重规划在「搬运中」状态下触发
- 重规划须避开已知的阻塞节点
- 重规划失败时任务进入「异常」状态
- 记录重规划原因和新的路径（推荐基线）

---

### 6.3 交通避让模块

#### 6.3.1 冲突检测

**行为**：系统实时检测多台设备路径中存在的交通冲突。

**冲突类型**：

| 冲突类型 | 说明 |
|---|---|
| 节点冲突 | 两台或多台设备在同一时间段到达同一通道节点 |
| 对向冲突 | 两台设备在同一段通道上相向而行 |
| 尾随冲突 | 两台设备在同一段通道上同向但距离过近 |

**业务规则**：
- 冲突检测基于各设备当前规划路径和实时位置
- 检测到冲突后触发避让策略调度

#### 6.3.2 避让调度

**行为**：系统按避让策略对冲突设备进行调度，避免碰撞和死锁。

**避让策略**：

| 策略 | 说明 |
|---|---|
| 优先级让行 | 低优先级任务的设备让行，暂停等待高优先级设备先行通过 |
| 先到先行 | 先到达冲突节点的设备先行，后到设备暂停等待 |
| 绕行替代 | 若存在替代路径，调度后到设备绕行避让冲突节点 |

**业务规则**：
- 默认避让策略为「优先级让行 + 先到先行」组合（推荐基线）
- 若优先级相同，按先到先行处理
- 避让时被暂停的设备状态保持「作业中」，但标记为「等待避让」
- 避让冲突解决后，被暂停的设备恢复行进
- 避让调度须避免死锁（多台设备互相等待导致永久阻塞）；检测到潜在死锁时，调度其中一台设备绕行或回退（推荐基线）

**不应发生的行为**：
- 两台设备在同一节点发生物理碰撞
- 多台设备互相等待形成死锁

---

### 6.4 执行监控模块

#### 6.4.1 实时状态监控

**行为**：调度员可实时查看所有搬运任务和设备的执行状态。

**监控视图内容**：

| 监控项 | 说明 |
|---|---|
| 任务列表 | 所有活跃任务及其当前状态（待分配/已分配/搬运中/异常） |
| 设备列表 | 所有设备及其当前状态（空闲/作业中/离线/故障）和实时位置 |
| 任务执行进度 | 搬运中任务已走路径、当前位置、预计剩余时长 |
| 异常告警 | 当前处于异常状态的任务和故障设备 |

**业务规则**：
- 调度员可按状态、设备、优先级筛选任务列表
- 异常任务和故障设备在监控视图中醒目标识
- 设备实时位置随上报数据更新（推荐基线）

#### 6.4.2 执行事件记录

**行为**：系统记录搬运执行过程中的关键事件，形成完整执行日志。

**记录事件类型**：

| 事件类型 | 说明 |
|---|---|
| 任务分配 | 记录分配方式、设备和时间 |
| 路径规划完成 | 记录规划路径和预计时长 |
| 设备出发 | 记录出发时间和起始位置 |
| 位置更新 | 设备上报的中间位置点（推荐基线） |
| 避让暂停/恢复 | 记录避让原因、暂停和恢复时间 |
| 路径重规划 | 记录重规划原因和新路径 |
| 到达目标 | 记录到达时间和最终位置 |
| 异常事件 | 记录异常类型、发生时间和异常描述 |
| 任务完成/取消 | 记录完成/取消时间和操作人 |

**业务规则**：
- 执行事件按时间顺序记录，与任务和设备关联
- 调度员可在任务详情中查看完整执行事件序列

#### 6.4.3 异常告警

**行为**：任务或设备出现异常时，系统向调度员发出告警。

**业务规则**：
- 异常类型包括：设备故障、路径阻塞无法恢复、设备长时间未上报位置（推荐基线）
- 异常告警在监控视图中醒目展示
- 异常任务状态变为「异常」，需调度员人工介入

### 6.5 任务统计模块

#### 6.5.1 任务统计指标

**行为**：系统对已完成搬运任务进行统计，提供关键运营指标。

**统计指标**：

| 指标 | 说明 |
|---|---|
| 任务总量 | 统计周期内已完成的搬运任务总数 |
| 任务完成率 | 已完成任务数 / 总任务数（含取消和异常） |
| 平均搬运时长 | 已完成任务的平均执行时长（从分配到完成） |
| 设备利用率 | 设备作业时长 / 设备在线总时长 |
| 异常率 | 异常任务数 / 总任务数 |
| 任务优先级分布 | 各优先级任务数量占比 |
| 设备任务分布 | 各设备执行的任务数量 |

**业务规则**：
- 统计数据来源于已完成任务的执行记录
- 统计周期支持按日、周、月筛选（推荐基线）

#### 6.5.2 统计查询

**行为**：调度员查看任务统计报表。

**业务规则**：
- 可按时间范围、设备、优先级维度筛选统计结果
- 统计结果以列表和图表形式展示（推荐基线）
- 可导出统计结果（推荐基线）

## 9. 推荐基线

| 编号 | 推荐基线 | 理由 |
|---|---|---|
| RB-01 | 自动分配优先选择距源库位最近的空闲设备 | 减少空驶距离，提高效率 |
| RB-02 | 任务按优先级高低决定分配顺序 | 高优先级任务应优先处理 |
| RB-03 | 每台设备同一时间仅执行一个任务 | 避免资源争用和调度复杂度过高 |
| RB-04 | 路径规划优先选择最短路径 | 减少搬运时长和能耗 |
| RB-05 | 默认避让策略为优先级让行 + 先到先行 | 平衡公平性和效率 |
| RB-06 | 避让调度须检测和避免死锁 | 防止多设备互相等待导致系统瘫痪 |
| RB-07 | 执行事件记录设备中间位置点 | 提供完整的执行轨迹用于追溯 |
| RB-08 | 设备长时间未上报位置时触发异常告警 | 及时发现设备失联或卡死 |
| RB-09 | 任务取消后设备恢复空闲 | 释放设备资源供后续任务使用 |
| RB-10 | 统计支持按日/周/月筛选 | 满足不同粒度的运营分析需求 |
| RB-11 | 统计结果可导出 | 支持离线分析和汇报 |

## 10. 验收场景

### AC-01：创建搬运任务

- 验收条件：调度员可创建搬运任务，任务包含源库位、目标库位、货物信息和优先级，创建后进入待分配状态。
- 入口类型：用户界面
- 验证动作：调度员填写源库位、目标库位、货物名称、货物数量和优先级，提交创建。
- 预期结果：系统生成唯一任务ID；任务信息包含源库位、目标库位、货物信息、优先级、创建人和创建时间；任务状态为「待分配」；调度员在任务列表中可看到新创建的任务。
- 证据类型：interaction, runtime-render

### AC-02：自动分配搬运任务

- 验收条件：待分配任务可由系统自动分配给空闲设备。
- 入口类型：后台任务
- 验证动作：存在空闲设备时，系统对待分配任务执行自动分配。
- 预期结果：任务分配到一台空闲设备；设备状态变为「作业中」；任务状态从「待分配」变为「已分配」；分配记录包含分配方式（自动）、分配设备和分配时间。
- 证据类型：other

### AC-03：手动分配搬运任务

- 验收条件：调度员可手动将待分配任务指定给空闲设备。
- 入口类型：用户界面
- 验证动作：调度员在待分配任务列表中选择任务，手动选择一台空闲设备执行分配。
- 预期结果：任务分配到所选设备；设备状态变为「作业中」；任务状态变为「已分配」；分配记录包含分配方式（手动）、分配设备和分配时间。
- 证据类型：interaction, runtime-render

### AC-04：路径规划

- 验收条件：任务分配后系统为设备规划从当前位置到源库位再到目标库位的可行走路径。
- 入口类型：后台任务
- 验证动作：任务进入「已分配」状态后，系统执行路径规划。
- 预期结果：规划路径为由仓库地图实际通道节点构成的有序序列；路径起点为设备当前位置，经过源库位，终点为目标库位；记录预计搬运距离和预计时长；任务状态可进入「搬运中」。
- 证据类型：other

### AC-05：交通冲突检测与避让

- 验收条件：多台设备路径存在冲突时，系统按避让策略调度，避免碰撞和死锁。
- 入口类型：后台任务
- 验证动作：两台设备规划路径在同一通道节点存在时空冲突，系统检测到冲突并执行避让调度。
- 预期结果：被避让的设备暂停等待或绕行替代路径；优先级让行时低优先级任务设备让行；冲突解决后被暂停设备恢复行进；不发生设备碰撞；执行事件中记录避让暂停和恢复。
- 证据类型：other

### AC-06：实时执行监控

- 验收条件：调度员可实时查看所有搬运任务和设备的执行状态。
- 入口类型：用户界面
- 验证动作：调度员打开监控视图，查看任务列表和设备列表。
- 预期结果：监控视图展示所有活跃任务的状态、所有设备的状态和实时位置；搬运中任务展示已走路径、当前位置和预计剩余时长；异常任务和故障设备醒目标识；可按状态、设备、优先级筛选任务列表。
- 证据类型：interaction, runtime-render

### AC-07：执行事件记录与追溯

- 验收条件：搬运执行过程的关键事件被完整记录，调度员可在任务详情中查看。
- 入口类型：用户界面
- 验证动作：任务完成后，调度员查看任务详情中的执行事件序列。
- 预期结果：执行事件按时间顺序排列，包含任务分配、路径规划完成、设备出发、避让暂停/恢复、到达目标和任务完成等事件；每条事件包含事件类型、发生时间和相关描述。
- 证据类型：interaction, runtime-render

### AC-08：异常处理

- 验收条件：搬运过程中出现异常时，任务进入异常状态并通知调度员，调度员可处理恢复或取消。
- 入口类型：用户界面
- 验证动作：搬运中设备报告故障，任务进入「异常」状态；调度员查看异常告警，处理后恢复执行或取消任务。
- 预期结果：任务状态变为「异常」；监控视图中醒目展示异常告警；调度员处理后任务恢复为「搬运中」或进入「已取消」；异常事件和处理过程记录在执行事件中。
- 证据类型：interaction, runtime-render

### AC-09：任务完成

- 验收条件：设备到达目标库位后任务可被确认完成，系统自动记录统计数据。
- 入口类型：用户界面
- 验证动作：设备到达目标库位，调度员或系统确认任务完成。
- 预期结果：任务状态变为「已完成」；记录到达时间、完成时间和最终位置；设备状态恢复为「空闲」；系统自动生成任务统计数据（搬运时长等）；任务进入终态不可再变更。
- 证据类型：interaction, runtime-render

### AC-10：任务取消

- 验收条件：调度员可取消未完成的搬运任务。
- 入口类型：用户界面
- 验证动作：调度员对待分配、已分配或搬运中任务执行取消操作。
- 预期结果：待分配和已分配任务直接取消；搬运中任务需人工确认后取消；任务状态变为「已取消」并进入终态；若设备在执行中，设备恢复「空闲」；记录取消人和取消时间。
- 证据类型：interaction, runtime-render

### AC-11：任务统计查询

- 验收条件：调度员可查看已完成搬运任务的统计指标。
- 入口类型：用户界面
- 验证动作：调度员选择时间范围，查看任务统计报表。
- 预期结果：统计指标包含任务总量、任务完成率、平均搬运时长、设备利用率、异常率、任务优先级分布和设备任务分布；可按时间范围、设备和优先级筛选；结果以列表和图表形式展示。
- 证据类型：interaction, runtime-render

### AC-12：任务状态生命周期

- 验收条件：搬运任务状态流转符合定义的生命周期。
- 入口类型：内部
- 验证动作：验证任务状态仅在定义的合法路径上流转。
- 预期结果：任务状态仅能从「待分配→已分配→搬运中→已完成/已取消/异常」流转；异常可恢复为搬运中或转为已取消；已完成和已取消为终态不可变更。
- 证据类型：other
