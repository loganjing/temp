# k17-robot 设备管理平台需求文档

## 1. 目标

开发设备管理平台，包含设备状态监测、故障诊断、远程升级、维修工单和设备履历五大功能模块，所有业务数据须通过数据库持久化存储。（用户明确提出）

## 2. 核心模块需求

### 2.1 设备状态监测（用户明确提出）

- 支持查看设备列表，展示每台设备的基本信息（设备编号、名称等）和当前状态
- 设备状态包括：运行中、待机、故障、离线
- 支持查看单台设备的详细信息

### 2.2 故障诊断（用户明确提出）

- 支持为指定设备记录故障信息，包括故障描述和发生时间
- 支持查看设备的故障记录列表
- 故障记录可关联到具体设备

### 2.3 远程升级（用户明确提出）

- 支持对指定设备发起远程升级操作
- 支持跟踪升级状态，状态包括：进行中、成功、失败
- 支持查看设备的升级记录及结果

### 2.4 维修工单（用户明确提出）

- 支持创建维修工单并关联到指定设备
- 支持维修工单状态流转，状态包括：待处理、处理中、已完成
- 支持查看维修工单列表及工单详情
- 支持在工单中记录维修结果信息

### 2.5 设备履历（用户明确提出）

- 支持查看单台设备的完整历史记录
- 履历内容聚合该设备的状态变更、故障记录、升级记录和维修记录，按时间顺序展示

## 3. 数据持久化（用户明确提出）

- 所有模块的业务数据须通过数据库持久化存储
- 各模块写入的数据须可通过相应的查询行为读回，不依赖内存或临时文件

## 4. 关键流程

### 4.1 故障处理流程（推荐基线）

设备状态监测发现/记录故障 → 录入故障诊断信息 → 创建维修工单 → 执行维修并记录结果 → 设备履历聚合展示

说明：模块间数据流转为推荐基线，用户未明确要求自动化触发。各模块可独立操作，也可按流程联动。

### 4.2 远程升级流程（推荐基线）

对设备发起远程升级 → 跟踪升级状态 → 记录升级结果 → 设备履历聚合展示

## 5. 验收场景

### AC-01：设备状态监测

- 验收条件：用户可查看设备列表及各设备的当前状态
- 入口类型：用户界面
- 验证动作：进入设备状态监测页面，查看设备列表
- 预期结果：显示设备列表，每台设备展示编号、名称和当前状态（运行中/待机/故障/离线）
- 证据类型：runtime-render

### AC-02：故障诊断记录

- 验收条件：用户可为设备记录故障信息并查看故障记录
- 入口类型：用户界面
- 验证动作：选择一台设备，录入故障描述并保存，随后查看该设备的故障记录列表
- 预期结果：故障信息保存成功，故障记录列表中可读回刚录入的故障描述和发生时间
- 证据类型：interaction, session-persistence

### AC-03：远程升级

- 验收条件：用户可对设备发起远程升级并查看升级结果
- 入口类型：用户界面
- 验证动作：选择一台设备发起远程升级，查看升级状态和结果记录
- 预期结果：升级状态可跟踪（进行中/成功/失败），升级结果记录可查看
- 证据类型：interaction, session-persistence

### AC-04：维修工单管理

- 验收条件：用户可创建维修工单、推进工单状态并记录维修结果
- 入口类型：用户界面
- 验证动作：创建一条关联设备的维修工单，将状态从待处理更新为处理中再为已完成，填写维修结果，查看工单列表和详情
- 预期结果：工单创建成功，状态可流转（待处理→处理中→已完成），工单列表和详情可查看，维修结果信息已记录且可读回
- 证据类型：interaction, session-persistence

### AC-05：设备履历

- 验收条件：用户可查看单台设备的完整历史记录
- 入口类型：用户界面
- 验证动作：选择一台已有故障记录、升级记录和维修记录的设备，查看其设备履历
- 预期结果：履历页面按时间顺序展示该设备的历史事件，包含故障诊断、远程升级和维修工单相关记录
- 证据类型：runtime-render

### AC-06：数据持久化

- 验收条件：各模块写入的业务数据通过数据库持久化存储，可再次读取验证
- 入口类型：内部
- 验证动作：在各模块中创建业务数据（故障记录、升级记录、维修工单）后，通过对应查询行为读取
- 预期结果：所有写入的数据均可通过数据库查询读回，数据持久存储不丢失
