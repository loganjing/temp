## 1. 系统定位与业务目标

### 1.1 定位

Land 是房地产开发企业从“发现一块地”到“判断是否值得买、如何开发、选择哪套方案、提交领导决策，并将结果交给下游部门”的拿地决策平台，不是单纯计算工具。

平台要解决的核心问题（用户提出）：

1. 把分散在 Excel、地图、公开资料、历史项目和个人经验中的信息集中到一个地块档案。
2. 把位置、土地权属、规划限制、市场竞品、产品组合、售价和成本组织成可复核的投资判断。
3. 允许业务人员快速试算多种开发方案，同时保留每一个版本，避免新方案覆盖原始判断。
4. 让管理层先看到结论、风险和推荐方案；需要时可以继续追溯到明细和依据。
5. 将正式采用的方案冻结留存，形成可审计的决策记录，并为合同、财务、项目执行等下游工作提供受控的数据出口。
6. 在固定业务规则与人工判断之间建立边界：计算结果必须稳定、可解释；AI 和人工调整只能形成新方案或建议，不能悄悄改掉正式版本。

### 1.2 目标使用场景

- 新地块初筛：短时间判断“继续研究、谈价、实地查看、合作开发还是放弃”。
- 正式可行性研究：把一块地拆成产品、面积、售价、车位、成本和费用，计算整体收益。
- 多方案决策：比较不同容积率、产品结构、效率、售价、成本和合作条件下的收益与风险。
- 复杂项目：多业态、多期、多地块和公共成本分摊，并汇总为整体项目结论。
- 管理层汇报：生成投资摘要、市场依据、核心指标、敏感性结果和建议动作。
- 决策后交接：保留批准版本，向下游提供只读查看或 Excel/后续财务系统接续所需的信息。

### 1.3 两层使用体验

| 用户层 | 主要关注 | 典型操作 |
| --- | --- | --- |
| 一线业务人员、投资/土地团队 | 数据是否准确、假设是否合理、改一个参数后全盘如何变化 | 建地块、查资料、填参数、调整产品与成本、试算、比较、提交 |
| 管理层、审批人 | 是否值得继续、预计赚多少、最怕什么、建议选哪一套 | 看结论、看关键依据、比较候选方案、通过/退回/选择方案 |

管理层看到的是“少而关键”的结论，不应被迫阅读完整计算表；但每个结论都必须能够回到明细和业务依据。

### 1.4 建设顺序与优先级（用户提出）

- **第一阶段（拿地判断闭环）**：地块台账、地块档案、地图、竞品/土地参考、快速评估、住宅正式测算、方案复制比较、管理层看板、基础审批、采用版本冻结。
- **第二阶段（复杂项目和可控交接）**：成本套餐与规则维护、敏感性增强、反算、JV、多期多业态、公共成本分摊、工业模板、只读交接、带依据的 Excel 导出。
- **第三阶段（投资组合与智能化）**：现金流、IRR/NPV、AI 公开资料分析、方案自动优化、移动端管理层问答、历史项目迁移、财务系统对接、跨项目组合分析。

## 3. 核心业务对象与状态

### 3.1 核心业务对象（用户提出）

| 业务对象 | 业务含义 | 生命周期要求 |
| --- | --- | --- |
| 地块机会 | 一宗正在评估或已经决策的土地机会，是所有资料和方案的归属中心 | 从新建、研究中、审批中，到完成、放弃/终止 |
| 地块档案 | 地块的名称、位置、权属、规划、附件、地图和研究进展 | 基础事实长期保留，变更需留痕 |
| 快速评估 | 用少量关键输入对土地机会做初筛 | 可快速修改，形成是否继续研究的判断 |
| 开发方案 | 一套完整的开发假设和测算结果，包括产品、面积、售价、成本和收益 | 可复制、可比较、可正式化、可冻结 |
| 基准方案 | 当前项目的基础版本，作为后续方案调整的起点 | 不被 AI 或临时试算覆盖 |
| 候选方案 | 从基准或其他方案复制出的调整版本 | 可反复修改，适合讨论和比较 |
| 正式方案 | 已完成检查、可以提交领导审批的版本 | 提交后应限制随意修改 |
| 采用方案 | 最终支持项目决策的版本 | 一经采用永久保留，不因后续研究变化而被覆盖 |
| 参考项目/竞品 | 周边竞品、历史成交地块、公司历史项目 | 记录来源、时间、可信度，支持后续复核 |
| 参数规则 | 各州、各业态、各费用项和政策的默认口径 | 可维护、可追溯；修改不改变历史正式方案 |
| 决策记录 | 推荐、谈价、实地查看、放弃、合作等最终动作和理由 | 与地块及采用方案一起长期保存 |

### 3.2 地块机会状态（用户提出）

1. **处理中**：正在收集资料、快速评估、方案研究或内部讨论。
2. **审批中**：已选定一个或多个正式方案，等待领导或指定审批人判断。
3. **已完成**：评估完成并明确采用的方案；完成后仍可查看，原则上不再直接改动采用版本。
4. **已放弃/已终止**：明确不继续推进，保留放弃原因和当时的判断依据。

状态允许由有权限的业务负责人手动调整（真实业务可能先线下决定、后补录系统），但每次状态变化必须记录时间、操作人、原状态、新状态和备注。

### 3.3 方案状态（用户提出）

- 草稿：正在填写或试算，可保存、刷新后继续。
- 已保存：作为可回溯的版本留存，但不能作为正式审批依据。
- 已正式化：完成必要检查并被标记为可提交审批的方案。
- 审批中：已进入领导审阅，不应被普通编辑覆盖。
- 已采用/已冻结：被最终决策选中的版本，只读保留。
- 未采用：同批方案中未被选中的版本，仍可查看；如需修改应复制为新方案。
- 已退回：审批人要求调整，原则上复制后形成新版本再提交。〔推荐〕（说明书建议项：退回后复制新方案调整再提交，不直接修改审批中的版本）

## 4. 业务模块需求

模块边界按用户任务划分，不按页面或内部实现划分。编号与说明书一致。

### M01 地块机会台账（P0）

- 支持新建地块机会，至少填写地块名称，后续逐步补齐资料。
- 支持按名称搜索，按状态、地区、负责人、更新时间、是否已完成等条件筛选。
- 列表展示核心摘要：地块名称、地区、面积、当前阶段、采用方案、预计 GDV、总开发成本、税前利润、利润率、负责人、更新时间。
- 支持从列表进入：地块档案、快速评估、正式测算、方案比较、地图、报告和审批记录。
- 已完成或已进入审批的地块不得无痕删除；应改为放弃/终止并保留原因。
- 支持进度概览（资料收集、市场研究、测算、审批是否完成）和地块附件（地契、规划资料、地主报价、会议材料、现场照片等）。
- 规则：地块是所有测算和方案的归属中心，不能出现脱离地块的孤立方案；地块状态与方案状态分开管理；完成意味着已有明确决策版本，不是点击“完成”按钮。

### M02 地块档案与权属核查（P0）

- 基本资料：地块/项目名称、内部编号；州、城市、地区、详细地址；地契/地权文件、Lot 信息、产权或租期、永久/租赁性质；总土地面积（默认平方英尺展示，保留英亩等原始单位）；当前用途、规划用途、分区、允许开发类型；地主报价、总地价、单位地价、付款条件、土地融资假设；是否需要用途转换、转换溢价、发展费及其他政府收费；地块所有权和公司资产归属。
- 核查清单：记录尚未确认事项——地契产权是否核实、现有用途是否支持目标开发、是否需要用途转换或额外审批、容积率/密度是否有政府依据、学校/墓地/道路/排水/公共设施贡献、发展费计入地价还是项目成本、现场交通/地形/拆除条件、哪些是假设/已确认/待确认。
- 规则：
  - 地块事实与测算假设必须区分；“免费持有”“需要转换”“无学校贡献”等应作为假设显示在报告中。
  - 州/地区可自动带出默认口径，业务人员可手动选择适用计算口径；地址与计算口径是两个独立字段。
  - 政府规则变化时更新后续方案的默认口径，不回写历史正式方案。
  - 地块所有权与公司资产归属不绑在个人名下。

### M03 位置、地图与周边环境（P0）

- 地图显示地块位置，可用点或不规则边界表示实际地块形状；每个项目支持独立颜色、标记和说明。
- 支持查看道路、交通节点、商场、学校、医院、山体、水体、现有住宅和商业项目等周边信息。
- 支持保存地图视图用于报告；报告中的地图保持稳定，不因后续地图操作改变历史版本。
- 支持跳转外部地图继续查看路线和现场位置；支持在地图上查看历史成交地块和竞品项目并与资料联动。
- 规则：地图信息是辅助判断，不自动替代产权、规划和政府审批核实；地图标记和项目资料归公司账号/公司资产管理。

### M04 市场与竞品研究（P0）

- 两类资料必须分开：
  1. **土地交易参考**：历史土地成交、附近地价、地价/平方英尺、地价占收入比例、交易时间、交易条件和资料来源。
  2. **住宅/商业竞品**：项目名称、距离、产品类型、户型面积、售价、单位售价、总户数、已售/在售、去化率、市场定位、优惠和可负担产品。
  两类资料可在报告中一起呈现，但不能把土地成交价直接当住宅售价，也不能把竞品报价当已验证成交价。
- 支持手工录入、导入或引用周边项目和历史地块；记录资料来源、发布/采集日期、成交或挂牌、可信度和备注。
- 支持按距离、地区、产品类型、价格区间和项目状态筛选；支持竞品户型、面积、售价、单位价格、去化情况和定位对比。
- 形成市场机会判断（高端/中端/可负担产品缺口、目标客群、建议产品方向）；支持展示区域热点、价格趋势、历史项目基准和可接受地价区间。
- 规则：AI 抓取或推断的资料默认“待确认”，不能自动成为正式方案的唯一依据；报告区分“市场事实”“业务判断”和“测算假设”；数据不足时提示需购买详细报告、实地调查或向政府确认，不伪造精确结论。

### M05 快速评估与机会筛选（P0）

- 核心输入：地块位置、面积、用途/规划、容积率或密度；初步产品类型、预计单位数或可售面积；单位售价/每平方英尺售价；初步土地成本和附加地价费用；初步建筑成本、杂项/政府贡献、专业费用、销售和市场费用、融资费用；可负担住房、土著配额和折扣等政策假设。
- 输出：预计总销售收入（GDV）；土著配额/折扣后净销售收入；建筑及基础设施成本、杂项及政府贡献、专业及项目费用、销售/市场费用、融资费用；总开发成本、税前利润和利润率；单位面积土地成本、土地成本占净收入比例、总成本占收入比例；PASS / REJECT / DROP 或“资料不足”初筛判断；下一步建议（继续市场研究、核查地契、实地查看、与地主谈价、合作开发或放弃）。
- 业务特点：快速评估是多个土地机会并列的投资漏斗，系统应提供“快速列表/组合视图”，能横向比较多个机会，而不仅是进入一个地块逐项查看。

### M06 开发方案与产品组合（P0）

- 产品维度：业态（住宅、公寓、服务式公寓、酒店、办公、零售、医疗、学校等）；产品档次/户型（Type A/B/C/D、可负担产品、Madani/SAMM/RSKU 等业务分类）；各产品面积占比或单位数占比；每单位建筑面积、可售面积、单位数、每单位车位数；单位售价、每平方英尺售价、可负担产品固定单价或政策价格；土著配额、土著折扣、可负担房比例和其他销售限制；车位（固定车位、访客车位、内部额外车位、车位面积和车位配比）；公共设施（会所、配套楼层、停车楼、道路、管网和其他公共空间）。
- 方案操作：新建基准方案；从基准方案复制不同容积率、密度、产品组合、效率、售价或成本标准的候选方案；支持按百分比调整产品组合，也支持直接调整某一产品的单位数、面积或售价；调整后自动显示是否超出总面积、总单位数、总收入或配比约束；支持把方案标记为草稿、正式化、候选或最终采用；方案名称应包含业务可识别的假设（如“容积率 4.0 / 可负担产品 15% / 不含会所”）。
- 关键规则：
  - 产品占比、效率等总和必须被校验；调整后不等于 100% 时必须提示并要求修正。
  - 产品类型计算逻辑可不同，但公共配套、车位、道路、管网等需明确分摊方式。
  - 政府最低车位要求与营销/内部目标车位必须分开记录。
  - 方案中每个假设都应能说明来源：政府要求、历史项目、市场判断、客户输入或人工估算。

### M07 正式可行性测算（P0）

**面积和开发强度**：总土地面积；容积率或单位密度；总建筑面积 GFA（含/不含车位两种口径）；净可售/可使用面积 NFA；不含车位效率、含车位综合效率；总单位数、每英亩单位数；塔楼、停车楼/裙房、配套设施等建筑面积分类。不同州面积口径可能不同（当前明确存在“雪兰莪特殊口径”和“其他州通用口径”两套）；系统按地区给出默认口径，允许业务人员手动选择，并在方案中保存所用口径和版本。

**收入**（对每种产品分别记录并汇总）：产品占比、单位数、每单位面积、总可售面积、单位售价或每平方英尺售价、产品销售额、土著配额和折扣、可负担产品的政策数量/价格/收入、车位及其他可销售项目收入。收入链路：`产品面积 × 产品售价 → 各产品销售额 → 总销售收入 → 土著配额/折扣调整 → 净销售收入`。

**成本**（按业务责任和管理用途拆分，不把所有项目塞进“杂项”）：

1. 土地成本：土地总价、单位地价、法律费、印花税、土地融资和相关手续费。
2. 主体建筑：塔楼、停车楼、配套楼层、结构、机电、外立面、初步工程等。
3. 基础设施：场地平整、土方、拆除、内部/外部道路、排水、管网、垃圾房、保安亭、景观、公共区域装修、变电站、废物处理、标识、健身设施、充电设施等。
4. 家具、设备和装修：厨房、空调、热水器、智能家居、活动/固定家具、室内设计等。
5. 预备费、税费和建筑相关税费。
6. 杂项及政府贡献：测量、示范单位、开发商牌照、规划费、用途转换溢价、发展费、租期延长、地契测量、供电、污水、供水、道路排水、河流排水、墓地、通信等。
7. 专业及项目管理费用。
8. 销售与市场费用、法律费用。
9. 融资费用：土地贷款、建设融资及持有期间利息。

**收益**：总开发成本 TDC；税前利润 PBT；税后利润 PAT（如财务规则提供）；利润率 PM＝税前利润 ÷ 净销售收入；单位、可售面积、建筑面积和每英亩的成本/收益指标；收入结构、总成本结构、成本内部明细结构。核心收益链路：`总销售收入 − 土著/政策折扣 = 净销售收入；净销售收入 − 总开发成本 = 税前利润；税前利润 ÷ 净销售收入 = 利润率`。

**可解释性**：每个汇总数字可展开查看组成项；每个可调整项显示单位、计算依据、来源和备注；固定项、自动计算项、人工估算项、政策项有明显区分；全部空缺费用明确为 0 或“待确认”，不让用户误以为已纳入；估算阶段保留计算精度，显示时可按业务习惯四舍五入，但不能用显示值反过来破坏计算值。

### M08 成本、费用与政策口径维护（P0/P1）

- 可维护内容：各州面积计算口径和默认方案；建筑成本、基础设施、家装和公共配套的成本套餐；不同装修标准、家具配置、停车配置的成本档位；土地用途转换溢价、发展费、政府贡献和公共设施费用；土著配额、折扣、可负担住房比例和政府车位要求；专业费、项目管理费、销售市场费、融资费的比例或固定值；费用项名称、说明、计量方式和适用地区/业态；下拉选项、单位、业务术语和提示文案。
- 费用录入要求：每个费用项至少支持以下一种方式——固定金额；按土地面积；按建筑面积或可售面积；按收入比例；按成本比例；按单位数、车位数或项目年限。
- 成本和费用“尽量全量列出”，无需使用的项目可填 0 或停用，避免日后因缺少空白项反复改表；对确有未知费用的类别，提供 Others 空白项、备注和来源。

### M09 复杂项目、多期、多业态与分摊（P1）

- 一个地块下建立多个期次；每期可包含住宅、服务式公寓、酒店、办公、零售、医疗、学校等业态；每个业态独立记录土地分配、建筑面积、可售面积、单位/房间/钥匙数量、售价、成本和收益。
- 公共成本单独记录，并按约定的可售面积、建筑面积或其他业务比例分摊；显示分摊前金额、分摊规则和各期承担金额，并校验分摊后总额一致。
- 支持按地块、期次、业态查看，也支持汇总为整个项目的 GDV、TCC、TDC、利润和利润率；允许比较不同分期比例、效率比例、产品比例、酒店/学校/会所有无等组合。
- 规则：不同业态的收入、成本、销售节奏可能不同，不能把所有行当成住宅；“不含酒店”“含学校”“含会所”“含/不含可负担住房”等应作为方案假设，不得只写在文件名中；多期项目土地成本可按土地面积或建筑面积等方式分配，采用哪种方式必须可见并可调整；历史 Excel 中的断链或错误引用只作为业务案例和结构依据，不能自动视为正确结果。

### M10 方案版本、比较与决策分析（P0）

- 版本要求：基准方案永远保留；AI、管理层或业务人员的临时调整默认产生预览或复制方案，不覆盖基准方案；复制时保留来源方案、复制时间、复制人和修改说明；方案可长期保存，支持回看当时的假设和结果；正式化后才能进入审批，审批中不允许普通用户直接覆盖；已采用版本冻结，需要进一步研究时复制出新方案。
- 比较内容（同时比较多套方案）：土地面积、容积率/密度、效率和总单位数；产品组合、业态比例、可负担住房比例和车位配置；各产品售价、总销售收入、净销售收入；土地成本、建筑成本、基础设施、家装、杂项、专业费、销售市场费、融资费；总开发成本、税前利润、利润率、单位/每平方英尺指标；现金投入、回款周期、IRR/NPV（现金流模块启用后）；风险和未确认事项。
- 管理层既能看到“摘要比较”，又能进入某一方案查看详细组成和假设差异。

### M11 敏感性、压力测试与反算（P1，建筑成本维度为会议明确必含项）

- 分析维度至少支持：土地总价或单位地价；产品售价/平均售价；建筑成本或成本套餐；容积率、密度、建筑效率；用途转换溢价、发展费、政府贡献；融资比例、利率和融资年限；产品组合、可负担产品比例、车位数量。
- 使用方式：用户输入变量范围（可逗号分隔或批量复制编辑）；系统生成二维或多维组合结果；结果展示利润率、利润、总成本、净收入等关键指标；用颜色提示目标利润率（如 18% 目标线），颜色规则可配置、不写死在页面；支持指定目标利润率反算可接受最高地价、最低售价或可承受最高建筑成本；对明显不可行的组合给出风险提示，不展示没有业务价值的“零利润盈亏平衡线”作为主要结论。

### M12 合作开发与收益分配（P1）

- 记录各方角色（地主、开发商、投资方等）；记录土地、土地融资、建设资金由谁承担；配置股权比例、利润分成比例和其他优先安排；计算各方承担的土地成本、资金投入、利润、回报和回报率；支持比较 80/20、70/30、65/35 等不同合作比例。
- 规则：在总项目收益与合作方收益之间建立清晰对应关系；合作条款属于方案假设，变更合作比例应复制新方案并留痕；报告需明确“项目赚多少”和“我方最终拿到多少”不是同一个指标。

### M13 现金流与投资回报（P1，依赖财务确认）

- 业务内容：土地支付节点和土地融资；规划、转换、政府贡献和前期费用支付节点；建设进度与分期建设成本；销售启动、签约、收款和交付节点；不同回款速度、回款比例和销售情形推演；融资提款、利息、还款和资金缺口；现金净流量、峰值资金需求、IRR、NPV、回报周期和融资比较。
- 规则：现金流规则必须由财务部门确认后正式使用；规则未确认前，页面应明确是“初步情景”，不能与正式利润结论混用。

### M14 投资报告、看板与决策建议（P0）

- 报告结构：
  1. 项目结论：建议继续/放弃/谈价/实地查看/合作开发，及一句话原因。
  2. 地块概况：位置、面积、产权、用途、规划、地主报价、支付条件和待核查事项。
  3. 位置和可达性：地图、道路、周边商业、学校、医院、竞品和客群范围。
  4. 市场研究：竞品、历史交易、售价、去化、市场缺口和价格依据。
  5. 开发方案：产品组合、面积、单位、效率、车位、可负担产品和政策假设。
  6. 财务摘要：GDV、土著折扣、净 GDV、土地成本、建筑成本、总开发成本、税前利润、利润率。
  7. 成本结构：收入中的土地、建筑、费用、利润占比；成本内部明细占比。
  8. 敏感性与风险：地价、售价、建筑成本、容积率等变量变化后的结果。
  9. 合作或分期方案：不同合作分成、分期或业态组合的影响。
  10. 推荐动作：应继续做什么、由谁做、完成条件是什么。
- 看板要求：默认先展示结论和核心指标，不把内部项目简报或尚未完成的中间内容放在最前面；固定展示项目定位、收益结论、推荐方案、风险和下一步动作；历史成交和详细计算放在后续区域；新数据尚未核算完成时不把不完整结果伪装成最终结论；管理层从 AI 或移动端提问时，结论必须能跳回对应地块和方案明细。

### M15 审批、冻结与决策留痕（P0）

- 审批流程：
  1. 业务人员完成一个或多个方案。
  2. 将需要领导看的方案正式化。
  3. 从正式化方案中选择一套或多套提交审批。
  4. 审批人查看摘要、明细、市场依据和风险。
  5. 审批人选择采用方案，或退回要求调整。
  6. 通过后，选中的方案成为采用/冻结版本；未选中的方案保留为未采用历史。
  7. 退回时说明原因；业务人员复制原方案调整后重新提交，不直接改审批中的版本。〔推荐〕（说明书建议项）
  8. 地块标记为已完成时，必须关联一个明确的采用方案。
- 权限原则：
  - 默认所有相关人员可查看，只有方案负责人或授权业务人员可编辑。
  - 其他人员如需调整，应复制方案。
  - 管理层重点查看和决策，不默认拥有直接修改基础方案的权限。〔推荐〕（说明书建议项：领导默认只读，通过复制提出调整）
  - 审批人可查看详细计算和依据，但不修改业务团队的基础数据。
- 审计要求：记录提交人、审批人、审批时间、意见、选中的方案、退回次数、每次版本差异和最终状态；历史正式方案和采用方案永久保留。

### M16 结果交接与下游协作（P1）

- 当前实际工作常通过 Excel 交接；目标是系统提供可控的结果导出，最好保留公式、数据依据和关键假设；下游只需复制数据时提供不带公式的受控结果文件，但必须附带口径说明。
- 下游人员使用只读页面或专门交接视图，不获得投资基础数据的广泛编辑权限；未来可与金蝶等财务系统衔接，但必须先统一数据口径、字段和正式版本规则。
- 交接内容：地块和产权基本信息；采用方案及其版本号；收入、成本、费用、利润和利润率；全部假设、政策口径、分摊规则和待确认事项；审批结论、审批意见和决策日期；可供下游继续工作的明细数据和附件。
- 如需调整，不改投资冻结版本，由下游发起业务变更或新版本申请。

### M17 AI 助手与智能分析（P1）

- AI 可以做：根据地块名称、位置和已有档案整理竞品、历史成交、规划公开资料和政策线索；归纳市场趋势、竞品差异、产品缺口和风险；根据用户指令调整产品比例、售价、容积率、装修标准、车位或成本项目形成新方案建议；针对达不到目标利润率的方案说明应降低地价、提高售价、优化产品组合或降低成本的方向；自动生成多方案摘要、敏感性结论和管理层问答；在移动端为管理层提供核心指标和方案解释。
- AI 不能做：不能自行发明未经确认的固定计算公式；不能把推测数据伪装成政府或市场事实；不能覆盖基准方案、正式方案或采用方案；不能绕过审批直接改变项目状态；不能将未确认的公开信息直接写入正式结论。
- 人机协作规则：
  1. AI 输出先作为建议、草稿或临时方案。
  2. 用户查看来源、确认关键参数。
  3. 用户确认后才同步成为平台中的可追溯方案。
  4. AI 生成的方案必须能跳转到后台明细，看到相同的业务口径和计算依据。
  5. 管理层在 AI 端的临时问答默认不改变内部基础版本。

### M18 用户、权限与业务参数维护（P0）

- 用户角色见第 2 章；权限原则见 M15。
- 参数维护原则：业务术语、字段说明和选项名称可维护；州属默认规则、政策比例和费用标准可维护；修改参数必须记录生效时间、修改人和适用范围；新规则只影响新建或重新选择规则的方案，历史正式方案保留当时口径；对存在争议的规则，允许保留人工选择并要求填写备注。

## 5. 核心业务链路与计算口径

### 5.1 关键链路（用户提出）

1. **机会到决策链**：`地块机会 → 权属/规划核查 → 地图与周边 → 土地交易/竞品 → 快速评估 → 正式方案 → 敏感性/风险 → 管理层审批 → 采用/放弃 → 下游交接`。任何环节的结论都应能回到前一环节的资料和假设。
2. **收入到利润链**：`产品组合 → 面积/单位 → 售价 → 产品销售额 → 总销售收入 → 政策配额/折扣 → 净销售收入 → 各类成本费用 → 总开发成本 → 税前利润 → 利润率`。“销售收入”和“净销售收入”必须同时保留，不能只展示一个笼统的 GDV。
3. **方案版本链**：`基准方案 → 复制候选 → 调整变量 → 保存历史 → 正式化 → 审批 → 采用并冻结`。临时试算、AI 建议、管理层询问都只能进入基准方案的副本或预览，不得直接覆盖正式版本。
4. **审批与冻结链**：`草稿 → 已保存 → 正式化 → 审批中 → 通过并选择采用方案 → 冻结 → 项目完成`。“项目完成”必须回答：采用了哪套方案，以及该方案在什么时间、由谁批准。
5. **证据到结论链**：`来源资料 → 业务事实/市场判断 → 测算假设 → 计算结果 → 风险提示 → 推荐动作`。来源不明、未确认或 AI 推断的内容应标记，不与政府确认数据混为一谈。
6. **地价总额与单位地价双向链**：支持“先填总地价由面积反算单位地价”和“先填单位地价由面积反算总地价”两种录入；两边同时存在时以“最后编辑的字段”为本次计算输入，保留显示精度和实际计算精度，不因界面四舍五入导致两边长期不一致。
7. **地区口径链**：当前至少存在两套面积计算口径（雪兰莪特殊口径、其他州通用口径）；系统按州属/地址自动给默认口径；业务人员可手动切换并填写原因；地址和口径版本是两个独立业务信息；政府规则变化时新增或更新口径，历史方案仍保留原口径。
8. **车位链**：`产品/单位数 → 固定车位 → 访客车位 → 内部目标车位 → 车位面积/GFA → 车位相关成本与收益`。政府最低车位要求与市场/营销内部目标可能不同，必须分别展示、分别可调，并明确最终用于测算的是哪一项。
9. **多业态公共成本链**：`各业态独立成本 + 公共成本 → 按约定口径分摊 → 各期/各业态成本 → 全项目汇总`。分摊必须满足“各分项之和等于总额”，并可反查分摊前后数字。
10. **管理层结论链**：`完整明细 → 核心指标 → 推荐方案 → 关键风险 → 可承受范围 → 下一步动作`。管理层不需要先学习测算表，但不能失去查看依据和明细的权利。

### 5.2 业务指标与口径（用户提出）

| 指标 | 业务含义 | 必须说明的口径 |
| --- | --- | --- |
| GDV | 按方案销售产生的总收入 | 是否含车位、商业、酒店、其他可售项目 |
| 土著配额/折扣 | 因配额和折扣导致的收入调整 | 配额比例、折扣比例、适用产品 |
| 净 GDV | 调整政策折扣后的销售收入 | 调整前后都要可追溯 |
| GFA | 总建筑面积 | 是否含车位、公共设施、停车楼/裙房 |
| NFA | 净可售/可使用面积 | 由哪个地区口径、效率如何得到 |
| 效率 | 建筑面积转为可售/可用面积的比例 | 含不含车位，塔楼和公共部分是否分开 |
| TCC | 主体建筑及相关建造成本 | 是否含基础设施、家装、预备费、税费 |
| TDC | 总开发成本 | 土地、建造、杂项、专业、销售、融资是否齐全 |
| PBT | 税前利润 | 净 GDV 减总开发成本 |
| PAT | 税后利润 | 需有财务确认的税务口径〔未规定〕 |
| PM | 利润率 | 税前利润 ÷ 净 GDV；目标线可配置 |
| 土地成本占比 | 地价对项目收入的压力 | 分母是 GDV 还是净 GDV 必须统一 |
| 单位/面积指标 | 与历史项目和竞品比较 | 每单位、每建筑面积、每可售面积、每英亩需区分 |
| IRR/NPV | 投资时间价值和资金回报 | 仅在现金流假设经财务确认后作为正式指标 |

- 历史材料中“总成本占收入比例”管理判断（低于 50% 优秀、50%–55% 可接受、56%–60% 高风险、超过 60% 不建议）可作为公司可配置的决策红线候选，未经确认不作为所有项目通用结论。〔未规定〕
- 土地成本占比的分母（GDV 或净 GDV）必须统一。〔未规定〕具体采用哪个分母待业务确认。

## 6. 用户旅程（摘要）

- **旅程 A（土地团队从发现机会到快速判断）**：新建地块机会并补齐权属、用途、地价、付款条件等资料和附件 → 地图确认位置、边界、交通和周边 → 录入/引用土地成交和竞品并标来源与可信度 → 建立快速评估（选地区/政策口径，输入容积率、产品、售价、成本）→ 系统输出 GDV、净 GDV、TCC、TDC、PBT、PM、土地成本占比和风险提示 → 选择下一步（正式测算、谈价、实地查看、查产权/政府、JV、放弃）→ 保存初筛版本和判断理由。
- **旅程 B（从基准方案形成正式可行性研究）**：从快速评估进入正式测算生成基准方案 → 确认面积、州属、适用口径、容积率/密度和效率 → 设计产品组合（占比、单位数、面积、售价、可负担产品、车位）→ 核对 GFA、NFA、总单位数、车位总数和比例平衡 → 核对销售收入、土著配额/折扣和净销售收入 → 逐项补充九类成本 → 展开汇总核对业务组成、补充假设与来源 → 系统计算 TDC、PBT、PAT、PM 和单位指标并提示不平衡或缺失 → 保存基准方案，必要时正式化。
- **旅程 C（不破坏原方案的前提下探索新方案）**：复制基准方案为候选 → 修改变量（容积率、产品比例、售价、效率、车位、装修标准、建设成本、可负担比例、分期或合作分成）→ 系统自动更新并提示约束 → 写明方案假设 → 复制多套方案保留独立结果 → 进入方案比较 → 敏感性和目标利润反算确认地价/售价/成本可接受范围 → 将最有价值的方案正式化准备提交。
- **旅程 D（多期、多业态项目整体评估）**：一个地块下建立多期 → 每期设置业态 → 每业态设置面积、产品、价格、单位/房间数量、车位和独立成本 → 设置共享成本及分摊规则 → 分别查看各期/各业态收入、成本、利润和回报 → 汇总整体指标 → 比较不同组合 → 将分摊依据、总额校验结果和特殊假设写入报告。
- **旅程 E（管理层审阅并确定采用方案）**：打开地块看板先看推荐结论、核心指标、风险和下一步 → 查看位置、竞品、土地资料和关键假设 → 比较多套正式方案（GDV、TDC、PBT、PM、现金需求和敏感性）→ 有疑问时进入方案详情追溯，或通过 AI 询问假设变化影响 → 选择采用方案或退回并填写调整意见 → 通过后采用方案冻结、其他方案标为未采用 → 地块状态改为已完成，记录决策日期、负责人、审批意见和下一步交接对象。
- **旅程 F（评估完成后交给下游部门）**：确认采用方案及审批记录 → 生成受控交接结果（采用方案、明细、假设、来源、审批意见和附件）→ 以只读页面或 Excel 提供给下游并说明每个关键数字的来源和口径 → 下游复制/接入自己的模板或未来直接进入财务系统 → 如需调整，由下游发起业务变更或新版本申请，不改投资冻结版本。
- **旅程 G（AI 辅助研究与移动查询）**：用户告知 AI 地块名称、位置或要比较的方案 → AI 汇总已有档案、竞品、交易、政策和测算结果并标出来源和不确定项 → 用户要求调整产品比例、售价、成本或容积率 → AI 生成预览或候选方案并解释变量影响 → 用户确认后候选方案进入平台保存，未确认内容只停留在临时分析 → 管理层在移动端查看摘要，需要时打开后台明细。
- **旅程 H（业务负责人维护地区规则和成本标准）**：管理员新增或修改州属、业态、成本套餐、费用项、政策比例和下拉选项 → 指定生效时间和适用范围 → 新方案选择默认口径，业务人员有理由时可手动切换 → 系统保留参数变更记录，历史正式方案仍显示原口径。

## 7. 关键横切规则

1. **事实与假设分层**：地块事实、市场事实、业务判断、测算假设、计算结果、风险提示、推荐动作必须区分呈现；来源不明、未确认或 AI 推断的内容明确标记，不与确认数据混同。
2. **版本不可覆盖原则**：基准方案、正式方案、采用方案不被 AI、管理层或临时试算覆盖；一切调整通过复制或预览产生新版本。
3. **永久与长期保留**：采用方案与决策记录永久保留；历史正式方案永久保留；方案版本长期保存并支持回看；地块基础事实长期保留且变更留痕。
4. **公司资产归属**：地块所有权、地图标记、项目资料和账号归属公司，不依附单一员工个人账号。
5. **计算精度**：估算阶段保留计算精度；显示可按业务习惯四舍五入，显示值不得反写或破坏计算值（含地价双向录入场景）。
6. **政策与口径不写死**：政策、车位、可负担产品和州属计算口径可能变化，默认值不写死为永久规则；参数修改记录生效时间、修改人和适用范围，只影响后续新建方案。
7. **历史 Excel 材料使用原则**：Excel 字段、业务概念和分析结构可作为需求依据；正式公式和政策数字必须由业务负责人确认后才能作为验收口径；历史文件中的异常结果、断链或错误引用不能复制为系统规则；会议明确的业务意图优先于旧文件偶然写法。

## 8. 未规定与待确认事项

以下事项由说明书明确提出但尚未形成最终统一口径，作为产品验收前的业务决策清单，本文不替用户决定（〔未规定〕）：

1. 多审批人是“全部通过”还是“任意一人通过”。
2. “已完成”是否必须选择采用方案（本文按说明书正文“必须关联采用方案”执行），以及完成后项目状态能否再次打开。
3. 审批退回后原方案继续修改还是强制复制新方案（说明书建议复制新方案，本文作为推荐基线）。
4. 领导是否允许直接编辑方案（说明书建议默认只读、通过复制提出调整，本文作为推荐基线）。
5. UAT 是否必须提供带公式 Excel 导出，还是先提供带依据的结果导出。
6. 下游团队需要只读页面、无公式数据文件、带公式文件，还是未来直接接财务系统。
7. 雪兰莪特殊口径与其他州口径的正式名称、适用州、切换权限和生效日期。
8. 政府最低车位要求、内部营销目标车位的正式字段和最终采用规则。
9. 可负担产品类型、比例、价格和各州适用政策的完整清单。
10. 发展费、学校、墓地、道路、排水等贡献何时计入项目成本、何时由地主承担或计入地价。
11. 工业项目模板、工业成本项、税费、单位和收益口径。
12. 现金流的标准回款节点、回款比例、施工进度、融资方式和财务验收标准（现金流规则未经财务确认前仅作“初步情景”）。
13. 敏感性分析的正式目标利润率、颜色区间、默认范围和可调整维度。
14. 历史项目是否全部迁移，还是只迁移进行中项目；迁移后的数据是否允许重新计算。
15. AI 可访问的公开资料来源、抓取频率、引用格式和人工确认责任人。
16. 地图使用公司的账号和资产归属方式，以及外部地图服务的商业授权边界。
17. PAT 的税务口径；IRR/NPV 的财务确认规则。
18. 土地成本占比的分母（GDV 或净 GDV）统一口径。

## 9. 验收标准

以下 AC 覆盖说明书第 10 章业务验收语言及核心目标（快速评估、AI 人机协作）。入口类型仅表示交互入口，不指定页面布局或产品载体。

### AC-01：地块机会可建立、归档与检索
- 验收条件：业务人员可新建地块机会（至少填写地块名称）并逐步补充权属、位置、规划、地价、付款条件、附件和待核查事项；可按名称搜索并按状态、地区、负责人、更新时间等条件筛选；列表展示地块名称、地区、面积、当前阶段、采用方案、预计 GDV、总开发成本、税前利润、利润率、负责人和更新时间等核心摘要；已完成或已进入审批的地块不得无痕删除，只能放弃/终止并保留原因；写入的地块资料可通过读取行为读回。
- 入口类型：用户界面
- 验证动作：新建仅含名称的地块机会并保存；补充地契、规划、地价、付款条件等资料与附件并保存；按名称搜索并按状态筛选；刷新后重新打开该地块查看资料；对已进入审批的地块尝试删除。
- 预期结果：地块可创建、补充并保存；搜索和筛选能定位该地块；列表显示核心摘要字段；刷新重开后已保存资料仍可读回；审批中/已完成地块的删除被拒绝，仅允许放弃/终止并要求填写原因。
- 证据类型：interaction, session-persistence, error-feedback

### AC-02：地图展示真实位置且历史报告稳定
- 验收条件：地图显示地块真实位置，可用点或不规则边界表示实际地块形状；可查看道路、主要交通节点、商场、学校、医院、现有住宅和商业项目等周边信息；保存的地图视图用于报告后保持稳定，不因后续地图操作改变历史版本。
- 入口类型：用户界面
- 验证动作：打开地块地图查看位置与边界形状；查看周边配套信息；保存地图视图到报告；随后在地图上执行新的操作（移动、缩放、标记其他项目），再查看原报告中的地图。
- 预期结果：地图正确显示地块位置与边界形状；周边信息可见；报告中的地图视图与保存时一致，不随后续操作变化。
- 证据类型：runtime-render, interaction

### AC-03：快速评估产出初筛结论并支持多机会横向比较
- 验收条件：对地块输入位置、面积、用途/规划、容积率或密度、初步产品与售价、土地成本和主要成本等少量关键输入后，系统输出预计总销售收入（GDV）、土著配额/折扣后净销售收入、各项成本、总开发成本、税前利润、利润率、单位面积土地成本和土地成本占比，并给出 PASS / REJECT / DROP 或“资料不足”初筛判断及下一步建议；系统提供快速列表/组合视图，可横向比较多个机会，而不仅进入单个地块逐项查看。
- 入口类型：用户界面
- 验证动作：新建快速评估填写核心输入并试算；修改其中一个关键输入（如售价或容积率）重新试算；在快速评估列表/组合视图中比较多个机会。
- 预期结果：输出完整的初筛指标、判断结论和下一步建议；输入修改后结果同步更新；组合视图可横向比较多个机会的核心指标。
- 证据类型：interaction, runtime-render

### AC-04：正式测算联动更新、输入校验与地价双向录入
- 验收条件：修改土地面积、容积率/密度、效率、产品比例、售价、车位或成本后，相关收入、成本和收益同步更新；产品占比、效率等总和不等于 100%，或单位数与面积不匹配、车位不足或超过约束时，系统明确提示并要求修正；总地价与单位地价可双向录入，以最后编辑的字段为本次计算输入，显示精度不导致两边长期不一致；土地、主体建筑、基础设施、家装、预备费税费、杂项/政府贡献、专业及项目管理、销售市场、融资等成本全部单独可见，不把所有项目塞进“杂项”。
- 入口类型：用户界面
- 验证动作：进入正式测算调整产品占比使其总和不等于 100%；调整容积率和售价观察结果联动；分别以总地价和单位地价两种方式录入并交替编辑；查看成本分类展示。
- 预期结果：调整后收入、成本、收益联动更新；占比不平衡出现明确提示并要求修正；两种地价录入方式均能按土地面积换算且以最后编辑项为计算输入、两边不因精度出现持续不一致；九类成本分别可见。
- 证据类型：interaction, error-feedback, runtime-render

### AC-05：测算结果可展开、可追溯且空缺显式
- 验收条件：每个汇总数字可展开查看组成项；每个可调整项显示单位、计算依据、来源和备注；固定项、自动计算项、人工估算项、政策项有明显区分；全部空缺费用明确为 0 或“待确认”，不让用户误以为已纳入；方案中每个假设能说明来源（政府要求、历史项目、市场判断、客户输入或人工估算）；“销售收入”与“净销售收入”同时保留。
- 入口类型：用户界面
- 验证动作：展开一个汇总指标（如总开发成本或税前利润）逐级查看组成项；查看某费用项的依据、来源和类型标注；留空一项费用查看显示；查看收入汇总。
- 预期结果：汇总可逐级展开到业务明细；费用项的口径、来源和类型可见；空缺费用显示 0 或“待确认”；销售收入与净销售收入同时展示。
- 证据类型：interaction, runtime-render

### AC-06：方案版本隔离，修改与 AI 试算不覆盖正式版本
- 验收条件：基准方案永远保留，不被 AI、管理层或业务人员的临时调整覆盖；从基准或其他方案复制候选方案时保留来源方案、复制时间、复制人和修改说明；正式化后进入审批的方案不被普通编辑覆盖；已采用版本冻结只读；退回的方案复制出新版本再提交〔推荐〕；修改候选方案或 AI 试算后，原基准/正式/采用方案内容不变。
- 入口类型：用户界面
- 验证动作：从基准方案复制候选方案并修改多个变量后保存；核对基准方案内容；对一个已正式化/审批中的方案尝试直接编辑；让 AI 试算一次调整；核对基准方案与已采用方案内容。
- 预期结果：候选方案独立保存修改结果；基准方案保持复制前内容不变；正式化、审批中、已采用的方案不被普通编辑或 AI 覆盖，需复制新方案；复制记录来源方案、时间、复制人和修改说明。
- 证据类型：interaction, session-persistence, authorization

### AC-07：多方案并列比较且可下钻明细
- 验证动作：选择两套以上方案进入比较视图；查看摘要比较；从比较视图进入其中一个方案的明细与假设。
- 验收条件：可同时比较多套方案，比较内容至少包括土地面积、容积率/密度、效率和总单位数，产品组合、业态比例、可负担住房比例和车位配置，各产品售价、总销售收入、净销售收入，土地成本、建筑成本、基础设施、家装、杂项、专业费、销售市场费、融资费，总开发成本、税前利润、利润率、单位/每平方英尺指标，以及风险和未确认事项；管理层既能看摘要比较，也能进入某一方案查看详细组成和假设差异。
- 入口类型：用户界面
- 预期结果：比较视图按维度并列展示各方案指标与差异；可从比较视图进入单方案明细与假设。
- 证据类型：runtime-render, interaction

### AC-08：审批闭环、采用冻结与全程留痕
- 验收条件：只有已正式化的方案能提交审批；审批人可查看摘要、明细、市场依据和风险，选择采用方案或退回并说明原因；通过后选中方案成为采用/冻结版本（只读），未选中方案保留为未采用历史；地块标记为已完成时必须关联一个明确的采用方案；放弃/终止保留原因；审计记录提交人、审批人、审批时间、意见、选中方案、退回次数、每次版本差异和最终状态；历史正式方案和采用方案永久保留。
- 入口类型：用户界面
- 验证动作：尝试提交一个未正式化的草稿方案（应被拒绝）；将正式化方案提交审批；以审批人身份查看并退回一次（填写原因）；业务人员复制调整后重新提交；审批通过并采用其中一套方案；将地块标记为已完成；查看审批与决策记录并刷新确认仍在。
- 预期结果：草稿不能提交审批；退回要求填写原因且原版本不被直接修改（复制后调整）；采用后该方案冻结只读、同批其他方案标记未采用；地块完成必须关联采用方案；提交人、审批人、时间、意见、退回次数、版本差异和最终状态全程可查且持久保留。
- 证据类型：interaction, authorization, session-persistence

### AC-09：管理层看板结论优先且核心数字可追溯
- 验收条件：管理层打开地块看板先看到结论（建议继续/放弃/谈价/实地查看/合作开发及一句话原因）、核心指标、推荐方案、关键风险和下一步动作，不必先阅读完整计算表；历史成交和详细计算放在后续区域；所有核心数字可追溯到具体方案和业务依据；新数据尚未核算完成时，不把不完整结果伪装成最终结论。
- 入口类型：用户界面
- 验证动作：以管理层身份打开地块看板；从结论或核心指标跳转到对应方案明细与业务依据；查看一个测算尚未完成的方案。
- 预期结果：看板首屏呈现结论、核心指标、推荐方案、风险和下一步动作；点击可回溯到方案明细和来源；未完成核算的内容被明确标注，不展示为最终结论。
- 证据类型：runtime-render, interaction

### AC-10：下游受控交接且投资基础数据不可被下游修改
- 验收条件：评估完成后可生成受控交接结果，包含地块和产权基本信息、采用方案及其版本号、收入/成本/费用/利润和利润率、全部假设、政策口径、分摊规则和待确认事项、审批结论、审批意见和决策日期、明细数据和附件；下游人员通过只读页面或受控导出的结果文件（附带口径说明）使用，不获得投资基础数据的广泛编辑权限；如需调整，不改投资冻结版本，由下游发起业务变更或新版本申请。
- 入口类型：用户界面
- 验证动作：对已完成地块生成交接结果；以下游部门角色查看交接内容；尝试修改投资基础数据；对冻结版本发起调整。
- 预期结果：交接内容完整包含口径、依据、假设和审批记录；下游角色为只读，修改被拒绝；调整只能通过业务变更或新版本申请进行，冻结版本不被改动。
- 证据类型：interaction, authorization, runtime-render

### AC-11：多期多业态独立核算与公共成本分摊总额一致
- 验收条件：一个地块下可建立多个期次，每期可包含住宅、服务式公寓、酒店、办公、零售、医疗、学校等多种业态；每个业态独立记录土地分配、建筑面积、可售面积、单位/房间/钥匙数量、售价、成本和收益；公共成本单独记录并按约定的可售面积、建筑面积或其他业务比例分摊，显示分摊前金额、分摊规则和各期承担金额，并校验分摊后总额一致；支持按地块、期次、业态查看，也支持汇总为整个项目的 GDV、TCC、TDC、利润和利润率；“不含酒店”“含学校”“含会所”“含/不含可负担住房”等作为方案假设显式记录，不只写在文件名中；多期土地成本分配方式可见并可调整。
- 入口类型：用户界面
- 验证动作：建立两期、每期两种业态的项目；录入各业态收入成本与公共成本分摊规则；查看分摊前金额、分摊规则、各期承担金额和总额校验结果；查看按期/按业态和全项目汇总；调整土地成本分配方式。
- 预期结果：各期各业态分别核算并可查看；公共成本分摊前后金额、规则和各期承担额可见，分摊后各分项之和等于总额；项目整体汇总指标正确；方案假设与分配方式显式记录且调整生效。
- 证据类型：interaction, runtime-render

### AC-12：车位政府要求与内部目标分离记录
- 验收条件：政府最低车位要求与营销/内部目标车位分别记录、分别可调并可比较；最终用于测算的口径明确标示；车位数量变化联动车位面积/GFA 及车位相关成本与收益。
- 入口类型：用户界面
- 验证动作：在方案中分别录入政府最低要求和内部目标两组车位数量；调整其中一组；查看测算采用的车位数量、车位面积和相关成本。
- 预期结果：两组车位数量分别保存、并列显示且可比较；测算明确标示采用哪一组并保持一致；车位面积/GFA 与车位相关成本收益随调整更新。
- 证据类型：interaction, runtime-render

### AC-13：敏感性分析含建筑成本并支持目标反算
- 验收条件：敏感性分析至少支持土地总价/单位地价、产品售价、建筑成本、容积率/密度/效率、用途转换溢价/发展费/政府贡献、融资比例/利率/年限、产品组合/可负担比例/车位数量等维度（建筑成本为会议明确必含维度）；用户输入变量范围（可逗号分隔或批量复制编辑）后系统生成二维或多维组合结果，展示利润率、利润、总成本、净收入等关键指标；用颜色提示目标利润率（如 18% 目标线），颜色规则可配置、不写死在页面；支持指定目标利润率反算可接受最高地价、最低售价或可承受最高建筑成本；对明显不可行的组合给出风险提示，不以“零利润盈亏平衡线”作为主要结论。
- 入口类型：用户界面
- 验证动作：选择建筑成本与售价两个维度输入范围生成结果矩阵；修改目标利润率线的颜色规则；指定目标利润率反算可接受最高地价；查看明显不可行的组合。
- 预期结果：建筑成本维度可参与敏感性并正确联动利润率、利润、总成本、净收入；结果矩阵用可配置颜色提示目标线；反算返回对应上限值；不可行组合有风险提示。
- 证据类型：interaction, runtime-render

### AC-14：口径参数版本化，历史正式方案按原口径复现
- 验收条件：各州面积计算口径（当前至少雪兰莪特殊口径与其他州通用口径两套）、成本套餐、政策比例、费用项等参数可维护；系统根据州属/地址自动给出默认口径，业务人员可手动切换适用口径并填写原因；地址与计算口径为两个独立信息；参数修改记录生效时间、修改人和适用范围；新规则只影响新建或重新选择规则的方案，历史正式方案保留当时口径并可按原口径复现。
- 入口类型：用户界面
- 验证动作：修改某州默认口径或成本参数并记录生效信息；新建方案查看默认口径并手动切换（填写原因）；打开修改前已正式化的历史方案查看其口径与计算结果。
- 预期结果：新方案默认采用新口径且可手动切换并记录原因；历史正式方案仍显示并按原口径计算，结果与口径修改前一致；参数变更记录生效时间、修改人和适用范围。
- 证据类型：interaction, session-persistence

### AC-15：AI 输出以建议形式流转，经确认才进入平台
- 验收条件：AI 可根据地块名称、位置和已有档案整理竞品、历史成交、规划公开资料和政策线索，归纳市场趋势、竞品差异和产品缺口，并按用户指令调整产品比例、售价、容积率、装修标准、车位或成本项目形成新方案建议；AI 抓取或推断的资料默认“待确认”并标注来源；AI 生成的调整先作为建议、草稿或临时方案，用户查看来源并确认关键参数后才同步为平台中可追溯的方案；AI 不能覆盖基准方案、正式方案或采用方案，不能绕过审批直接改变项目状态，不能将未确认的公开信息写入正式结论；管理层在 AI 端的临时问答不改变内部基础版本；AI 生成的方案可跳转到后台明细，看到相同的业务口径和计算依据。
- 入口类型：用户界面
- 验证动作：让 AI 汇总某地块的竞品与历史成交资料并查看来源与待确认标记；让 AI 调整产品比例生成新方案建议；在确认前核对基准方案与正式方案内容；确认建议后查看该方案明细与计算依据。
- 预期结果：AI 输出标注来源与“待确认”状态；未经确认的建议不进入正式方案库、基准/正式/采用方案不变；用户确认后方案进入平台且可追溯，可跳转后台明细核对相同口径和计算依据。
- 证据类型：interaction, runtime-render

## 10. 范围说明

- 本基线覆盖说明书全部 18 个业务模块（M01–M18）及三条建设阶段的业务范围；优先级与建设顺序按说明书第 8、13 章执行（P0/第一阶段优先交付拿地判断闭环）。

- 正式业务口径以本文件、客户确认的 Excel 模板、会议决策和 UAT 结果为准；历史 Excel 中的字段与结构可作需求依据，异常结果和错误引用不作系统规则。
