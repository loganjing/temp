# 工单系统（128-ticket）需求基线

## 1. 目标

为多公司环境提供一套工单系统：公司用户提交带问题分类与 SLA 优先级（P0–P4）的工单，工单按公司隔离；系统按公司配置的业务组与"分类→业务组"规则自动分配；业务组成员在工作台处理、回复、转派并完成工单；完成后向提交人邮箱发送通知邮件，提交人可进行满意度评价；系统提供按公司、部门维度的工单分布统计与运营仪表盘，并记录关键操作日志。

## 2. 用户与角色

| 角色 | 来源 | 职责 |
| --- | --- | --- |
| 提交人 | 用户明确 | 提交工单（信息含姓名、邮箱、公司、部门）；参与多轮回复；工单完成后收到邮件通知并进行满意度评价 |
| 处理人（业务组成员） | 用户明确 | 在工作台查看/处理待处理工单；处理时查看提交人完整信息；回复、转派、完成工单 |
| 公司配置角色 | 推荐（必要闭合） | 为公司添加业务组、设置成员、维护"分类→业务组"自动分配规则 |

> 提交人与处理人直接来自用户需求。"允许给某个公司增加多个业务组"需要一个配置操作入口，故以最小推荐补充配置角色；其命名与权限体系未规定，可调整。

## 3. 核心概念与规则

### 3.1 工单
工单由系统生成唯一工单ID，包含以下信息（均为用户明确要求）：
- 主题、描述
- 分类（问题分类）
- SLA 优先级：P0–P4
- 提交人信息：姓名、邮箱、公司、部门
- 创建时间

工单支持多轮回复：每轮回复记录回复人与回复时间，按时间在工单详情中展示。

### 3.2 公司与业务组
- 工单按公司隔离（见 3.5）。
- 一个公司可拥有多个业务组；每个业务组可设置成员（用户明确）。
- 公司级自动分配规则：工单按分类自动分配到该公司的某个业务组（用户明确）。
- [推荐] 规则未命中时，工单保持"待分配"状态，可经转派操作人工归属到业务组。

### 3.3 SLA 优先级与问题分类
- 优先级取值 P0–P4（用户明确）；各优先级对应的 SLA 时限数值未规定。
- 问题分类用于自动分配规则与统计维度；具体分类清单未规定，可由配置维护。

### 3.4 工单生命周期
状态集合（用户明确）：创建、待分配、待处理、完成、取消。

流转顺序：
- 创建 → 待分配：工单提交后进入分配流程。
- 待分配 → 待处理：工单归属到业务组后（自动分配命中或人工转派归属）。
- 待处理 → 完成：处理人完成处理。
- 取消：未完成（非"完成"）状态的工单可被取消（[推荐] 取消时机未规定，保守取"完成前任意状态可取消"）。

[推荐] "创建"到"待分配"的转换按"提交后即进入分配流程"闭合；草稿/暂存等中间形态不在本基线内。

### 3.5 公司数据隔离（用户明确）
- 任何工单数据（列表、详情、回复、统计、工作台）仅对同公司用户可见、可操作。
- 业务组与分配规则为公司级配置，作用域限于本公司。
- 统计分析以公司范围为边界，支持公司、部门维度。

### 3.6 操作日志（用户明确"记录相关日志"）
[推荐闭合] 工单关键操作（创建、分配、回复、转派、完成、取消、评价）记录操作日志，含操作类型、操作人、操作时间。日志保留期限与查看入口未规定。

## 4. 用户旅程

### 4.1 提交人旅程
1. 提交人创建工单：填写主题、描述，选择问题分类与 SLA 优先级（P0–P4）；提交人信息（姓名、邮箱、公司、部门）随工单记录，创建时间由系统记录。
2. 工单进入分配流程，按公司"分类→业务组"规则自动归属业务组。
3. 提交人可在工单内进行多轮回复。
4. 工单完成后，提交人邮箱收到完成通知邮件。
5. 提交人对已完成工单进行满意度评价。

### 4.2 处理人旅程
1. 业务组成员进入工单工作台，查看待处理工单列表，可筛选、搜索、排序，并按公司维度筛选。
2. 打开工单详情，查看提交人完整信息：姓名、公司、部门、历史工单。
3. 处理人回复工单（多轮），必要时转派给其他业务组或成员。
4. 处理完成后执行完成操作：系统记录处理人与处理时间，状态变为"完成"，并向提交人邮箱发送通知邮件。

### 4.3 业务组配置旅程
1. 配置角色为公司添加多个业务组，为各业务组设置成员。
2. 维护"分类 → 业务组"自动分配规则。
3. 此后该公司新建工单按分类自动归属对应业务组。

## 5. 功能需求

### 5.1 工单管理
- 创建工单：字段见 3.1；创建后进入生命周期流转（3.4）。
- 多轮回复：提交人与处理人均可回复；每轮记录回复人、回复时间并按时间展示。
- 公司隔离：见 3.5。
- SLA 优先级（P0–P4）与问题分类：见 3.3。

### 5.2 工单分配
- 业务组管理：公司可增加多个业务组，每个业务组可设置成员。
- 自动分配：按公司维护"分类→业务组"规则，新建工单按分类自动分配到对应业务组。
- [推荐] 未命中规则时保持待分配，经转派人工归属。

### 5.3 工单协作（转派）
- 工单可被转派到其他业务组（或组内成员），归属变更后工单仍为待处理。
- 转派操作记录操作日志。

### 5.4 工单处理与完成
- 处理时可查看提交人完整信息：姓名、公司、部门、历史工单（限公司隔离范围）。
- 完成时记录处理人与处理时间；状态变为"完成"。

### 5.5 邮件通知
- 工单完成后向提交人邮箱发送通知邮件（用户明确）。
- 邮件模板、发送方、发送重试策略未规定。

### 5.6 用户评价
- 工单完成后，提交人可对该工单进行满意度评价（基于上下文：完成通知后的评价入口）。
- 满意度形式（分值/等级）未规定；评价结果需可读回并进入满意度统计。

### 5.7 统计分析与仪表盘
- 工单分布：支持按公司、部门维度统计工单分布。
- 运营仪表盘指标（用户明确列出）：工单量、平均响应时间、满意度、热点问题等。
  - [推荐口径] 平均响应时间：统计范围内工单从创建到首次回复的平均时长。
  - [推荐口径] 满意度：已评价工单的平均满意度结果。
  - [推荐口径] 热点问题：按问题分类聚合的工单量排名。
- 统计范围受公司隔离约束（3.5）。

### 5.8 工单工作台
- 查看待处理工单列表。
- 筛选：支持按公司维度筛选（用户明确）；分类、优先级等筛选条件为推荐默认项。
- 搜索：[推荐] 支持按工单ID、主题等关键字搜索。
- 排序：[推荐] 支持按创建时间、优先级等字段排序。

### 5.9 操作日志
见 3.6。

## 6. 来源与未规定事项汇总

用户明确：工单字段（工单ID、主题、描述、分类、提交人信息含邮箱、创建时间）、多轮回复、公司隔离、SLA 优先级 P0–P4、问题分类、五状态生命周期、业务组与成员、按分类自动分配、转派、处理时查看提交人完整信息、完成记录处理人/处理时间、完成邮件通知、满意度评价、公司/部门分布统计、仪表盘四类运营指标、工作台筛选/搜索/排序/公司维度筛选、记录相关日志。

推荐基线（最小闭合，可调整）：
- 公司配置角色（业务组/成员/规则维护）。
- 自动分配未命中时保持待分配，经转派人工归属。
- 未完成工单可取消。
- 平均响应时间、满意度、热点问题的统计口径。
- 工作台搜索、排序与筛选的默认字段集合。
- 操作日志的操作范围与字段。

未规定（不在本基线内，不构成验收项）：SLA 时限数值、分类清单、邮件模板与发送方、评价形式细节、日志保留期限、草稿/暂存形态、权限体系与角色命名。

## 7. 验收标准

### AC-01：提交人可创建工单并包含完整信息
- 验收条件：提交人提交工单后，系统生成含工单ID、主题、描述、分类、SLA 优先级（P0–P4）、提交人信息（姓名、邮箱、公司、部门）和创建时间的工单记录。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份进入工单创建入口，填写主题、描述，选择问题分类和优先级，提交工单。
- 预期结果：工单创建成功并生成唯一工单ID；工单详情可见主题、描述、分类、优先级、提交人姓名/邮箱/公司/部门及创建时间；工单状态为生命周期初始状态。
- 证据类型：interaction, runtime-render
- 共享流程组：工单主旅程

### AC-02：工单支持多轮回复
- 验收条件：同一工单可进行多轮回复，每轮回复记录并展示回复人和回复时间。
- 入口类型：用户界面
- 验证动作：在工单详情中由不同回复人（如提交人与处理人）先后进行两次以上回复。
- 预期结果：工单详情按时间展示全部回复内容，每条回复可见回复人身份与回复时间。
- 证据类型：interaction, runtime-render
- 共享流程组：工单主旅程

### AC-03：工单按公司隔离
- 验收条件：任何用户只能访问其所属公司的工单数据（列表、详情、回复、统计、工作台），无法查看或操作其他公司的工单。
- 入口类型：用户界面
- 验证动作：以A公司提交人身份查看工单列表，并尝试访问B公司已存在工单的详情入口。
- 预期结果：A公司用户的工单列表仅包含A公司工单；无法查看或操作B公司工单详情；统计与工作台数据同样仅限本公司范围。
- 证据类型：authorization, runtime-render

### AC-04：工单生命周期状态流转
- 验收条件：工单按"创建 → 待分配 → 待处理 → 完成"流转，未完成的工单可被取消，每次流转后状态可观察。
- 入口类型：用户界面
- 验证动作：依次创建工单（创建状态）、进入分配流程（待分配）、确认归属业务组（待处理）、执行完成操作（完成）；另创建一个工单并在待处理状态下执行取消。
- 预期结果：每步操作后工单状态显示为对应状态；取消后工单状态为"取消"，不再进入处理流程；完成的工单状态为"完成"。
- 证据类型：interaction, runtime-render
- 共享流程组：工单主旅程

### AC-05：业务组管理与按分类自动分配
- 验收条件：可为某公司添加多个业务组并设置成员；配置公司级"分类→业务组"规则后，该公司新建工单按分类自动归属到对应业务组。
- 入口类型：用户界面
- 验证动作：为公司A添加两个业务组并分别设置成员；配置分类X→业务组一的自动分配规则；以公司A提交人身份创建分类为X的工单。
- 预期结果：业务组与成员配置保存成功并可读回；新工单自动归属业务组一，进入待处理状态，业务组成员可在工作台看到该工单。
- 证据类型：interaction, runtime-render

### AC-06：工单转派
- 验收条件：处理人可将工单转派给其他业务组或成员，转派后工单归属变更且操作留痕。
- 入口类型：用户界面
- 验证动作：在待处理工单详情中执行转派到另一业务组的操作。
- 预期结果：工单归属业务组变更为目标业务组，工单仍处于待处理状态，转派操作被记录（操作日志）。
- 证据类型：interaction, runtime-render

### AC-07：工单处理时查看提交人完整信息并记录处理结果
- 验收条件：处理工单时可查看提交人完整信息（姓名、公司、部门、历史工单）；工单完成后记录处理人与处理时间。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单详情，查看提交人信息面板及其历史工单列表；执行完成操作后查看工单记录。
- 预期结果：详情中可见提交人姓名、公司、部门及其历史工单（限本公司范围）；完成后工单记录处理人身份与处理时间，状态变为"完成"。
- 证据类型：interaction, runtime-render
- 共享流程组：工单主旅程

### AC-08：工单完成后发送邮件通知
- 验收条件：工单完成后，系统向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：完成一个由邮箱为E的提交人创建的工单，随后检查邮箱E的收件结果。
- 预期结果：邮箱E收到该工单的完成通知邮件，邮件内容可识别对应工单。
- 证据类型：interaction, other
- 共享流程组：工单主旅程

### AC-09：提交人满意度评价
- 验收条件：工单完成后，提交人可对该工单进行满意度评价，评价结果被记录并可读回。
- 入口类型：用户界面
- 验证动作：提交人对一个已完成工单提交满意度评价，随后再次查看该工单。
- 预期结果：评价提交成功；工单详情或评价入口可读回已提交的满意度结果。
- 证据类型：interaction, session-persistence
- 共享流程组：工单主旅程

### AC-10：统计分析与运营仪表盘
- 验收条件：统计分析支持按公司、部门维度展示工单分布；仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：进入统计分析页面，分别按公司、部门维度查看工单分布；查看仪表盘各运营指标。
- 预期结果：分布视图按所选维度聚合工单数量；仪表盘可见工单量、平均响应时间、满意度、热点问题指标，数值与当前统计范围（受公司隔离约束）内的数据一致。
- 证据类型：runtime-render

### AC-11：工单工作台
- 验收条件：处理人可在工作台查看待处理工单列表，并支持筛选（含公司维度）、搜索、排序。
- 入口类型：用户界面
- 验证动作：在工作台分别执行筛选（按公司维度及分类/优先级等条件）、搜索（按工单ID或主题等关键字）、排序（按创建时间或优先级等字段）操作。
- 预期结果：列表按所选条件更新；公司维度筛选生效且不越过公司隔离边界；搜索命中相关工单；列表顺序符合所选排序字段。
- 证据类型：interaction, runtime-render

### AC-12：操作日志记录
- 验收条件：工单关键操作（创建、分配、回复、转派、完成、取消、评价）留有日志记录，包含操作类型、操作人与操作时间。
- 入口类型：内部
- 验证动作：对同一工单依次执行创建、分配、回复、转派、完成、评价等操作后，查询该工单的操作日志。
- 预期结果：每个关键操作均有对应日志条目，包含操作类型、操作人、操作时间。
