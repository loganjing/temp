# 工单系统需求文档

> Work Item: wi-t1000076 | Code: T1000076 | 项目: JLGSpace-88

## 1. 目标

构建一个面向多公司的工单管理系统，支持工单从创建到完成的完整生命周期管理，包括工单分配、协作转派、处理通知、用户评价、统计分析和工作台等功能，并按公司维度进行数据隔离。

## 2. 角色与权限边界

以下角色由用户明确描述的功能需求推导得出，用于说明各功能的操作主体：

| 角色 | 来源 | 职责 |
|------|------|------|
| 工单提交人 | 用户明确提出"提交人信息" | 创建工单、多轮回复、接收完成通知、满意度评价 |
| 工单处理人 | 用户明确提出"处理人"、"处理时间" | 处理工单、查看提交人完整信息、记录处理结果 |
| 业务组成员 | 用户明确提出"业务组可以设置成员" | 作为工单分配的目标对象 |
| 系统管理员 | 用户明确提出"给某个公司增加多个业务组" | 管理公司的业务组与成员、配置分类自动分配规则 |

> 用户未明确指定角色权限矩阵、认证方式或组织架构管理流程，以上角色仅描述功能操作主体，不推断具体权限模型。

## 3. 核心实体与状态模型

### 3.1 工单实体

工单包含以下字段（用户明确提出）：

| 字段 | 说明 |
|------|------|
| 工单ID | 唯一标识 |
| 主题 | 工单标题 |
| 描述 | 工单详细内容 |
| 分类 | 问题分类 |
| SLA优先级 | P0、P1、P2、P3、P4 五个级别 |
| 提交人信息 | 含姓名、邮箱、公司、部门 |
| 创建时间 | 工单创建时间戳 |
| 当前状态 | 生命周期状态 |
| 处理人 | 处理工单的人员 |
| 处理时间 | 工单处理完成的时间戳 |

### 3.2 工单回复

工单支持多轮回复，每条回复包含：

| 字段 | 说明 |
|------|------|
| 回复人 | 发起回复的人员 |
| 回复时间 | 回复的时间戳 |
| 回复内容 | 回复的具体文本 |

### 3.3 工单生命周期

用户明确提出的工单状态：创建、待分配、待处理、完成、取消。

状态流转规则：

```
创建 → 待分配 → 待处理 → 完成
  ↓       ↓       ↓
  └───────┴───────┴──→ 取消
```

- **创建**：工单提交后的初始状态
- **待分配**：工单等待分配到业务组或处理人
- **待处理**：工单已分配，等待处理人处理
- **完成**：工单处理完毕，系统发送邮件通知提交人
- **取消**：工单在完成前的任意状态可被取消

> 推荐基线：创建状态的工单若有分类自动分配规则匹配，可直接流转到待处理状态，跳过待分配。此为最小必要规则，不替代用户对分配策略的进一步决定。

### 3.4 公司隔离

用户明确提出"工单按公司隔离"。此规则适用于所有工单相关操作：

- 工单数据仅在所属公司范围内可见和可操作
- 业务组、分类自动分配规则均以公司为边界独立配置
- 统计分析、工作台筛选均遵守公司维度隔离

> 推荐基线：公司隔离作为所有工单查询和操作的隐式过滤条件执行，确保不同公司之间的工单数据互不可见。此为闭合核心目标必需的最小规则。

## 4. 功能模块需求

### 4.1 工单管理

**工单创建**（用户明确提出）：
- 创建工单时填写：主题、描述、分类、SLA优先级（P0-P4）
- 系统自动记录：工单ID、提交人信息（姓名、邮箱、公司、部门）、创建时间
- 创建后进入"创建"状态，随后流转到"待分配"或（有自动分配规则时）"待处理"

**工单回复**（用户明确提出）：
- 支持在工单上进行多轮回复
- 每条回复记录回复人和回复时间
- 回复按时间顺序排列

### 4.2 工单分配

用户明确提出两个分配能力：

**业务组管理**：
- 允许给某个公司增加多个业务组
- 每个业务组可以设置成员
- 业务组以公司为边界独立管理

**分类自动分配**：
- 允许为某个公司配置"分类→业务组"的映射规则
- 工单创建时，根据工单分类匹配对应业务组，自动分配到该业务组
- 未配置映射规则的分类，工单保持待分配状态等待手动分配

### 4.3 工单协作

**工单转派**（用户明确提出）：
- 支持将工单从一个业务组或处理人转派到另一个业务组或处理人
- 转派操作在工单处于"待处理"状态时执行
- 转派后工单继续保持在"待处理"状态，由新的接收方处理

### 4.4 工单处理

用户明确提出两个处理能力：

**提交人信息查看**：
- 处理工单时可查看提交人的完整信息：姓名、公司、部门
- 可查看提交人的历史工单记录

**工单处理与完成**：
- 处理人完成工单处理后，系统记录处理人和处理时间
- 工单状态流转到"完成"
- 工单完成时系统发送邮件通知提交人（邮件发送至提交人邮箱）

### 4.5 用户评价

**满意度评价**（用户明确提出）：
- 用户收到工单完成通知后，可对该工单进行满意度评价
- 评价结果与工单关联记录

> 用户未明确评价的具体形式（如星级、评分范围），此项保持未规定，不自行推断评价量表。

### 4.6 统计分析

用户明确提出两个统计能力：

**工单分布统计**：
- 支持按公司维度统计工单分布
- 支持按部门维度统计工单分布

**运营仪表盘**：
- 工单量：统计工单总数及各状态分布
- 平均响应时间：统计工单从创建到处理完成的平均耗时
- 满意度：汇总用户满意度评价数据
- 热点问题：按分类统计工单频次，识别高频问题分类

> 用户未明确统计的时间范围、刷新频率或具体计算口径，以上指标为用户明确列出的运营指标，不推断额外指标。

### 4.7 工单工作台

**待处理工单列表**（用户明确提出）：
- 查看待处理工单列表
- 支持筛选：包括按公司维度筛选
- 支持搜索：按工单主题等关键词搜索
- 支持排序：按创建时间、优先级等排序

### 4.8 操作日志

**日志记录**（用户明确提出）：
- 记录工单相关操作日志
- 覆盖工单生命周期中的关键操作：创建、分配、转派、处理、完成、取消

> 推荐基线：日志至少记录操作类型、操作人、操作时间和关联工单ID，用于追溯工单处理过程。此为闭合"记录相关日志"目标的最小必要内容。用户未明确日志的查询界面或保留策略，保持未规定。

## 6. 验收场景

### AC-01：工单创建与生命周期管理

- 验收条件：提交人可创建包含完整字段的工单，工单经历创建→待分配→待处理→完成的状态流转，且支持取消。
- 入口类型：用户界面
- 验证动作：创建一个工单（填写主题、描述、分类、SLA优先级），查看工单初始状态和自动生成的字段（工单ID、提交人信息、创建时间）；随后将工单分配到处理人，处理完成后查看状态变为完成；另创建一个工单并执行取消操作。
- 预期结果：工单创建后包含所有规定字段且状态为"创建"；分配后状态变为"待处理"；完成后状态变为"完成"；取消后状态变为"取消"，且各状态流转记录可追溯。
- 证据类型：interaction, runtime-render, session-persistence

### AC-02：工单多轮回复

- 验收条件：多个用户可对同一工单进行多轮回复，每条回复记录回复人和回复时间。
- 入口类型：用户界面
- 验证动作：在一个已创建的工单上，由不同用户依次添加多条回复。
- 预期结果：所有回复按时间顺序显示，每条回复包含回复人、回复时间和回复内容，且回复数量与添加次数一致。
- 证据类型：interaction, runtime-render

### AC-03：工单按公司隔离

- 验收条件：不同公司的工单数据互不可见，工单操作仅限本公司范围内。
- 入口类型：用户界面
- 验证动作：在A公司创建工单后，切换到B公司上下文查看工单列表和工作台。
- 预期结果：B公司无法看到A公司的任何工单数据；A公司的业务组、分配规则等配置对B公司不可见。
- 证据类型：interaction, authorization

### AC-04：业务组管理与分类自动分配

- 验收条件：可为公司创建多个业务组并设置成员，配置分类到业务组的映射规则后，新工单按分类自动分配到对应业务组。
- 入口类型：用户界面
- 验证动作：为某公司创建两个业务组并分别添加成员；配置"分类A→业务组1"的自动分配规则；创建一个分类为A的工单。
- 预期结果：业务组和成员创建成功；分类为A的工单创建后自动分配到业务组1，状态流转到待处理；未配置映射的分类创建工单后保持待分配状态。
- 证据类型：interaction, runtime-render, session-persistence

### AC-05：工单转派

- 验收条件：待处理状态的工单可转派到其他业务组或处理人，转派后工单保持待处理状态。
- 入口类型：用户界面
- 验证动作：将一个待处理工单从当前业务组转派到另一个业务组。
- 预期结果：工单转派成功，接收方变更为新业务组，工单状态保持待处理，转派操作记录在日志中。
- 证据类型：interaction, runtime-render

### AC-06：工单处理、完成与邮件通知

- 验收条件：处理人可查看提交人完整信息（姓名、公司、部门、历史工单），完成处理后系统记录处理人和处理时间，工单状态变为完成并发送邮件通知提交人。
- 入口类型：用户界面
- 验证动作：在待处理工单的处理界面查看提交人完整信息和历史工单；执行完成操作，检查工单状态、处理人、处理时间记录，并验证提交人邮箱收到完成通知邮件。
- 预期结果：处理界面显示提交人的姓名、公司、部门和历史工单列表；完成后工单状态为"完成"，处理人和处理时间已记录；提交人邮箱收到工单完成通知邮件。
- 证据类型：interaction, runtime-render, session-persistence, other

### AC-07：用户满意度评价

- 验收条件：工单完成后，用户可对该工单进行满意度评价，评价结果与工单关联。
- 入口类型：用户界面
- 验证动作：在已完成的工单上执行满意度评价操作。
- 预期结果：评价提交成功，评价结果与工单关联并可查看。
- 证据类型：interaction, runtime-render, session-persistence

### AC-08：统计分析与运营仪表盘

- 验收条件：系统提供按公司、部门维度的工单分布统计，以及包含工单量、平均响应时间、满意度、热点问题的运营仪表盘。
- 入口类型：用户界面
- 验证动作：在统计分析页面查看按公司维度的工单分布数据、按部门维度的工单分布数据；在仪表盘页面查看工单量、平均响应时间、满意度指标和热点问题分类。
- 预期结果：工单分布统计按公司和部门维度正确展示；仪表盘显示工单量（含各状态分布）、平均响应时间、满意度汇总数据和热点问题分类排名，且数据与实际工单数据一致。
- 证据类型：runtime-render

### AC-09：工单工作台

- 验收条件：工作台展示待处理工单列表，支持按公司筛选、关键词搜索和排序。
- 入口类型：用户界面
- 验证动作：打开工单工作台，执行按公司筛选、输入关键词搜索、按创建时间和优先级排序操作。
- 预期结果：待处理工单列表正确展示；按公司筛选后仅显示该公司的待处理工单；搜索结果匹配关键词；排序结果按所选字段正确排列。
- 证据类型：interaction, runtime-render

### AC-10：操作日志记录

- 验收条件：工单的创建、分配、转派、处理、完成、取消等关键操作均被记录在日志中。
- 入口类型：内部
- 验证动作：执行工单创建、分配、转派、处理、完成和取消操作后，查看对应的操作日志。
- 预期结果：每项操作均有对应的日志记录，包含操作类型、操作人、操作时间和关联工单ID，且操作顺序与执行顺序一致。
- 证据类型：session-persistence
