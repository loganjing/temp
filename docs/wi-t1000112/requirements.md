## 1. 项目背景与目标

### 1.1 项目背景

企业内部需要一个统一的工单管理系统，用于接收、分配、处理和跟踪各类业务问题与请求。当前缺乏结构化的工单流转机制，导致问题响应不及时、处理过程不可追溯、跨团队协作效率低。

### 1.2 目标用户

| 用户角色 | 说明 |
|---|---|
| 工单提交人 | 公司内部员工，提交问题或请求，跟踪处理进度，完成后进行满意度评价 |
| 业务组管理员 | 负责管理业务组成员、配置工单分类与业务组的自动分配规则 |
| 工单处理人 | 业务组成员，接收分配到本组的工单并进行处理 |
| 系统管理员 | 管理公司、业务组、分类等基础数据配置 |

### 1.3 成功结果

- 工单从提交到完成的全流程可追溯，包含提交人信息、处理人信息、多轮回复记录和状态变更时间线
- 工单能够按照公司-分类规则自动分配到对应业务组，减少人工分配成本
- 工单处理人可查看提交人完整画像（姓名、公司、部门、历史工单），提升处理效率
- 工单转派操作支持跨业务组协作
- 用户可对已完成工单进行满意度评价

## 3. 用户旅程与关键场景

### 3.1 提交人工单旅程

1. 提交人填写工单主题、描述、选择分类，设置SLA优先级
2. 系统记录提交人信息（姓名、邮箱、公司、部门）和创建时间
3. 工单状态为「创建」，随后自动流转为「待分配」
4. 系统按分类自动分配到业务组，或由管理员手动分配
5. 工单状态变为「待处理」，提交人可查看处理进度
6. 提交人可进行多轮回复补充信息
7. 处理人完成处理后，工单状态变为「完成」
8. 提交人收到完成通知，可进行满意度评价

### 3.2 处理人工单旅程

1. 处理人查看分配到本业务组的待处理工单列表
2. 打开工单详情，查看工单主题、描述、分类、SLA优先级
3. 查看提交人完整信息：姓名、公司、部门、历史工单列表
4. 进行工单回复（多轮），系统记录回复人和回复时间
5. 如需其他业务组协助，执行转派操作
6. 处理完成后，记录处理人、处理时间，工单状态变为「完成」

### 3.3 业务组管理员工单分配旅程

1. 管理员为公司创建多个业务组
2. 为每个业务组设置成员
3. 配置工单分类与业务组的自动分配规则（某分类→某业务组）
4. 新建工单按分类自动匹配到业务组
5. 如自动分配规则未匹配，管理员可手动分配

### 3.4 工单转派旅程

1. 处理人A在处理过程中发现工单不属于本组职责范围
2. 处理人A执行转派操作，选择目标业务组或目标处理人
3. 工单流转到目标方，原处理人记录转派原因
4. 目标处理人接手工单继续处理
5. 转派记录保留在工单操作历史中

## 4. 核心实体与术语

| 实体 | 说明 |
|---|---|
| **工单 (Ticket)** | 核心业务对象，记录用户提交的问题或请求，包含主题、描述、分类、SLA优先级、状态等 |
| **工单回复 (Ticket Reply)** | 工单下的多轮沟通记录，包含回复人、回复内容、回复时间 |
| **公司 (Company)** | 工单提交人所属组织，是业务组和分配规则的归属主体 |
| **业务组 (Business Group)** | 公司下的协作单元，包含若干成员，负责处理分配到本组的工单 |
| **业务组成员 (Group Member)** | 隶属于某业务组的处理人，可接收和处理分配到本组的工单 |
| **工单分类 (Category)** | 对工单类型的分类标签，用于自动分配规则匹配 |
| **SLA优先级 (Priority)** | 工单的优先级等级，取值 P0-P4，P0最高 |
| **分配规则 (Assignment Rule)** | 将某公司的某分类工单自动分配到指定业务组的映射规则 |
| **工单操作记录 (Ticket Operation Log)** | 记录工单生命周期中的关键操作（创建、分配、转派、处理、完成、取消等） |
| **满意度评价 (Satisfaction Rating)** | 提交人对已完成工单的服务质量评价 |

## 5. 状态模型与业务规则

### 5.1 工单状态定义

| 状态 | 说明 |
|---|---|
| **创建 (Created)** | 工单刚提交后的初始状态 |
| **待分配 (Pending Assignment)** | 工单已提交，等待分配到业务组 |
| **待处理 (Pending Processing)** | 工单已分配到业务组，等待处理人处理 |
| **完成 (Completed)** | 工单已处理完成 |
| **取消 (Cancelled)** | 工单被取消，不再处理 |

### 5.2 状态转换图

```
创建 ──创建后自动流转──> 待分配
待分配 ──自动分配/手动分配──> 待处理
待处理 ──处理完成──> 完成
待处理 ──转派──> 待处理（目标业务组）
待处理 ──取消──> 取消
待分配 ──取消──> 取消
创建 ──取消──> 取消
完成 ──（终态）── 无
取消 ──（终态）── 无
```

### 5.3 通用业务规则

| 规则编号 | 规则描述 |
|---|---|
| BR-01 | 工单创建后自动从「创建」流转为「待分配」 |
| BR-02 | 待分配状态下，系统按公司-分类规则自动匹配业务组；匹配成功后自动流转为「待处理」 |
| BR-03 | 待分配状态下，如无匹配的自动分配规则，由业务组管理员手动分配后流转为「待处理」 |
| BR-04 | 工单转派后状态保持「待处理」，但归属业务组变更为目标业务组 |
| BR-05 | 工单一旦进入「完成」或「取消」终态，不可再流转到其他状态 |
| BR-06 | 工单回复在「待处理」状态下可多轮进行；「完成」后提交人仍可追加回复（推荐基线） |
| BR-07 | 满意度评价仅在工单状态为「完成」后可由提交人进行，且每个工单仅可评价一次 |
| BR-08 | SLA优先级 P0 为最高优先级，P4 为最低；推荐按优先级高低决定处理顺序（推荐基线） |
| BR-09 | 转派操作需记录转派人、目标业务组/处理人、转派原因和转派时间 |
| BR-10 | 处理完成后需记录处理人、处理时间、最终处理状态 |

## 6. 分模块功能需求

### 6.1 工单管理模块

#### 6.1.1 工单创建

**行为**：提交人创建新工单，填写必要信息后提交。

**输入字段**：

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|:---:|---|
| 工单ID | 系统生成 | - | 全局唯一标识 |
| 主题 | 文本 | ✅ | 工单标题 |
| 描述 | 富文本 | ✅ | 工单详细内容 |
| 分类 | 选择 | ✅ | 问题分类 |
| SLA优先级 | 选择 | ✅ | P0/P1/P2/P3/P4 |
| 提交人姓名 | 自动填充 | - | 来自用户信息 |
| 提交人邮箱 | 自动填充 | - | 来自用户信息 |
| 提交人公司 | 自动填充 | - | 来自用户信息 |
| 提交人部门 | 自动填充 | - | 来自用户信息 |
| 创建时间 | 系统生成 | - | 提交时刻 |

**业务规则**：
- 创建后自动生成工单ID
- 提交人信息从当前登录用户自动填充，不可手动修改
- 创建后状态自动流转为「待分配」

**边界与异常**：
- 主题不能为空
- 分类必须在系统已配置的分类列表中选择
- 提交人必须有所属公司，否则提示无法创建工单

#### 6.1.2 工单回复

**行为**：工单处理过程中，提交人和处理人可进行多轮回复。

**输入字段**：

| 字段 | 类型 | 是否必填 | 说明 |
|---|---|:---:|---|
| 回复内容 | 富文本 | ✅ | 回复正文 |
| 回复人 | 系统记录 | - | 当前操作用户 |
| 回复时间 | 系统生成 | - | 回复提交时刻 |

**业务规则**：
- 回复按时间顺序排列，最新回复在最下
- 每条回复记录回复人和回复时间
- 工单「完成」后提交人仍可追加回复（推荐基线）

**不应发生的行为**：
- 回复内容不能为空
- 非工单相关人员不能查看和回复工单

#### 6.1.3 工单列表与详情

**行为**：用户可查看工单列表和工单详情。

**业务规则**：
- 提交人可查看自己提交的工单列表
- 处理人可查看分配到本业务组的工单列表
- 工单详情页展示：主题、描述、分类、SLA优先级、提交人信息（含邮箱）、创建时间、当前状态、回复记录、操作历史
- 工单详情页可查看提交人完整信息面板（姓名、公司、部门、历史工单列表）

#### 6.1.4 SLA优先级与分类

**行为**：工单支持SLA优先级设置和问题分类。

**业务规则**：
- SLA优先级取值范围：P0、P1、P2、P3、P4，其中 P0 为最高
- 优先级在创建时设置，可在处理过程中由处理人或管理员调整（推荐基线）
- 分类由系统管理员预配置，创建工单时从列表选择

### 6.2 工单分配模块

#### 6.2.1 业务组管理

**行为**：允许为某个公司增加多个业务组，每个业务组可设置成员。

**业务规则**：
- 每个公司下可创建多个业务组
- 每个业务组可设置多个成员
- 成员来源于公司内用户
- 业务组管理员可添加、移除成员

**数据关系**：
- 公司 1:N 业务组
- 业务组 N:N 成员（用户）

#### 6.2.2 自动分配规则

**行为**：允许某公司的工单按照分类自动分配到某个业务组。

**配置方式**：
- 管理员为某公司配置「分类 → 业务组」的映射规则
- 例如：公司A 的「网络故障」分类 → 业务组「IT运维组」

**业务规则**：
- 一个分类在同一公司下只能映射到一个业务组
- 一个业务组可接收多个分类的工单
- 工单创建后进入「待分配」状态时，系统自动匹配该工单所属公司+分类对应的分配规则
- 匹配成功：自动分配到对应业务组，工单流转为「待处理」
- 匹配失败：工单保持「待分配」，等待管理员手动分配
- 手动分配：管理员选择目标业务组后，工单流转为「待处理」

**不应发生的行为**：
- 不同公司之间不能共享分配规则
- 删除分类前，已关联的分配规则需先解除

---

### 6.3 工单协作模块

#### 6.3.1 工单转派

**行为**：处理人可将工单转派给其他业务组或处理人。

**操作流程**：
1. 处理人在待处理工单详情页点击「转派」
2. 选择目标业务组或目标处理人
3. 填写转派原因
4. 确认转派

**业务规则**：
- 转派后工单状态保持「待处理」，归属业务组变更为目标业务组
- 转派记录包含：转派人、目标业务组/处理人、转派原因、转派时间
- 转派操作记录在工单操作历史中
- 工单在「待处理」状态下可多次转派（推荐基线）
- 工单在「完成」或「取消」状态下不可转派

**不应发生的行为**：
- 不能转派给自己
- 不能转派给不存在的业务组或处理人

### 6.4 工单处理模块

#### 6.4.1 提交人信息查看

**行为**：处理人在处理工单时可查看提交人的完整信息。

**展示信息**：

| 信息项 | 说明 |
|---|---|
| 姓名 | 提交人真实姓名 |
| 公司 | 提交人所属公司 |
| 部门 | 提交人所属部门 |
| 历史工单 | 提交人过往提交的工单列表，含工单主题、状态、创建时间 |

**业务规则**：
- 处理人在工单详情页可查看提交人信息面板
- 历史工单列表按创建时间倒序排列
- 点击历史工单可跳转到对应工单详情（推荐基线）

#### 6.4.2 工单处理完成

**行为**：处理人完成工单处理后，标记工单为完成状态。

**记录信息**：

| 信息项 | 说明 |
|---|---|
| 处理人 | 执行完成操作的用户 |
| 处理时间 | 完成操作的时刻 |
| 工单状态 | 变更为「完成」 |

**业务规则**：
- 完成操作需记录处理人、处理时间和最终状态
- 完成后工单进入终态，不可再变更状态
- 完成后提交人收到通知，可进行满意度评价

#### 6.4.3 工单取消

**行为**：提交人或管理员可取消未完成的工单。

**业务规则**：
- 工单在「创建」「待分配」「待处理」状态下可取消
- 取消后工单进入终态，不可再变更状态
- 取消需记录操作人和操作时间（推荐基线）

---

### 6.5 用户评价模块

#### 6.5.1 满意度评价

**行为**：工单完成后，提交人对处理结果进行满意度评价。

**评价方式**：
- 满意度评分（推荐使用1-5星或满意/不满意，具体方式作为推荐基线，待后续确认）

**业务规则**：
- 仅工单状态为「完成」时可评价
- 仅提交人本人可评价自己提交的工单
- 每个工单仅可评价一次，评价后不可修改（推荐基线）
- 评价后系统记录评价人、评价时间、评价内容

**不应发生的行为**：
- 非提交人不能对该工单进行评价
- 工单未完成时不能评价
- 重复评价同一工单

## 9. 推荐基线与设计假设

| 编号 | 推荐基线 | 理由 |
|---|---|---|
| RB-01 | 工单完成后提交人仍可追加回复 | 便于补充反馈信息，属于工单沟通的自然延伸 |
| RB-02 | SLA优先级可在处理过程中调整 | 处理过程中可能需根据实际情况调整优先级 |
| RB-03 | 工单按SLA优先级高低决定处理顺序 | 高优先级工单应优先处理，符合SLA管理通行做法 |
| RB-04 | 工单在待处理状态下可多次转派 | 实际协作中可能需要多次转派才能找到合适的处理方 |
| RB-05 | 满意度评价采用1-5星评分 | 通用评价方式，简洁有效 |
| RB-06 | 每个工单仅可评价一次，评价后不可修改 | 保证评价的公正性和一致性 |
| RB-07 | 工单取消需记录操作人和操作时间 | 操作审计需要 |
| RB-08 | 点击历史工单可跳转到对应工单详情 | 提升处理人查阅效率 |
| RB-09 | 业务组管理员可由系统管理员指定 | 需有角色分配机制 |

## 10. 验收场景

### AC-01：创建工单

| 项 | 内容 |
|---|---|
| 编号 | AC-01 |
| 强制程度 | 必须 |
| 入口类型 | UI/浏览器 |
| 适用角色 | 提交人 |
| 前置条件 | 用户已登录，且有所属公司 |
| 动作 | 填写工单主题、描述，选择分类和SLA优先级（P0-P4），提交创建 |
| 预期结果 | 系统生成唯一工单ID；工单信息包含主题、描述、分类、SLA优先级、提交人信息（姓名、邮箱、公司、部门）和创建时间；工单初始状态为「创建」后自动流转为「待分配」；提交人在工单列表中可看到新创建的工单 |
| 证据类型 | 工单详情页展示完整字段与状态 |

### AC-02：工单自动分配

| 项 | 内容 |
|---|---|
| 编号 | AC-02 |
| 强制程度 | 必须 |
| 入口类型 | 后台任务（系统自动） |
