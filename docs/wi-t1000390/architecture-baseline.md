# 架构基线：Timeling 专注时段记录系统

> 引用批准需求基线：`docs/wi-t1000390/requirements.md`（SHA-256: `d33aee88398c837aa7a87938954765abdcee28cacf08e1175f584af880e29451`）

## 1. 技术路线

单页面 React + Vite SPA，纯浏览器端运行，无服务端、无数据库、无认证、无后台任务、无外部集成、无跨设备同步。数据归属于当前浏览器配置文件，刷新或重新打开页面后仍可读回，不与其他浏览器、设备或用户共享。

- **构建工具**：Vite（开发服务器 `npm run dev`，生产构建 `npm run build`）
- **运行方式**：开发期通过 Vite 开发服务器在 localhost 提供单页面；生产构建产物为静态 HTML + JS + CSS，可直接用任意静态服务器托管
- **实现入口**：`index.html` → `src/main.tsx` 挂载 React 根组件

## 2. 页面与交互范围

单页面自上而下分为三个区域，对应需求中明确提出的三项展示要求：

| 区域 | 位置 | 职责 | 对应需求 |
|------|------|------|----------|
| 累计专注时长 | 页面上方 | 实时显示当日已完成专注番茄钟的累计时长（已完成数量 × 25 分钟） | §3.3 |
| 番茄钟倒计时 + 当日记录列表 | 页面中部 | 番茄钟倒计时控件（启动/暂停/恢复/重置）与当日已完成专注时段列表 | §3.1, §3.2 |
| 专注热力图 | 页面下方 | 按时段展示当日专注分布，颜色深浅反映专注强度 | §3.4 |

### 番茄钟状态机

番茄钟倒计时在浏览器端使用 `setInterval`（1 秒 tick）驱动，状态流转如下：

```
idle → focusing（25:00 倒计时）→ focusing 结束 → resting（5:00 倒计时）→ resting 结束 → idle
                    ↓ 暂停              ↓ 暂停
                 paused-focusing     paused-resting
                    ↓ 恢复              ↓ 恢复
```

- `idle`：待启动，显示 25:00，等待用户点击"开始"
- `focusing`：专注倒计时运行中，每秒递减
- `paused-focusing`：专注倒计时暂停
- `resting`：休息倒计时运行中
- `paused-resting`：休息倒计时暂停
- 专注倒计时归零时：自动生成一条当日专注记录（完成时间、专注时长 25 分钟），然后自动进入休息倒计时
- 休息倒计时归零时：回到 `idle`，等待用户手动开始下一个专注时段

### 当日记录列表

- 每完成一个专注番茄钟，向当日列表追加一条记录：`{ completedAt: ISO 时间戳, durationMin: 25 }`
- 列表仅展示当日记录，按完成时间倒序排列

### 专注热力图

- 将一天划分为时段格子（以每小时一格，共 24 格）
- 每格的颜色深浅由该时段内完成的专注番茄钟数量决定：0 个为最浅色，数量越多颜色越深
- 热力图在每次专注番茄钟完成后自动更新

## 3. 数据归属与持久化

### 存储机制

使用浏览器 `localStorage` 按日期键保存当日数据，数据仅限当前浏览器配置文件。

**存储结构**：

```typescript
interface DayRecord {
  date: string;              // YYYY-MM-DD，作为 localStorage 键
  sessions: SessionRecord[]; // 当日完成的专注番茄钟列表
}

interface SessionRecord {
  completedAt: string;  // ISO 8601 时间戳，如 "2026-10-27T14:25:00.000Z"
  durationMin: number;  // 专注时长（分钟），固定为 25
}
```

**localStorage 键**：`timeling:{YYYY-MM-DD}`，值为 `SessionRecord[]` 的 JSON 序列化字符串。

**读写边界**：

- **写入时机**：专注倒计时归零时，读取当日键 → 追加新记录 → 写回
- **读取时机**：页面加载时读取当日键，恢复当日列表、累计专注时长和热力图
- **跨天处理**：页面加载时以当前日期计算键名；若当日键不存在，视为空列表开始新的一天。历史日期的键不主动清理，但不在界面展示（需求明确排除跨天数据查看）
- **数据不共享**：localStorage 绑定当前浏览器配置文件，不跨浏览器、不跨设备、不跨用户

### 运行时状态

- **持久化状态**：当日专注记录列表（`SessionRecord[]`）
- **会话内状态（不持久化）**：番茄钟当前阶段（idle/focusing/resting）、剩余秒数、暂停状态。页面刷新后番茄钟回到 `idle`，当日已完成的记录列表仍可读回

## 4. 可重复验证方式

番茄钟倒计时依赖定时器（`setInterval`），涉及长状态路径（25 分钟 + 5 分钟）和定时任务。为使验收可重复执行，说明以下测试控制方式，**仅在测试环境使用**，正常运行仍按产品要求执行。

### 受影响的验收场景

- **AC-01**（完成专注时段并自动记录）：需等待 25 分钟专注倒计时归零才能验证自动记录
- **AC-02**（累计专注时长更新）：需完成至少一个专注番茄钟才能验证累计时长
- **AC-03**（专注热力图展示）：需完成至少一个专注番茄钟才能验证热力图标记

### 验证控制入口

在开发环境（`import.meta.env.DEV` 为 `true` 时）暴露一个全局测试控制对象 `window.__TIMELING_TEST__`，提供以下方法：

- `fastForwardFocus()`: 将专注倒计时剩余秒数设为 0，触发完成逻辑（等价于自然归零），生成一条当日记录并进入休息阶段
- `fastForwardRest()`: 将休息倒计时剩余秒数设为 0，触发休息完成逻辑，回到 `idle`
- `setFocusTickSeconds(sec: number)`: 临时设置专注阶段每 tick 递减的秒数（用于加速倒计时验证），测试结束后恢复为 1
- `clearTodaySessions()`: 清除当日 localStorage 键，恢复到空列表初态

**验证流程示例（AC-01/AC-02/AC-03）**：

1. 打开页面，确认当日列表为空、累计时长为 0、热力图全浅色
2. 点击"开始"启动专注倒计时
3. 调用 `window.__TIMELING_TEST__.fastForwardFocus()` 触发专注完成
4. 确认当日列表新增一条记录（完成时间 + 25 分钟），累计时长显示 25 分钟，热力图对应时段格子颜色加深
5. 重复步骤 2-4 可验证多次完成后的累计和热力图更新

**AC-04（刷新后数据保留）**：

1. 完成至少一个专注番茄钟（可通过 `fastForwardFocus` 加速）
2. 刷新页面
3. 确认当日记录列表、累计专注时长、热力图与刷新前一致

### 恢复初态

调用 `clearTodaySessions()` 清除当日 localStorage 键并重置页面状态，恢复到空列表初态，便于重复执行验收。
