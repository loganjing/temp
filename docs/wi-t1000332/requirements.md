# 工单系统需求基线（134-ticket）

来源标注约定：
- 【用户】= 本任务用户明确提出的需求；
- 【推荐】= 为闭合核心目标补充的推荐基线，保守、可逆、可观察，用户可调整或否决；
- 其余关键缺口保持"未规定"，不在本基线中代用户决定。

## 1. 目标

【用户】构建工单系统，覆盖工单从提交、分配、处理到完成/取消的完整生命周期，并提供公司级数据隔离、SLA 优先级、多轮回复、转派协作、完成邮件通知、满意度评价、统计分析与运营仪表盘、工单工作台和操作日志。

## 2. 角色与使用对象

- 提交人【用户】：公司内提交工单的用户，信息含姓名、公司、部门、邮箱；可多轮回复工单，收到完成通知邮件并进行满意度评价。
- 处理人【用户】：业务组成员，通过工单工作台查看与处理分配到本组的工单，可回复、转派、完成工单并查看提交人完整信息。
- 配置操作者【推荐】：为所属公司维护业务组、成员与分类自动分配规则的操作者。权限模型与角色边界未规定，本基线不做权限设计。

## 3. 工单数据要求

单张工单记录以下信息【用户】：

| 信息项 | 要求 |
| --- | --- |
| 工单ID | 系统内唯一标识【用户】（生成格式未规定） |
| 主题 / 描述 | 提交时填写 |
| 分类 | 提交时选择，用于自动分配与统计 |
| SLA 优先级 | P0–P4 五级【用户】 |
| 提交人信息 | 姓名、公司、部门、邮箱【用户】 |
| 创建时间 | 系统记录 |
| 所属公司 | 工单公司隔离与分配的公司归属【用户】 |
| 回复记录 | 多轮，每轮含回复人、回复时间【用户】 |
| 处理记录 | 处理人、处理时间【用户】 |

## 4. 端到端流程与生命周期

工单主流程（完整说明一次，功能需求按编号引用）：

1. 配置：为某公司创建多个业务组并设置成员（5.4）；配置"分类 → 业务组"自动分配规则（5.4）。
2. 提交：提交人填写主题、描述、分类并选择优先级创建工单（5.1），系统记录工单ID、提交人完整信息与创建时间，工单进入"创建"状态。
3. 分配：工单按分类自动分配到对应业务组，进入"待处理"；未匹配规则时保持"待分配"等待人工分配【推荐】。
4. 处理：处理人从工作台（5.9）查看待处理工单，接手后可查看提交人完整信息（5.6），与提交人多轮回复（5.2），必要时转派（5.5）。
5. 完成：处理人完成处理，系统记录处理人与处理时间，工单状态变为"完成"（终态），并向提交人邮箱发送完成通知邮件（5.6）。
6. 评价：提交人收到完成的工单后进行满意度评价（5.7）。
7. 运营：全流程关键操作写入操作日志（5.10）；工单分布与运营指标在统计分析与仪表盘呈现（5.8）。

生命周期状态集合【用户】：创建、待分配、待处理、完成、取消。

状态流转【推荐】：创建 →（进入分配流程）→ 待分配 →（分配到业务组）→ 待处理 →（处理完成）→ 完成；未到终态的工单（创建/待分配/待处理）可被取消，进入"取消"；完成与取消为终态，不再流转。

## 5. 功能需求

### 5.1 工单提交与管理
- 【用户】提交人提交工单，填写主题、描述、分类，设置 SLA 优先级（P0–P4）；系统生成唯一工单ID，记录提交人完整信息与创建时间（见第 3 节）。
- 【用户】提交后的工单信息可通过查看读回。

### 5.2 工单多轮回复
- 【用户】工单支持多轮回复；每轮回复记录回复人与回复时间。
- 回复人范围（提交人、处理人等）未规定；验证按第 4 节流程第 4 步的双向回复执行。

### 5.3 公司数据隔离
- 【用户】工单按公司隔离：某公司的工单仅本公司可见与可操作，不向其他公司用户展示。
- 【用户】业务组、成员与自动分配规则均按公司维度维护（见 5.4）。
- 【用户】统计分析支持按公司维度汇总查看（见 5.8），不改变工单本身的公司归属隔离。

### 5.4 业务组与工单分配
- 【用户】允许给某个公司增加多个业务组；每个业务组可设置成员。
- 【用户】允许为某个公司配置工单按分类自动分配到某个业务组的规则；新工单按其分类自动分配。
- 【推荐】未匹配到分配规则的工单保持"待分配"，等待人工分配。

### 5.5 工单转派
- 【用户】支持工单转派操作：将工单转派给其他处理人/业务组继续处理。
- 转派对象的具体范围与操作权限未规定；转派作为关键操作被日志记录（5.10）。

### 5.6 工单处理与完成通知
- 【用户】处理工单时可查看提交人的完整信息，包括姓名、公司、部门、历史工单等。
- 【用户】处理工单后记录处理人、处理时间等；工单完成且系统向提交人邮箱发送完成通知邮件。

### 5.7 用户满意度评价
- 【用户】用户收到完成的工单后进行满意度评价。
- 【推荐】评价采用分值形式（1–5 分），使"满意度"运营指标可计算；评价形式可由用户调整。

### 5.8 统计分析
- 【用户】支持按公司、部门维度统计工单分布。
- 【用户】统计与分析仪表盘查看运营指标：工单量、平均响应时间、满意度、热点问题等。
- 【推荐】指标口径：平均响应时间 = 工单创建至首次回复的平均时长；热点问题 = 工单量最多的问题分类；满意度 = 满意度评价分值的平均。

### 5.9 工单工作台
- 【用户】查看待处理工单列表。
- 【用户】支持筛选、搜索、排序，并可按公司维度筛选。
- 【推荐】搜索按工单ID/主题关键字，筛选含优先级、分类条件；具体条件集合可由用户调整。

### 5.10 操作日志
- 【用户】记录工单相关操作日志，覆盖创建、分配、回复、转派、处理、完成、取消、评价等关键操作，含操作人与操作时间。
- 日志的查看入口与保留期限未规定。

## 6. 验收场景

### AC-01：提交工单并完整记录基础信息
- 验收条件：提交人提交工单后，系统生成唯一工单ID，并完整记录主题、描述、分类、SLA 优先级（P0–P4）、提交人信息（姓名、公司、部门、邮箱）与创建时间，再次查看时可读回。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份提交一张工单（填写主题、描述、分类并设置优先级），保存后打开该工单详情查看。
- 预期结果：工单具有系统生成的唯一ID；主题、描述、分类、优先级、提交人姓名/公司/部门/邮箱、创建时间与提交内容一致并可读回。
- 证据类型：interaction, session-persistence
- 共享流程组：工单端到端流程

### AC-02：工单按公司隔离
- 验收条件：某公司的工单仅本公司可见与可操作，其他公司用户无法查看或操作该工单。
- 入口类型：用户界面
- 验证动作：A公司提交人提交工单后，以B公司用户身份进入工单列表、工作台与搜索，并尝试直接访问该工单。
- 预期结果：B公司用户在列表、工作台与搜索结果中看不到A公司工单；直接访问该工单时不可见或被拒绝。
- 证据类型：authorization, error-feedback

### AC-03：工单多轮回复
- 验收条件：工单支持多轮回复，每轮记录回复人与回复时间，回复按时间顺序保留展示。
- 入口类型：用户界面
- 验证动作：在工单详情中，由提交人与处理人先后进行两次以上回复，然后查看该工单的回复记录。
- 预期结果：每条回复显示对应回复人与回复时间，多轮回复全部按顺序保留。
- 证据类型：interaction
- 共享流程组：工单端到端流程

### AC-04：工单生命周期状态流转
- 验收条件：工单按"创建 → 待分配 → 待处理 → 完成"流转，未到终态的工单可被取消；完成与取消为终态。
- 入口类型：用户界面
- 验证动作：创建一张工单并观察初始状态，经过自动分配与处理后将其完成，过程中核对各阶段状态；另创建一张工单在处理前执行取消。
- 预期结果：第一张工单状态依次呈现创建、待分配/待处理、完成；第二张工单进入"取消"状态且不再流转。
- 证据类型：interaction
- 共享流程组：工单端到端流程

### AC-05：业务组与成员管理
- 验收条件：可为某个公司增加多个业务组，并为每个业务组设置成员，配置保存后可读回。
- 入口类型：用户界面
- 验证动作：为公司A创建两个业务组，分别添加不同成员并保存，随后查看该公司业务组配置。
- 预期结果：两个业务组独立存在，各自成员与配置一致并可读回，不同业务组之间互不混淆。
- 证据类型：interaction, session-persistence

### AC-06：按分类自动分配工单到业务组
- 验收条件：公司配置"分类 → 业务组"规则后，新提交工单按其分类自动分配到对应业务组并进入"待处理"；未匹配分类的工单保持"待分配"【推荐】。
- 入口类型：用户界面
- 验证动作：为公司A配置某分类指向业务组G的自动分配规则，提交一张该分类的工单，查看其分配归属与状态；再提交一张未配置规则分类的工单，查看其状态。
- 预期结果：匹配分类的工单自动分配到业务组G并进入"待处理"；未匹配分类的工单保持"待分配"。
- 证据类型：interaction
- 共享流程组：工单端到端流程

### AC-07：工单转派
- 验收条件：处理中的工单可被转派给其他处理人/业务组，转派后由新对象继续处理。
- 入口类型：用户界面
- 验证动作：将一张待处理工单从处理人/业务组甲转派给乙，随后以乙的身份查看其工作台与该工单归属。
- 预期结果：工单处理归属变为乙；乙可在其工作台/待处理列表中看到该工单并继续处理。
- 证据类型：interaction

### AC-08：处理工单时查看提交人完整信息
- 验收条件：处理人打开工单时可查看提交人的姓名、公司、部门及其历史工单。
- 入口类型：用户界面
- 验证动作：以提交人身份预先提交多张工单，处理人打开其中一张已分配工单，查看提交人信息。
- 预期结果：显示提交人姓名、公司、部门，并列出其历史工单，历史工单与该提交人实际提交记录一致。
- 证据类型：interaction
- 共享流程组：工单端到端流程

### AC-09：工单完成记录与邮件通知
- 验收条件：工单处理完成后，记录处理人与处理时间，工单状态变为"完成"，并向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：处理人完成一张工单后，查看该工单的处理记录与状态，并检查提交人邮箱收件情况。
- 预期结果：工单状态为"完成"，处理人与处理时间被记录；提交人邮箱收到工单完成通知邮件。
- 证据类型：interaction, other
- 共享流程组：工单端到端流程

### AC-10：用户满意度评价
- 验收条件：工单完成后，提交人可对该工单进行满意度评价，评价被记录并关联到该工单。
- 入口类型：用户界面
- 验证动作：提交人在工单完成后对该工单提交满意度评价，随后查看该工单。
- 预期结果：评价提交成功；该工单上可查到此提交人的满意度评价记录。
- 证据类型：interaction, session-persistence
- 共享流程组：工单端到端流程

### AC-11：按公司与部门维度统计工单分布
- 验收条件：统计分析支持按公司维度、部门维度展示工单分布，分布数据与实际工单一致。
- 入口类型：用户界面
- 验证动作：准备若干来自不同公司、不同提交人部门的工单，在统计视图中分别选择公司维度与部门维度查看分布。
- 预期结果：公司维度与部门维度下的工单分布数量与实际工单数据一致。
- 证据类型：interaction

### AC-12：运营指标仪表盘
- 验收条件：统计与分析仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标，指标值与底层工单数据一致。
- 入口类型：用户界面
- 验证动作：在已有完整工单数据（含回复、完成、评价记录）的环境下打开统计与分析仪表盘，逐项核对指标。
- 预期结果：工单量、平均响应时间（创建至首次回复【推荐】）、满意度（评价平均值【推荐】）、热点问题（工单量最多的分类【推荐】）均可见，且与底层工单数据计算结果一致。
- 证据类型：interaction

### AC-13：工单工作台列表
- 验收条件：工作台展示待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：在工作台对待处理工单列表分别执行筛选（含公司维度筛选）、关键字搜索与排序操作，核对列表结果。
- 预期结果：列表按所选条件正确过滤与排序；按公司维度筛选后仅显示所选公司的工单；搜索命中的工单与关键字匹配。
- 证据类型：interaction

### AC-14：操作日志记录
- 验收条件：工单关键操作（创建、分配、回复、转派、处理、完成、取消、评价）被记录为日志，含操作人与操作时间，与实际操作一致。
- 入口类型：内部
- 验证动作：对一张工单依次执行创建、分配、回复、转派、处理、完成等操作，再对另一张工单执行取消与评价，随后查询工单操作日志。
- 预期结果：日志完整记录上述关键操作，每条日志含操作人与操作时间，与实际执行的操作一致。
