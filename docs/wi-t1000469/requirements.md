# 工单系统需求文档

## 1. 目标

构建一个工单管理系统，支持工单的创建、分配、协作、处理和评价全生命周期管理。系统面向提交人和处理人两类核心参与者，通过业务组和分类自动分配机制提升工单流转效率。

> 本节为对用户目标的概括性陈述。

## 2. 角色

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单、查看工单进度、对已完工单进行满意度评价 | 用户明确提出 |
| 处理人 | 处理分配到的工单、回复工单、转派工单 | 用户明确提出（回复人、处理人） |
| 业务组管理员 | 为公司创建业务组、设置成员、配置分类到业务组的分配规则 | 用户明确提出（"允许给某个公司增加多个业务组"隐含管理操作） |

> 角色名称仅用于需求描述，不表示系统已指定权限模型或 RBAC 设计。

## 3. 工单管理

### 3.1 工单基本信息

工单创建时必须包含以下字段（用户明确提出）：

- **工单ID**：系统生成的唯一标识
- **主题**：工单标题
- **描述**：工单详细内容
- **分类**：问题分类
- **提交人信息**：包括姓名、邮箱
- **创建时间**：工单提交的时间
- **SLA优先级**：P0（最高）至 P4（最低），共五个级别
- **问题分类**：用于自动分配的依据

### 3.2 多轮回复

工单支持多轮回复（用户明确提出）：

- 每条回复记录回复人和回复时间
- 回复按时间顺序排列，形成完整对话链

### 3.3 工单生命周期

工单具有以下状态（用户明确提出）：

| 状态 | 说明 | 进入条件 |
|------|------|----------|
| 创建 | 工单刚提交的初始状态 | 提交人提交工单 |
| 待分配 | 等待分配到业务组 | 工单创建后进入 |
| 待处理 | 已分配到业务组，等待处理人处理 | 分配完成（手动或自动） |
| 完成 | 工单已处理完毕 | 处理人完成处理 |
| 取消 | 工单被取消 | 提交人或处理人取消工单 |

状态流转方向：

```
创建 → 待分配 → 待处理 → 完成
                ↓
              取消
```

> 推荐基线：取消操作可从待分配或待处理状态触发。具体可取消的状态范围未由用户明确规定，推荐保守允许从"待分配"和"待处理"状态取消。

## 4. 功能点

### 4.1 工单分配

#### 4.1.1 业务组管理（用户明确提出）

- 允许给某个公司增加多个业务组
- 每个业务组可以设置成员（处理人列表）

#### 4.1.2 分类自动分配（用户明确提出）

- 允许为某个公司配置工单分类到业务组的分配规则
- 工单创建后，根据其分类自动匹配规则，将工单分配到对应的业务组
- 分配后工单状态从"待分配"转为"待处理"

> 推荐基线：当分类无匹配规则时，工单保持在"待分配"状态等待手动分配。此为可逆、可观察的保守默认值。

### 4.2 工单协作

#### 4.2.1 工单转派（用户明确提出）

- 支持将工单从一个处理人或业务组转派到另一个处理人或业务组
- 转派后工单仍处于"待处理"状态
- 转派操作应记录转派人、转派目标和转派时间

> 推荐基线：转派记录作为工单操作日志的一部分，便于追溯。此为闭合核心目标（可追溯的转派协作）所必需的最小缺口补充。

### 4.3 工单处理

#### 4.3.1 提交人信息查看（用户明确提出）

处理工单时可查看提交人的完整信息：

- 姓名
- 公司
- 部门
- 历史工单（该提交人之前提交的所有工单列表）

#### 4.3.2 处理记录（用户明确提出）

工单处理完成后记录：

- 处理人
- 处理时间
- 工单状态（完成后状态变为"完成"）

### 4.4 用户评价

#### 4.4.1 满意度评价（用户明确提出）

- 用户收到工单完成通知后，可对工单处理结果进行满意度评价
- 评价关联到具体工单

> 用户未明确指定评价的分级方式（如星级、评分、选项），此项保持未规定，不自行推断。

## 5. 验收标准

### AC-01：提交人可创建工单并填写完整信息

- 验收条件：提交人能够创建工单，填写主题、描述、分类，系统自动记录工单ID、提交人信息（含邮箱）和创建时间，并设置SLA优先级（P0-P4）和问题分类。
- 入口类型：用户界面
- 验证动作：提交人填写工单表单并提交。
- 预期结果：工单创建成功，可查看到工单ID、主题、描述、分类、提交人信息（含邮箱）、创建时间、SLA优先级和问题分类，工单进入"待分配"状态。
- 证据类型：runtime-render, interaction

### AC-02：工单支持多轮回复

- 验收条件：在工单详情中，处理人和提交人可以进行多轮回复，每条回复记录回复人和回复时间，回复按时间顺序展示。
- 入口类型：用户界面
- 验证动作：在已创建的工单中添加多条回复。
- 预期结果：所有回复均可见，每条回复显示回复人身份和回复时间，回复按时间先后顺序排列。
- 证据类型：runtime-render, interaction, session-persistence

### AC-03：工单生命周期状态正确流转

- 验收条件：工单能够在"创建 → 待分配 → 待处理 → 完成"和"取消"状态间正确流转，每次状态变更可观察。
- 入口类型：用户界面
- 验证动作：创建工单后观察初始状态；完成分配后观察状态变为"待处理"；处理人完成处理后观察状态变为"完成"；在另一工单上执行取消操作观察状态变为"取消"。
- 预期结果：工单状态按照生命周期定义正确流转，当前状态可在工单详情中观察到。
- 证据类型：runtime-render, interaction, session-persistence

### AC-04：公司可管理多个业务组及成员

- 验收条件：可以为某个公司增加多个业务组，并为每个业务组设置成员。
- 入口类型：用户界面
- 验证动作：为一个公司创建多个业务组，并为每个业务组添加成员。
- 预期结果：业务组和成员创建成功，可查看该公司下所有业务组及其成员列表。
- 证据类型：runtime-render, interaction, session-persistence

### AC-05：工单按分类自动分配到业务组

- 验收条件：为某公司配置分类到业务组的分配规则后，新创建的工单根据其分类自动分配到对应业务组，状态从"待分配"转为"待处理"。
- 入口类型：用户界面
- 验证动作：配置分类与业务组的分配规则，然后创建一个该分类的工单。
- 预期结果：工单自动分配到对应业务组，工单状态变为"待处理"，可在工单详情中查看到分配的业务组。
- 证据类型：runtime-render, interaction, session-persistence

### AC-06：支持工单转派操作

- 验收条件：处于"待处理"状态的工单可以被转派到另一个处理人或业务组，转派后工单仍为"待处理"状态。
- 入口类型：用户界面
- 验证动作：在一个待处理工单上执行转派操作，选择目标处理人或业务组。
- 预期结果：工单成功转派，工单详情中可查看到新的处理人或业务组，工单状态保持"待处理"。
- 证据类型：runtime-render, interaction, session-persistence

### AC-07：处理工单时可查看提交人完整信息并记录处理结果

- 验收条件：处理人在处理工单时可查看提交人的完整信息（姓名、公司、部门、历史工单），处理完成后系统记录处理人、处理时间和工单状态。
- 入口类型：用户界面
- 验证动作：处理人打开一个待处理工单，查看提交人信息区域，完成处理操作。
- 预期结果：工单详情中显示提交人的姓名、公司、部门和该提交人的历史工单列表；处理完成后工单记录处理人、处理时间，状态变为"完成"。
- 证据类型：runtime-render, interaction, session-persistence

### AC-08：用户可对已完成工单进行满意度评价

- 验收条件：工单完成后，提交人可对该工单进行满意度评价，评价关联到具体工单。
- 入口类型：用户界面
- 验证动作：提交人打开一个已完成的工单，提交满意度评价。
- 预期结果：评价提交成功，可在工单详情中查看到该工单的满意度评价结果。
- 证据类型：runtime-render, interaction, session-persistence
