# 贪吃蛇游戏 架构基线

## 设计依据

本设计基于已批准的需求基线 `docs/wi-t1000049/requirements.md`（sha256: dbff4661e8da08d438f47f86d94306c86bc05c9c90bf2b8216da33dee791aaa3）。产品语义（游戏规则、方向控制、食物增长、碰撞结束、重新开始）不在此扩展或重裁。

## 路线结论

**简单前端（simple-frontend）**：贪吃蛇游戏的全部行为在浏览器内完成，不涉及服务端权威数据、认证、后台任务、外部服务或跨设备共享。

## 页面与交互范围

单个 SPA 页面承载完整游戏体验：

- **游戏区域**：基于网格的渲染画布（Canvas 或 CSS Grid），蛇身、食物在网格内呈现。
- **方向控制**：键盘方向键（↑↓←→）或等价手势输入，驱动蛇移动方向变更。
- **状态显示**：分数在游戏进行中实时显示；游戏结束时显示最终分数。
- **游戏控制**：开始入口与游戏结束后的重新开始入口。

游戏交互状态以帧/步驱动，蛇按当前方向每时间步前进一格，方向输入在下一步生效。掉头约束（不可直接反向）由输入校验逻辑保证。

## 浏览器状态与数据归属

游戏运行时状态全部保存在浏览器内存中：

- 蛇身坐标数组
- 食物坐标
- 当前移动方向
- 分数
- 游戏状态（进行中 / 结束）

重新开始时重置上述全部状态为初始值。本应用不使用 `localStorage` 持久化，因为需求基线未要求刷新或重开后数据保留；游戏状态在页面刷新后恢复初始即可。

## 实现入口与运行方式

- **技术栈**：React + Vite SPA
- **实现入口**：Vite 开发服务器，通过 `npm run dev` 启动
- **构建产物**：`npm run build` 生成静态前端产物，可部署到任意静态托管

## 接口与校验边界

- **方向输入校验**：接受与当前方向不互为反向的方向变更；互为反向时忽略，保持原方向。
- **食物生成校验**：新食物坐标必须落在蛇身未占据的空格内。
- **碰撞判定**：每步移动后检查蛇头是否越出边界或与蛇身重叠，满足条件时游戏结束。

## 范围外

不包含服务端 API、数据库、认证、后台任务、外部集成或同步层，与需求基线范围外声明一致。
