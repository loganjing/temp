# 工单系统需求基线

- Work Item：wi-t1000312
- 业务任务：126-ticket
- 阶段：requirements
- 日期：2026-10-20

## 1. 目标

为多公司共用环境提供完整的工单服务闭环（用户明确提出）：公司用户提交带问题分类与 SLA 优先级（P0-P4）的工单；系统按公司配置的分类规则将工单自动分配到业务组；处理人在工作台处理工单，与提交人多轮沟通，必要时转派协作；工单完成时记录处理信息并发送邮件通知；提交人进行满意度评价；平台提供按公司、部门维度的工单分布统计与运营仪表盘，并记录工单相关操作日志。工单数据按公司隔离。

## 2. 角色与权限边界

用户未指定具体角色名称与权限体系；以下角色由功能描述推导，仅用于描述旅程与验收（推导说明，非用户指定）：

- **提交人**：公司内提交工单的用户，可创建工单、查看本公司工单、参与多轮回复、在工单完成后进行满意度评价。
- **处理人**：业务组成员，在工作台查看并筛选待处理工单，回复、转派、完成工单，处理时可查看提交人完整信息。
- **配置管理员**：为公司维护业务组、业务组成员与"分类 → 业务组"分配规则的用户。

公司隔离规则（用户明确提出）：工单数据按公司隔离。推荐基线：公司内账号（如提交人）只能查看和操作本公司的工单；工作台的"按公司维度筛选"与统计的"按公司维度"意味着存在可跨公司查看的处理/运营视角，其账号体系与权限范围未规定。

## 3. 核心对象与数据要求

### 3.1 工单

用户明确提出工单包含：工单ID（系统内唯一）、主题、描述、分类、提交人信息（含邮箱）、创建时间。

同一对象上的关联数据（功能闭合必需）：

- SLA 优先级：P0-P4 之一（用户明确提出，作为工单字段；各优先级的具体响应时限未规定）。
- 状态：见 §4。
- 处理记录：处理人、处理时间（用户明确提出，见 §5.7）。
- 回复列表：见 §5.2。
- 满意度评价：见 §5.9。

提交人信息（用户在处理功能中明确列出）：姓名、公司、部门、邮箱；同时支撑 §5.11 的按部门统计。

### 3.2 回复

- 字段：回复人、回复时间（用户明确提出）；回复内容为"回复"的最小必要组成（推荐基线）。

### 3.3 业务组与分类分配规则

- **业务组**：属于某个公司，含组名与成员列表（用户明确提出：允许给某个公司增加多个业务组，每个业务组可以设置成员）。
- **分类分配规则**：公司内"问题分类 → 业务组"的映射，支撑工单按分类自动分配（用户明确提出）。

## 4. 生命周期状态

用户指定状态集合：创建、待分配、待处理、完成、取消。
流转规则为推荐基线（用户仅指定状态集合，未指定流转；以下为最小必要闭合，可调整）：

1. 提交人提交工单后处于**待分配**（"创建"按提交动作理解；若需作为独立状态，则流转为 创建 → 待分配）。
2. 待分配 → 待处理：工单被分配到业务组（自动分配见 §5.5，或人工分配）。
3. 待处理 → 完成：处理人完成处理。
4. 未完成的工单可被**取消**；取消为终态。
5. 完成、取消均为终态，关闭后再次查看状态保持不变。

## 5. 模块需求

### 5.1 工单创建与查看（用户界面）

- 提交人创建工单时填写主题、描述、分类，并选择 SLA 优先级（P0-P4）；提交人信息（姓名、公司、部门、邮箱）随工单记录。
- 创建成功后可通过工单详情读回全部基础字段（见 AC-01）。

### 5.2 多轮回复（用户界面）

- 同一工单支持多轮回复，提交人与处理方可交替回复。
- 每条回复记录回复人、回复时间（用户明确提出）与回复内容，按时间顺序展示（见 AC-04）。

### 5.3 公司隔离

- 工单数据按公司隔离（用户明确提出）：一个公司的账号不能查看或操作另一个公司的工单（列表、搜索、详情均不可见，见 AC-03）。

### 5.4 分类与 SLA 优先级

- 工单支持问题分类与 SLA 优先级 P0-P4 设置（用户明确提出）。分类目录内容与各优先级的 SLA 时限未规定。

### 5.5 业务组与自动分配

- 允许为某个公司增加多个业务组，每个业务组可设置成员（用户明确提出，见 AC-05）。
- 允许为公司配置"分类 → 业务组"分配规则；该公司新工单按分类自动分配到对应业务组（用户明确提出，见 AC-06）。
- 推荐基线：无匹配分配规则时，工单保持待分配等待人工处理；其余降级行为未规定。

### 5.6 工单转派

- 支持工单转派操作（用户明确提出）：将已分配工单转派给其他业务组或处理人；转派后归属改变，且操作可在工单上追溯（见 AC-07）。
- 推荐基线：转派后工单保持待处理状态。

### 5.7 工单处理与提交人完整信息

- 处理人处理工单时可查看提交人的完整信息：姓名、公司、部门、历史工单（用户明确提出，见 AC-08）。历史工单为该提交人提交的工单列表。
- 工单处理完成后记录处理人、处理时间等（用户明确提出，见 AC-09）。

### 5.8 完成与邮件通知

- 工单完成且发送邮件进行通知（用户明确提出）。推荐基线：通知发送至工单记录的提交人邮箱，邮件包含工单标识（工单ID或主题）；发送机制与内容模板未规定。

### 5.9 满意度评价

- 用户收到工单后进行满意度评价（用户明确提出）。推荐基线：工单完成后提交人可提交评价，评价结果与评价人可读回；满意度采用评分制（如 1-5 分）以支撑 §5.11 的满意度统计，具体尺度未规定可调整。

### 5.10 工单工作台

- 查看待处理工单列表，支持筛选、搜索、排序，可按公司维度筛选（用户明确提出，见 AC-11）。
- 除公司维度外的筛选字段集合与排序字段未规定，按实际入口核对。

### 5.11 统计分析与仪表盘

- 支持按公司、部门维度统计工单分布（用户明确提出）。
- 统计与分析仪表盘可查看运营指标：工单量、平均响应时间、满意度、热点问题等（用户明确提出，见 AC-12）。
- 推荐口径（可调整）：平均响应时间 = 工单创建至首次回复的平均时长；热点问题 = 按问题分类聚合的工单量排名；满意度 = 已评价工单的平均评分。

### 5.12 操作日志

- 记录工单相关日志（用户明确提出）。推荐基线：记录工单关键操作（创建、分配、转派、回复、完成、取消、评价），每条含操作人、操作时间与操作类型，并可在工单上查看（见 AC-13）。

## 6. 用户旅程

### 旅程A：工单端到端闭环（提交人 + 处理人 + 配置管理员）

1. 配置管理员为公司建立业务组并设置成员（§5.5，AC-05），配置"分类 → 业务组"分配规则。
2. 提交人创建工单（§5.1，AC-01）；系统按分类自动分配到业务组（§5.5，AC-06），工单进入待处理（§4）。
3. 处理人在工作台发现该工单（§5.10，AC-11），打开后查看提交人完整信息（§5.7，AC-08），与提交人多轮回复（§5.2，AC-04）；需要协作时转派（§5.6，AC-07）。
4. 处理人完成处理：工单进入完成，记录处理人/处理时间（§5.7，AC-09），系统发送邮件通知提交人（§5.8，AC-09）。
5. 提交人收到通知后对工单进行满意度评价（§5.9，AC-10）。
6. 全程关键操作记录日志（§5.12，AC-13）；统计与仪表盘反映最新数据（§5.11，AC-12）。

### 旅程B：处理人日常处理

处理人在工作台通过筛选、搜索、排序定位待处理工单（§5.10，AC-11），逐张完成查看提交人信息、回复、转派与完成处理（§5.2、§5.6、§5.7、§5.8）。

## 7. 非功能可观察约束

- 公司数据隔离（用户明确提出）：见 §5.3，作为验收项（AC-03）。
- 其余非功能要求（性能、并发、存储、部署）未规定。

## 8. 验收场景

### AC-01：提交人可创建工单并读回完整基础信息

- 验收条件：新工单创建成功后，其全部基础字段可通过工单详情读回。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份创建工单，填写主题、描述、选择分类与 SLA 优先级，提交后打开该工单详情查看。
- 预期结果：工单具有系统生成的唯一工单ID；详情可读回主题、描述、分类、优先级（P0-P4 之一）、提交人姓名/公司/部门/邮箱、创建时间；初始状态为待分配。
- 证据类型：runtime-render, interaction, session-persistence
- 共享流程组：工单端到端

### AC-02：工单生命周期状态可流转并保持

- 验收条件：工单按生命周期状态流转，且状态在关闭后再次查看时保持。
- 入口类型：用户界面
- 验证动作：对一张待分配工单执行分配（或命中自动分配）后再执行完成；对另一张未完成工单执行取消；然后重新打开两张工单详情。
- 预期结果：第一张工单状态依次呈现待分配 → 待处理 → 完成，第二张状态为取消；重新查看后状态不变。
- 证据类型：runtime-render, interaction, session-persistence
- 共享流程组：工单端到端

### AC-03：工单数据按公司隔离

- 验收条件：一个公司的账号不能查看或操作另一个公司的工单。
- 入口类型：用户界面
- 验证动作：以公司A提交人账号查看工单列表、搜索关键词并尝试打开公司B的工单；再以公司B账号对照执行。
- 预期结果：公司A账号的列表、搜索结果、详情均不出现公司B的工单，反之亦然；无法越权访问对方公司的工单。
- 证据类型：authorization, runtime-render

### AC-04：工单支持多轮回复并记录回复人与回复时间

- 验收条件：提交人与处理方可对同一工单进行多轮回复，回复记录可读回。
- 入口类型：用户界面
- 验证动作：在一张已分配工单中，由处理人回复一次、提交人再回复一次，然后查看工单回复区。
- 预期结果：回复按时间顺序展示至少两条，每条包含回复人、回复时间与回复内容，两轮回复的回复人和时间可区分。
- 证据类型：runtime-render, interaction, session-persistence
- 共享流程组：工单端到端

### AC-05：可为公司配置多个业务组及其成员

- 验收条件：公司可创建多个业务组并为每个业务组设置成员，配置保存后可读回。
- 入口类型：用户界面
- 验证动作：为某公司新增两个业务组，分别添加不同成员，保存后查看该公司业务组列表。
- 预期结果：业务组列表包含新增的两个组；每个组可读回其成员列表，与设置一致。
- 证据类型：runtime-render, interaction, session-persistence

### AC-06：工单按分类自动分配到业务组

- 验收条件：已配置分类分配规则的公司，新工单按其分类自动分配到对应业务组，无需人工选择。
- 入口类型：用户界面
- 验证动作：为公司配置"分类X → 业务组G"规则后，以该公司提交人身份提交一张分类为X的工单，查看工单归属与状态。
- 预期结果：工单自动归属业务组G（业务组G成员可见该工单），状态进入待处理；提交过程中未要求提交人选择业务组。
- 证据类型：runtime-render, interaction

### AC-07：工单支持转派并可追溯

- 验收条件：已分配工单可转派给其他业务组或处理人，转派后归属改变且可追溯。
- 入口类型：用户界面
- 验证动作：将一张待处理工单从业务组G1转派到业务组G2（或另一处理人），查看工单归属与操作记录。
- 预期结果：工单归属变为G2/新处理人；工单的日志或记录中可见转派操作与转派目标。
- 证据类型：runtime-render, interaction, session-persistence

### AC-08：处理工单时可查看提交人完整信息

- 验收条件：处理人打开工单时可查看提交人姓名、公司、部门及其历史工单。
- 入口类型：用户界面
- 验证动作：处理人打开一张已分配工单的提交人信息区，并打开该提交人的历史工单。
- 预期结果：可见提交人的姓名、公司、部门；可查看该提交人提交的历史工单列表（含此前创建的其他工单）。
- 证据类型：runtime-render

### AC-09：工单完成记录处理信息并邮件通知提交人

- 验收条件：工单完成时记录处理人与处理时间，并向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：处理人将一张待处理工单标记完成，查看工单记录，并检查提交人邮箱（或邮件发送记录）。
- 预期结果：工单状态变为完成；工单记录包含处理人与处理时间；提交人邮箱收到工单完成通知邮件（含工单标识）。
- 证据类型：runtime-render, session-persistence, other
- 共享流程组：工单端到端

### AC-10：提交人可对已完成工单进行满意度评价

- 验收条件：工单完成后提交人可提交满意度评价，评价结果可读回。
- 入口类型：用户界面
- 验证动作：提交人在一张已完成工单上提交满意度评价，然后查看该工单。
- 预期结果：评价保存成功；工单上可读回评价结果与评价人。
- 证据类型：runtime-render, interaction, session-persistence
- 共享流程组：工单端到端

### AC-11：工单工作台支持筛选、搜索、排序与公司维度筛选

- 验收条件：工作台展示待处理工单列表，筛选、搜索、排序及公司维度筛选组合生效。
- 入口类型：用户界面
- 验证动作：在工作台用关键词搜索，按公司维度筛选，再按创建时间或优先级排序，观察列表变化。
- 预期结果：列表仅展示符合当前条件组合的工单；按公司筛选后仅显示所选公司的工单；排序顺序与所选字段一致；清除条件后恢复默认的待处理工单列表。
- 证据类型：runtime-render, interaction

### AC-12：统计分析与运营仪表盘

- 验收条件：可查看按公司、部门维度的工单分布统计，以及工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：构造已知分布的工单数据后，打开统计分析与仪表盘，分别查看按公司维度、按部门维度的工单分布，以及工单量、平均响应时间、满意度、热点问题四类指标。
- 预期结果：按公司、按部门维度分别呈现工单分布，数值与构造数据一致；仪表盘四类指标可见且与实际工单数据一致。
- 证据类型：runtime-render

### AC-13：工单关键操作记录日志

- 验收条件：工单的关键操作被记录为日志，含操作人、时间与操作内容，可查看。
- 入口类型：用户界面
- 验证动作：对一张工单依次执行创建、回复、转派、完成后，查看该工单的操作日志。
- 预期结果：日志包含上述各操作记录，每条含操作人、操作时间与操作类型，按时间排列。
- 证据类型：runtime-render, session-persistence
- 共享流程组：工单端到端
