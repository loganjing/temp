# 工单系统需求基线

> Work Item: wi-t1000087 · Issue: T1000087 · 项目: JLGSpace-88

## 1. 目标与范围

构建一个工单管理系统，支持工单的创建、分配、处理、协作、评价和统计分析全生命周期管理，按公司隔离数据，面向多公司多业务组的运营场景。

**用户明确提出的需求范围：**

- 工单管理：基础信息、多轮回复、公司隔离、SLA 优先级、问题分类、生命周期状态管理
- 工单分配：业务组管理、按分类自动分配
- 工单协作：转派操作
- 工单处理：查看提交人完整信息、记录处理人/处理时间、完成后邮件通知
- 用户评价：满意度评价
- 统计分析：按公司/部门维度统计、运营仪表盘
- 工单工作台：待处理列表、筛选/搜索/排序
- 操作日志记录

## 2. 角色说明

以下角色由用户描述的操作场景推导，用于明确各功能的操作主体；用户未显式定义角色名称，此处标注为推荐基线。

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单、回复工单、接收完成通知、进行满意度评价 | 用户描述的操作场景推导 |
| 处理人 | 被分配处理工单的成员，属于某业务组；处理工单、回复、转派 | 用户描述的操作场景推导 |
| 管理员 | 管理公司的业务组和成员、配置分类自动分配规则 | 用户描述"允许给某个公司增加多个业务组"推导 |

> 未规定：角色的权限粒度、角色创建与管理的具体方式。用户未提及管理员如何被指定，保持未规定。

## 3. 核心实体与业务规则

### 3.1 工单（用户明确提出）

| 属性 | 说明 |
|------|------|
| 工单 ID | 系统生成的唯一标识 |
| 主题 | 工单标题 |
| 描述 | 工单详细内容 |
| 分类 | 问题分类（用户明确要求支持问题分类） |
| SLA 优先级 | P0 / P1 / P2 / P3 / P4（用户明确提出） |
| 提交人信息 | 包含姓名、邮箱；处理时还需展示公司、部门、历史工单 |
| 创建时间 | 工单提交时记录 |
| 公司 | 工单归属的公司，用于数据隔离 |
| 当前状态 | 生命周期状态，见 §4 |

| 处理时间 | 处理完成时记录 |

### 3.2 工单回复（用户明确提出）

- 工单支持多轮回复
- 每条回复记录回复人和回复时间

### 3.3 业务组（用户明确提出）

- 每个公司可配置多个业务组
- 每个业务组可设置成员
- 支持配置"分类 → 业务组"的自动分配规则，使某公司的工单按分类自动分配到对应业务组

### 3.4 满意度评价（用户明确提出）

- 提交人在工单完成后可进行满意度评价
- 用户未规定评价的具体维度或评分方式，保持未规定

### 3.5 操作日志（用户明确提出）

- 记录工单相关的操作日志
- 用户未规定日志的具体字段和保留策略，保持未规定

### 3.6 公司隔离（用户明确提出）

- 工单数据按公司隔离，不同公司之间不可见对方工单
- 业务组、分配规则等配置也按公司隔离

## 4. 工单生命周期

用户明确提出以下状态：**创建、待分配、待处理、完成、取消**。

状态流转规则（推荐基线——用户列出状态但未描述全部转换条件，以下为闭合核心流程的必要推荐）：

```
创建 → 待分配 → 待处理 → 完成
         ↘        ↘
           取消      取消
```

| 转换 | 触发条件 | 说明 |
|------|---------|------|
| 创建 → 待分配 | 提交人提交工单 | 工单创建后进入待分配状态 |
| 待分配 → 待处理 | 工单被分配到处理人（自动分配到业务组后，由业务组成员接单或被指派） | 分配完成后进入待处理 |
| 待处理 → 完成 | 处理人完成处理 | 记录处理人和处理时间，发送邮件通知 |
| 创建/待分配/待处理 → 取消 | 工单被取消 | 取消为终态 |

> 未规定：取消操作的具体权限归属（谁能取消工单）。保持未规定，由后续设计或实现阶段确认。

## 5. 用户旅程

### 旅程 A：工单提交到完成（端到端主流程）

1. 提交人创建工单（填写主题、描述、分类、优先级），系统记录提交人信息（含邮箱）和创建时间
2. 工单进入待分配状态；系统按分类自动分配规则将工单分配到对应业务组
3. 业务组处理人接单或被指派，工单进入待处理状态
4. 处理人在处理过程中可查看提交人完整信息（姓名、公司、部门、历史工单）
5. 处理人与提交人可通过多轮回复沟通
6. 处理人完成处理，系统记录处理人和处理时间，工单进入完成状态
7. 系统向提交人邮箱发送完成通知邮件
8. 提交人收到通知后对工单进行满意度评价

### 旅程 B：工单转派

1. 处理人在待处理状态下发起转派操作
2. 工单转派到新的处理人（可跨业务组）
3. 工单继续处于待处理状态，新处理人继续处理

### 旅程 C：工单工作台

1. 处理人打开工单工作台，查看待处理工单列表
2. 支持按公司维度筛选、搜索、排序
3. 处理人选择工单进入处理流程

## 6. 模块需求

### 6.1 工单管理模块

- **工单创建**：提交人填写主题、描述、分类、SLA 优先级（P0-P4）；系统自动记录工单 ID、提交人信息（含邮箱）、创建时间、所属公司
- **多轮回复**：提交人和处理人均可对工单进行回复，每条回复记录回复人和回复时间；回复按时间顺序排列
- **公司隔离**：所有工单数据按公司隔离
- **SLA 优先级**：支持 P0 / P1 / P2 / P3 / P4 五级优先级设置
- **问题分类**：工单创建时需选择分类，分类用于自动分配规则匹配

### 6.2 工单分配模块

- **业务组管理**：管理员可为每个公司创建多个业务组，每个业务组可设置成员
- **分类自动分配规则**：管理员可配置"公司 + 分类 → 业务组"的映射规则；工单创建后系统按规则自动将工单分配到对应业务组
- > 未规定：当某分类未配置规则时的处理方式（是否待手动分配），保持未规定

### 6.3 工单协作模块

- **工单转派**：支持将工单从当前处理人转派到其他处理人；转派操作记录在日志中
- > 未规定：转派是否限制在同一公司内。鉴于公司隔离规则，推荐基线为转派仅限同公司内

### 6.4 工单处理模块

- **提交人信息查看**：处理工单时，处理人可查看提交人的完整信息，包括姓名、公司、部门、历史工单列表
- **处理记录**：工单完成时，系统记录处理人和处理时间
- **邮件通知**：工单完成后，系统向提交人邮箱发送完成通知邮件

### 6.5 用户评价模块

- **满意度评价**：工单完成后，提交人可对工单处理结果进行满意度评价
- 评价数据纳入统计分析

### 6.6 统计分析模块

- **工单分布统计**：支持按公司维度、部门维度统计工单分布
- **运营仪表盘**：展示工单量、平均响应时间、满意度、热点问题等运营指标

### 6.7 工单工作台模块

- **待处理列表**：展示当前待处理工单列表
- **筛选**：支持按公司维度筛选，支持按分类、优先级等条件筛选
- **搜索**：支持按主题、工单 ID 等关键词搜索
- **排序**：支持按创建时间、优先级等字段排序

### 6.8 日志模块

- **操作日志**：记录工单相关操作（创建、分配、转派、回复、处理完成、取消、评价等）
- > 未规定：日志的具体字段、展示方式和保留策略，保持未规定

## 7. 验收场景

### AC-01：提交人可创建工单并包含完整基础信息（含公司隔离）

- 验收条件：提交人创建工单后，工单包含所有必填属性，且不同公司间数据相互隔离
- 入口类型：用户界面
- 验证动作：提交人填写主题、描述、分类、优先级后提交工单；切换到另一公司查看工单列表
- 预期结果：
  - 工单创建成功，包含系统生成的工单 ID、主题、描述、分类、SLA 优先级（P0-P4）、提交人信息（含邮箱）、创建时间
  - 工单归属提交人所在公司
  - 切换到另一公司后，无法看到该公司之外创建的工单
- 证据类型：interaction, session-persistence

### AC-02：工单支持多轮回复，记录回复人和回复时间

- 验收条件：提交人和处理人可对同一工单进行多次回复，每条回复可读回回复人和回复时间
- 入口类型：用户界面
- 验证动作：在已创建的工单中，不同用户依次添加多条回复
- 预期结果：
  - 所有回复按时间顺序展示
  - 每条回复显示对应的回复人和回复时间
  - 回复内容持久保存，重新查看时仍可读回
- 证据类型：interaction, session-persistence

### AC-03：工单支持 SLA 优先级设置和问题分类

- 验收条件：工单创建时可设置 P0-P4 优先级并选择问题分类，且优先级和分类可被工作台筛选和统计使用
- 入口类型：用户界面
- 验证动作：创建工单时选择不同优先级和分类，提交后在工单详情和工作台中查看
- 预期结果：
  - 优先级可设置为 P0、P1、P2、P3、P4 五个等级
  - 分类在创建时可选择
  - 工单详情和工作台列表中显示优先级和分类
- 证据类型：interaction, session-persistence

### AC-04：工单按生命周期状态流转

- 验收条件：工单状态按"创建 → 待分配 → 待处理 → 完成"流转，且支持取消
- 入口类型：用户界面
- 验证动作：创建工单后观察状态为待分配；分配处理人后观察状态变为待处理；处理人完成后观察状态变为完成；在待分配或待处理状态下取消工单
- 预期结果：
  - 工单创建后进入待分配状态
  - 分配后进入待处理状态
  - 处理完成后进入完成状态
  - 取消操作后工单进入取消状态（终态）
  - 各状态变更可在工单详情中观察到
- 证据类型：interaction, session-persistence

### AC-05：管理员可配置业务组并实现按分类自动分配

- 验收条件：管理员可为公司创建业务组并设置成员，配置分类→业务组规则后，新工单按分类自动分配到对应业务组
- 入口类型：用户界面
- 验证动作：
  - 管理员为公司 A 创建业务组"技术支持组"和"账务组"，分别添加成员
  - 配置规则：分类"技术问题"→技术支持组，分类"账务问题"→账务组
  - 提交人创建分类为"技术问题"的工单
- 预期结果：
  - 业务组和成员创建成功并可读回
  - 分类规则配置成功
  - 新创建的"技术问题"分类工单自动分配到技术支持组
  - 工单详情中显示所属业务组
- 证据类型：interaction, session-persistence

### AC-06：处理人可转派工单

- 验收条件：待处理状态下的工单可被转派到其他处理人，转派后新处理人可见并接手该工单
- 入口类型：用户界面
- 验证动作：处理人在待处理工单中发起转派，选择另一处理人作为接收人
- 预期结果：
  - 转派操作成功，工单的处理人变更为新处理人
  - 新处理人在工作台中可见该工单
  - 工单保持待处理状态
  - 转派操作记录在日志中
- 证据类型：interaction, session-persistence

### AC-07：处理人可查看提交人完整信息并完成处理，完成后发送邮件通知

- 验收条件：处理工单时可查看提交人完整信息（姓名、公司、部门、历史工单）；完成处理后记录处理人和处理时间，并向提交人邮箱发送通知邮件
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息面板；完成处理后标记工单为完成
- 预期结果：
  - 提交人信息面板显示姓名、公司、部门、历史工单列表
  - 工单完成后记录处理人和处理时间
  - 工单状态变为完成
  - 提交人邮箱收到工单完成通知邮件
- 证据类型：interaction, session-persistence, other

### AC-08：提交人可对已完成工单进行满意度评价

- 验收条件：工单完成后，提交人可对工单进行满意度评价，评价数据持久保存
- 入口类型：用户界面
- 验证动作：提交人打开已完成工单，提交满意度评价
- 预期结果：
  - 评价提交成功
  - 评价数据持久保存，重新查看工单时可读回评价结果
  - 评价数据可被统计分析模块使用
- 证据类型：interaction, session-persistence

### AC-09：支持按公司/部门维度统计工单分布并展示运营仪表盘

- 验收条件：统计分析模块可按公司、部门维度展示工单分布，并在仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标
- 入口类型：用户界面
- 验证动作：在统计分析页面选择按公司/部门维度查看工单分布；打开运营仪表盘查看各项指标
- 预期结果：
  - 工单分布统计按公司和部门维度正确展示
  - 仪表盘展示工单量、平均响应时间、满意度、热点问题等指标
  - 指标数据与实际工单数据一致
- 证据类型：runtime-render, session-persistence

### AC-10：工单工作台支持筛选、搜索和排序

- 验收条件：工单工作台展示待处理工单列表，支持按公司筛选、关键词搜索和多字段排序
- 入口类型：用户界面
- 验证动作：
  - 打开工单工作台查看待处理工单列表
  - 按公司维度筛选工单
  - 按主题或工单 ID 搜索
  - 按创建时间或优先级排序
- 预期结果：
  - 工作台显示待处理工单列表
  - 按公司筛选后仅显示该公司的工单
  - 搜索结果匹配关键词
  - 排序结果按所选字段正确排列
- 证据类型：interaction, session-persistence

### AC-11：系统记录工单相关操作日志

- 验收条件：工单的创建、分配、转派、回复、处理完成、取消、评价等操作均被记录在操作日志中
- 入口类型：用户界面
- 验证动作：执行一系列工单操作（创建、分配、回复、转派、完成、评价），查看操作日志
- 预期结果：
  - 每个操作在日志中有对应记录
  - 日志记录可按工单关联查看
- 证据类型：interaction, session-persistence
