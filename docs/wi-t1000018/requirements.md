# 工单系统需求文档（156-ticket）

## 1. 目标

构建一个工单管理系统，支持工单从创建到完成的全生命周期管理，覆盖工单分配、协作转派、处理、评价、统计分析与工作台等核心功能。系统按公司隔离数据，支持 SLA 优先级和问题分类驱动的自动分配。

## 2. 角色与权限边界

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单、查看自己工单进度、完成后进行满意度评价 | 用户明确提出 |
| 处理人 | 业务组成员，处理分配到本组的工单，可查看提交人完整信息 | 用户明确提出 |
| 管理员 | 管理公司业务组及成员配置、配置分类-业务组自动分配规则 | 用户明确提出（"允许给某个公司增加多个业务组"隐含管理角色） |

> 未明确规定的权限粒度（如角色与菜单的细粒度绑定）保持未规定。

## 3. 核心实体与规则

### 3.1 工单（Ticket）

| 字段 | 说明 | 来源 |
|------|------|------|
| 工单ID | 唯一标识 | 用户明确提出 |
| 主题 | 工单标题 | 用户明确提出 |
| 描述 | 工单详细内容 | 用户明确提出 |
| 分类 | 问题分类 | 用户明确提出 |
| 提交人信息 | 含姓名、邮箱、公司、部门 | 用户明确提出 |
| 创建时间 | 工单创建的时间戳 | 用户明确提出 |
| SLA优先级 | P0-P4 五级 | 用户明确提出 |
| 当前状态 | 生命周期状态 | 用户明确提出 |
| 处理人 | 记录处理人及处理时间 | 用户明确提出 |

### 3.2 工单回复（Ticket Reply）

- 支持多轮回复，每轮记录回复人和回复时间。  
  来源：用户明确提出
- 回复归属于同一工单，按时间顺序展示。

### 3.3 公司隔离

- 所有工单、业务组、成员关系均按公司隔离，一个公司的工单数据对其他公司不可见。  
  来源：用户明确提出

### 3.4 业务组（Business Group）

- 一个公司可配置多个业务组。  
  来源：用户明确提出
- 每个业务组可设置成员（处理人）。  
  来源：用户明确提出
- 业务组归属公司，跨公司不可见。  
  来源：推荐基线（公司隔离规则的必要延伸，确保隔离完整性）

### 3.5 分类-业务组自动分配规则

- 可为某公司的工单按分类配置自动分配到指定业务组。  
  来源：用户明确提出
- 一条规则绑定（公司, 分类）→ 业务组。  
  来源：推荐基线（闭合自动分配功能的最小规则模型）

## 4. 工单生命周期

状态流转图：

```
创建 → 待分配 → 待处理 → 完成
  │                          ↑
  │                          │
  └──→ 取消           （转派回到待处理或待分配）
```

| 状态 | 说明 |
|------|------|
| 创建 | 工单提交后的初始状态 |
| 待分配 | 等待分配到业务组 |
| 待处理 | 已分配到业务组，等待处理人处理 |
| 完成 | 处理人完成处理，触发邮件通知 |
| 取消 | 工单被取消，不再处理 |

- 转派操作可在处理过程中将工单转派给其他业务组或处理人，转派后工单回到待处理或待分配状态。  
  来源：用户明确提出

## 5. 功能需求

### 5.1 工单管理

- 工单创建时记录：工单ID、主题、描述、分类、提交人信息（含邮箱）、创建时间、SLA优先级（P0-P4）。
- 工单支持多轮回复，记录回复人、回复时间。
- 工单数据按公司隔离。

### 5.2 工单分配

- **业务组管理**：允许给某个公司增加多个业务组，每个业务组可设置成员。
- **自动分配**：允许某公司的工单按照分类自动分配到某个业务组。
  - 分配规则：根据工单分类匹配该公司下的分类-业务组分配规则，将工单分配到对应业务组。
  - 无匹配规则时的行为保持未规定，不自动指定默认业务组。

### 5.3 工单协作

- **转派操作**：支持将工单转派给其他业务组或处理人。
- 转派时记录转派人、转派目标、转派时间。  
  来源：推荐基线（转派操作的必要审计字段，确保转派可追溯）

### 5.4 工单处理

- **查看提交人信息**：处理工单时可查看提交人的完整信息，包括姓名、公司、部门、历史工单列表。
- **记录处理信息**：工单处理后记录处理人、处理时间。
- **完成通知**：工单完成时发送邮件通知提交人。

### 5.5 用户评价

- 用户收到已完成工单后可进行满意度评价。  
  来源：用户明确提出
- 评价结果关联工单，可供统计分析使用。  
  来源：推荐基线（评价数据需可被统计分析引用，闭合统计需求）

### 5.6 统计分析

- **工单分布统计**：支持按公司、部门维度统计工单分布。
- **运营仪表盘**：查看工单量、平均响应时间、满意度、热点问题等运营指标。

### 5.7 工单工作台

- 查看待处理工单列表。
- 支持筛选（含按公司维度筛选）、搜索、排序。

### 5.8 操作日志

- 记录工单相关操作日志，包括但不限于：工单创建、分配、转派、处理、完成、取消。  
  来源：用户明确提出"记录相关日志"；日志覆盖的操作范围为推荐基线（确保关键生命周期操作可审计）

## 6. 验收场景

### AC-01：工单创建与生命周期状态流转

- 验收条件：提交人创建工单后，工单从初始状态经历完整生命周期状态流转（待分配 → 待处理 → 完成），取消路径可独立触发，各状态可观察。
- 入口类型：用户界面
- 验证动作：提交人创建一个工单，观察其初始状态；管理员/系统将其分配到业务组后观察状态变更为待处理；处理人完成处理后观察状态变更为完成；另创建一个工单并执行取消操作。
- 预期结果：工单创建后记录工单ID、主题、描述、分类、提交人信息（含邮箱）、创建时间、SLA优先级；状态按预期流转；取消的工单不可继续处理。
- 证据类型：interaction, runtime-render

### AC-02：工单多轮回复

- 验收条件：在工单详情页可以对工单进行多轮回复，每轮回复记录回复人和回复时间，按时间顺序展示。
- 入口类型：用户界面
- 验证动作：在已创建的工单上连续发起多次回复，查看回复列表。
- 预期结果：每条回复显示回复人、回复时间、回复内容；回复按时间顺序排列。
- 证据类型：interaction, runtime-render

### AC-03：工单按分类自动分配到业务组

- 验收条件：为公司配置业务组和成员后，配置分类-业务组自动分配规则；创建该分类的工单后，工单自动分配到对应业务组，状态变为待处理。
- 入口类型：用户界面
- 验证动作：管理员为某公司创建业务组并添加成员，配置某分类自动分配到该业务组；提交人创建该分类的工单。
- 预期结果：工单自动分配到对应业务组，工单状态变为待处理，工单关联到目标业务组。
- 证据类型：interaction, runtime-render

### AC-04：工单转派

- 验收条件：处理人可将工单转派给其他业务组或处理人，转派后工单状态回到待处理或待分配，转派记录可追溯。
- 入口类型：用户界面
- 验证动作：处理人在待处理工单上执行转派操作，选择目标业务组或处理人。
- 预期结果：工单关联到新的业务组或处理人；转派记录包含转派人、目标、时间。
- 证据类型：interaction, runtime-render

### AC-05：工单处理—查看提交人信息与完成通知

- 验收条件：处理人在处理工单时可查看提交人完整信息（姓名、公司、部门、历史工单），完成处理后记录处理人和处理时间，并向提交人发送邮件通知。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单，查看提交人信息面板；执行完成操作后检查邮件通知。
- 预期结果：提交人信息面板展示姓名、公司、部门、历史工单列表；工单完成后记录处理人和处理时间；提交人邮箱收到工单完成通知邮件。
- 证据类型：interaction, runtime-render, session-persistence

### AC-06：用户满意度评价

- 验收条件：工单完成后，提交人可对工单进行满意度评价，评价结果关联工单且可被统计引用。
- 入口类型：用户界面
- 验证动作：提交人进入已完成的工单，进行满意度评价。
- 预期结果：评价提交成功后工单关联评价结果；评价数据可被统计分析模块引用。
- 证据类型：interaction, runtime-render

### AC-07：统计分析—工单分布与运营仪表盘

- 验收条件：系统按公司、部门维度统计工单分布，运营仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标。
- 入口类型：用户界面
- 验证动作：在统计分析页面切换公司、部门维度筛选，查看仪表盘各指标卡片。
- 预期结果：工单分布按所选维度聚合展示；仪表盘展示工单量、平均响应时间、满意度、热点问题等指标，数据与实际工单数据一致。
- 证据类型：runtime-render

### AC-08：工单工作台筛选、搜索、排序

- 验收条件：工作台展示待处理工单列表，支持筛选（含按公司维度）、搜索、排序。
- 入口类型：用户界面
- 验证动作：进入工单工作台，使用筛选条件（含公司维度）、关键字搜索、排序功能操作工单列表。
- 预期结果：列表按所选条件过滤、搜索结果匹配关键字、排序按所选字段排列；按公司维度筛选仅展示对应公司的工单。
- 证据类型：interaction, runtime-render

### AC-09：工单操作日志

- 验收条件：工单的创建、分配、转派、处理、完成、取消等关键操作被记录在操作日志中，日志包含操作类型、操作人、操作时间。
- 入口类型：用户界面
- 验证动作：执行工单创建、分配、转派、处理、完成、取消等操作后，查看工单操作日志。
- 预期结果：每个关键操作在日志中有对应记录，记录包含操作类型、操作人、操作时间。
- 证据类型：runtime-render, session-persistence

### AC-10：公司数据隔离

- 验收条件：一个公司的工单、业务组、成员关系对其他公司不可见。
- 入口类型：用户界面
- 验证动作：以A公司身份创建工单和业务组，切换到B公司身份查看工单列表和业务组列表。
- 预期结果：B公司无法看到A公司的工单、业务组及成员数据。
- 证据类型：authorization, runtime-render
