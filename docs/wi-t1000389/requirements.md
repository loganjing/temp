# 教师管理系统需求文档

## 1. 目标

提供一个教师管理系统，支持对教师信息的增加、查看、编辑和删除（增删改查）操作。

## 2. 核心行为与规则

### 2.1 教师信息字段

| 字段 | 说明 | 来源 |
|------|------|------|
| 教师名称 | 教师的姓名 | 用户明确提出 |
| 教授课程 | 教师所教授的课程 | 用户明确提出 |
| 年级 | 教师所教授的年级 | 用户明确提出 |
| 手机 | 教师的手机号码 | 用户明确提出 |
| 邮箱 | 教师的电子邮箱 | 用户明确提出 |

### 2.2 功能行为

- **增加教师**：用户可填写教师名称、教授课程、年级、手机、邮箱字段，保存后创建一条新的教师记录。成功保存后可通过查看操作读回该记录。
- **查看教师**：用户可查看已保存的教师记录列表。
- **编辑教师**：用户可修改已有教师记录的任意字段，保存后更改生效。成功保存后可通过查看操作读回更新后的数据。
- **删除教师**：用户可删除已有的教师记录，删除后该记录不再出现在教师列表中。

### 2.3 推荐基线

- 手机字段建议符合基本手机号格式校验（防止明显无效输入），邮箱字段建议符合基本邮箱格式校验。此为推荐基线，用户可在实现阶段调整或移除。

## 3. 未规定事项

- 用户角色与权限未规定。
- 部署平台、技术栈、存储方案未规定。
- 分页、排序、搜索等列表增强功能未规定。
- 数据持久化周期与存储介质未规定。

## 4. 验收场景

### AC-01：用户可新增教师并读回记录
- 验收条件：用户填写教师名称、教授课程、年级、手机、邮箱并保存后，该教师记录出现在教师列表中。
- 入口类型：用户界面
- 验证动作：在教师管理界面填写一条完整的教师信息并提交保存，然后查看教师列表。
- 预期结果：新保存的教师记录出现在列表中，各字段值与录入内容一致。
- 证据类型：interaction, runtime-render

### AC-02：用户可编辑教师信息并读回更改
- 验收条件：用户修改已有教师记录的字段并保存后，更新后的数据出现在教师列表中。
- 入口类型：用户界面
- 验证动作：在教师列表中选择一条已有记录，修改其中一个或多个字段并保存，然后查看教师列表。
- 预期结果：该记录的字段值更新为修改后的内容。
- 证据类型：interaction, runtime-render

### AC-03：用户可删除教师记录
- 验收条件：用户删除一条教师记录后，该记录不再出现在教师列表中。
- 入口类型：用户界面
- 验证动作：在教师列表中选择一条已有记录并执行删除操作，然后查看教师列表。
- 预期结果：被删除的教师记录不再出现在列表中。
- 证据类型：interaction, runtime-render
