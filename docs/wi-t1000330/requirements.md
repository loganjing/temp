# 工单系统需求（133-ticket）

## 1. 目标与范围

为多公司环境提供一套工单系统，覆盖工单从提交、分配、处理、完成到用户评价的完整闭环，并支持公司级分配配置、处理协作（转派）、统计分析与运营仪表盘、工单工作台和操作日志。【用户明确提出，整理】

本期范围：

- 工单管理（字段、多轮回复、公司隔离、SLA 优先级、生命周期）
- 工单分配（业务组与成员、分类自动分配）
- 工单协作（转派）
- 工单处理（处理上下文、处理记录、完成邮件通知）
- 用户评价（满意度）
- 统计分析（公司/部门分布统计、运营仪表盘）
- 工单工作台（待处理列表与筛选、搜索、排序）
- 操作日志

用户未明确排除任何范围外能力，无范围外排除项记录。

## 2. 操作视角

系统不预设完整角色与权限体系（未规定）；从用户描述导出以下操作视角：

| 视角 | 来源 | 主要操作 |
| --- | --- | --- |
| 提交人 | 用户明确提出（提交人信息、满意度评价） | 提交工单、查看与回复工单、接收完成通知、满意度评价 |
| 处理人 | 用户明确提出（处理人、业务组成员） | 查看待处理工单、查看提交人完整信息、回复、处理、转派 |
| 分配配置操作者 | 功能要求导出（业务组与分配规则配置），角色未规定 | 为公司维护业务组、成员与分类自动分配规则 |
| 跨公司视角使用者 | 功能要求导出（公司维度筛选与统计），角色未规定 | 按公司维度筛选工作台、查看按公司维度的统计分布 |

处理人来自业务组成员（见 4.2.1）。

## 3. 核心规则

### 3.1 公司隔离【用户明确提出】

- 工单归属提交人所属公司，按公司隔离。
- 提交人与业务组处理人在列表、详情、回复、处理等工单访问中只能触达本公司工单。
- 工作台的公司维度筛选与按公司/部门的分布统计属于跨公司数据视角，面向具备跨公司数据访问的使用者【推荐基线 R8】；其权限边界未规定。

### 3.2 生命周期【用户明确提出】

状态：创建、待分配、待处理、完成、取消。

| 流转 | 说明 | 来源 |
| --- | --- | --- |
| 创建 → 待分配 | 工单提交形成"创建"状态后进入待分配并启动分配 | 推荐基线 R1 |
| 待分配 → 待处理 | 分配动作完成（分类规则自动分配，或人工分配） | 自动分配为用户明确提出；人工分配为推荐基线 R1 |
| 待处理 → 完成 | 处理人完成处理，记录处理人与处理时间 | 用户明确提出 |
| 完成前 → 取消 | 取消为分支终态 | 取消为用户明确提出；可取消时机为推荐基线 R7 |

### 3.3 SLA 优先级【用户明确提出】

- 工单支持设置 SLA 优先级，分级为 P0-P4 五级。
- 各级 SLA 时限与响应目标未规定。

### 3.4 问题分类【用户明确提出】

- 工单带分类（问题分类）字段。
- 分类用于分类自动分配（见 4.2.2）与热点问题统计（见 4.6.2）。
- 分类清单的维护方式未规定。

## 4. 模块需求

### 4.1 工单管理

**4.1.1 工单字段**【用户明确提出】

工单记录包含：工单ID、主题、描述、分类、创建时间、SLA 优先级（P0-P4）、提交人信息（姓名、公司、部门、邮箱）。工单ID 唯一标识一条工单【推荐基线】。

**4.1.2 多轮回复**【用户明确提出】

- 工单支持多轮回复。
- 每轮回复记录回复人、回复时间与回复内容，按时间先后呈现。

**4.1.3 公司隔离**：见 3.1。

### 4.2 工单分配

**4.2.1 业务组**【用户明确提出】

- 可为一个公司配置多个业务组。
- 每个业务组可设置成员；成员即该组工单的处理人。
- 业务组与成员按公司维度管理，本公司配置只作用于本公司工单的分配。

**4.2.2 分类自动分配**【用户明确提出】

- 可为一个公司配置"分类 → 业务组"的自动分配规则。
- 该公司工单提交后，按其分类自动分配到对应业务组。
- 匹配时机：工单处于待分配时执行规则匹配；命中规则则分配至对应业务组并进入待处理；未命中时停留待分配，等待人工分配到业务组【推荐基线 R1】。
- 同一分类对应多条规则时的处理方式未规定。

### 4.3 工单协作（转派）【用户明确提出】

- 支持工单转派：将工单处理责任转给其他处理人。
- 转派操作记录转派信息（转派人、时间），处理责任随转派转移。
- 转派目标为其他处理人；转派到业务组未规定。

### 4.4 工单处理

**4.4.1 处理上下文**【用户明确提出】

- 处理工单时可查看提交人的完整信息：姓名、公司、部门、历史工单（该提交人过往提交的工单）。

**4.4.2 处理记录与完成通知**【用户明确提出】

- 工单处理完成后记录处理人、处理时间等处理信息。
- 工单完成时发送邮件通知；通知对象为提交人邮箱【推荐基线 R2】。
- 完成以外的其他邮件通知触发点（如创建、分配、转派时是否通知）未规定。

### 4.5 用户评价【用户明确提出】

- 提交人收到完成的工单后，可对该工单进行满意度评价。
- 评价为量化评分，用于满意度统计【推荐基线 R3】；具体分值尺度未规定。
- 评价时间窗口与评价修改/删除规则未规定。

### 4.6 统计分析

**4.6.1 工单分布统计**【用户明确提出】

- 支持按公司、部门维度统计工单分布。
- 部门维度取提交人所属部门。

**4.6.2 统计与分析仪表盘**【用户明确提出】

- 提供统计与分析仪表盘，可查看：工单量、平均响应时间、满意度、热点问题等运营指标。
- 指标口径：
  - 平均响应时间 = 工单创建到首次回复的时间间隔【推荐基线 R4】。
  - 热点问题 = 按问题分类聚合的工单量排行【推荐基线 R5】。
  - 满意度 = 用户评价（见 4.5）的聚合结果。

### 4.7 工单工作台【用户明确提出】

- 查看待处理工单列表。
- 支持筛选、搜索、排序；筛选包含公司维度。
- 业务组处理人在公司隔离范围内查看本公司待处理工单（见 3.1）；公司维度筛选面向跨公司视角使用者（见 3.1、推荐基线 R8）。

### 4.8 操作日志【用户明确提出】

- 系统记录工单相关日志。
- 覆盖范围推荐为工单关键操作：创建、分配、回复、转派、处理完成、取消、评价等，操作日志可查询【推荐基线 R6】。
- 日志保留时长未规定。

## 5. 用户旅程

### 旅程 A：提交人闭环

提交人创建工单（主题、描述、分类、SLA 优先级，见 4.1.1）→ 工单进入分配流程（旅程 B）→ 提交人查看工单并参与多轮回复（见 4.1.2）→ 工单完成，提交人邮箱收到通知（见 4.4.2）→ 提交人进行满意度评价（见 4.5）。

### 旅程 B：分配与处理

工单提交进入待分配 → 分类规则匹配，自动分配到对应业务组（见 4.2.2）【或人工分配，推荐基线 R1】→ 业务组成员在工作台看到待处理工单（见 4.7）→ 处理人查看提交人完整信息与历史工单（见 4.4.1）→ 回复与处理（见 4.1.2）→ 需要时转派给其他处理人（见 4.3）→ 完成，记录处理人、处理时间并邮件通知提交人（见 4.4.2）。

### 旅程 C：公司分配配置

配置操作者为公司创建业务组并设置成员（见 4.2.1）→ 配置"分类 → 业务组"自动分配规则（见 4.2.2）→ 该公司后续新工单按分类自动分配。

## 6. 推荐基线与未规定事项

### 推荐基线（最小必要，用户可调整）

| 编号 | 事项 | 推荐基线 |
| --- | --- | --- |
| R1 | 自动分配未命中时 | 工单停留待分配，可人工分配到业务组后进入待处理 |
| R2 | 完成邮件通知对象 | 提交人邮箱（由提交人邮箱字段与评价闭环推导） |
| R3 | 满意度评价形式 | 量化评分，支撑满意度统计 |
| R4 | 平均响应时间口径 | 工单创建到首次回复的时间间隔 |
| R5 | 热点问题口径 | 按问题分类聚合的工单量排行 |
| R6 | 日志覆盖范围 | 工单关键操作（创建、分配、回复、转派、处理完成、取消、评价）留痕并可查询 |
| R7 | 取消时机 | 工单完成前可取消 |
| R8 | 公司维度筛选/统计视角 | 面向具备跨公司数据访问的使用者 |

### 未规定事项（保持未规定，不构成验收依据）

- 各 SLA 优先级（P0-P4）的时限与响应目标
- 问题分类清单的维护方式
- 同一分类对应多条分配规则的冲突处理
- 转派目标是否可为业务组
- 评价时间窗口与评价修改/删除规则
- 分配配置操作者、跨公司视角使用者的正式角色与权限体系
- 除完成外的其他邮件通知触发点
- 日志保留时长

## 7. 验收场景

### AC-01：提交人可创建包含完整信息的工单

- 验收条件：提交人提交工单后，系统形成一条可读回的完整工单记录。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份填写主题、描述、分类并选择 SLA 优先级（P0-P4 任一），提交工单；随后打开该工单详情。
- 预期结果：工单详情显示工单ID、主题、描述、分类、创建时间、所选 SLA 优先级，以及提交人姓名、公司、部门、邮箱；工单处于生命周期初始状态。
- 证据类型：interaction, session-persistence
- 共享流程组：工单闭环

### AC-02：工单生命周期按状态流转并支持取消

- 验收条件：工单按"创建→待分配→待处理→完成"正常流转，并支持取消进入取消终态。
- 入口类型：用户界面
- 验证动作：创建一单工单并依次执行分配（规则自动或人工）、处理完成，观察各阶段状态；另创建一单工单，在完成前执行取消。
- 预期结果：第一单状态依次变为待分配、待处理、完成；第二单取消后状态为取消，不再进入处理流程。
- 证据类型：interaction, session-persistence
- 共享流程组：工单闭环

### AC-03：工单按公司隔离

- 验收条件：不同公司的用户互相无法访问对方公司的工单。
- 入口类型：用户界面
- 验证动作：以 A 公司提交人提交工单；切换为 B 公司用户（提交人或处理人），查看工单列表、工作台与详情入口，并尝试直接打开 A 公司工单。
- 预期结果：B 公司用户在列表、工作台、详情中均看不到 A 公司工单；直接访问 A 公司工单时被拒绝并收到无权限反馈。
- 证据类型：authorization, error-feedback

### AC-04：工单支持多轮回复

- 验收条件：工单详情中的多轮回复完整可查。
- 入口类型：用户界面
- 验证动作：在一单工单中由不同用户先后进行两轮及以上回复，随后查看该工单的回复记录。
- 预期结果：每轮回复记录回复人、回复时间与回复内容，按时间先后完整呈现。
- 证据类型：interaction, session-persistence

### AC-05：公司可配置业务组与成员

- 验收条件：公司可建立多个业务组并为每个业务组设置成员。
- 入口类型：用户界面
- 验证动作：为某公司创建两个业务组并分别添加成员；重新查看该公司的业务组配置。
- 预期结果：两个业务组及其成员均保存并可读回；同一公司可并行存在多个业务组。
- 证据类型：interaction, session-persistence
- 共享流程组：分配配置

### AC-06：工单按分类自动分配到业务组

- 验收条件：配置自动分配规则后，该公司新工单按分类自动进入对应业务组。
- 入口类型：用户界面
- 验证动作：为公司配置"分类 X → 业务组 G"的自动分配规则；以该公司提交人提交一单分类为 X 的工单；以组 G 成员身份打开工作台。
- 预期结果：该工单自动分配至业务组 G，状态进入待处理；组 G 成员在待处理工单列表中可见该工单。
- 证据类型：interaction, session-persistence
- 共享流程组：分配配置

### AC-07：处理人可转派工单

- 验收条件：待处理工单可转派给其他处理人，处理责任随转派转移。
- 入口类型：用户界面
- 验证动作：处理人对一单待处理工单执行转派，选择另一名处理人；由新处理人查看并继续处理该工单。
- 预期结果：转派后工单处理责任转移至新处理人；转派记录（转派人、时间）可查。
- 证据类型：interaction, session-persistence
- 共享流程组：处理中操作

### AC-08：处理时可查看提交人完整信息与历史工单

- 验收条件：工单处理视图提供提交人完整信息。
- 入口类型：用户界面
- 验证动作：处理人打开一单待处理工单的处理视图，查看提交人信息区。
- 预期结果：可查看提交人姓名、公司、部门，以及该提交人的历史工单列表。
- 证据类型：runtime-render
- 共享流程组：处理中操作

### AC-09：工单完成记录处理信息并发送邮件通知

- 验收条件：工单完成时形成处理记录并通知提交人。
- 入口类型：用户界面
- 验证动作：处理人完成一单工单后查看工单记录；检查提交人邮箱收件情况。
- 预期结果：工单状态为完成，工单记录处理人与处理时间；提交人邮箱收到工单完成通知邮件。
- 证据类型：interaction, other
- 共享流程组：工单闭环

### AC-10：提交人可对已完成工单进行满意度评价

- 验收条件：已完成工单可被提交人评价且评价结果留存。
- 入口类型：用户界面
- 验证动作：提交人收到工单完成通知后，对已完成工单提交满意度评价；随后再次查看该工单。
- 预期结果：评价保存并与该工单关联，再次查看时可读回；评价结果可供满意度统计使用。
- 证据类型：interaction, session-persistence
- 共享流程组：工单闭环

### AC-11：按公司与部门维度统计工单分布

- 验收条件：统计视图按所选维度呈现工单分布。
- 入口类型：用户界面
- 验证动作：打开统计分析的工单分布视图，分别切换公司维度与部门维度。
- 预期结果：工单分布按所选维度聚合呈现，分布数量与实际工单数据一致。
- 证据类型：runtime-render

### AC-12：运营仪表盘展示核心运营指标

- 验收条件：统计与分析仪表盘呈现运营指标。
- 入口类型：用户界面
- 验证动作：打开统计与分析仪表盘。
- 预期结果：可查看工单量、平均响应时间、满意度、热点问题等运营指标，指标随实际工单数据变化。
- 证据类型：runtime-render

### AC-13：工作台支持筛选、搜索与排序

- 验收条件：待处理工单列表可按条件检索与排序。
- 入口类型：用户界面
- 验证动作：打开工单工作台，分别使用筛选（含公司维度）、关键字搜索与排序操作。
- 预期结果：待处理工单列表按条件变化正确刷新，筛选、搜索、排序结果与工单数据一致。
- 证据类型：interaction, runtime-render

### AC-14：关键操作记录日志

- 验收条件：工单关键操作留有可查询的日志记录。
- 入口类型：用户界面
- 验证动作：对一单工单依次执行创建、分配、回复、转派、完成（或取消）、评价等操作后，查询该工单的相关日志。
- 预期结果：关键操作均留有日志记录（操作类型、操作人、时间），日志可查询。
- 证据类型：runtime-render, session-persistence
