# 工单系统需求基线

> WorkItem: wi-t1000083 · IssueTask: T1000083  
> 来源标注约定：【用户】= 用户明确提出；【基线】= 已确认产品规则；【推荐】= 闭合核心目标所必需的保守推荐基线；【未规定】= 当前未明确，保持开放。

---

## 1. 目标与范围

### 1.1 目标

构建一个面向多公司的工单系统，支持工单从创建到完成的全生命周期管理，包括工单分配、协作转派、处理通知、用户评价、统计分析和工作台等功能。（【用户】）

### 1.2 核心对象

- **工单（Ticket）**：用户提交的问题或请求，按公司隔离，经历完整生命周期流转。
- **公司（Company）**：工单归属与隔离的顶层组织单元。
- **业务组（Business Group）**：公司下属的工单处理单元，拥有成员列表。
- **用户**：包括工单提交人和工单处理人，归属于某个公司和部门。

### 1.3 角色定义

| 角色 | 说明 | 来源 |
|------|------|------|
| 工单提交人 | 创建工单的用户，可回复工单、在工单完成后进行满意度评价 | 【用户】 |
| 工单处理人 | 被分配到业务组、负责处理工单的用户，可回复、处理、转派工单 | 【用户】 |
| 业务组管理员 | 管理业务组成员、配置分类分配规则的用户 | 【用户】（由"允许给某个公司增加多个业务组"推断） |

> 公司级管理员和业务组管理员的权限边界未由用户明确划分；本基线将"为公司增加业务组并设置成员"和"配置分类自动分配规则"统一归为管理操作，不进一步拆分权限层级。【未规定】

## 2. 工单生命周期

工单状态流转如下（【用户】）：

```
创建 → 待分配 → 待处理 → 完成
                ↘ 取消
```

| 状态 | 说明 | 触发条件 |
|------|------|----------|
| 创建 | 工单刚被提交人创建 | 提交人提交工单 |
| 待分配 | 工单等待分配到业务组 | 创建后自动进入；或转派后重新进入 |
| 待处理 | 工单已分配到业务组/处理人，等待处理 | 分配完成后进入 |
| 完成 | 工单处理完毕 | 处理人标记完成 |
| 取消 | 工单被取消 | 提交人或处理人取消工单 |

**状态规则：**
- 工单可从「待分配」或「待处理」状态被取消。（【推荐】——用户列出取消为独立状态，未说明取消入口，推荐从活跃状态均可取消）
- 已「完成」或「取消」的工单不可再变更状态。（【推荐】——终态不可逆，闭合生命周期必需）
- 工单按公司隔离：用户只能查看和处理所属公司范围内的工单，不能跨公司访问。（【用户】）

## 3. 业务规则

### 3.1 工单基本属性（【用户】）

| 属性 | 说明 |
|------|------|
| 工单ID | 系统生成的唯一标识 |
| 主题 | 工单标题 |
| 描述 | 工单详细内容 |
| 分类 | 问题分类 |
| 提交人信息 | 包含姓名、邮箱 |
| 创建时间 | 工单提交时间 |
| SLA优先级 | P0-P4 五级 |
| 状态 | 当前生命周期状态 |

### 3.2 SLA 优先级（【用户】）

工单支持 P0-P4 五级优先级设置，用于标识工单紧急程度。具体各级别的响应时限和处理时限未由用户明确指定。【未规定】

### 3.3 工单回复（【用户】）

- 工单支持多轮回复。
- 每条回复记录回复人和回复时间。
- 提交人和处理人均可回复工单。

### 3.4 公司隔离（【用户】）

- 工单、业务组、分类分配规则均按公司隔离。
- 用户只能访问所属公司的工单和相关数据。
- 统计分析和工作台筛选均受公司范围约束。

### 3.5 操作日志（【用户】）

- 记录工单生命周期中的关键操作日志，包括但不限于：创建、分配、转派、处理、完成、取消。
- 日志记录操作人、操作时间和操作类型。

## 4. 模块需求

### 4.1 工单管理

**工单创建（【用户】）**
- 提交人填写主题、描述、分类，系统自动记录提交人信息（含邮箱）和创建时间。
- 工单创建后进入「待分配」状态。

**工单回复（【用户】）**
- 支持多轮回复，每条回复记录回复人和回复时间。
- 回复在工单详情中以时间线展示。

### 4.2 工单分配

**业务组管理（【用户】）**
- 允许为某个公司增加多个业务组。
- 每个业务组可以设置成员（处理人）。

**分类自动分配（【用户】）**
- 允许为某个公司配置规则：按工单分类自动分配到指定业务组。
- 工单创建后，系统根据分类匹配分配规则，将工单分配到对应业务组。
- 分配后工单进入「待处理」状态。

**手动分配（【推荐】）**
- 当分类无匹配的自动分配规则时，工单保持「待分配」状态，可由处理人手动分配到业务组。
- 此为闭合分配流程的推荐基线：用户明确要求按分类自动分配，未说明无匹配规则时的行为，推荐保留手动分配兜底。

### 4.3 工单协作（转派）

**转派操作（【用户】）**
- 支持将工单从一个业务组/处理人转派到另一个业务组/处理人。
- 转派后工单进入「待处理」状态（已分配到新接收方）。
- 转派操作记录在操作日志中。

### 4.4 工单处理

**提交人信息查看（【用户】）**
- 处理工单时可查看提交人的完整信息，包括：姓名、公司、部门、历史工单列表。

**处理记录（【用户】）**
- 工单完成后，记录处理人、处理时间。
- 工单标记为「完成」状态。

**邮件通知（【用户】）**
- 工单完成时，系统发送邮件通知提交人。
- 通知接收地址为提交人邮箱。

### 4.5 用户评价

**满意度评价（【用户】）**
- 工单完成后，提交人可对工单处理结果进行满意度评价。
- 评价入口在工单完成后对提交人可见。
- 满意度评价结果用于统计分析。

> 用户原文为"用户收到工单后进行满意度评价"，结合上下文（评价针对处理结果），理解为工单完成后提交人进行评价。评价维度（如星级、评分范围）未由用户明确指定。【未规定】

### 4.6 统计分析

**工单分布统计（【用户】）**
- 支持按公司维度统计工单分布。
- 支持按部门维度统计工单分布。

**运营指标仪表盘（【用户】）**
- 展示以下运营指标：
  - 工单量
  - 平均响应时间
  - 满意度
  - 热点问题（按分类聚合的高频问题）

### 4.7 工单工作台

**待处理列表（【用户】）**
- 展示待处理工单列表。
- 支持按公司维度筛选。
- 支持搜索（按主题等关键字）。
- 支持排序（按创建时间、优先级等）。

> 工作台面向工单处理人，展示当前用户需处理的工单。筛选、搜索、排序的具体字段组合未由用户全部指定，以用户明确列出的为准。【未规定】

## 5. 验收场景

### AC-01：提交人创建工单并完成全生命周期流转

- **验收条件**：提交人能创建工单，工单经历分配、处理、完成的全生命周期，各状态正确流转，且全程按公司隔离。
- **入口类型**：用户界面
- **验证动作**：提交人创建一张包含主题、描述、分类的工单；工单创建后处于「待分配」状态；系统按分类规则自动分配到业务组，工单进入「待处理」；处理人处理后标记完成，工单进入「完成」状态。
- **预期结果**：
  - 工单创建后记录工单ID、主题、描述、分类、提交人信息（含邮箱）、创建时间、SLA优先级。
  - 状态依次经历：创建 → 待分配 → 待处理 → 完成。
  - 提交人仅能看到自己公司的工单，无法看到其他公司工单。
- **证据类型**：runtime-render, interaction, session-persistence

### AC-02：工单支持多轮回复

- **验收条件**：提交人和处理人能在同一工单中进行多轮回复，每条回复记录回复人和回复时间。
- **入口类型**：用户界面
- **验证动作**：在工单详情中，提交人和处理人分别多次回复工单。
- **预期结果**：
  - 所有回复按时间线展示。
  - 每条回复显示回复人和回复时间。
  - 回复内容持久保存，重新打开工单仍可见。
- **证据类型**：interaction, session-persistence

### AC-03：业务组管理与分类自动分配

- **验收条件**：管理员能为公司创建多个业务组并设置成员，能配置按分类自动分配规则，新工单按分类自动分配到对应业务组。
- **入口类型**：用户界面
- **验证动作**：为公司A创建业务组G1和G2，分别添加成员；配置规则使分类"网络问题"分配到G1、分类"软件故障"分配到G2；提交人分别提交两个不同分类的工单。
- **预期结果**：
  - 业务组G1、G2创建成功，成员可设置和查看。
  - 分类为"网络问题"的工单自动分配到G1。
  - 分类为"软件故障"的工单自动分配到G2。
  - 分配后工单状态为「待处理」。
- **证据类型**：interaction, session-persistence

### AC-04：工单转派

- **验收条件**：处理人能将工单转派到其他业务组或处理人，转派后工单归新接收方处理。
- **入口类型**：用户界面
- **验证动作**：在「待处理」状态的工单中，处理人执行转派操作，选择目标业务组或处理人。
- **预期结果**：
  - 转派成功后工单归属变更到目标业务组/处理人。
  - 工单状态保持「待处理」。
  - 转派操作记录在操作日志中，含操作人、操作时间。
- **证据类型**：interaction, session-persistence

### AC-05：处理时查看提交人完整信息

- **验收条件**：处理人在处理工单时可查看提交人的完整信息，包括姓名、公司、部门和历史工单。
- **入口类型**：用户界面
- **验证动作**：处理人打开待处理工单的详情页，查看提交人信息区域。
- **预期结果**：
  - 显示提交人姓名、公司、部门。
  - 显示提交人的历史工单列表。
- **证据类型**：runtime-render, interaction

### AC-06：工单完成记录与邮件通知

- **验收条件**：工单完成后系统记录处理人和处理时间，并向提交人邮箱发送完成通知邮件。
- **入口类型**：用户界面
- **验证动作**：处理人将工单标记为完成。
- **预期结果**：
  - 工单状态变为「完成」。
  - 系统记录处理人和处理时间。
  - 提交人邮箱收到工单完成通知邮件。
- **证据类型**：interaction, session-persistence, other

### AC-07：用户满意度评价

- **验收条件**：工单完成后，提交人能对处理结果进行满意度评价，评价结果可被统计分析使用。
- **入口类型**：用户界面
- **验证动作**：工单完成后，提交人在工单详情中进行满意度评价。
- **预期结果**：
  - 评价入口在工单完成后对提交人可见。
  - 提交人提交评价后，评价结果持久保存。
  - 评价结果可在统计分析的满意度指标中体现。
- **证据类型**：interaction, session-persistence

### AC-08：工单取消

- **验收条件**：活跃状态的工单可被取消，取消后工单进入终态不可再变更。
- **入口类型**：用户界面
- **验证动作**：在「待分配」或「待处理」状态的工单中执行取消操作。
- **预期结果**：
  - 工单状态变为「取消」。
  - 取消后的工单不可再进行回复、分配、处理等操作。
  - 取消操作记录在操作日志中。
- **证据类型**：interaction, session-persistence

### AC-09：工单工作台筛选搜索排序

- **验收条件**：处理人能在工作台查看待处理工单列表，并按公司筛选、按关键字搜索、按字段排序。
- **入口类型**：用户界面
- **验证动作**：处理人打开工作台，按公司筛选工单列表，输入关键字搜索，按创建时间排序。
- **预期结果**：
  - 工作台展示当前用户待处理的工单列表。
  - 公司筛选后仅显示选中公司的工单。
  - 搜索结果匹配关键字。
  - 排序结果按选定字段正确排列。
- **证据类型**：runtime-render, interaction

### AC-10：统计分析与运营仪表盘

- **验收条件**：系统能按公司和部门维度统计工单分布，并在仪表盘展示工单量、平均响应时间、满意度和热点问题等运营指标。
- **入口类型**：用户界面
- **验证动作**：打开统计分析页面，查看工单分布统计和运营指标仪表盘。
- **预期结果**：
  - 工单分布可按公司维度和部门维度展示。
  - 仪表盘展示工单量、平均响应时间、满意度、热点问题（按分类聚合）指标。
  - 统计数据基于实际工单数据计算。
- **证据类型**：runtime-render

### AC-11：操作日志记录

- **验收条件**：工单生命周期中的关键操作均记录日志，含操作人、操作时间和操作类型。
- **入口类型**：用户界面
- **验证动作**：创建工单后进行分配、回复、转派、处理、完成等操作，查看工单的操作日志。
- **预期结果**：
  - 每个关键操作（创建、分配、转派、处理、完成、取消）均有日志记录。
  - 日志包含操作人、操作时间、操作类型。
  - 日志按时间顺序排列，持久保存。
- **证据类型**：interaction, session-persistence
