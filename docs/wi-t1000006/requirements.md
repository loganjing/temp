# 工单系统 需求说明

业务任务：144-ticket

需求来源标注约定：**用户明确提出**＝本次业务任务原文要求；**推荐基线**＝为闭合核心目标所必需、保守可逆的补充口径，可由用户修正；**未规定**＝本次不假定内容，不构成隐含承诺。

验收入口类型仅表示交互入口（人工操作或系统自动执行），不代表指定 Web、桌面端、移动端或设备适配载体。

## 1. 目标

为一家面向多公司（多租户）的服务团队提供可运行的工单处理能力：公司内用户提交工单，工单按公司隔离，按分类自动落到对应业务组，由处理人协作处理并记录处理与回复过程，完成后通知提交人并由提交人评价，同时提供分布统计、运营指标仪表盘、工单工作台与操作日志。

## 2. 角色

| 角色 | 来源 | 主要行为 |
| --- | --- | --- |
| 提交人 | 用户明确提出（提交人信息、用户评价、历史工单） | 提交工单、查看与回复工单、接收完成通知、提交满意度评价 |
| 处理人（业务组成员） | 用户明确提出（业务组成员、回复人、转派、处理人） | 在工作台查看待处理工单、查看提交人完整信息、回复、转派、完成工单 |
| 配置人 | 推荐基线 | 维护本公司业务组与成员、维护本公司分类自动分配规则；具体角色定义与授权方式**未规定** |
| 管理者 | 用户明确提出（统计分析、仪表盘） | 查看按公司/部门维度的工单分布与运营指标 |

## 3. 核心对象

- **工单**：工单ID（唯一）、主题、描述、分类、优先级（P0–P4）、状态、所属公司、所属业务组、提交人信息（姓名、公司、部门、邮箱）、创建时间、当前处理人、处理时间、回复记录、满意度评价。
- **回复**：回复人、回复内容、回复时间；同一工单可有多条。
- **业务组**：所属公司、名称、成员；同一公司可有多个业务组。
- **分类自动分配规则**：公司 + 分类 + 目标业务组。
- **满意度评价**：评价内容/结果、评价时间。
- **日志记录**：操作对象、操作人（或系统）、时间、操作类型。

## 4. 关键规则

1. **公司隔离**（用户明确提出）：工单、业务组配置、自动分配规则与统计数据均按公司隔离，跨公司不可见、不可访问、不可操作。
2. **SLA 优先级**（用户明确提出）：工单可设置 P0–P4 优先级，并可设置问题分类；各优先级对应的响应/解决时限口径**未规定**（属于用户的政策决定，不在本次基线内设定）。
3. **生命周期**（用户明确提出）：状态包含 创建、待分配、待处理、完成、取消，正常流转为 创建 → 待分配 → 待处理 → 完成。推荐基线：处于创建/待分配/待处理的工单可取消，已完成的工单不可取消。
4. **自动分配**（用户明确提出）：某公司可配置“分类 → 业务组”规则；符合规则的工单创建后自动归入目标业务组，无需人工指定。未命中任何规则时的人工分配去向**未规定**。
5. **转派**（用户明确提出）：待处理工单可由当前处理方转派给其他处理人/业务组，转派后由新的处理方继续处理。转派过程是否需要保留原处理方轨迹**未规定**。
6. **处理记录**（用户明确提出）：工单完成时记录处理人与处理时间。
7. **完成通知**（用户明确提出）：工单完成时向提交人邮箱发送完成通知邮件。
8. **满意度评价**（用户明确提出）：工单完成后提交人可提交满意度评价。推荐基线：评价结果以有序评分刻度表示以便聚合统计，具体刻度**未规定**。
9. **统计口径**（用户明确提出统计维度与指标；以下计算口径为推荐基线）：分布统计按公司与部门维度汇总工单数量；平均响应时间按“工单创建时间 → 首次回复时间”的间隔计算；热点问题按分类出现的工单数量排序取靠前项；满意度按已提交的评价聚合。
10. **日志**（用户明确提出）：记录工单相关操作日志。推荐基线：至少覆盖创建、分配/自动分配、转派、回复、状态变更（完成/取消）、评价、完成通知、业务组与自动分配规则配置变更。
11. **数据读回**（推荐基线）：所有新增或修改成功的工单、回复、业务组配置、自动分配规则、评价与日志，均可通过相应查看入口读回一致内容。更长期的持久性（跨重启/重部署）**未规定**。

## 5. 端到端旅程

- **J1 提交人旅程**：提交工单（填写主题、描述、分类、优先级）→ 工单进入 创建/待分配 → 命中分类规则时自动归入业务组 → 处理期间多轮回复 → 工单完成并收到完成通知邮件 → 提交满意度评价 → 可随时查看该工单全部回复与状态。（验收见 AC-01、AC-02、AC-05、AC-07、AC-10、AC-11）
- **J2 处理人旅程**：在工作台查看本公司待处理工单 → 筛选/搜索/排序定位工单 → 打开工单查看提交人完整信息与历史工单 → 回复或转派 → 处理完成后结束工单（记录处理人、处理时间）。（验收见 AC-08、AC-09、AC-14、AC-05）
- **J3 配置人旅程**：为公司建立多个业务组并设置成员 → 配置“分类 → 业务组”自动分配规则 → 新建该分类工单验证自动落组。（验收见 AC-06、AC-07）
- **J4 管理者旅程**：查看按公司/部门的工单分布 → 查看仪表盘上的工单量、平均响应时间、满意度与热点问题 → 按公司维度在工作台查看待处理积压。（验收见 AC-12、AC-13、AC-14）

## 6. 验收场景

### AC-01：提交人可创建工单并读回完整工单信息
- 验收条件：提交人可提交一张工单，系统生成唯一工单ID，并记录主题、描述、分类、优先级、提交人信息（姓名、公司、部门、邮箱）与创建时间；保存后重新打开该工单可读回与提交内容一致的信息。
- 入口类型：用户界面
- 验证动作：以某公司提交人身份填写并提交工单（主题、描述、分类、优先级），随后关闭并重新打开该工单详情。
- 预期结果：详情显示唯一工单ID、主题、描述、分类、优先级、提交人姓名/公司/部门/邮箱与创建时间，且与提交内容一致；工单ID不与已有工单重复。
- 证据类型：runtime-render, session-persistence

### AC-02：工单支持多轮回复
- 验收条件：工单支持多轮回复，每条回复记录回复人、回复时间与回复内容；重新打开工单可读回按时间顺序排列的全部回复。
- 入口类型：用户界面
- 验证动作：在同一工单上由处理人回复一次、再由提交人回复一次，随后重新打开该工单。
- 预期结果：工单显示全部回复，每条包含回复人与回复时间，顺序与发生顺序一致。
- 证据类型：interaction, session-persistence

### AC-03：工单与配置按公司隔离
- 验收条件：工单、业务组配置与统计数据按公司隔离，其他公司的用户无法查看或操作不属于本公司的对象。
- 入口类型：用户界面
- 验证动作：在 A 公司账号下打开工单工作台、工单详情与业务组配置，并尝试打开 B 公司已存在的工单与业务组。
- 预期结果：仅出现 A 公司范围内的工单、业务组与统计；B 公司的对象不可见且无法打开或操作。
- 证据类型：authorization

### AC-04：工单可设置 SLA 优先级与问题分类
- 验收条件：工单可设置 P0–P4 优先级与问题分类，两者可按工单读回，并可作为工作台筛选依据。
- 入口类型：用户界面
- 验证动作：为工单分别设置 P0、P4 与不同分类并保存，重新打开该工单，并在工作台按所设分类筛选。
- 预期结果：工单显示所设置的优先级（P0/P4）与分类；按该分类筛选后的列表包含该工单。
- 证据类型：interaction, session-persistence

### AC-05：工单生命周期流转与处理记录
- 验收条件：工单状态覆盖创建、待分配、待处理、完成、取消并按 创建 → 待分配 → 待处理 → 完成 流转；完成时记录处理人与处理时间。推荐基线：处于创建/待分配/待处理的工单可取消，已完成工单不可取消。
- 入口类型：用户界面
- 验证动作：新建工单并观察其状态；执行分配使其进入待处理；处理完成后重新打开工单查看处理人与处理时间；另取一张未完成工单执行取消，再尝试取消一张已完成工单。
- 预期结果：状态依次可读回为 创建、待分配、待处理、完成；完成工单显示处理人与处理时间；未完成工单取消后状态为取消；对已完成工单的取消不生效（被拒绝或不可操作）。
- 证据类型：interaction, session-persistence

### AC-06：公司可维护多个业务组与成员
- 验收条件：同一公司可建立多个业务组，每个业务组可设置成员，业务组与成员归属可读回。
- 入口类型：用户界面
- 验证动作：为某公司创建两个业务组并分别为其添加不同成员，重新打开业务组配置。
- 预期结果：两个业务组均存在，各自成员与其设置一致；修改成员后读回结果随之更新。
- 证据类型：interaction, session-persistence

### AC-07：工单按分类自动分配到业务组
- 验收条件：公司可为某分类配置自动分配的业务组，符合该规则的新工单在创建后自动归入目标业务组，无需人工分配。
- 入口类型：后台任务
- 验证动作：为该公司某分类配置“分类 → 业务组”规则，随后创建一张该分类的工单并打开该工单。
- 预期结果：该工单创建后归属为规则指定的业务组，且该归属在工单上可读回。
- 证据类型：session-persistence

### AC-08：工单可转派
- 验收条件：待处理工单可从当前处理方转派给其他处理人或业务组，转派后由新的处理方继续处理该工单。
- 入口类型：用户界面
- 验证动作：处理人 A 将一张待处理工单转派给处理人 B，随后以处理人 B 打开工单工作台与工单详情。
- 预期结果：该工单的处理方为 B，B 可在工作台找到并继续处理该工单。
- 证据类型：interaction, session-persistence

### AC-09：处理工单时可查看提交人完整信息
- 验收条件：处理人处理工单时可查看提交人完整信息，包括姓名、公司、部门与历史工单。
- 入口类型：用户界面
- 验证动作：以处理人身份打开一张工单（其提交人已存在其他历史工单），查看提交人信息区域。
- 预期结果：显示提交人姓名、公司、部门，并列出该提交人的历史工单。
- 证据类型：runtime-render, interaction

### AC-10：工单完成时向提交人发送邮件通知
- 验收条件：工单完成时系统向该工单提交人的邮箱发送完成通知邮件。
- 入口类型：后台任务
- 验证动作：将一张带有提交人邮箱的工单流转为完成，随后查看该工单的通知发送结果记录（与 AC-15 的日志记录对应）。
- 预期结果：针对该工单向提交人邮箱地址发出完成通知，发送结果可查（成功，或存在明确的失败记录）。
- 证据类型：other

### AC-11：提交人可提交满意度评价
- 验收条件：工单完成后，提交人可提交满意度评价，评价内容与时间可在工单上读回并可用于满意度统计。推荐基线：评价结果以有序评分刻度表达，具体刻度未规定。
- 入口类型：用户界面
- 验证动作：以提交人身份对一张已完成工单提交满意度评价，随后重新打开该工单。
- 预期结果：工单显示该次评价结果与评价时间，读回内容与提交一致。
- 证据类型：interaction, session-persistence

### AC-12：按公司与部门维度统计工单分布
- 验收条件：可按公司维度与部门维度统计工单分布（各维度下的工单数量），统计结果与当前数据范围内实际工单一致。
- 入口类型：用户界面
- 验证动作：在已知数量的工单数据下，打开按公司的工单分布与按部门的工单分布统计。
- 预期结果：统计中该公司数量与该公司实际工单数量一致；部门维度数量之和与对应范围内工单数量一致。
- 证据类型：runtime-render

### AC-13：运营指标仪表盘
- 验收条件：仪表盘展示工单量、平均响应时间、满意度与热点问题等运营指标。推荐基线：平均响应时间＝工单创建至首次回复的间隔平均值；热点问题＝按分类的工单数量排序靠前项；满意度＝已提交评价的聚合结果。
- 入口类型：用户界面
- 验证动作：在已知工单、回复与评价数据下打开统计与分析仪表盘，对照检查各指标。
- 预期结果：仪表盘展示工单量、平均响应时间、满意度与热点问题，且各指标数值与所用数据按上述口径计算结果一致。
- 证据类型：runtime-render

### AC-14：工单工作台支持查看与筛选
- 验收条件：工单工作台展示待处理工单列表，支持筛选、搜索、排序，并可按公司维度筛选。
- 入口类型：用户界面
- 验证动作：打开工单工作台，输入关键字搜索、按列表字段排序、按公司维度筛选。
- 预期结果：列表仅展示待处理工单；搜索、排序与公司筛选均改变列表内容，结果与所设条件一致。
- 证据类型：runtime-render, interaction

### AC-15：工单相关操作记录日志
- 验收条件：工单相关关键操作产生日志记录，含操作对象、操作人（或系统）与时间。推荐基线：记录范围覆盖创建、分配/自动分配、转派、回复、状态变更（完成/取消）、评价、完成通知与业务组、自动分配规则的配置变更。
- 入口类型：内部
- 验证动作：依次执行建单、自动分配、回复、转派、完成（含通知）与评价，随后查看日志记录。
- 预期结果：上述每项操作均有对应日志条目，且包含操作对象、操作人（或系统）与时间。
- 证据类型：other

## 7. 未规定事项（本次不假定）

- 各 SLA 优先级（P0–P4）的时限数值与超时处理方式。
- 未命中自动分配规则时工单的处理去向与人工分配方式。
- 转派是否保留原处理方轨迹、是否限制转派次数。
- 满意度评价的具体刻度、是否允许修改评价。
- 通知邮件的模板、渠道配置与失败重试策略。
- 非目标（排除项）：用户未声明任何排除项，因此本次不设非目标，也不据此限制实现范围。
- 产品载体与设备适配（Web/桌面/移动）、登录与授权机制的技术实现、数据存储技术。
