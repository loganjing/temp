# 实现报告（工单系统 / 144-ticket）

业务任务：144-ticket。阶段：implementation（开发实现）。本报告汇总两个并行实现任务的交付、验证证据与遗留事项。

## 1. 交付概述

按已批准需求（`docs/wi-t1000006/requirements.md`）、架构基线（`docs/wi-t1000006/architecture-baseline.md`）与技术契约（`docs/wi-t1000006/technical-contract.md`）完成工单系统全栈实现，应用包为 `app/ticket-system`。

- **T01 服务端**（`src/server/**`、`src/shared/**`、`test/**`）：身份上下文、工单域（创建含分类自动分配、多轮回复、分配、转派、完成、取消、满意度评价、通知结果）、组织配置（业务组与成员、分类→业务组规则、本公司成员）、统计与分析（公司/部门分布、运营指标）、操作日志的全部端点与服务端逻辑；新增迁移 `0004_identity.sql`、`0005_org_config.sql`、`0006_tickets.sql`、`0007_notifications.sql`；共享契约 `src/shared/contracts.ts`。
- **T02 前端**（`src/client/**`）：应用壳与启动上下文、工单工作台（待处理队列×详情并列）、工单详情与操作、我的工单与评价、业务组与分配规则配置、统计与分析仪表盘、操作日志；Modern SaaS 视觉基线。

## 4. 设计差异与处理

1. **业务组成员读回（AC-06）**：技术契约 `GET /api/org/groups` 原只返回 `memberCount`，无法在重新打开配置时读回各组成员。需求 AC-06 要求“业务组与成员归属可读回”，为实现该验收条件，在列表条目上**附加式**扩展了 `memberIds` 与 `members: [{ memberId, displayName }]`，未删除或改写契约既有字段。该扩展为对设计缺口的可逆闭合，建议后续在技术契约中补记。
2. **认证中间件返回值（协调者修复）**：`src/server/platform/auth.ts` 的 `requireAnyAuth` 包装未 `return` authkit 的认证响应，导致 401 未生效、1 个端点测试失败。该缺陷由 T01 定位并在沙箱验证修复，但因 T01 在二轮无法写入该文件，由协调者按已验证方案落地（外层 `return await`，内层保持 `Promise<void>` 兼容）。修复后 `npm test` 11/11 通过、`typecheck:server` 退出码 0。
3. **完成通知邮件**：SMTP 配置来自环境变量（`SMTP_*`），未配置时发送失败并记录 `status=failed` 与错误原因，不回滚完成状态（符合架构 ADR-7）。
4. **未规定项口径**：SLA 优先级仅作标记；未命中规则工单停留“待分配”；转派保留轨迹不限次数；评价 1–5 不可修改；邮件纯文本模板不重试。
