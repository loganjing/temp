# 工单系统需求（127-ticket）

## 1. 目标

面向多公司环境提供完整工单服务：公司用户提交工单，工单按公司隔离并按分类自动分配到业务组；处理人处理、回复、转派工单，完成时记录处理信息并向提交人发送邮件通知；提交人进行满意度评价；运营侧通过工作台跟进待处理工单，并通过统计与仪表盘分析公司/部门分布及运营指标。

标注约定：未标注来源的条目为用户明确提出；【推荐基线】为闭合核心流程所必需的保守默认，用户可调整；【未规定】为用户未明确且不阻塞当前验收的事项。

## 2. 使用对象

| 对象 | 说明 | 来源 |
|---|---|---|
| 提交人 | 公司用户；提交工单、参与多轮回复，收到完成通知后进行满意度评价 | 用户明确提出（提交人信息含姓名/公司/部门/邮箱） |
| 处理人 | 业务组成员；处理工单、回复、转派 | 用户明确提出（业务组可设置成员；记录处理人） |
| 业务组配置操作者 | 为公司配置业务组、成员及分类自动分配规则 | 操作能力为用户明确提出；具体操作者角色【未规定】 |
| 跨公司视角使用者 | 工作台公司维度筛选、按公司/部门统计所需的跨公司数据访问者 | 能力为用户明确提出；具体角色与授权模型【未规定】 |

## 3. 核心对象与字段

- 工单：工单ID（唯一）、主题、描述、问题分类、SLA优先级（P0–P4）、状态、所属公司、提交人信息（姓名、公司、部门、邮箱）、创建时间、处理人、处理时间。
- 回复：回复内容、回复人、回复时间；同一工单可多轮。
- 业务组：隶属某公司，一个公司可有多个；每个业务组含成员列表。
- 自动分配规则：公司维度，问题分类 → 业务组的映射。
- 满意度评价：与工单关联的评分；分值形式【推荐基线：1–5 分数值评分，支撑满意度统计聚合】。
- 操作日志：操作者、时间、动作。

## 4. 工单生命周期

状态集合（用户明确提出）：创建、待分配、待处理、完成、取消。

- 创建：工单提交生成后的初始状态。
- 待分配：等待分配业务组/处理人。
- 待处理：已分配，处理中尚未完成。
- 完成：处理完毕；终态。完成时向提交人发送邮件通知（见 6.4）。
- 取消：终止；终态。完成前可取消【推荐基线：创建/待分配/待处理状态均可取消，完成后不可取消】。

主流程：创建 → 待分配 → 待处理 → 完成。

## 5. 端到端旅程

1. 公司用户提交工单，填写主题、描述、问题分类并设置 P0–P4 优先级。
2. 系统按该公司“分类→业务组”规则自动分配；无匹配时保持待分配，可手动分配【推荐基线】。
3. 业务组处理人查看提交人完整信息与历史工单，多轮回复沟通，必要时转派。
4. 处理完成后工单进入完成，系统记录处理人与处理时间，并向提交人邮箱发送通知邮件。
5. 提交人收到通知后对该工单进行满意度评价。
6. 运营侧通过工作台跟进待处理工单，通过统计与仪表盘分析分布与运营指标。

## 6. 模块需求

### 6.1 工单管理
- 创建：提交人填写主题、描述、问题分类并设置 SLA 优先级（P0–P4）；系统记录提交人信息（姓名、公司、部门、邮箱）与创建时间，生成唯一工单ID。
- 查看：工单详情完整展示第 3 节所列工单字段。
- 回复：同一工单支持多轮回复，每轮记录回复人与回复时间。
- 公司隔离：工单归属提交人所在公司；其他公司用户不可查看或操作该公司工单（含列表、详情、回复、处理、转派入口）。
- 优先级创建后是否可调整：【未规定】。

### 6.2 工单分配
- 业务组管理：可为某公司增加多个业务组；每个业务组可设置成员，成员可维护。
- 自动分配：公司配置“问题分类→业务组”规则后，该公司新工单按分类自动分配至对应业务组，状态进入待处理。
- 兜底与手动分配：无匹配规则的工单保持待分配，可手动指定业务组/处理人后进入待处理【推荐基线】。
- 分配到组后由组内成员处理；认领方式（指派个人或成员自取）【未规定】。

### 6.3 工单协作（转派）
- 待处理工单可转派给其他业务组或处理人【推荐基线：用户要求“支持工单转派操作”，转派对象取业务组或处理人以闭合流程】。
- 转派后工单保持待处理状态；转派动作记入操作日志，可追溯。

### 6.4 工单处理与通知
- 处理工单时可查看提交人完整信息：姓名、公司、部门、历史工单。
- 处理后记录处理人与处理时间。
- 工单完成时向提交人发送邮件通知，邮箱取自工单上记录的提交人邮箱。

### 6.5 用户评价
- 工单完成后，提交人可对该工单进行满意度评价；评价结果用于满意度统计。
- 评分形式【推荐基线：1–5 分】；评价提交后是否可修改【未规定】。

### 6.6 统计分析
- 分布统计：支持按公司维度、部门维度统计工单分布。
- 运营仪表盘：展示工单量、平均响应时间、满意度、热点问题等运营指标。
  - 平均响应时间定义【推荐基线：工单创建到首次回复的时间间隔均值】。
  - 热点问题定义【推荐基线：按问题分类聚合的高频工单排序】。
- 跨公司统计与公司维度筛选依赖相应数据权限（见第 2 节）。

### 6.7 工单工作台
- 展示待处理工单列表。
- 支持筛选、搜索、排序；公司维度筛选为用户明确提出的要求。
- 搜索匹配字段与排序字段【推荐基线：搜索匹配工单ID/主题/提交人；排序支持创建时间、优先级；筛选支持状态、分类、优先级、公司】。

### 6.8 操作日志
- 关键操作记录日志：创建、分配、转派、回复、处理、完成、取消、评价等，含操作者、时间、动作。
- 日志查看入口【未规定】；日志需可检索以支持追溯与验收。

## 7. 验收标准

### AC-01：提交人可创建工单并记录完整信息
- 验收条件：公司用户可提交工单，系统记录工单ID、主题、描述、分类、SLA优先级、提交人信息（姓名、公司、部门、邮箱）与创建时间，并可在详情中读回。
- 入口类型：用户界面
- 验证动作：以某公司用户身份提交一张工单（填写主题、描述、分类，选择优先级 P2），随后打开该工单详情。
- 预期结果：工单生成唯一ID；详情页完整展示主题、描述、分类、优先级、提交人姓名/公司/部门/邮箱与创建时间。
- 证据类型：interaction，runtime-render

### AC-02：工单支持多轮回复并记录回复人与回复时间
- 验收条件：同一工单可进行多轮回复，每轮记录回复人与回复时间，按时间可追溯。
- 入口类型：用户界面
- 验证动作：对同一工单由不同人员先后回复两次，查看回复记录。
- 预期结果：两轮回复均存在，各自显示回复人与回复时间，先后顺序正确。
- 证据类型：interaction，runtime-render

### AC-03：工单按公司隔离
- 验收条件：工单归属提交人所在公司，其他公司用户无法查看或操作该工单。
- 入口类型：用户界面
- 验证动作：A公司用户提交工单后，以B公司用户身份尝试通过列表、详情及操作入口访问该工单。
- 预期结果：B公司用户无法看到或打开A公司工单，访问被拒绝且不泄露工单内容。
- 证据类型：authorization，error-feedback

### AC-04：工单按生命周期流转
- 验收条件：工单沿创建→待分配→待处理→完成的主流程流转；完成前可取消；完成与取消为终态。
- 入口类型：用户界面
- 验证动作：创建一张工单，依次执行分配与处理完成，观察状态变化；另取一张待处理工单执行取消。
- 预期结果：工单分配后进入待处理，处理完成后为完成；完成后状态不可再变更；取消后为取消且不再进入处理流程。
- 证据类型：interaction，session-persistence

### AC-05：公司业务组与成员管理
- 验收条件：可为某公司创建多个业务组，为各业务组设置成员，成员信息保存后可读回。
- 入口类型：用户界面
- 验证动作：为某公司新增两个业务组，分别添加不同成员。
- 预期结果：两个业务组独立存在，各自成员列表保存正确。
- 证据类型：interaction，runtime-render

### AC-06：工单按分类自动分配到业务组
- 验收条件：配置公司“分类→业务组”规则后，该公司新工单按分类自动分配到对应业务组并进入待处理；无匹配规则时保持待分配且可手动分配（推荐基线）。
- 入口类型：用户界面
- 验证动作：为公司C配置规则“分类X→业务组G1”，提交一张分类为X的工单；再提交一张无规则匹配分类的工单并手动分配。
- 预期结果：第一张工单自动归属G1且状态为待处理；第二张保持待分配，手动分配后进入待处理。
- 证据类型：interaction，runtime-render

### AC-07：工单转派
- 验收条件：待处理工单可转派给其他业务组或处理人（推荐基线），转派后仍为待处理且转派记录可追溯。
- 入口类型：用户界面
- 验证动作：将一张已分配到业务组G1的工单转派给G2（或另一处理人）。
- 预期结果：工单当前归属变为G2/该处理人，状态保持待处理，转派记录可查。
- 证据类型：interaction，runtime-render

### AC-08：处理人可查看提交人完整信息并记录处理信息
- 验收条件：处理工单时可查看提交人姓名、公司、部门与历史工单；处理后记录处理人与处理时间。
- 入口类型：用户界面
- 验证动作：处理人打开一张待处理工单，查看提交人信息与历史工单，并执行处理操作。
- 预期结果：信息面板显示提交人姓名、公司、部门及其历史工单；处理后工单记录显示处理人与处理时间。
- 证据类型：interaction，runtime-render

### AC-09：工单完成后发送邮件通知
- 验收条件：工单完成时，系统向提交人邮箱发送完成通知邮件。
- 入口类型：用户界面
- 验证动作：完成一张提交人邮箱为已知可达地址的工单，随后检查该邮箱。
- 预期结果：提交人收到工单完成通知邮件，邮件内容可识别对应工单。
- 证据类型：other

### AC-10：提交人满意度评价
- 验收条件：工单完成后，提交人可对该工单提交满意度评价，评价被记录并可用于统计。
- 入口类型：用户界面
- 验证动作：工单完成后，提交人提交满意度评分，随后查看该工单。
- 预期结果：评价保存成功并在工单上可见。
- 证据类型：interaction，runtime-render

### AC-11：按公司与部门维度统计工单分布
- 验收条件：统计功能可分别按公司维度与部门维度展示工单分布。
- 入口类型：用户界面
- 验证动作：准备多公司、多部门的工单数据，打开统计页面并分别切换公司、部门维度。
- 预期结果：各维度分布数据与实际工单数据一致，维度可切换。
- 证据类型：runtime-render

### AC-12：运营仪表盘展示核心指标
- 验收条件：仪表盘展示工单量、平均响应时间、满意度、热点问题指标，数值与底层数据一致。
- 入口类型：用户界面
- 验证动作：在已知数据集下打开仪表盘，逐项核对各指标。
- 预期结果：工单量、平均响应时间、满意度、热点问题正确展示，数据变化后指标随之更新。
- 证据类型：runtime-render

### AC-13：工单工作台列表
- 验收条件：工作台展示待处理工单列表，支持筛选（含公司维度）、搜索与排序。
- 入口类型：用户界面
- 验证动作：以具备多公司查看权限的账号进入工作台，依次使用公司筛选、关键词搜索与排序操作。
- 预期结果：列表仅包含待处理工单；筛选、搜索结果与排序顺序符合所选条件。
- 证据类型：interaction，runtime-render

### AC-14：关键操作记录日志
- 验收条件：创建、分配、转派、回复、处理、完成、取消、评价等关键操作产生含操作者、时间、动作的日志记录。
- 入口类型：内部
- 验证动作：依次执行上述关键操作后检索系统日志。
- 预期结果：每个操作均有对应日志条目，包含操作者、时间与动作，顺序与实际操作一致。
