# 访客系统需求文档

> Work Item: wi-t1000026 | 项目: jlgguest | 场景: 新建

## 1. 目标

开发一个移动端访客管理系统，包含移动端访客登记界面、后端服务和数据库，支持访客信息录入、持久化存储，以及审批人员对来访人员的审核操作。

## 2. 角色与旅程

### 角色

| 角色 | 说明 | 来源 |
|------|------|------|
| 访客 | 在移动端填写个人信息并提交登记的人员 | 用户明确提出 |
| 审批人 | 在审批后端系统中查看来访登记并进行审核操作的人员 | 用户明确提出 |

### 旅程

**访客登记旅程**：访客在移动端打开登记界面 → 填写个人信息（手机号、身份证号、公司、姓名、访问事由、被访人、预计到访时间）→ 提交登记 → 等待审批结果。

**审批旅程**：审批人在审批后端系统中查看待审核的访客登记列表 → 查看访客详细信息 → 执行通过或拒绝 → 访客登记状态更新为已通过或已拒绝。

## 3. 功能模块需求

### 3.1 访客登记（移动端）

- 移动端提供访客信息登记界面，访客可在此界面填写并提交个人信息。
- 登记字段如下：

| 字段 | 说明 | 来源 |
|------|------|------|
| 姓名 | 访客真实姓名，必填 | 用户明确提出 |
| 手机号码 | 手工填写，必填 | 用户明确提出 |
| 身份证号 | 访客身份证号码，必填 | 用户明确提出 |
| 公司信息 | 访客所属公司名称，必填 | 用户明确提出 |
| 访问事由 | 本次来访目的说明，必填 | 用户明确提出 |
| 被访人 | 本次访问的接待人员姓名，必填 | 用户授权补充（"其他的你可以发挥"） |
| 预计到访时间 | 访客计划的到访日期与时间，必填 | 用户授权补充（"其他的你可以发挥"） |
| 车牌号 | 访客驾驶车辆的车牌号，选填 | 用户授权补充（"其他的你可以发挥"） |

- 必填字段未填写时，提交操作应阻止完成并提示对应字段。
- 提交成功后，访客登记记录进入"待审核"状态。

### 3.2 审批后端系统

- 审批后端系统提供待审核访客登记列表，审批人可查看所有待审核的访客记录。
- 审批人可查看单条访客登记的完整信息。
- 审批人可对每条待审核记录执行"通过"或"拒绝"操作。
- 审批操作完成后，该访客登记的状态更新为"已通过"或"已拒绝"。
- 审批后端系统支持查看已处理的访客登记记录（含已通过、已拒绝）。

### 3.3 访客登记状态

访客登记记录的状态流转如下：

| 状态 | 说明 |
|------|------|
| 待审核 | 访客提交登记后的初始状态 |
| 已通过 | 审批人执行通过操作后的状态 |
| 已拒绝 | 审批人执行拒绝操作后的状态 |

- 状态变更只能由审批人的审批操作触发；访客提交后无法自行修改或撤销。

## 4. 验收场景

### AC-01：访客可在移动端填写并提交登记信息

- 验收条件：访客在移动端登记界面填写所有必填字段（姓名、手机号、身份证号、公司信息、访问事由、被访人、预计到访时间）后可成功提交，提交后登记记录进入待审核状态。
- 入口类型：用户界面
- 验证动作：在移动端打开访客登记界面，填写全部必填字段并点击提交。
- 预期结果：提交成功，系统提示登记已提交，该记录状态为"待审核"。
- 证据类型：interaction, runtime-render

### AC-02：必填字段缺失时阻止提交

- 验收条件：当任一必填字段为空时，提交操作被阻止并提示对应缺失字段。
- 入口类型：用户界面
- 验证动作：在移动端登记界面留空一个或多个必填字段，点击提交。
- 预期结果：提交未成功，界面提示具体缺失的必填字段。
- 证据类型：error-feedback, interaction

### AC-03：访客登记记录持久化存储并可读取

- 验收条件：访客提交登记后，记录持久化保存至数据库；审批后端系统可读取到该条记录的完整信息。
- 入口类型：内部
- 验证动作：访客在移动端提交一条登记记录后，在审批后端系统查看待审核列表。
- 预期结果：审批后端系统的待审核列表中出现该条记录，且记录内容与访客提交的信息一致。
- 证据类型：session-persistence

### AC-04：审批人可审核来访人员并更新状态

- 验收条件：审批人可在审批后端系统中对待审核的访客记录执行通过或拒绝操作，操作后记录状态分别变为"已通过"或"已拒绝"，且已处理记录可在已处理列表中查看。
- 入口类型：用户界面
- 验证动作：在审批后端系统的待审核列表中选择一条访客记录，查看其完整信息，执行"通过"或"拒绝"操作。
- 预期结果：该记录状态更新为"已通过"或"已拒绝"，且该记录出现在已处理列表中，状态信息正确。
- 证据类型：interaction, session-persistence
