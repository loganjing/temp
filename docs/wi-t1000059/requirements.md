# k18-robot 需求文档

## 1. 目标

开发设备管理平台，覆盖设备状态监测、故障诊断、远程升级、维修工单和设备履历五大功能模块。用户明确要求所有业务数据需要数据库存储。

## 2. 用户旅程

### 旅程 A：从故障发现到维修闭环

1. 在设备状态监测中查看设备运行状态
2. 发现异常后通过故障诊断记录故障信息
3. 基于故障创建维修工单
4. 工单处理后完成维修
5. 以上所有事件归入设备履历

### 旅程 B：远程升级

1. 选择目标设备发起远程升级
2. 跟踪升级进度
3. 升级完成后结果归入设备履历

## 3. 模块需求

### 3.1 设备状态监测

- 可查看设备的当前运行状态
- 状态变化被记录并支持按设备回溯
- 支持查看设备列表及各自状态

### 3.2 故障诊断

- 可记录设备故障信息，包括故障类型、严重程度和发生时间
- 故障记录关联到具体设备
- 可按设备查看故障记录列表

### 3.3 远程升级

- 可对设备发起远程升级
- 可跟踪升级进度和最终结果（成功/失败）
- 升级记录关联到具体设备

### 3.4 维修工单

- 可创建维修工单，关联设备（和故障，如有）
- 工单可被处理并标记完成
- 可查看工单列表及当前状态

### 3.5 设备履历

- 按设备聚合展示状态变化、故障、升级和维修工单记录
- 可按设备查询完整履历
- 履历内容来源于其他四个模块产生的事件

## 4. 数据持久化

> 用户明确提出：所有业务数据需要数据库存储。

- 各模块写入的数据可通过相应读取行为读回
- 数据在应用重启后仍然保留
- 不指定具体数据库技术选型

## 5. 未规定事项

以下内容用户未明确，不在当前基线中规定，留待后续补充或由实现阶段决策：

- 设备类型范围与数量规模
- 状态监测为实时推送还是周期采集
- 远程升级的具体协议与升级包格式
- 工单分配、审批等流转细节
- 用户角色与权限划分
- 部署方式与运行环境

## 6. 验收标准

### AC-01：设备状态可监测和回溯

- 验收条件：设备当前状态可查看，状态变化被记录且可按设备回溯。
- 入口类型：用户界面
- 验证动作：查看某设备的当前运行状态，并查看该设备的历史状态记录。
- 预期结果：能看到设备当前运行状态，以及过往状态变化记录。
- 证据类型：runtime-render, interaction

### AC-02：故障可诊断和记录

- 验收条件：设备故障信息可被记录并关联具体设备，且可在故障列表中查看。
- 入口类型：用户界面
- 验证动作：对某设备记录一条故障信息（含故障类型、严重程度、发生时间），然后在故障列表中查看该记录。
- 预期结果：故障记录成功保存并显示，且关联到对应设备。
- 证据类型：runtime-render, interaction, session-persistence

### AC-03：远程升级可发起和跟踪

- 验收条件：可对设备发起远程升级，并跟踪升级进度和最终结果。
- 入口类型：用户界面
- 验证动作：对某设备发起远程升级，查看升级进度和结果。
- 预期结果：升级过程可跟踪，最终显示成功或失败结果。
- 证据类型：runtime-render, interaction

### AC-04：维修工单可创建、处理和完成

- 验收条件：维修工单可创建并关联设备和故障，工单可被处理并标记完成，工单状态可在列表中查看。
- 入口类型：用户界面
- 验证动作：创建一条关联设备和故障的维修工单，处理并完成该工单，查看工单列表。
- 预期结果：工单从创建到完成的全过程可追踪，状态变化可见。
- 证据类型：runtime-render, interaction, session-persistence

### AC-05：设备履历聚合完整

- 验收条件：按设备查看履历时，可看到该设备的状态变化、故障、升级和维修工单记录。
- 入口类型：用户界面
- 验证动作：选择一个已有状态变化、故障、升级和工单记录的设备，查看其设备履历。
- 预期结果：履历页面展示该设备来自各模块的全部事件记录。
- 证据类型：runtime-render, interaction

### AC-06：数据通过数据库持久存储

- 验收条件：各模块写入的数据通过数据库存储，应用重启后数据仍然保留。
- 入口类型：用户界面
- 验证动作：在各模块创建测试数据，重启应用后再次查看对应数据。
- 预期结果：重启后所有先前写入的数据均可正常读取。
- 证据类型：session-persistence
