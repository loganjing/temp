# 工单系统需求文档（136-ticket）

> 工作项：wi-t1000334 · 阶段：requirements
> 记号说明：【用户】= 用户明确提出；【推荐】= 为闭合核心目标提出的保守默认，用户可调整；【未规定】= 用户未提出，保持开放。未标注来源的条目均为【用户】。

## 1. 目标

为多公司环境提供工单端到端管理闭环，覆盖以下核心目标（均为用户明确提出）：

1. 工单管理：工单ID、主题、描述、分类、提交人信息（含邮箱）、创建时间；多轮回复（回复人、回复时间）；工单按公司隔离；SLA优先级（P0-P4）与问题分类；完整生命周期（创建、待分配、待处理、完成、取消）。
2. 工单分配：为公司增加多个业务组并设置成员；公司工单按分类自动分配到业务组。
3. 工单协作：工单转派。
4. 工单处理：处理时可查看提交人完整信息（姓名、公司、部门、历史工单等）；处理后记录处理人、处理时间；工单完成后发送邮件通知。
5. 用户评价：用户进行满意度评价。
6. 统计分析：按公司、部门维度统计工单分布；统计与分析仪表盘（工单量、平均响应时间、满意度、热点问题等运营指标）。
7. 工单工作台：待处理工单列表，支持筛选、搜索、排序，可按公司维度筛选。
8. 记录工单相关操作日志。

## 2. 操作主体与旅程

### 2.1 操作主体

| 主体 | 职责 | 来源 |
|---|---|---|
| 提交人 | 创建工单、跟踪进度、多轮回复、接收完成邮件通知、满意度评价 | 【用户】 |
| 处理人 | 在工作台查看待处理工单、回复、转派、完成处理 | 【用户】 |
| 业务组成员 | 业务组成员构成工单承接方，处理分配到本组的工单 | 【用户】 |
| 业务组与分配规则管理者 | 为公司创建业务组、设置成员、配置分类分配规则 | 【未规定】（见 §7.2） |

### 2.2 提交人旅程

1. 填写主题、描述，选择问题分类与 SLA 优先级（P0-P4），提交工单。
2. 系统生成工单ID，记录提交人信息（姓名、邮箱、公司、部门）与创建时间。
3. 工单进入分配流程，按分类自动分配到业务组。
4. 提交人跟踪处理进度，与处理人多轮回复。
5. 工单完成，提交人收到邮件通知。
6. 提交人对工单进行满意度评价。

### 2.3 处理人旅程

1. 在工单工作台查看待处理工单列表（筛选、搜索、排序，可按公司筛选）。
2. 打开工单详情，查看提交人完整信息：姓名、公司、部门、历史工单。
3. 与提交人多轮回复沟通。
4. 需要其他业务组承接时执行转派。
5. 处理完成：系统记录处理人、处理时间，工单状态变为完成，并触发邮件通知。

### 2.4 业务组配置旅程

1. 为公司创建业务组（可多个）。
2. 为每个业务组设置成员。
3. 配置"问题分类 → 业务组"的分配规则。
4. 该公司新工单按分类自动分配到对应业务组。

## 3. 核心对象与术语

| 对象 | 说明 |
|---|---|
| 工单 | 核心业务对象：工单ID、主题、描述、分类、SLA优先级、提交人信息（姓名、邮箱、公司、部门）、创建时间、当前状态、归属业务组 |
| 工单回复 | 工单下的多轮沟通记录：回复人、回复内容、回复时间 |
| 公司 | 工单、业务组与分配规则的隔离主体 |
| 业务组 | 公司下的工单承接单元，由成员组成 |
| 业务组成员 | 隶属业务组、承接本组工单的用户 |
| 问题分类 | 工单类型标签，自动分配规则的匹配维度 |
| SLA优先级 | P0-P4 五级；P0 最高、P4 最低【推荐：次序】 |
| 分配规则 | 公司内"问题分类 → 业务组"映射，驱动自动分配 |
| 满意度评价 | 提交人对已完成工单的评价结果 |
| 操作日志 | 工单关键操作的记录 |

## 4. 工单生命周期

状态集合【用户】：创建、待分配、待处理、完成、取消。

```
创建 ──进入分配流程──> 待分配 ──自动分配/手动分配到业务组──> 待处理 ──处理完成──> 完成
创建 / 待分配 / 待处理 ──取消──> 取消
待处理 ──转派──> 待处理（归属业务组变更）
完成、取消 ──终态，不再流转
```

| 规则 | 内容 | 来源 |
|---|---|---|
| LC-1 | 工单提交后的初始状态为「创建」，随后进入「待分配」等待分配 | 【用户】状态集合 /【推荐】流转 |
| LC-2 | 工单分配到业务组后进入「待处理」 | 【推荐】 |
| LC-3 | 处理完成后进入「完成」，记录处理人与处理时间 | 【用户】 |
| LC-4 | 「创建」「待分配」「待处理」状态下的工单可被取消 | 【推荐】 |
| LC-5 | 「完成」「取消」为终态，不可再流转到其他状态 | 【推荐】 |
| LC-6 | 转派后状态保持「待处理」，归属业务组变更 | 【推荐】 |
| LC-7 | 工单按公司隔离：用户不能查看或操作其他公司的工单 | 【用户】 |

## 5. 模块需求

### 5.1 工单管理

#### 5.1.1 工单创建与信息记录

- 提交人填写：主题、描述、问题分类、SLA优先级（P0/P1/P2/P3/P4）。
- 系统生成：唯一工单ID、创建时间。
- 系统记录提交人信息：姓名、邮箱【用户】；公司、部门【推荐：公司为隔离与统计主体、部门为统计维度的必要闭合】。
- 创建成功后，工单全部信息可通过详情读回。
- 主题、分类、优先级缺失时不可提交【推荐：必填校验】。

#### 5.1.2 多轮回复

- 提交人与处理人可对工单进行多轮回复。
- 每条回复记录回复人、回复时间。
- 回复按时间顺序在工单中可读回，可继续追加回复。
- 回复可用状态范围：完成前可回复；工单完成后是否可追加回复【未规定】。

#### 5.1.3 SLA优先级与问题分类

- 优先级取值 P0-P4；P0 最高、P4 最低【推荐：次序】。
- 分类是自动分配规则的匹配维度（见 5.2.2）。
- 优先级是否影响处理排序、创建后能否调整【未规定】。

#### 5.1.4 公司隔离

- 工单归属提交人所属公司；列表、搜索、详情与操作均不可跨公司访问。
- 业务组与分配规则为公司私有，不跨公司共享【推荐：与"给某个公司增加业务组"一致】。
- 统计分析按公司、部门维度查看分布（见 5.6）；跨公司统计视图的访问角色【未规定】。

### 5.2 工单分配

#### 5.2.1 业务组与成员管理

- 可为某个公司创建多个业务组。
- 每个业务组可设置多个成员。
- 管理操作（创建业务组、增减成员）的角色与权限【未规定】。
- 成员变更后，组内已分配工单的归属不受影响【推荐】。

#### 5.2.2 按分类自动分配

- 可为某公司配置"问题分类 → 业务组"的分配规则。
- 该公司工单创建后，系统按工单分类匹配分配规则，自动分配到对应业务组。
- 分配成功后工单状态进入「待处理」，归属业务组在工单上可查看【推荐：可观察】。
- 分类无匹配规则时：【推荐】工单保持「待分配」，可手动分配到业务组（手动分配为推荐兜底，非用户明确）。

### 5.3 工单协作：转派

- 待处理工单可执行转派，转派目标为其他业务组【推荐：目标粒度为业务组】。
- 是否可转派给具体处理人【未规定】。
- 转派后工单归属变更，状态保持「待处理」【推荐】。
- 转派记录转派人、转派目标、转派时间【推荐：可追溯必要闭合】。
- 转派次数：允许多次【推荐】。
- 「完成」「取消」状态下的工单不可转派【推荐】。

### 5.4 工单处理

#### 5.4.1 提交人完整信息查看

- 处理工单时可查看提交人完整信息：姓名、公司、部门、历史工单等。
- 历史工单为提交人过往提交的工单列表（主题、状态、创建时间等），按创建时间倒序【推荐】。

#### 5.4.2 处理记录与完成通知

- 工单处理完成后，系统记录处理人、处理时间。
- 工单完成后系统发送邮件通知。
- 通知收件人：提交人（邮箱取自提交人信息）【推荐闭合】。
- 邮件内容可识别对应工单（工单ID/主题）【推荐】。

### 5.5 用户评价

- 工单完成后，提交人可对工单进行满意度评价【推荐闭合：用户表述"用户收到工单后"结合完成邮件通知语境，评价入口在工单完成后】。
- 评价形式：满意度等级评分【推荐：如 1-5 级；用户未明确形式】。
- 系统记录评价人、评价时间、评价结果【推荐】。
- 每个工单评价一次，提交后不可修改【推荐】。
- 评价结果供满意度指标统计使用（见 5.6.2）。

### 5.6 统计分析

#### 5.6.1 维度分布统计

- 支持按公司维度统计工单分布。
- 支持按部门维度统计工单分布；部门口径为提交人所属部门【推荐】。

#### 5.6.2 统计与分析仪表盘

- 展示运营指标：工单量、平均响应时间、满意度、热点问题。
- 指标口径【推荐】：
  - 平均响应时间 = 统计范围内工单「创建 → 首条回复」时长的平均值；
  - 满意度 = 基于满意度评价结果的聚合（如平均分）；
  - 热点问题 = 按问题分类聚合的工单量排名。
- 指标随所选公司/部门维度联动【推荐】。
- 仪表盘与统计的访问角色、权限【未规定】。

### 5.7 工单工作台

- 展示待处理工单列表。
- 支持筛选、搜索、排序。
- 支持按公司维度筛选；该能力对可访问多公司工单数据的用户生效，跨公司访问的角色【未规定】（与 5.1.4 公司隔离并存：普通用户默认仅见本公司工单）。
- 搜索与排序字段范围【推荐】：关键字命中主题/工单ID；排序支持创建时间、优先级等。

### 5.8 操作日志

- 系统记录工单相关操作日志。
- 记录范围【推荐闭合：覆盖工单关键操作】：创建、分配、转派、回复、状态变更、处理完成、取消、满意度评价。
- 每条日志记录操作类型、操作人、操作时间、关联工单【推荐】。
- 日志查看入口、导出与保留周期【未规定】。

## 6. 验收场景

### AC-01：提交人创建工单并完整记录工单信息
- 验收条件：提交人创建工单后，系统生成唯一工单ID并完整记录主题、描述、问题分类、SLA优先级（P0-P4）、提交人信息（姓名、邮箱、公司、部门）和创建时间，全部信息可读回。
- 入口类型：用户界面
- 验证动作：以某公司用户身份进入工单创建入口，填写主题与描述，选择问题分类和 SLA 优先级（如 P1），提交后打开该工单详情。
- 预期结果：系统生成工单ID；详情页可完整读回主题、描述、分类、优先级、提交人姓名与邮箱、公司、部门、创建时间；工单处于生命周期起点状态（创建，随后进入待分配，见 AC-04）。
- 证据类型：runtime-render, interaction, session-persistence
- 共享流程组：ticket-lifecycle

### AC-02：工单按公司隔离
- 验收条件：用户仅能查看与操作本公司工单，无法通过列表、搜索或直接访问获取其他公司的工单。
- 入口类型：用户界面
- 验证动作：公司A用户创建至少一张工单；切换为公司B用户登录，在工单列表与工作台中搜索该工单主题/工单ID，并尝试直接打开其详情。
- 预期结果：公司B用户的列表、搜索结果不包含公司A的工单；直接访问公司A工单详情被拒绝（提示无权限或不存在）。
- 证据类型：authorization, error-feedback

### AC-03：工单多轮回复
- 验收条件：工单参与人可进行多轮回复，每条回复记录回复人与回复时间，回复序列按时间顺序可读回。
- 入口类型：用户界面
- 验证动作：在一张已分配的工单详情中，先由处理人提交一条回复，再由提交人提交一条回复，重复两轮后查看回复列表。
- 预期结果：全部回复按提交时间顺序展示；每条回复显示对应回复人与回复时间；可继续追加新回复。
- 证据类型：interaction, session-persistence
- 共享流程组：ticket-lifecycle

### AC-04：工单生命周期状态流转
- 验收条件：工单状态沿「创建→待分配→待处理→完成」主路径流转，未完成工单可取消；「完成」「取消」为终态不可再变更。
- 入口类型：用户界面
- 验证动作：创建工单并观察初始状态；完成分配使其进入待处理；执行处理完成操作观察状态；另建一张工单执行取消；对已完成的工单尝试执行转派或再次完成。
- 预期结果：状态依次呈现创建、待分配、待处理、完成；取消工单状态变为取消；对终态工单的状态变更与转派操作被拒绝；各状态变更在工单上可见。
- 证据类型：runtime-render, interaction, error-feedback
- 共享流程组：ticket-lifecycle

### AC-05：业务组管理与按分类自动分配
- 验收条件：可为公司创建多个业务组并设置成员；配置分类分配规则后，该公司新工单按分类自动分配到对应业务组并进入待处理状态。
- 入口类型：用户界面
- 验证动作：为公司创建两个业务组并分别为其添加成员；配置"分类X→业务组1"的分配规则；以该公司提交人创建一张分类X工单，查看工单归属。
- 预期结果：两个业务组创建成功且成员可见；新工单被自动分配到业务组1（而非业务组2），状态变为待处理，归属业务组在工单详情中可查。
- 证据类型：interaction, session-persistence
- 共享流程组：ticket-lifecycle

### AC-06：工单转派
- 验收条件：处理人可将待处理工单转派到其他业务组；转派后工单归属变更为目标业务组，转派记录可追溯。
- 入口类型：用户界面
- 验证动作：在已分配到业务组1的待处理工单上执行转派，选择业务组2为目标并确认；查看工单详情的归属与操作记录。
- 预期结果：工单归属变更为业务组2，状态仍为待处理；转派记录（转派人、目标业务组、时间）可查；业务组2可继续处理该工单。
- 证据类型：interaction, session-persistence
- 共享流程组：ticket-processing

### AC-07：工单处理记录与提交人完整信息
- 验收条件：处理人处理工单时可查看提交人完整信息（姓名、公司、部门、历史工单）；完成处理后系统记录处理人与处理时间。
- 入口类型：用户界面
- 验证动作：以提交人先提交两张及以上工单；处理人打开其中一张待处理工单，查看提交人信息面板；执行完成处理后查看工单处理记录。
- 预期结果：信息面板展示提交人姓名、公司、部门及其历史工单列表；完成后工单记录处理人（当前操作用户）与处理时间（当前时刻附近），状态变为完成。
- 证据类型：runtime-render, interaction, session-persistence
- 共享流程组：ticket-processing

### AC-08：工单完成邮件通知
- 验收条件：工单完成时系统自动向提交人邮箱发送完成通知邮件，通知内容可识别对应工单。
- 入口类型：后台任务
- 验证动作：完成一张已知提交人邮箱的工单，随后查询系统的邮件发送记录。
- 预期结果：存在一条发往该提交人邮箱的完成通知记录；邮件内容包含可识别该工单的信息（如工单ID或主题）；未完成的工单不产生完成通知。
- 证据类型：other（邮件发送记录）

### AC-09：满意度评价
- 验收条件：工单完成后提交人可提交满意度评价，评价结果被记录并计入满意度统计。
- 入口类型：用户界面
- 验证动作：提交人打开一张已完成的本人工单，选择满意度等级并提交评价；再次查看该工单并尝试重复提交评价。
- 预期结果：评价提交成功，工单上可见评价结果与评价人/评价时间；重复提交同一工单的评价被拒绝。
- 证据类型：interaction, session-persistence, error-feedback

### AC-10：统计分布与运营仪表盘
- 验收条件：统计分析支持按公司、部门维度查看工单分布；仪表盘展示工单量、平均响应时间、满意度、热点问题运营指标，数值与底层数据一致。
- 入口类型：用户界面
- 验证动作：准备跨两家公司、多个部门、多个分类的工单数据（含回复与评价）；打开统计/仪表盘页面，分别切换公司维度与部门维度。
- 预期结果：分布统计随所选维度变化且与实际工单数据一致（各公司/各部门工单数正确）；仪表盘展示工单量、平均响应时间、满意度、热点问题四类指标，数值与底层数据一致。
- 证据类型：runtime-render

### AC-11：工单工作台
- 验收条件：工作台展示待处理工单列表，筛选、搜索、排序与按公司筛选可组合使用并正确收敛列表结果。
- 入口类型：用户界面
- 验证动作：在工作台待处理列表中，分别执行按分类/优先级筛选、按主题关键字搜索、按创建时间排序、按公司维度筛选，并组合上述条件。
- 预期结果：列表仅展示满足全部所选条件的待处理工单；搜索能命中主题关键字；排序按所选字段有序；按公司筛选后仅显示所选公司的工单。
- 证据类型：interaction, runtime-render

### AC-12：工单操作日志
- 验收条件：系统对工单关键操作记录日志，日志包含操作类型、操作人、操作时间与关联工单，与实际操作一致。
- 入口类型：内部
- 验证动作：执行一轮完整工单操作（创建→分配→回复→转派→完成→评价），随后查询系统日志数据。
- 预期结果：每个关键操作均有对应日志记录；日志的操作人、时间、关联工单与实际执行一致；无对应操作时不产生日志。
- 证据类型：other（日志数据）

## 7. 推荐基线与未规定事项

### 7.1 推荐基线（保守默认，用户可调整）

| 编号 | 推荐内容 | 闭合目的 |
|---|---|---|
| RB-01 | 优先级次序 P0 最高、P4 最低 | 优先级语义可用 |
| RB-02 | 状态流转：创建→待分配→待处理→完成；创建/待分配/待处理可取消；完成/取消为终态 | 用户给出状态集合但未给出流转规则 |
| RB-03 | 提交人信息包含公司、部门 | 公司隔离与部门统计的必要数据 |
| RB-04 | 分配规则无匹配时保持待分配，可手动分配 | 自动分配失败的兜底路径 |
| RB-05 | 转派目标为业务组，记录转派人/目标/时间 | 转派可观察、可追溯 |
| RB-06 | 完成通知收件人为提交人，邮件内容可识别工单 | 邮件通知可验收 |
| RB-07 | 满意度采用等级评分（如 1-5 级），每单一次、不可修改 | 评价形式与统计口径可用 |
| RB-08 | 平均响应时间 =「创建→首条回复」时长的平均值 | 仪表盘指标口径 |
| RB-09 | 热点问题 = 按问题分类聚合的工单量排名 | 仪表盘指标口径 |
| RB-10 | 日志覆盖创建/分配/转派/回复/状态变更/完成/取消/评价，含操作人/时间/关联工单 | "记录相关日志"的可观察闭合 |
| RB-11 | 历史工单按创建时间倒序展示 | 提交人信息可读性 |
| RB-12 | 终态（完成/取消）工单不可转派、不可评价未完成工单 | 生命周期一致性 |
