# k11-robot 设备管理平台需求

## 1. 需求目标

开发一套设备管理平台（k11-robot），支持对 K11 机器人设备的全生命周期管理。用户明确提出以下功能：

- **设备状态监测**：实时查看设备运行状态
- **故障诊断**：识别和记录设备故障，记录诊断结果
- **远程升级**：对设备发起远程升级并跟踪结果
- **维修工单**：管理设备维修工单的创建与处理
- **设备履历**：记录和追溯设备完整生命周期信息
- **数据库存储**：所有业务数据需持久化存储

### 推荐基线

以下为闭合核心目标所必需的最小补充，用户未明确提出：

- **设备登记**：状态监测、故障诊断、远程升级和设备履历均以设备为操作对象，系统需支持设备信息的登记与基本管理，否则其他模块无法关联到具体设备。此项为必要前提，非独立功能目标。
- **数据持久化可读回性**：用户明确要求数据库存储，所有模块写入的数据在会话结束后应可通过相应读取行为读回。此处描述为可观察的持久化行为，不指定具体数据库技术选型。

### 未规定事项

- 用户角色、权限体系与服务对象未规定
- 技术栈、部署平台和数据库选型未规定
- 设备类型范围和故障分类体系未规定
- 升级协议和设备通信方式未规定
- 系统并发规模和性能指标未规定

## 2. 用户旅程

### 2.1 设备登记与状态监测

1. 用户在系统中登记新设备，录入设备基本信息（设备编号、名称、型号等）
2. 系统为设备建立档案，设备进入可监测状态
3. 用户查看设备列表，选择具体设备查看当前运行状态
4. 设备状态变更时，系统更新并展示最新状态

### 2.2 故障诊断与维修

1. 设备出现异常，系统记录故障信息（故障设备、故障描述、发生时间等）
2. 用户查看故障详情，进行故障诊断，记录诊断结果
3. 基于故障情况，创建维修工单
4. 工单被接收并处理，记录维修过程和结果
5. 维修完成后关闭工单，设备状态恢复

### 2.3 远程升级

1. 用户选择目标设备，发起远程升级任务
2. 系统向设备推送升级内容，跟踪升级进度
3. 升级完成后，系统记录升级结果并更新设备履历
4. 升级失败时，系统记录失败原因

### 2.4 设备履历查询

1. 用户选择设备，查看设备完整履历
2. 履历展示设备从登记以来的所有关键事件：状态变更、故障记录、升级记录、维修记录
3. 用户可按事件类型筛选查看

## 3. 模块需求

### 3.1 设备管理（推荐基线）

此模块为其他模块的必要前提，非用户独立提出的功能目标。

- 支持设备登记，录入设备编号、名称、型号等基本信息
- 支持设备列表查看和单个设备详情查看
- 支持设备信息编辑
- 设备删除后，关联的履历数据应保留可追溯

### 3.2 设备状态监测

- 实时展示设备当前运行状态
- 支持按状态筛选设备列表
- 状态变更时更新设备状态记录
- 支持查看设备状态变更历史

### 3.3 故障诊断

- 支持记录设备故障信息：关联设备、故障描述、发生时间
- 支持查看故障列表和故障详情
- 支持记录故障诊断结果和处理建议
- 支持将故障关联到维修工单
- 故障可标记处理状态（如：待诊断、已诊断、已解决），具体状态值由实现确定

### 3.4 远程升级

- 支持创建远程升级任务：选择目标设备、指定升级内容
- 支持查看升级任务列表和详情
- 支持跟踪升级进度和状态（如：待升级、升级中、成功、失败），具体状态值由实现确定
- 升级完成后自动记录到设备履历
- 升级失败时记录失败原因

### 3.5 维修工单

- 支持创建维修工单：关联设备、描述维修原因、设定优先级
- 工单支持状态流转（如：待处理 → 处理中 → 已完成 → 已关闭），具体状态值由实现确定
- 支持记录维修过程信息：维修内容、更换零件、维修时间
- 支持工单列表查看和按状态筛选
- 工单完成后自动记录到设备履历

### 3.6 设备履历

- 自动汇聚设备全生命周期事件：设备登记、状态变更、故障记录、升级记录、维修记录
- 支持按设备查看完整履历，按时间倒序展示
- 履历记录由各模块自动写入，不可手动修改
- 支持按事件类型筛选履历记录

### 3.7 数据持久化

- 所有模块的业务数据通过数据库持久化存储
- 写入的数据在会话结束后可通过相应读取行为读回
- 设备履历数据基于其他模块的写入数据自动汇聚

## 4. 验收标准

### AC-01：设备登记与状态监测

- 验收条件：用户可登记设备并查看设备运行状态。
- 入口类型：用户界面
- 验证动作：登记一台新设备，录入设备编号和名称；在设备列表中找到该设备并查看其状态。
- 预期结果：设备成功登记并出现在设备列表中；可查看设备当前运行状态。
- 证据类型：runtime-render, interaction

### AC-02：故障诊断

- 验收条件：用户可记录设备故障并进行诊断。
- 入口类型：用户界面
- 验证动作：对已登记设备创建一条故障记录，填写故障描述；查看故障详情并记录诊断结果。
- 预期结果：故障记录成功创建并出现在故障列表中；诊断结果可保存并查看。
- 证据类型：runtime-render, interaction

### AC-03：远程升级

- 验收条件：用户可对设备发起远程升级并跟踪结果。
- 入口类型：用户界面
- 验证动作：选择已登记设备，创建远程升级任务；查看升级任务状态和进度。
- 预期结果：升级任务成功创建并出现在升级任务列表中；可查看升级任务的当前状态。
- 证据类型：runtime-render, interaction

### AC-04：维修工单

- 验收条件：用户可创建维修工单并完成工单状态流转。
- 入口类型：用户界面
- 验证动作：对已登记设备创建维修工单；将工单状态流转至已完成；记录维修内容。
- 预期结果：工单成功创建并可查看；工单状态可流转并保存；维修内容可记录并查看。
- 证据类型：runtime-render, interaction

### AC-05：设备履历

- 验收条件：设备履历自动汇聚全生命周期事件，可按设备查看。
- 入口类型：用户界面
- 验证动作：对一台已有故障记录和维修记录的设备，查看其设备履历。
- 预期结果：履历页面展示设备的登记、故障、维修等事件记录，按时间倒序排列。
- 证据类型：runtime-render

### AC-06：数据持久化

- 验收条件：所有业务数据通过数据库持久化存储，写入后可读回。
- 入口类型：内部
- 验证动作：创建设备、故障、升级任务、维修工单等数据后，重新加载页面或重新进入系统查看对应数据。
- 预期结果：所有已创建的数据在重新加载后仍然存在并可正常读取。
- 证据类型：session-persistence
