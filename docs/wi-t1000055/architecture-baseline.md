# 架构基线：贪吃蛇游戏（175-snake）

> 批准的需求基线：`docs/wi-t1000055/requirements.md`（SHA-256 已校验）

## 1. 页面与交互范围

单页面 React/Vite SPA，一个画布占据主要视口区域，旁边显示当前分数与游戏结束提示。

交互范围：

- 方向输入（键盘方向键 / WASD）改变蛇移动方向；游戏运行期间蛇按当前方向持续自动移动。
- 蛇吃到食物后身体增长一节、分数增加，新食物在空白格随机生成。
- 蛇头碰到边界或自身时游戏结束，界面显示最终得分。
- 游戏结束后通过按键或按钮重新开始，恢复初始短蛇、零分。

## 2. 浏览器状态与数据归属

全部游戏状态——蛇身坐标队列、移动方向、食物位置、分数、运行/结束标志——驻留在浏览器内存中的 React 组件 state 内，不写入 `localStorage` 或任何服务端存储。数据生命周期限定于当前页面会话；刷新或关闭页面后状态清空。需求未要求跨页面、跨设备或跨用户持久化，因此不需要持久层。

## 3. 实现入口与运行方式

- **框架**：React 18 + Vite，TypeScript。
- **渲染**：Canvas 2D API 绘制游戏区域、蛇身和食物；使用 `requestAnimationFrame` 驱动游戏循环，以固定时间步长推进蛇的移动。
- **目录结构**（精简，3 个核心文件）：
  - `src/engine.ts` — 纯函数游戏引擎：状态类型定义、方向常量、`step`（推进一步）、`spawnFood`（随机生成食物）、碰撞检测。
  - `src/App.tsx` — React 组件：管理游戏状态、Canvas 绘制、键盘输入、游戏循环、分数显示与重新开始。
  - `src/main.tsx` — Vite 入口，挂载 `App` 到 `#root`。
- **运行方式**：`npm run dev` 启动 Vite 开发服务器；`npm run build` 生产构建。

## 4. 渲染与游戏循环

- Canvas 网格化：固定列数 × 行数（如 20×20），每格等比例像素。
- `requestAnimationFrame` 循环累积时间，达到步长间隔（如 120ms）时调用 `engine.step` 更新状态，随后重绘 Canvas。
- 蛇身用队列结构存储格子坐标，头部入队、尾部出队（吃食物时不出队）。

## 5. 确定性验证支持

以下验证控制入口仅用于测试环境，正常运行不暴露：

- AC-01 涉及随机食物生成：通过测试钩子固定食物位置（`setFood`），避免随机性阻塞验证。
- AC-01 / AC-02 涉及自动推进与动画：通过测试钩子手动推进单步（`step`），不依赖 `requestAnimationFrame` 时序。
- AC-03 涉及状态重置：通过测试钩子读取状态（`getState`）确认蛇长与分数归零。

实现时在测试环境通过 `window.__snakeTest`（或等价命名空间）暴露 `step`、`setFood`、`getState` 三个最小控制入口；生产构建不包含此钩子或将其设为 no-op。
