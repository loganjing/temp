# 设备管理平台需求（k14-robot）

## 1. 目标

为 JLG 机器人/设备构建统一的设备管理平台，覆盖设备状态监测、故障诊断、远程升级、维修工单和设备履历五大功能，所有业务数据通过数据库持久化存储，确保写入后可读回。

> 项目名：jlgrobot。本需求为初始构建基线。

## 2. 用户明确提出的要求

以下为任务描述中用户明确提出的核心目标，不做扩展推断：

1. **设备状态监测**：对设备运行状态进行监测。
2. **故障诊断**：对设备故障进行诊断。
3. **远程升级**：对设备进行远程升级。
4. **维修工单**：管理维修工单。
5. **设备履历**：记录并查看设备履历。
6. **数据库存储**：业务数据需通过数据库存储。

## 3. 推荐基线与未规定事项

| 事项 | 来源 | 说明 |
|------|------|------|
| 数据库存储 | 用户明确提出 | 明确要求持久化存储，不指定具体数据库产品与技术选型 |
| 设备状态数据来源 | 未规定 | 设备主动上报或平台主动采集均可满足核心验收，不指定 |
| 远程升级对象 | 未规定 | 固件或软件包升级均可满足核心验收，不指定包类型 |
| 故障诊断方式 | 未规定 | 自动诊断或人工辅助诊断均可满足核心验收，不指定算法 |

| 产品载体（Web/桌面/移动） | 未规定 | 用户未指定终端形态，验收入口标为"用户界面"，不推断页面布局与设备适配 |

## 4. 核心行为与规则

### 4.1 设备状态监测

- 系统应能记录设备的状态信息，至少包含设备标识、状态（如在线/离线/运行中/故障）及关键运行参数。
- 状态记录写入数据库后，可通过设备标识查询其当前与历史状态。
- 操作人员可在用户界面查看设备状态列表与单个设备的状态详情。

### 4.2 故障诊断

- 系统应能记录设备故障事件，至少包含故障设备、故障描述、发生时间、故障状态。
- 故障状态支持流转，至少包含"已记录—诊断中—已诊断—已关闭"。
- 诊断信息（诊断结论、处理建议）可写入并随故障事件读回。
- 操作人员可在用户界面查看故障列表与故障详情，并推进故障状态。

### 4.3 远程升级

- 系统应能向指定设备发起远程升级任务，至少包含目标设备、升级包标识、升级状态。
- 升级状态支持流转，至少包含"待执行—执行中—成功—失败"。
- 升级结果可写入并读回，失败时记录失败原因。
- 操作人员可在用户界面发起升级、查看升级任务列表与状态详情。

### 4.4 维修工单

- 系统应能创建维修工单，至少关联设备，包含工单描述、工单状态。
- 工单状态支持流转，至少包含"待处理—处理中—已完成—已关闭"。
- 工单可关联故障事件（可选），处理记录可写入并读回。
- 操作人员可在用户界面创建工单、查看工单列表与详情、推进工单状态。

### 4.5 设备履历

- 系统应能按设备汇聚其历史记录，至少包含状态变更、故障事件、升级任务、维修工单。
- 履历信息来源于上述各模块已持久化的数据，按时间顺序呈现。
- 操作人员可在用户界面按设备查看其完整履历。

### 4.6 数据持久化

- 所有模块的业务数据（设备、状态、故障、升级任务、工单及履历关联数据）均写入数据库。
- 任何写入操作成功后，通过对应的读取行为可读回该数据。

## 5. 验收场景

### AC-01：设备状态可监测并查看
- 验收条件：系统记录设备状态并持久化，操作人员可在界面查看设备当前与历史状态。
- 入口类型：用户界面
- 验证动作：记录一条设备状态后，在设备状态界面按设备标识查询。
- 预期结果：列表与详情中可读到该设备的状态及关键参数。
- 证据类型：runtime-render, interaction, session-persistence

### AC-02：故障事件可记录、诊断并流转
- 验收条件：故障事件写入数据库，支持诊断信息记录与状态流转，可读回。
- 入口类型：用户界面
- 验证动作：记录一条故障事件，填写诊断结论，将状态从"已记录"推进至"已关闭"，随后查看故障详情。
- 预期结果：故障详情中可读到故障描述、诊断结论及完整状态流转记录。
- 证据类型：runtime-render, interaction, session-persistence

### AC-03：远程升级可发起并跟踪结果
- 验收条件：可向设备发起远程升级任务，升级状态可流转，结果与失败原因可读回。
- 入口类型：用户界面
- 验证动作：对指定设备发起一次升级任务，将其状态推进至"成功"或"失败"，随后查看升级任务详情。
- 预期结果：升级任务详情中可读到目标设备、升级包标识、最终状态；失败时可读到失败原因。
- 证据类型：runtime-render, interaction, session-persistence

### AC-04：维修工单可完整流转
- 验收条件：维修工单创建后写入数据库，支持状态流转与处理记录，可读回。
- 入口类型：用户界面
- 验证动作：创建一张关联设备的维修工单，填写处理记录，将状态从"待处理"推进至"已关闭"，随后查看工单详情。
- 预期结果：工单详情中可读到关联设备、工单描述、处理记录及完整状态流转。
- 证据类型：runtime-render, interaction, session-persistence

### AC-05：设备履历汇集设备历史记录
- 验收条件：按设备查看履历时，可读到该设备的状态、故障、升级、工单历史记录。
- 入口类型：用户界面
- 验证动作：在已存在状态、故障、升级、工单数据的前提下，按设备查看其履历。
- 预期结果：履历页面按时间顺序呈现该设备的状态变更、故障事件、升级任务与维修工单记录。
- 证据类型：runtime-render, session-persistence

### AC-06：业务数据持久化存储
- 验收条件：所有模块的业务数据写入数据库，写入后可通过对应读取行为读回。
- 入口类型：内部
- 验证动作：对各模块分别执行一次写入与读取。
- 预期结果：每次写入成功后，对应读取可返回刚写入的数据。
- 证据类型：session-persistence
