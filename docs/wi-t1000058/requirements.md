# 工单管理系统需求（ticket-1）

> Work Item: wi-t1000058 · 阶段：requirements
> 来源标注约定：【用户】= 用户明确提出；【推荐】= 为闭合核心目标补充的最小推荐基线；其余开放项见第 6 节。

## 1. 目标

面向多公司客户的服务支持场景，提供工单从提交、分配、处理、协作转派到完成评价的完整闭环管理。【用户】

## 2. 用户与范围

用户明确提出的使用方：

- **提交人**：创建工单、提供含邮箱的提交人信息、参与多轮回复、收到处理完成的工单后进行满意度评价。【用户】
- **处理人**：业务组成员，接收分配的工单，查看提交人完整信息并处理工单，完成后留下处理记录。【用户】

范围外（已确认排除项）：用户未提出任何明确排除项。
业务组、成员与分配规则由谁维护（操作者角色与权限）保持未规定（见第 6 节）。

## 3. 核心对象与业务规则

### 3.1 工单

工单包含以下信息，创建成功后可通过查看行为读回全部字段：【用户】

| 信息项 | 说明 |
| --- | --- |
| 工单ID | 每张工单具有唯一标识（生成规则未规定） |
| 主题 | 工单标题 |
| 描述 | 问题详细描述 |
| 分类 | 所属问题分类（具体分类值列表未规定） |
| 提交人信息 | 含提交人姓名、邮箱 |
| 创建时间 | 工单创建时系统记录 |
| SLA 优先级 | P0–P4 五级，创建工单时设置（后续是否可调整未规定） |

### 3.2 工单回复

- 工单支持多轮回复，提交人与处理方均可发起回复。【用户】
- 每轮回复记录：回复人、回复时间、回复内容。【用户】
- 回复按时间先后排列，在工单上可读。

### 3.3 状态生命周期

状态集合：**创建、待分配、待处理、完成、取消**。【用户】

流转规则：

- 工单录入保存后处于"创建"状态，进入分配环节；
- 若该公司配置了匹配该分类的自动分配规则，工单自动归属对应业务组，进入"待处理"；【用户】
- 若无匹配规则，工单停留"待分配"，可通过分配操作归属某业务组后进入"待处理"。【推荐：无匹配规则时的最小闭合，否则"待分配"不可达后续状态】
- "待处理"工单处理完成后进入"完成"；【用户】
- 工单在完成前（创建、待分配、待处理）可被取消，取消后生命周期终止。【推荐：取消入口的最小闭合】

### 3.4 公司、业务组与成员

- 一个公司可拥有多个业务组。【用户】
- 每个业务组可设置成员，业务组成员即处理该公司工单的候选处理人。【用户】

### 3.5 工单分配（自动）

- 公司可配置"问题分类 → 业务组"的自动分配规则。【用户】
- 配置后，该公司新创建的该分类工单按规则自动分配到对应业务组。【用户】

### 3.6 工单转派（协作）

- 处于"待处理"的工单可执行转派。【用户】
- 转派目标为其他业务组或其成员。【推荐：转派目标缺口的最小闭合】
- 转派后工单状态保持"待处理"，归属变更为转派目标。【推荐】
- 转派操作留有记录：转派人、转派时间、转派目标。【推荐：转派可观察、可追溯的最小闭合】

### 3.7 工单处理

- 处理人处理工单时，可查看提交人的完整信息：姓名、公司、部门、历史工单（该提交人既往创建的工单列表）。【用户】
- 处理完成后记录：处理人、处理时间、工单状态，工单状态更新为"完成"。【用户】

### 3.8 满意度评价

- 工单完成后（提交人收到处理完成的工单后），提交人可对该工单进行满意度评价。【用户】
- 评价提交成功后与工单关联，评价结果可读回。【用户】
- 评价量表的具体形式（等级/分值等）未规定，验收按"提交一个满意度评价结果并可读回"的最小语义执行。

## 4. 端到端旅程

1. 提交人创建工单，填写主题、描述、分类，设置 P0–P4 优先级，提交人信息含姓名与邮箱，系统记录创建时间与唯一工单ID。
2. 工单进入分配环节：该公司已配置该分类的自动分配规则时，自动归属对应业务组并进入"待处理"；否则停留"待分配"，经分配操作归属业务组。
3. 业务组成员（处理人）处理工单：查看提交人完整信息（姓名、公司、部门、历史工单），与提交人多轮回复沟通，每轮记录回复人与回复时间。
4. 处理过程中如需协作，可将工单转派至其他业务组或其成员，转派留有记录。
5. 处理完成后记录处理人与处理时间，工单状态更新为"完成"。
6. 提交人收到处理完成的工单后进行满意度评价，评价与工单关联可查。
7. 完成前的任一状态（创建、待分配、待处理），工单可被取消，生命周期终止。

## 5. 验收场景

### AC-01：提交人可创建工单并读回完整信息

- 验收条件：新工单包含工单ID、主题、描述、分类、提交人姓名与邮箱、创建时间和 P0–P4 优先级；创建成功后可读回全部字段。
- 入口类型：用户界面
- 验证动作：以提交人身份新建工单，填写主题与描述、选择问题分类与优先级（如 P2），提交人信息含姓名与邮箱；提交后打开该工单详情查看。
- 预期结果：工单创建成功并生成唯一工单ID，记录创建时间；详情中可读回主题、描述、分类、优先级（P0–P4）、提交人姓名与邮箱、创建时间。
- 证据类型：runtime-render, interaction, session-persistence

### AC-02：工单生命周期状态流转与处理记录正确

- 验收条件：工单按 创建→待分配→待处理→完成 流转；完成时记录处理人、处理时间与最终状态；未完成状态可取消。
- 入口类型：用户界面
- 验证动作：创建一张无自动分配规则命中的工单，确认处于"待分配"；执行分配操作使其归属某业务组；处理完成后查看状态与处理记录。另创建一张工单，在未完成状态下执行取消。
- 预期结果：分配后工单状态为"待处理"且归属该业务组；完成处理后状态为"完成"，可查到处理人与处理时间；取消后状态为"取消"，不再进入处理流程。
- 证据类型：runtime-render, interaction, session-persistence

### AC-03：工单支持多轮回复并记录回复人与回复时间

- 验收条件：提交人与处理方可在同一工单下进行多轮（不少于两轮）回复，每轮记录回复人与回复时间，按时间顺序可读。
- 入口类型：用户界面
- 验证动作：在一张已分配的工单下，处理人回复一次，提交人再回复一次，随后查看该工单的回复记录。
- 预期结果：两条回复按时间先后排列，各自显示回复人身份与回复时间，内容与提交内容一致。
- 证据类型：runtime-render, interaction, session-persistence

### AC-04：公司可维护多个业务组及其成员

- 验收条件：可为同一公司添加多个业务组，并为每个业务组设置成员，配置结果可读回。
- 入口类型：用户界面
- 验证动作：为某公司新建两个业务组（如"网络组"与"账务组"），分别添加成员，保存后查看该公司的业务组列表。
- 预期结果：该公司业务组列表包含两个新建业务组，各业务组的成员与所配置一致。
- 证据类型：runtime-render, interaction, session-persistence

### AC-05：工单按分类自动分配到业务组

- 验收条件：公司配置"分类→业务组"规则后，该公司新创建的该分类工单自动归属对应业务组并进入"待处理"，无需人工分配。
- 入口类型：用户界面
- 验证动作：为某公司配置"分类A→业务组G"的自动分配规则；以该公司提交人身份创建分类A的工单，随后查看工单归属与状态。
- 预期结果：新工单自动归属业务组G，状态为"待处理"。
- 证据类型：runtime-render, interaction, session-persistence

### AC-06：待处理工单可转派并留有记录

- 验收条件：待处理工单可转派至其他业务组或其成员；转派后归属变更、状态保持"待处理"，且留有转派记录（转派人、转派时间、转派目标）。
- 入口类型：用户界面
- 验证动作：在一张"待处理"工单上执行转派，选择另一个业务组（或其成员）作为目标；随后查看工单归属、状态与转派记录。
- 预期结果：工单归属变更为转派目标，状态仍为"待处理"；转派记录可查，包含转派人、转派时间与转派目标。
- 证据类型：runtime-render, interaction, session-persistence

### AC-07：处理人可查看提交人完整信息

- 验收条件：处理工单时，处理人可查看提交人的姓名、公司、部门及其历史工单。
- 入口类型：用户界面
- 验证动作：处理人打开一张"待处理"工单，查看提交人信息区域及其历史工单列表。
- 预期结果：可见提交人姓名、公司、部门，以及该提交人既往创建的工单列表。
- 证据类型：runtime-render, interaction

### AC-08：工单完成后提交人可进行满意度评价

- 验收条件：工单完成后，提交人可对该工单提交满意度评价；评价结果与该工单关联并可读回。
- 入口类型：用户界面
- 验证动作：工单完成后，提交人打开该工单并提交满意度评价；随后查看该工单的评价结果。
- 预期结果：评价提交成功，该工单上可读回对应的满意度评价结果。
- 证据类型：runtime-render, interaction, session-persistence

## 6. 未规定事项（保持开放，不构成当前基线）

- 工单ID的生成规则；问题分类的预定义值列表。
- 业务组、成员与分配规则维护功能的操作者角色与权限模型。
- 优先级创建后是否可调整；SLA 时限与超时处理规则（用户仅要求 P0–P4 优先级设置，未提出时限承诺）。
- 满意度评价的量表形式及评价提交后是否可修改。
- 多轮回复是否触发状态变化或通知；回复内容的附件支持。
- 取消工单的操作者与取消原因是否必填。
