# 工单系统需求基线

## 1. 目标

构建一个按公司隔离的工单系统，支持工单从创建、分配、处理到完成/取消的完整生命周期，覆盖工单分配与转派协作、处理与邮件通知、用户满意度评价、统计分析仪表盘和工单工作台。

## 2. 角色与权限

以下角色由用户描述的功能行为中提取，用于说明各模块的操作主体：

| 角色 | 说明 | 来源 |
|------|------|------|
| 提交人 | 创建工单的用户，可查看自己提交的工单并进行满意度评价 | 用户明确提出 |
| 处理人 | 业务组成员，接收并处理工单，可转派工单 | 用户明确提出 |
| 管理员 | 为公司配置业务组、成员和自动分配规则 | 用户明确提出（功能点要求"允许给某个公司增加多个业务组"） |

权限边界：
- 工单按公司隔离：用户只能查看和操作本公司工单（用户明确提出）。
- 提交人可查看自己提交的工单；处理人可查看分配到本业务组的工单（推荐基线——用户仅说明工单按公司隔离，未细化到个人/业务组级别的可见性规则，此处推荐公司内按角色可见）。

## 3. 实体与状态

### 3.1 工单

| 属性 | 说明 |
|------|------|
| 工单ID | 唯一标识 |
| 主题 | 工单标题 |
| 描述 | 工单详情 |
| 分类 | 问题分类 |
| SLA优先级 | P0 / P1 / P2 / P3 / P4 |
| 提交人信息 | 姓名、邮箱、公司、部门 |
| 创建时间 | 工单创建时记录 |
| 处理人 | 处理工单的人员 |
| 处理时间 | 工单处理完成时间 |
| 状态 | 创建 / 待分配 / 待处理 / 完成 / 取消 |

### 3.2 工单回复

- 支持多轮回复，每轮记录回复人和回复时间（用户明确提出）。

### 3.3 业务组

- 属于某个公司，可设置成员（用户明确提出）。
- 一个公司可有多个业务组。

### 3.4 分配规则

- 按工单分类自动分配到某公司的某个业务组（用户明确提出）。

### 3.5 用户评价

- 提交人在工单完成后进行满意度评价（用户明确提出）。

### 3.6 操作日志

- 记录工单相关操作日志（用户明确提出）。

### 3.7 工单生命周期

```
创建 → 待分配 → 待处理 → 完成
                ↓         ↓
              转派      取消
```

| 状态 | 说明 | 来源 |
|------|------|------|
| 创建 | 工单刚创建，尚未分配 | 用户明确提出 |
| 待分配 | 等待分配到业务组或处理人 | 用户明确提出 |
| 待处理 | 已分配，等待或正在处理 | 用户明确提出 |
| 完成 | 工单已处理完成，触发邮件通知 | 用户明确提出 |
| 取消 | 工单被取消 | 用户明确提出 |

状态流转规则：
- 创建后进入待分配（用户明确提出）。
- 自动分配规则命中后，工单从待分配流转到待处理（用户明确提出）。
- 工单完成时记录处理人和处理时间，发送邮件通知提交人（用户明确提出）。
- 工单可被取消（用户明确提出）。取消的具体触发者和条件用户未规定，保持未规定。

## 4. 核心流程

### 旅程 1：工单创建与自动分配

1. 提交人填写工单主题、描述、分类和SLA优先级，提交创建。
2. 系统记录提交人信息（姓名、邮箱、公司、部门）和创建时间，工单进入待分配状态。
3. 系统根据该公司该分类的分配规则，自动将工单分配到对应业务组，工单进入待处理状态。
4. 若无匹配分配规则，工单保持在待分配状态，等待手动分配（推荐基线——用户要求自动分配但未说明未匹配时的行为）。

### 旅程 2：工单处理与转派

1. 处理人在工单工作台看到待处理工单。
2. 处理人打开工单详情，查看提交人完整信息（姓名、公司、部门、历史工单）。
3. 处理人通过多轮回复与提交人沟通。
4. 若需其他业务组处理，处理人执行转派操作，工单流转到目标业务组的待处理状态。
5. 处理人处理完成后，将工单标记为完成，系统记录处理人和处理时间，发送邮件通知提交人。

### 旅程 3：用户评价

1. 提交人收到工单完成通知后，进入工单进行满意度评价。
2. 评价提交后与工单关联保存。

### 旅程 4：统计分析

1. 管理员或处理人查看统计分析仪表盘。
2. 可按公司、部门维度查看工单分布。
3. 仪表盘展示工单量、平均响应时间、满意度、热点问题等运营指标。

## 5. 模块需求

### 5.1 工单管理

- 创建工单时必填：主题、描述、分类、SLA优先级（P0-P4）。
- 提交人信息（姓名、邮箱、公司、部门）和创建时间由系统自动记录。
- 支持多轮回复，每轮记录回复人和回复时间。
- 工单按公司隔离，不同公司的工单互不可见。
- 工单支持完整生命周期状态流转：创建 → 待分配 → 待处理 → 完成 / 取消。

### 5.2 工单分配

- 管理员可为某个公司增加多个业务组，每个业务组可设置成员。
- 管理员可配置分配规则：将某公司的某分类工单自动分配到指定业务组。
- 工单创建后，系统按分类匹配分配规则，自动分配到对应业务组并流转到待处理状态。

### 5.3 工单协作（转派）

- 处理人可将工单转派给其他业务组。
- 转派后工单状态保持待处理，接收方为目标业务组。
- 转派操作记录在操作日志中。

### 5.4 工单处理

- 处理工单时，处理人可查看提交人完整信息：姓名、公司、部门、历史工单列表。
- 工单完成后，系统记录处理人和处理时间。
- 工单完成时，系统发送邮件通知提交人（发送到提交人邮箱）。

### 5.5 用户评价

- 工单完成后，提交人可对工单进行满意度评价。
- 评价与工单关联保存，可在工单详情中查看。

### 5.6 统计分析

- 支持按公司维度统计工单分布。
- 支持按部门维度统计工单分布。
- 统计分析仪表盘展示以下运营指标：
  - 工单量
  - 平均响应时间
  - 满意度
  - 热点问题

### 5.7 工单工作台

- 查看待处理工单列表。
- 支持筛选（含按公司维度筛选）。
- 支持搜索。
- 支持排序。

### 5.8 操作日志

- 记录工单相关操作日志，包括但不限于创建、分配、转派、处理、完成、取消等操作。
- 日志记录操作人、操作时间和操作类型。

## 6. 验收场景

### AC-01：工单创建与生命周期管理

- 验收条件：提交人可创建工单，工单经历完整状态流转，支持多轮回复，且按公司隔离。
- 入口类型：用户界面
- 验证动作：提交人创建一个包含主题、描述、分类和SLA优先级的工单；另一用户回复该工单；将工单状态流转到完成；尝试从其他公司账号查看该工单。
- 预期结果：
  - 工单创建成功，自动记录提交人信息（姓名、邮箱、公司、部门）和创建时间，初始状态为创建/待分配。
  - 回复成功保存，记录回复人和回复时间，支持多轮回复。
  - 工单可从待分配流转到待处理，再流转到完成。
  - 其他公司账号无法查看该工单。
- 证据类型：interaction, session-persistence

### AC-02：业务组配置与自动分配

- 验收条件：管理员可为公司配置业务组和分配规则，工单创建后按分类自动分配到业务组。
- 入口类型：用户界面
- 验证动作：管理员为公司A创建业务组"技术支持组"并添加成员；配置分配规则——分类为"技术问题"的工单自动分配到"技术支持组"；提交人在公司A下创建分类为"技术问题"的工单。
- 预期结果：
  - 业务组创建成功，成员添加成功。
  - 分配规则配置成功。
  - 工单创建后自动匹配规则，分配到"技术支持组"，状态流转到待处理。
- 证据类型：interaction, session-persistence

### AC-03：工单转派

- 验收条件：处理人可将工单转派到其他业务组，转派后目标业务组可接收该工单。
- 入口类型：用户界面
- 验证动作：处理人对一个待处理工单执行转派操作，选择目标业务组；目标业务组成员查看工单列表。
- 预期结果：
  - 转派操作成功，工单出现在目标业务组的待处理列表中。
  - 转派操作记录在操作日志中。
- 证据类型：interaction, session-persistence

### AC-04：工单处理与邮件通知

- 验收条件：处理人可查看提交人完整信息，工单完成后记录处理人和处理时间并发送邮件通知。
- 入口类型：用户界面
- 验证动作：处理人打开待处理工单详情页查看提交人信息；处理后将工单标记为完成。
- 预期结果：
  - 工单详情页展示提交人完整信息：姓名、公司、部门、历史工单列表。
  - 工单完成后记录处理人和处理时间。
  - 系统向提交人邮箱发送工单完成通知邮件。
- 证据类型：interaction, session-persistence

### AC-05：用户满意度评价

- 验收条件：工单完成后，提交人可对工单进行满意度评价，评价与工单关联。
- 入口类型：用户界面
- 验证动作：提交人打开已完成的工单，进行满意度评价并提交。
- 预期结果：
  - 评价提交成功，与工单关联保存。
  - 评价结果可在工单详情中查看。
- 证据类型：interaction, session-persistence

### AC-06：统计分析与仪表盘

- 验收条件：可按公司和部门维度查看工单分布，仪表盘展示工单量、平均响应时间、满意度和热点问题。
- 入口类型：用户界面
- 验证动作：进入统计分析仪表盘，切换公司维度和部门维度查看工单分布。
- 预期结果：
  - 仪表盘展示工单分布数据，可按公司和部门维度切换。
  - 仪表盘展示工单量、平均响应时间、满意度、热点问题指标。
- 证据类型：interaction, visual-style

### AC-07：工单工作台

- 验收条件：工单工作台可查看待处理工单列表，支持筛选、搜索、排序和按公司维度筛选。
- 入口类型：用户界面
- 验证动作：进入工单工作台，执行搜索关键词、按公司筛选、按字段排序操作。
- 预期结果：
  - 工作台展示待处理工单列表。
  - 搜索可按关键词过滤工单。
  - 筛选可按公司维度过滤工单。
  - 排序可按指定字段排列工单。
- 证据类型：interaction

### AC-08：操作日志记录

- 验收条件：工单相关操作均记录操作日志，包含操作人、操作时间和操作类型。
- 入口类型：用户界面
- 验证动作：执行工单创建、分配、转派、完成等操作后，查看操作日志。
- 预期结果：
  - 每个操作在日志中有对应记录。
  - 日志记录操作人、操作时间和操作类型。
- 证据类型：interaction, session-persistence

## 7. 未规定事项

| 事项 | 说明 |
|------|------|
| 工单取消的触发者和条件 | 用户未规定，保持未规定 |
| 满意度评价的具体形式（星级/分数） | 用户未规定，保持未规定，由设计阶段决定 |
| 平均响应时间的计算口径 | 用户未规定具体计算方式，保持未规定 |
| 热点问题的判定标准 | 用户未规定具体判定逻辑，保持未规定 |
| 自动分配未匹配规则时的行为 | 推荐基线：保持待分配状态等待手动分配 |
| 公司内个人/业务组级别的工单可见性规则 | 推荐基线：公司内按角色可见，提交人看自己的工单，处理人看分配到本组的工单 |
| 邮件通知的内容模板 | 用户未规定，保持未规定 |
| 工单列表排序的默认排序字段 | 用户未规定，保持未规定 |
