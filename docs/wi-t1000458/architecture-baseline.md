# 教师管理系统 — 架构基线

## 需求基线引用

本设计基于已批准的需求快照 `docs/wi-t1000458/requirements.md`（sha256: `480fd7c8efd117d9cc23046dd91959cb0f65bf6ebf728f75a0da35d3140c40ba`），不扩展或修改产品语义。

## 应用类型

单用户前端 CRUD 应用，路线为 `simple-frontend`。

## 页面与交互范围

应用为单页应用（SPA），包含一个主视图：

- **教师列表视图**：以表格展示所有教师记录，每行包含教师名称、教授课程、年级、手机、邮箱字段，并在每行提供编辑和删除操作入口。
- **新增教师**：通过列表页顶部的新增按钮打开表单（弹窗或内联），填写五个字段后保存，成功后返回列表。
- **编辑教师**：点击列表行的编辑按钮打开预填表单，修改字段后保存，成功后返回列表。
- **删除教师**：点击列表行的删除按钮执行删除，成功后该行从列表消失。

所有交互在同一页面内完成，不涉及路由跳转或多页面导航。

## 浏览器状态与数据归属

- 教师记录存储在浏览器 `localStorage` 中，以 JSON 数组形式持久化。
- 数据在同一浏览器配置文件中刷新或重新打开页面后仍保留；不会与其他浏览器、设备或用户共享。
- 不存在服务端权威数据、数据库、认证/权限、后台任务或外部集成。
- 应用对 `localStorage` 的读写由应用自身负责，构成唯一的数据读写边界。

## 数据模型

每条教师记录为以下结构：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | string | 记录唯一标识，新增时由应用生成（如 `crypto.randomUUID()`） |
| name | string | 教师名称 |
| course | string | 教授课程 |
| grade | string | 年级 |
| phone | string | 手机号码 |
| email | string | 电子邮箱 |

## 接口与校验边界

- **新增/编辑表单校验**：五个业务字段（教师名称、教授课程、年级、手机、邮箱）均为必填；手机和邮箱需符合基本格式校验（手机为数字串，邮箱含 `@` 分隔符）。校验不通过时阻止保存并提示用户。
- **删除操作**：执行前需用户确认，避免误删。
- **localStorage 读写**：应用通过封装的存储函数统一读写，写入失败时向用户提示错误。

## 实现入口与运行方式

- 技术栈：React + Vite SPA。
- 新建应用使用 Vite 开发服务器启动，运行命令为 `npm run dev`。
- 应用入口为 `src/App.jsx`（或等效根组件），负责组合列表、表单和存储逻辑。
- 构建产物为静态前端文件，部署时由静态服务器承载。
